# Project Onboarding Plan

## Goal

Implement a narrow P1 project-onboarding slice that lets an agent or human send
one clear message, inspect a repository, and preview or create a draft
`.awf/workspace.yml` without launching a workspace. The path must be useful for
Codex, Claude Code, Gemini, OpenCode, OpenClaw, and humans, while remaining
generic AWF core behavior.

## Intended Files And Modules To Touch

- `docs/PROJECT_ONBOARDING.md`
  - Add the human/agent onboarding contract, copy-paste one-message prompt, CLI
    examples, preview interpretation, and the no-auto-launch smoke request
    shape.
- `src/awf/profiles/onboarding.py`
  - New small module for repo inspection, template selection, draft profile
    generation, YAML serialization, preview diagnostics, and smoke request
    construction.
  - Keep outputs typed with Pydantic or small dataclasses and build
    `WorkspaceProfile` objects using existing schema models.
- `src/awf/profiles/registry.py`
  - Reuse existing detector helpers where practical; only expose narrowly
    scoped helpers if needed for onboarding tests.
  - Avoid changing existing resolution order unless a test proves onboarding
    needs it.
- `src/awf/cli/main.py`
  - Add `awf profile init <path>` under the existing `profile_app`.
  - Default behavior: preview only, print structured output, and do not write
    `.awf/workspace.yml`.
  - Add `--write` to create `.awf/workspace.yml`, `--force` to overwrite, and
    `--include-smoke-request` to include an optional workspace request body.
- `tests/unit/profiles/test_project_onboarding.py`
  - New focused unit tests for detection, draft generation, diagnostics, and
    smoke request shape.
- `tests/unit/cli/test_cli.py` or `tests/unit/cli/test_profile_init.py`
  - Add CLI coverage for preview, write, no-overwrite, and smoke request output.

No migrations, lockfiles, service code, adapters, or frontend files should be
touched for this slice.

## Tests To Write First

Follow strict TDD. Add these tests before implementation and confirm the focused
test file fails for missing module/command or missing behavior.

1. `tests/unit/profiles/test_project_onboarding.py`
   - `test_detects_generic_template_for_unknown_repo`
     - Empty repo selects `generic`, low confidence, and reports missing
       validation commands.
   - `test_detects_python_template_and_generates_valid_profile`
     - `pyproject.toml` or `requirements.txt` produces a valid
       `WorkspaceProfile` with setup and `pytest -q` validation.
   - `test_detects_node_nextjs_template_from_package_json`
     - `package.json` with `next` selects the Node/Next.js template, package
       manager from lockfile, lint/test/build commands from scripts where
       present, and a valid draft profile.
   - `test_detects_docker_compose_template_and_reports_gaps`
     - `docker-compose.yml` selects Docker Compose/DinD, includes compose file
       setup/cleanup, and reports missing service health checks or ports when
       compose lacks them.
   - `test_detects_python_postgres_template`
     - Python repo with database signals, such as `alembic.ini`, `psycopg`,
       `asyncpg`, or `DATABASE_URL`, drafts a Postgres sidecar, database URL
       env, and a Postgres health check without embedding raw secrets.
   - `test_detects_node_playwright_template`
     - Node repo with `@playwright/test` or `playwright.config.*` includes a
       browser/Playwright validation command and reports missing app port or
       health check when no endpoint is detectable.
   - `test_detects_multi_service_template_when_compose_has_multiple_services`
     - Multi-service compose input selects a multi-service/DinD draft and
       reports services missing health checks, secrets, or exposed endpoints.
   - `test_preview_reports_missing_sections`
     - Preview diagnostics include separate `missing_services`,
       `missing_secrets`, `missing_ports`, `missing_validation_commands`, and
       `missing_healthchecks` lists.
   - `test_draft_yaml_round_trips_through_workspace_profile_schema`
     - Generated YAML parses with `yaml.safe_load` and validates through
       `WorkspaceProfile.model_validate`.
   - `test_smoke_request_shape_is_optional_and_does_not_launch`
     - Smoke request is omitted by default; when requested, output includes a
       v2 request-shaped dict with `workspace.profile` inline or `profile_ref`,
       sample repo/task/validation fields, and no API call side effect.

2. CLI tests
   - `test_profile_init_preview_prints_profile_and_diagnostics`
     - `CliRunner` invokes `awf profile init <tmp_repo>` and sees draft profile
       data plus missing-section diagnostics; no file is written.
   - `test_profile_init_write_creates_awf_workspace_yml`
     - `--write` creates `.awf/workspace.yml` and validates the contents.
   - `test_profile_init_refuses_to_overwrite_without_force`
     - Existing `.awf/workspace.yml` returns non-zero unless `--force` is set.
   - `test_profile_init_includes_optional_smoke_request`
     - `--include-smoke-request` includes the smoke request payload and still
       does not call the AWF API.

## Implementation Steps

1. Add failing tests for onboarding detection, profile draft generation, preview
   diagnostics, CLI behavior, and optional smoke request output.
2. Implement `src/awf/profiles/onboarding.py` with these small public functions:
   - `inspect_project(path: Path) -> ProjectInspection`
   - `draft_workspace_profile(inspection: ProjectInspection, template: str = "auto") -> DraftProfile`
   - `preview_project_onboarding(path: Path, template: str = "auto", include_smoke_request: bool = False) -> ProjectOnboardingPreview`
   - `write_workspace_profile(preview: ProjectOnboardingPreview, force: bool = False) -> Path`
3. Keep detection heuristic and deterministic:
   - `generic`: no known signals.
   - `python`: `pyproject.toml`, `requirements.txt`, `uv.lock`, or `pytest.ini`.
   - `node-nextjs`: `package.json`, lockfiles, and `next` dependency or config.
   - `docker-compose`: standard compose filenames.
   - `python-postgres`: Python plus Postgres/database signals.
   - `node-playwright`: Node plus Playwright dependency/config.
   - `multi-service`: compose with multiple services or common service
     directories such as `apps/`, `services/`, `backend/`, `frontend/`.
4. Generate profile drafts using existing `WorkspaceProfile`, `ProfileService`,
   `ProfileCommand`, `ProfileDocker`, `ProfileRuntime`,
   `ProfileHealthCheck`, `ProfileSecret`, and `ProfileValidation` models.
5. Serialize YAML with `yaml.safe_dump(sort_keys=False)` from
   `profile.model_dump(mode="json", exclude_none=True, by_alias=True)`.
6. Implement diagnostics from the generated profile and inspection:
   - Missing services: detected dependencies such as Postgres, Redis, browser,
     or compose services without corresponding profile service/compose plan.
   - Missing secrets: `${VAR}` placeholders or likely token env names that lack
     profile `secrets` declarations.
   - Missing ports: app/service endpoints not represented in `ports`.
   - Missing validation commands: no test/lint/build command could be inferred.
   - Missing health checks: services or endpoints without health checks.
7. Add `awf profile init` as a local filesystem command:
   - Default preview: emit JSON by default and pretty output when requested.
   - `--write`: create parent `.awf/` and write `.awf/workspace.yml`.
   - `--force`: allow overwrite.
   - `--template`: allow explicit template override for humans/agents.
   - `--include-smoke-request`: include optional request body only; never call
     `_call` or launch a workspace.
8. Add `docs/PROJECT_ONBOARDING.md` after behavior is green:
   - One-message prompt for each agent/human path.
   - Recommended `awf profile init . --format pretty` and `--write` workflow.
   - Template summary and what preview gaps mean.
   - Smoke request example clearly marked as optional and not auto-launched.
   - Guidance for adding secrets without raw secret values.


## Risks And Assumptions

- Detection is heuristic. The preview must expose uncertainty and missing
  fields instead of pretending the draft is production-ready.
- Compose parsing can become large quickly. Keep the first pass to service
  names, environment placeholders, ports, healthcheck presence, and compose file
  references.
- Python+Postgres and Node+Playwright signals vary by project. Tests should
  pin only deterministic signals and diagnostics.
- Existing `WorkspaceProfile` schema is sufficient for this slice. If a field
  is not representable, report it as a preview gap rather than expanding the
  schema.
- OpenClaw does not require a new adapter in this task. The onboarding contract
  should remain agent-neutral and useful to any agent that can run the CLI or
  read the docs.
- Generated profiles must not contain raw secrets. Use placeholders and profile
  secret declarations only.

## Explicit Non-Goals

- Do not auto-create workspaces, call the AWF API, push branches, open PRs, or
  start Docker services from `awf profile init`.
- Do not add a new agent adapter or alter Codex, Claude Code, Gemini,
  OpenCode, or OpenClaw execution behavior.
- Do not implement full compose-to-AWF service conversion for arbitrary Compose
  syntax.
- Do not add cloud secret leasing, egress enforcement changes, migrations, or
  scheduler changes.
- Do not lower coverage, lint, mypy, profile validation, or PR monitor quality
  gates.
