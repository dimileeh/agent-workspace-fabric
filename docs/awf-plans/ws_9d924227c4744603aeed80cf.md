# Plan: Advisory Overlap Coordination Warnings

## Goal

Implement a narrow scheduler/coordination slice that turns owned-path overlap
data from the advisory overlap graph into non-blocking coordination warnings for
agents and operators.

The feature must:

- keep owned-path overlap advisory only; workspace submission remains admitted;
- attach a bounded overlap/stale-policy coordination summary to workspace
  metadata;
- include that warning in agent planning and execution prompts;
- expose the warning through API/console-safe typed surfaces without leaking
  unbounded metadata.

## Current Code Landmarks

- `src/awf/service/workspaces.py`
  - `create_workspace_v2_row()` already computes active owned-path overlaps,
    writes an admitted `QueueDecision`, records `overlap_risk_summary`, and
    emits a `workspace.owned_path_overlap_risk` event.
  - `retry_workspace_row()` recomputes overlap events for retries.
  - Existing behavior is already non-blocking and must stay that way.
- `src/awf/service/overlap_graph.py`
  - Builds advisory graph nodes/edges with `severity="advisory"` and
    `blocks_launch=False`.
  - Has richer path match data than the current workspace warning payload.
- `src/awf/runtime/planning.py`
  - Builds planning, execution, and conformance prompts.
  - Currently accepts only the task prompt and artifact paths.
- `src/awf/control/executor.py`
  - `_run_agent_task_with_optional_planning()` passes `workspace.task_prompt`
    directly to non-planning agents and to planning/execution prompt builders.
- `src/awf/api/schemas.py`, `src/awf/service/workspace_observability.py`
  - Detail responses expose `latest_queue_decision`, but overview does not
    currently expose coordination warnings as a typed field.
- `apps/console/lib/types.ts` and `apps/console/components/console-dashboard.tsx`
  - Console can read queue decision dictionaries indirectly, but lacks a typed,
    compact coordination-warning display helper.

## Implementation Steps

1. Add a shared coordination warning shape

   Intended files:

   - `src/awf/api/schemas.py`
   - `src/awf/service/overlap_graph.py`
   - `src/awf/service/workspaces.py`

   Concrete approach:

   - Add Pydantic response models, likely:
     - `CoordinationOverlapResponse`
     - `WorkspaceCoordinationWarningResponse`
   - Keep fields bounded and operator-safe:
     - `warning_code`
     - `message`
     - `severity`
     - `blocks_launch`
     - `workspace_ids`
     - `overlaps`
     - `stale_policy_context`
     - optional truncation/count fields if needed.
   - Add a small helper that converts active overlap data into this shape using
     the same owned-path comparator as `overlap_graph.py`. Prefer reusing or
     extending overlap-graph helpers so the prompt/API context and graph agree
     on `severity="advisory"` and `blocks_launch=False`.

2. Persist workspace metadata without a migration

   Intended files:

   - `src/awf/service/workspaces.py`
   - possibly `src/awf/db/models.py` only if adding a read-only property; no new
     columns planned.

   Concrete approach:

   - Store the warning context inside existing JSON `Workspace.task_policy`,
     for example:

     ```json
     {
       "coordination": {
         "warnings": [
           {
             "warning_code": "OWNED_PATH_OVERLAP_RISK",
             "severity": "advisory",
             "blocks_launch": false,
             "stale_policy_context": {
               "trigger_type": "path_overlap",
               "stale_reason_code": "STALE_OVERLAP"
             }
           }
         ]
       }
     }
     ```

   - Merge with existing task policy fields such as `agent_model` and
     `out_of_scope_changes`; do not overwrite them.
   - For retries, recompute the warning from currently active overlaps so stale
     retry metadata does not carry old workspace ids.
   - Keep the existing `QueueDecision.overlap_risk_summary` keys compatible, or
     update exact tests intentionally if the summary is enriched.

3. Expose API-safe warnings

   Intended files:

   - `src/awf/api/schemas.py`
   - `src/awf/service/workspaces.py`
   - `src/awf/service/workspace_observability.py`

   Concrete approach:

   - Add `coordination_warnings: list[WorkspaceCoordinationWarningResponse]`
     with `default_factory=list` to `WorkspaceResponse` and
     `WorkspaceOverviewResponse`.
   - Populate it from sanitized `workspace.task_policy["coordination"]`.
   - Preserve the existing accepted-response `warnings` field for submission
     compatibility.

4. Add prompt rendering helpers

   Intended files:

   - `src/awf/runtime/planning.py`
   - `src/awf/control/executor.py`

   Concrete approach:

   - Add a small pure renderer, for example
     `render_coordination_warning_section(warnings) -> str`.
   - Extend `build_planning_prompt()` and `build_execution_prompt()` with an
     optional `coordination_warnings` parameter defaulting to an empty tuple.
   - Add a direct-run helper for non-planning workspaces so the bare task prompt
     is also preceded by coordination warnings when present.
   - The warning language should be explicit:
     - overlap is advisory and does not block launch;
     - coordinate around listed workspace ids/paths;
     - if target branch changes land in overlapping owned paths first, AWF stale
       policy may require rebase/revalidation via `STALE_OVERLAP`.
   - Do not add warnings to conformance prompts unless tests show a need; the
     task asks for planning/execution prompts.

5. Console visibility

   Intended files:

   - `apps/console/lib/types.ts`
   - `apps/console/lib/types-contract.test.ts`
   - new `apps/console/lib/coordination-format.ts`
   - new `apps/console/lib/coordination-format.test.mjs`
   - `apps/console/components/console-dashboard.tsx`

   Concrete approach:

   - Add TS interfaces mirroring the API response models.
   - Add a formatter that produces compact text such as
     `1 advisory overlap: ws_... src/** -> src/file.py`.
   - Show warnings in workspace summary/task details as a small amber advisory
     block or chip.
   - Keep display bounded and tolerant of missing fields for legacy API
     payloads.

## Risks And Mitigations

- Prompt bloat from many overlaps.
  - Bound rendered warnings by count and include truncation metadata.
- Divergence between queue-decision summaries, events, prompt context, and
  overlap graph.
  - Centralize warning construction and reuse the overlap comparator/path-match
    explanation helpers.
- Accidentally treating overlap as a lock or blocker.
  - Assert `blocks_launch is False`, queue decision stays `admitted`, and all
    high-risk classes remain non-blocking.
- Legacy workspaces without coordination metadata.
  - API and console should default to empty lists and tolerate missing fields.
- Stale policy confusion.
  - Prompt wording must say stale policy may require rebase/revalidation after
    target changes land; it must not imply the workspace is stale at launch.

## Assumptions

- Existing JSON `Workspace.task_policy` is acceptable for this narrow metadata
  slice, avoiding a migration.
- Active overlap scope remains the existing active statuses used by
  `ACTIVE_OWNED_PATH_OVERLAP_STATUSES` and the overlap graph.
- `OWNED_PATH_OVERLAP_RISK` remains the public warning code.
- `STALE_OVERLAP` / `path_overlap` are the right stale-policy references for
  overlapping owned paths once target branch changes land.

## Explicit Non-goals

- Do not add exclusive lock semantics.
- Do not block, delay, or reorder workspace admission based on owned-path
  overlap.
- Do not change merge eligibility or stale detection behavior beyond exposing
  context in metadata/prompts.
- Do not add a database migration unless implementation proves existing JSON
  metadata is insufficient.
- Do not change PR monitor merge behavior, branch management, push behavior, or
  AWF workspace lifecycle ownership.
