# Plan: P1 Profile-Defined App Endpoints

## Scope

Implement a narrow workspace-services slice for profile-declared app endpoints. A repo-local `.awf/workspace.yml` should be able to declare named endpoints with a service, port, URL path, health metadata, and visibility. AWF should resolve those endpoints into stable internal URLs for the agent container and validation commands, and expose only console-safe endpoint metadata through workspace detail and runtime responses.

The slice stays generic for Python, Node, and Compose-style local profiles. It does not add Kubernetes, GKE, ingress, reverse proxy, public tunneling, or Aira-specific behavior.

   - Extend `types.ts` and type-contract assertions so the console consumes the same endpoint shape as the API.

   - Add the Pydantic models and cross-field validation.
   - Add endpoint URL/environment resolution helpers.
   - Add sanitized API projection in one shared service helper.
   - Extend API schemas and console types.
   - Add minimal UI rendering in the existing runtime/detail panel.

7. Run targeted tests, then broader validation.
   - Keep changes scoped to endpoint metadata and generated agent/validation environment exposure.
   - Commit only during the implementation phase, not during this planning phase.

## Risks and Assumptions

- `app_endpoints` is a new explicit profile field. Existing `ports` remains supported as legacy profile metadata, but it is too ambiguous to infer service, path, health, and visibility safely.
- Endpoint URLs are internal Compose-network URLs for the agent and validation commands. They are not guaranteed to be reachable from the operator browser or host shell.
- Console-safe endpoint metadata must be derived from structured endpoint fields, not copied from arbitrary environment variables or legacy `ports` values.
- Profile `resolved_profile` is already persisted as JSON; this slice should not require a database migration.
- Validation commands run inside the agent container, so generated agent environment variables are sufficient for command access.
- The endpoint metadata shape should be additive for API clients. Existing workspace and runtime fields must remain backward-compatible.
- Query strings and URL userinfo are treated as unsafe for this slice. If a project needs tokens, it should use profile secrets or runtime env, not endpoint metadata.

## Non-Goals

- Do not add Kubernetes, GKE, cloud ingress, service mesh, public URL allocation, or host port publishing.
- Do not make app endpoints browser-clickable unless a later slice adds a host-safe proxy or published URL contract.
- Do not replace or remove the existing `ports` profile field.
- Do not redesign service healthchecks, Compose rendering, Docker lifecycle, or validation retry behavior beyond using endpoint metadata where needed.
- Do not add Aira-specific database, pgvector, Alembic, or service assumptions.
- Do not lower coverage targets, loosen profile linting, or bypass existing quality gates.
- Do not switch branches, push, rebase, or commit during this planning phase.
