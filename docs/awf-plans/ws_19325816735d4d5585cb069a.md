# Plan: Executor Worktree-Missing Reliability Fix

## Goal

Make `WorkspaceExecutor` stop cleanly when AWF's managed worktree path disappears during executor-owned work. A missing or non-directory worktree should be treated as an infrastructure problem, not as another validation failure that can enter repeated fix passes.

Expected user-visible outcome:

- workspace transitions to `failed` with `failure_reason = infrastructure_failure`
- actionable reason code/message uses `WORKTREE_MISSING`
- failure message names the missing path and executor action that needed it
- workspace event/log exposes the root cause for API and console timelines
- active validation operations are finished as failed when the worktree disappears during validation/fix-cycle
- operator `cancelled`, `destroying`, or `destroyed` status continues to win over executor failure handling

The PRD supports this shape: failed attempts need a failure taxonomy plus human-readable reason, and infrastructure failures cover storage/control-plane workspace failures.

## Current Code Context

Relevant implementation already lives primarily in `src/awf/control/executor.py`. The executor has these important seams:

- `_recheck_status(...)` and `_transition_if_current(...)` preserve stale-status/operator-control races.
- `_mark_failed(...)` refuses to convert a workspace if the status has moved since the expected phase.
- `_finish_pending_validate_operations(...)` and `_finish_pending_validate_operations_in_session(...)` are the right API/console operation-completion path for validation requests.
- post-agent commit, validation fix-cycle, and PR push all run git or PR operations against `worktree_path = config.worktrees_root / workspace_id`.

There is also nearby test coverage in:

- `tests/unit/control/test_executor_error_paths.py`
- `tests/unit/control/test_executor_validation_fix_cycle.py`
- `tests/unit/control/test_executor.py`

If the current branch already contains partial worktree guards or tests, the implementation phase should keep them, verify the exact contract below with failing/green tests, and only tighten missing behavior.

## Intended Files And Modules To Touch

  - Use a shared reason code constant: `WORKTREE_MISSING`.

  - Call the guard before validation fix-agent runs and before fix-pass git add/diff/commit.
  - Call the guard after successful validation and before PR push/open.

  - Preserve existing stale-status behavior by re-reading workspace status before marking failure.

## Tests To Write First

1. `test_missing_worktree_before_post_agent_commit_marks_infrastructure_failure`

   Location: `tests/unit/control/test_executor_error_paths.py`

   Setup:
   - Seed a ready workspace.
   - Do not create `config.worktrees_root / workspace_id`.
   - Queue only the initial successful agent adapter result.

   Assertions:
   - workspace status is `failed`
   - `failure_reason == "infrastructure_failure"`
   - `failure_message` includes `WORKTREE_MISSING`, the action `post_agent_commit`, and the path
   - a workspace event has `event_type == "workspace.executor_worktree_missing"` and `reason_code == "WORKTREE_MISSING"`
   - no git calls are made after the guard trips

2. `test_missing_worktree_during_fix_pass_stops_without_repeated_attempts`

   Location: `tests/unit/control/test_executor_validation_fix_cycle.py`

   Setup:
   - Seed a ready workspace with a real fake worktree directory.
   - Insert a pending or running `OperationType.validate` operation.
   - Queue initial agent and post-agent commit success.
   - Queue initial validation failure.
   - Let the fix-agent invocation return, then remove the worktree before fix-pass git add or before the next guarded fix-pass git step.

   Assertions:
   - workspace status is `failed`
   - `failure_reason == "infrastructure_failure"`
   - failure event/reason code is `WORKTREE_MISSING`
   - validate operation status is `failed`
   - validate operation `error_code == "WORKTREE_MISSING"`
   - operation result includes the current `validation_run_id`
   - no second validation command runs
   - no second fix-agent pass runs
   - final workspace failure is not `validation_failure`

3. `test_missing_worktree_before_pr_push_marks_infrastructure_failure`

   Location: `tests/unit/control/test_executor_error_paths.py`

   Setup:
   - Drive executor through successful initial commit and validation.
   - Remove the worktree after validation succeeds and before PR push/open.

   Assertions:
   - workspace fails from `pushing` with `infrastructure_failure`
   - reason/event code is `WORKTREE_MISSING`
   - no `git push` or `gh pr create` is attempted

4. `test_cancelled_or_destroyed_status_wins_over_missing_worktree`

   Location: `tests/unit/control/test_executor_error_paths.py`

   Setup:
   - Parameterize over `WorkspaceStatus.cancelled` and `WorkspaceStatus.destroyed`.
   - Simulate the workspace row moving to the operator-controlled status before the missing-worktree helper would mark it failed.
   - Ensure the worktree is missing at that point.

   Assertions:
   - final status remains `cancelled` or `destroyed`
   - `failure_reason` remains unset
   - stale-status skip behavior/event remains intact
   - no `WORKTREE_MISSING` failure transition converts the workspace to failed

Test mechanics:

- Use real temporary directories and `shutil.rmtree(...)` to create the missing-worktree condition.
- A small fake runner that removes the worktree after a specific subprocess call is acceptable.
- Do not monkeypatch the guard to skip behavior.
- Do not add skips, xfails, empty assertions, or broad monkeypatches that bypass the executor path.

## Implementation Steps

1. Define or verify executor-level constants/helpers:

   - `WORKTREE_MISSING_REASON_CODE = "WORKTREE_MISSING"`
   - `_worktree_missing_message(worktree_path: Path, action: str) -> str`
   - `_ensure_worktree_available(...) -> bool`

2. Guard behavior:

   - Return `True` when `worktree_path.is_dir()` is true.
   - Re-read the workspace row before failing anything.
   - If the row is absent, return `False` without crashing.
   - If the row status is not the expected executor status, record existing stale-status skip behavior and return `False`.
   - If the row is still in the expected status, log `executor.worktree_missing`.
   - Add workspace event `workspace.executor_worktree_missing` with reason code `WORKTREE_MISSING` and payload containing `action` and `worktree_path`.
   - Set `failure_reason = infrastructure_failure`, set an actionable failure message, and transition to `failed` with reason code `WORKTREE_MISSING`.

3. Validation/fix-cycle behavior:

   - Pass `validation_run_id` and requested tier into the guard for validation/fix-cycle checks.
   - When the guard trips with validation context, finish pending/running validate operations with:
     - `status = failed`
     - `error_code = WORKTREE_MISSING`
     - `error_message = _worktree_missing_message(...)`
     - `result.validation_run_id = current validation run id`
     - `result.requested_tier = requested tier`
     - `result.reason_code = WORKTREE_MISSING`
   - Do not start another fix pass after this infrastructure stop.

4. Guard call sites:

   - After `post_agent_commit` status recheck and before branch-drift/base-commit git operations.
   - Before invoking the validation fix-agent.
   - Before fix-pass `git add -A`.
   - Before fix-pass cached diff.
   - Before fix-pass commit.
   - After transition to `pushing` and before `PullRequestCreator.push_and_open(...)`.

5. Test helper updates:

   - Make executor test seed helpers create fake worktree directories by default where full execution is expected.
   - Keep an explicit `create_worktree=False` opt-out for missing-worktree tests.
   - Keep queued fake subprocess results minimal so tests prove short-circuiting by exhausted/unused calls.

## Risks And Assumptions

- Existing executor tests may rely on fake git subprocess calls without creating real worktree directories. Helper-level directory creation should keep that churn small.
- A missing path and a path that is not a directory are intentionally treated the same.
- Corrupt `.git` metadata, detached HEAD, permission errors, missing remotes, and push authentication failures stay on existing git/PR error paths unless a test exposes a direct missing-worktree misclassification.
- If operator destroy removes the directory before the database status changes, the executor can legitimately report `WORKTREE_MISSING`. If the database already records cancelled/destroyed/destroying, operator status must win.
- The validation run that captured the original test failure may remain failed with its original reason code. The executor stop reason and active operation error should carry `WORKTREE_MISSING`.
- No worktree recreation or reprovisioning is attempted here. Provisioning/cleanup owns lifecycle; the executor only detects and reports the lost invariant.

## Explicit Non-Goals

- Do not change the workspace state machine.
- Do not add a new `FailureReason` enum value.
- Do not weaken coverage thresholds, workspace coverage requirements, PRD coverage targets, or quality gates.
- Do not retry missing-worktree failures.
- Do not hide git failures behind generic retries.
- Do not change PR monitor, merge queue, GitManager, Provisioner, worker scheduling, or cleanup behavior unless a focused test proves an executor integration requirement.
- Do not manually push, rebase, switch branches, create PRs, or merge.
