# Plan: Executor Worktree-Missing Reliability Fix

## Goal

Make `WorkspaceExecutor` fail fast with an actionable infrastructure failure when AWF's managed worktree path disappears during executor-owned work, instead of letting git failures drive misleading validation retry loops.

Reason code: `WORKTREE_MISSING`

Expected terminal workspace failure:

- `status = failed`
- `failure_reason = infrastructure_failure`
- `failure_message` names the missing worktree path and the executor action that needed it
- workspace event/log includes `WORKTREE_MISSING` so the API and console can surface the root cause

## Intended Files To Touch

- `src/awf/control/executor.py`
  - Add a small private worktree guard/helper.
  - Call it before post-agent commit git operations.
  - Call it during the validation fix-cycle before fix-agent execution and before fix-pass git add/diff/commit.
  - Call it before PR push/open.
  - Finish active validation operations as failed when the guard trips while the workspace is in `validating`.
  - Preserve the existing stale-status behavior in `_recheck_status`, `_transition_if_current`, and `_mark_failed`.

- `tests/unit/control/test_executor_error_paths.py`
  - Add missing-worktree tests for post-agent commit, PR push/open, and cancelled/destroyed precedence.
  - Update local executor test helpers to create the fake worktree directory by default where full `execute()` paths need it.

- `tests/unit/control/test_executor_validation_fix_cycle.py`
  - Add the regression for the observed dogfood failure: worktree exists for initial validation, validation fails, then the worktree is removed before fix-pass git add.
  - Assert the executor stops immediately, marks infrastructure failure with `WORKTREE_MISSING`, finishes validate operations as failed, and does not run repeated fix attempts.
  - Update helper setup to create the fake worktree directory by default.

- `tests/unit/control/test_executor.py`
  - Update shared/full-path executor tests that use fake git calls so they create `tmp_path / "work" / "worktrees" / ws_id` before `execute()`.
  - Keep changes mechanical and limited to fixture/helper setup needed by the new real filesystem guard.

No migrations, enum changes, lockfile changes, profile changes, or API schema changes are planned. `WORKTREE_MISSING` can be stored as an event/operation reason code string while the coarse workspace failure remains the existing `FailureReason.infrastructure_failure`.

## Tests To Write First

1. `test_missing_worktree_before_post_agent_commit_marks_infrastructure_failure`
   - Seed a ready workspace.
   - Let the initial agent adapter call return success.
   - Ensure the managed worktree directory is absent before post-agent git work starts.
   - Assert:
     - workspace is `failed`
     - `failure_reason == "infrastructure_failure"`
     - failure message includes `WORKTREE_MISSING` or "worktree" plus the missing path
     - latest event reason code is `WORKTREE_MISSING`
     - no post-agent git commit/add/rev-list calls are made after the guard trips

2. `test_missing_worktree_during_fix_pass_stops_without_repeated_attempts`
   - Seed a ready workspace and create its worktree directory initially.
   - Create a running or pending `OperationType.validate` operation for the workspace.
   - Queue initial agent/commit results and an initial validation failure.
   - Run one fix-agent invocation, then remove the worktree before fix-pass `git add -A`.
   - Assert:
     - workspace is `failed`
     - `failure_reason == "infrastructure_failure"`
     - event/reason code is `WORKTREE_MISSING`
     - the validate operation is `failed` with `error_code == "WORKTREE_MISSING"`
     - there is no second validation command and no second fix-agent pass
     - the failure is not reported as `validation_failure`

3. `test_missing_worktree_before_pr_push_marks_infrastructure_failure`
   - Drive the executor through successful initial commit and validation.
   - Remove the worktree after validation success but before `PullRequestCreator.push_and_open`.
   - Assert:
     - workspace fails from the push stage with `infrastructure_failure`
     - reason/event code is `WORKTREE_MISSING`
     - `git push`/`gh pr create` is not attempted

4. `test_cancelled_or_destroyed_status_wins_over_missing_worktree`
   - Parameterize over `WorkspaceStatus.cancelled` and `WorkspaceStatus.destroyed`.
   - Simulate a race where the worktree is missing but the workspace row has already moved to operator-controlled terminal status before the missing-worktree failure helper would mark it failed.
   - Assert:
     - final status remains `cancelled` or `destroyed`
     - `failure_reason` remains unset
     - no `WORKTREE_MISSING` failure transition is recorded

Implementation tests should use real temporary directories/removal for the worktree condition. If a race needs exact timing, use a small local fake runner/helper that removes the directory after a specific recorded subprocess call; do not monkeypatch the guard to bypass behavior.

## Implementation Steps

1. Add constants/private helpers in `src/awf/control/executor.py`:
   - `WORKTREE_MISSING_REASON_CODE = "WORKTREE_MISSING"`
   - `_worktree_missing_message(worktree_path, action)`
   - `_ensure_worktree_available(...) -> bool`

2. The guard should:
   - Check `worktree_path.is_dir()` before git/agent/PR operations that require the checkout.
   - Log a structured event such as `executor.worktree_missing` with `workspace_id`, `action`, and `worktree_path`.
   - Re-read the workspace row before marking failure.
   - Only transition to `failed` if the row is still in the expected executor status.
   - If the row is already `cancelled`, `destroying`, `destroyed`, `completed`, or otherwise not the expected status, preserve stale-status behavior and return without converting it to failed.
   - Add a workspace event with reason code `WORKTREE_MISSING` and payload containing the action/path, then transition to `failed` with the same reason code.

3. Call the guard at these points:
   - After the `post_agent_commit` status recheck and before branch-drift/base-commit git work.
   - Inside the validation loop before invoking a validation fix-agent.
   - Immediately before fix-pass git add/diff/commit.
   - After transitioning to `pushing` and before `push_and_open`.

4. When the guard trips in the validation/fix-cycle:
   - Finish pending/running validate operations with `OperationStatus.failed`, `error_code = "WORKTREE_MISSING"`, and the actionable message.
   - Include the current validation run id in the operation result when one is available.
   - Do not rewrite an already-finished validation run that correctly recorded the test failure; the infrastructure failure is the executor stop reason and operation error.

5. Update affected executor tests to create fake worktree directories by default:
   - Prefer helper-level changes over per-test churn.
   - Allow opt-out/removal for the missing-worktree regressions.

## Risks And Assumptions

- Existing executor unit tests rely on fake git subprocesses and often do not create real worktree directories. Adding a real `Path.is_dir()` guard will require mechanical fixture updates, but this is expected and keeps tests honest.
- The guard detects a missing path or a path that is not a directory. It does not attempt to classify corrupt git metadata, detached HEAD issues, permissions problems, or missing remotes; those stay on existing git-error paths unless a later task expands the taxonomy.
- If an operator destroy removes the directory before the database status changes, the executor may mark `WORKTREE_MISSING` as infrastructure failure. If the database already shows cancelled/destroyed, operator status must win.
- Validation operations are the API/console-facing async operations; validation run provenance should remain accurate for commands that already finished before the worktree disappeared.
- No executor-side reprovisioning or worktree recreation is planned. AWF lifecycle/provisioning code owns creation and cleanup.

## Explicit Non-Goals

- Do not change the workspace state machine.
- Do not add a new `FailureReason` enum value.
- Do not change GitManager, Provisioner, PR monitor, merge queue, or worker scheduling behavior unless a test reveals a direct executor integration requirement.
- Do not retry missing-worktree failures.
- Do not weaken coverage thresholds, validation policy, or quality-gate protections.
- Do not manually push, rebase, switch branches, create PRs, or merge.
