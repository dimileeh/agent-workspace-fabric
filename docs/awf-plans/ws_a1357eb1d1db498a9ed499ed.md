## Implementation Approach

Add a generic supply-chain policy evaluator and plug it into the places AWF observes agent-produced command evidence or changed files. Reuse durable `PolicyFinding` rows so findings are visible through workspace detail and merge queue without creating a new data model.

The policy shape will live under `profile.security.supply_chain` and support warn/block modes per guardrail. I will keep the default compatibility-preserving posture non-blocking; tests will use explicit profile policy to prove warn and block behavior. The policy details will include allowed registry hosts and false-positive-safe command evidence handling.

Detection scope:

- Agent command evidence from `AgentRunResult.stdout/stderr` and `AgentRunError.result.stdout/stderr`, parsed conservatively from command-like evidence lines only, not arbitrary prose.
- Agent-authored changed paths before commit/push, including initial execution, validation-fix passes, and PR monitor repair/fix passes.
- Profile phase commands only if this can be done without blocking existing built-in setup semantics; otherwise the first implementation will focus on agent-run evidence and changed files per the backlog wording.

Structured finding reason codes:

- `SUPPLY_CHAIN_UNPINNED_DEPENDENCY_INSTALL`
- `SUPPLY_CHAIN_REMOTE_SCRIPT_EXECUTION`
- `SUPPLY_CHAIN_UNEXPECTED_REGISTRY_HOST`
- `SUPPLY_CHAIN_LOCKFILE_OUTSIDE_OWNED_PATHS`

Each finding will include severity, subject path or command evidence, explanation, and `details.recovery_guidance` with operator-facing next steps such as pin the dependency, use the lockfile-aware installer, add/declare the intended registry host, add the lockfile to owned paths, or remove the curl-pipe-shell pattern.

## Risks And Assumptions

- AWF cannot fully observe every subprocess an interactive coding agent runs inside its own CLI session. The implementation will use conservative command evidence from captured agent stdout/stderr plus changed-file evidence; it will avoid treating arbitrary prose as executed commands.
- Blocking before commit is safer than blocking only at merge, but it must preserve logs/findings and recovery guidance so operators can diagnose or redispatch.
- Existing built-in profiles intentionally run package setup commands (`npm ci`, `pnpm install --frozen-lockfile`, `uv pip install -e ...`). The scanner must not turn those known lockfile/local install patterns into noisy violations.
- Registry-host parsing should avoid recording full URLs with tokens or query strings. Findings should store host/category and a redacted command excerpt only.
- Existing `PolicyFinding` rows use `severity` values `warning` and `blocking`; reuse those instead of adding a migration.
- Coordination warning: this slice overlaps active work in `src/awf/service/**`, `src/awf/runtime/**`, `tests/unit/service/**`, `tests/unit/api/**`, and docs. Keep edits small and expect AWF stale policy to require revalidation if target-branch changes land first.
