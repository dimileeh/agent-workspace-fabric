## Scope and intent
Implement P1 pre-GKE hardening for callbacks without touching workspace API auth posture or broad delivery/retry architecture.

Goals:
- Enforce API token auth for callback create/list routes.
- Revalidate callback target at each delivery attempt.
- Add minimal callback policy settings for HTTPS-only and optional allowed host allowlist.
- Keep callback envelopes minimal and sanitized; tighten tests for envelope shape/absence of secrets/internals.

Out of scope (explicitly not to be implemented):
- Workspace create/list auth work.
- Request rate limiting.
- Rewriting callback storage, event generation, or retry scheduling.
- Full production secret management or fail-fast configuration beyond callback policy tests.
- Payload broadening beyond existing minimal envelope intent.

## Risks and assumptions
- DNS rebinding mitigation is limited to revalidation at delivery time using the same constrained checks as registration (plus optional policy); without a hardened resolver this remains bounded but not fully elimination of TOCTOU.
- `require_api_token` response status semantics are assumed to match existing token-gated routes in this codebase (likely 401 for missing, 403 for invalid); tests will lock this down.
- Allowlist syntax/normalization may require clarifying host canonicalization (IDN/lowercase/port handling); tests will define canonical policy.
- If `callback_events` schema lacks an existing explicit structured-failure location for validation failures, extension may be needed to preserve truthful retry metadata.
