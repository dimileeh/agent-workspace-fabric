# Plan: Docs/status consistency test for MCP client parity matrix

## Goal

Add an executable consistency test for `docs/MCP_CLIENT_PARITY.md` so the published API/CLI/MCP parity matrix cannot claim an implemented surface unless that surface is backed by real FastAPI routes, Typer CLI commands when documented, MCP tool registration, and contract-test coverage. Rows that are partial or missing/backlog must keep explicit unchecked backlog visibility instead of being treated as complete.

## Intended files/modules to touch

- `tests/unit/mcp/_parity_utils.py`
  - Extend the existing parser/helper module rather than creating a new parser.
  - Add shared normalizers for matrix cells as needed: status, backlog slice, REST endpoint extraction, MCP tool extraction, CLI command extraction, and implemented/partial/missing row classification.
- `tests/unit/mcp/test_mcp_parity_matrix_crossref.py`
  - Add or tighten tests that validate the published matrix against the real FastAPI route tree, Typer command tree, MCP tool registrations, and status/backlog semantics.
  - Prefer reusing existing extraction helpers already in this file where possible; move only broadly reused helpers into `_parity_utils.py` if that reduces duplication.
- `tests/unit/contracts/test_registry_smoke.py`
  - Extend the existing contract registry smoke tests so every matrix row marked `MCP implemented` with real operator capability coverage is represented by executable contract/parity coverage, or is explicitly documented as intentionally outside the contract harness with a non-implemented status/backlog.
- `tests/unit/contracts/_capabilities.py`
  - Update only if the new failing test exposes a real implemented matrix row missing from the contract registry.
  - Keep registry changes narrow and aligned with existing `ContractCapability` patterns.
- `docs/MCP_CLIENT_PARITY.md`
  - Update only if tests expose real docs drift, such as a row claiming `MCP implemented` without route/tool/CLI/contract backing, or a partial/missing row lacking an explicit `TODO§...` backlog reference.
- `TODO/pre-gke-industrial-readiness.md`
  - Check off only the exact backlog item, and only after the new targeted tests pass.

No unrelated docs, console files, migrations, generated OpenAPI, or lockfiles are in scope.

## Tests to write first

1. Add a failing docs/status consistency test under `tests/unit/mcp/test_mcp_parity_matrix_crossref.py` that iterates over `docs/MCP_CLIENT_PARITY.md` rows and enforces:

   - For implemented read-only rows currently covered by MCP operator-surface parity tests rather than `ContractCapability`, use an explicit small allowlist or coverage map with test references so the coverage is still executable and visible, not implicit.

## Risks and assumptions

- The current matrix includes implemented read-only rows that are covered by MCP operator-surface tests rather than the `ContractCapability` registry. The implementation should avoid forcing all read-only coverage into `_capabilities.py` unless that matches existing contract patterns.
- The CLI surface is intentionally absent for several implemented MCP/API rows. The test should require explicit `CLI absent`, not a command, for those rows.
- MCP tool discovery should prefer the repo's existing registration extraction unless runtime `list_tools()` proves more reliable without adding brittle service dependencies.
- Backlog references in the matrix currently use `TODO§...` markers, while the TODO file may not literally list every marker today. If the new test exposes that gap, the smallest acceptable fix is to add or preserve explicit unchecked backlog visibility without marking unrelated work complete.
- Coverage must remain at or above the AWF self target. This slice is primarily test/docs work, so coverage risk is low unless source drift must be fixed.
