# Plan: Start Here Quickstart

## Intended Files/Modules to Touch
- `README.md`: Add a concise top-level pointer to `docs/START_HERE.md`, ensuring existing sections are preserved.
- `docs/START_HERE.md`: Create a focused, under-5-minutes quickstart for fresh evaluators.

## Tests to Write First
- There are no specialized link checkers or docs-status tests for general markdown files in the repository. Validation will primarily rely on verifying that `README.md` correctly links to the new file, and that the new file adheres to the constraints (under 3 commands, prereqs first).

## Validation Commands
- `grep -q "docs/START_HERE.md" README.md`
- Visual inspection of `docs/START_HERE.md` to ensure:
  - Prerequisites are listed before the first command.
  - Three commands or fewer (e.g., clone, install, init).
  - Includes expected output snippets.
  - Includes failure next-actions.

## Risks, Assumptions, and Explicit Non-Goals
- **Risks**: High chance of concurrent edits to `README.md` by other AWF slices in this batch. We will strictly add one pointer line/section near the top and preserve everything else.
- **Assumptions**: 
  - Evaluators have `uv`, `docker`, and `git` installed as prerequisites.
  - The "three commands" recommended path is: 
    1. Clone the repository.
    2. Install the CLI (`uv tool install aira-awf`).
    3. Bootstrap local workspace / control plane (`awf init` or `awf init .`).
- **Explicit Non-Goals**:
  - Do not duplicate the OpenAPI artifact/API examples slice.
  - Do not duplicate the PR adoption slice.
  - Do not cover deep advanced configuration in this quickstart; deeper links will only be provided at the end of the proof.
