## Problem And Scope

T06/T07 added credential references and provider setup orchestration. T17 must harden every operator-facing setup/start diagnostic path so raw provider tokens and sensitive plain-file secret paths cannot leak while retaining enough state for support and debugging.

Current observations from the workspace:

- `src/awf/host_setup/rendering.py` already redacts token-shaped values and provider refs in first-run JSON/pretty output using the first-run/audit marker.
- `src/awf/common/redaction.py` redacts common token assignments, bearer headers, URL credentials, and known token shapes, but it does not yet redact `keyring://`, `env://`, or `plain-file://` provider refs in generic log text.
- `src/awf/service/support_bundle.py` redacts service/doctor/failure data but does not yet include sanitized host setup config/provider credential backend state.
- `src/awf/service/doctor/__init__.py` redacts known token values and URI credentials, but provider refs/plain-file refs need to flow through the stronger shared redaction contract.
- MCP `safe_result` payloads redact known tokens through service/provider readiness helpers, but MCP log reads in `src/awf/mcp/metrics_tools.py` return raw log chunks directly and provider refs/plain-file refs need shared redaction.

## Requirements Checklist

- Support bundles include useful setup state: config load status, provider status/source/backend, credential ref presence/kind, client status, consent flags, and source-checkout presence without raw secret values.
- Raw provider tokens and token-shaped rejected inputs are redacted in setup/start logs and diagnostics.
- Provider refs are not exposed verbatim in generic logs, support bundles, doctor output, or MCP payloads.
- Plain-file secret paths are omitted or replaced with a redaction marker; diagnostics may expose `backend=plain_file`, `credential_ref_present=true`, and `credential_ref_kind=plain_file` instead of the path.
- MCP surfaces cannot return raw secret values through structured content, text content, artifact metadata/content, or workspace log chunks.
- Existing first-run rendering behavior remains compatible; do not broaden or refactor unrelated setup/start behavior.

## Risks And Assumptions

- Redacting all provider refs removes some diagnostic specificity, especially env var names. The plan preserves backend/ref kind and presence to keep support bundles useful without exposing paths or references.
- Plain-file path sensitivity is treated conservatively: any `plain-file://` URI is redacted everywhere, regardless of consent. Consent may allow storage, not path disclosure.
- MCP test files are under an active overlap advisory. Keep changes small and avoid unrelated MCP fixtures.
- `awf service logs --follow` currently streams Docker output directly and is not the primary setup/start diagnostic path. This plan covers captured log reads and MCP log chunks; do not replace the streaming implementation unless acceptance testing proves it is necessary for this slice.
- Some token recognition intentionally favors false positives over leakage, especially truncated provider token prefixes.
- T09 setup MCP tools are not visible in the current checkout; if they land before implementation, add direct response redaction tests for those tools without expanding scope into MCP credential entry.
