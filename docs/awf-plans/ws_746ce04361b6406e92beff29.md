# Plan — Serialize unpinned-upper overlay discard against concurrent provision (#418 / #419)

Workspace: `ws_746ce04361b6406e92beff29`
Follow-up to #416 (deferred). Addresses **#418 and #419 together** — both reviewers flagged the
**same** TOCTOU race introduced by #416.

## Problem statement

PR #416 added the "discard + rebuild an unpinned, non-empty overlay `upper`" path in
`src/awf/node/auth_mounts_claude.py::_prepare_claude_overlay_mount`
(lines ~901–932). When a surviving `upper` is non-empty, unverifiable (no/mismatched
`base.signature` pin), and `not is_mounted(merged)`, the code:

1. broad guard: `not overlay_mounter.is_mounted(merged)` (line 905),
2. last-moment recheck: `not overlay_mounter.is_mounted(merged)` (line 919),
3. `shutil.rmtree(upper)` / `shutil.rmtree(work)` (lines 926–927).

The recheck→`rmtree` gap is a **TOCTOU window**: a concurrent *same-workspace* provision can
`mount()` the overlay between the recheck (step 2) and the `rmtree` (step 3), so the discard then
deletes an `upper`/`work` that is now the live backing layer of the other provision — destroying the
active workspace's Claude edits.

The DB-CAS provisioning claim already prevents concurrent same-workspace provisions **except** in the
**stale-lease-recovery window**, so the race is narrow but real (cursor: Medium severity). The double
`is_mounted` check is only a *mitigation*, not a fix — a mount can still land inside the residual gap.

## Locked design (from the task)

Add a **per-workspace overlay FLOCK** that serializes **both** the unpinned-upper **discard** path
**and** the overlay **mount/provision** path, so the discard (`is_mounted`-recheck + `rmtree`) is
**atomic** against a concurrent same-workspace mount. The lock must be honored by **both** sides — a
lock on only one side does not close the race. The DB-CAS claim stays the **primary** guard; this
flock is the **backstop** for the narrow stale-lease window. Lock acquisition/contention must be
**observable** (log + reason code when a discard is skipped because the lock is held or the overlay
became mounted).

Mechanism mirrors the existing `fcntl.flock` pattern already proven in
`src/awf/node/auth_mounts_claude_base.py` (`_CLAUDE_BASE_BUILD_LOCK_NAME`, `_ensure_shared_claude_base`,
`_claude_base_staging_build_is_live`): an exclusive advisory `flock` on a marker file, kernel-released
on `close`/process-death.

### Lock object

- File: `<claude_root>/.overlay.lock` where `claude_root == work_dir/auth/<workspace_id>/claude`
  (the per-workspace overlay scope; sibling of `upper`/`work`/`merged`/`base.signature`/markers).
- New module-private constant `_OVERLAY_PROVISION_LOCK_NAME = ".overlay.lock"`.
- The discard `rmtree(upper)`/`rmtree(work)` deletes only the scratch dirs, never the sibling lock
  file, so the lock is held continuously across discard. GC/teardown reap `target_root` wholesale,
  taking the lock file with it; no enumeration logic inspects `claude_root` for exactly
  `upper/work/merged` (`_overlay_upper_has_data` checks `upper` only), so the extra file is inert.

### Acquisition helper

New `@contextlib.contextmanager def _overlay_provision_lock(claude_root) -> Iterator[str]` yielding a
status `Literal["acquired", "contended", "unavailable"]`:

- `os.open(lock_path, O_CREAT|O_WRONLY, 0o600)` then `fcntl.flock(fd, LOCK_EX|LOCK_NB)`.
  - success → `"acquired"`.
  - `BlockingIOError`/`OSError` from `flock` (EWOULDBLOCK) → `"contended"` (a concurrent
    same-workspace provision holds it — the stale-lease window).
  - `OSError` from `os.open` (FS fault: ENOSPC, EROFS, EPERM) → `"unavailable"`.
- `finally`: `flock(fd, LOCK_UN)` (suppressing `OSError`) when acquired, then `os.close(fd)`. Kernel
  also frees the lock on process death, matching the base-build lock's crash semantics.

Catch **specific** exceptions only (`OSError`/`BlockingIOError`), never bare `Exception`
(AGENTS.md rule).

### Wiring into `_prepare_claude_overlay_mount`

To scope the lock across the discard **and** the mount without a giant re-indent of the ~280-line
function, split it into a thin wrapper + the existing body:

- **Wrapper `_prepare_claude_overlay_mount(...)`** (keeps the public-ish name; only caller is
  `_prepare_isolated_claude_auth` at line 477, no test calls it directly — verified):
  1. keep the early `supported()` and `_overlay_path_has_reserved_chars(...)` guards here (they
     return `None` *before* any lock, so copy-fallback hosts never create a `.overlay.lock`),
  2. `claude_root.mkdir(parents=True, exist_ok=True)` (lock file needs its parent; idempotent),
  3. `with _overlay_provision_lock(claude_root) as lock_state: return _prepare_claude_overlay_mount_locked(..., lock_state=lock_state)`.
- **Inner `_prepare_claude_overlay_mount_locked(..., lock_state: str)`** = the current body from
  `upper = claude_root / "upper"` (line 867) onward, unchanged except:
  - **`lock_state == "contended"`** (holder owns the real provision; we are the racing duplicate):
    - never `rmtree` and never attempt a *fresh* `mount()` off-lock (mounting unserialized reopens
      the race);
    - log `_CLAUDE_AUTH_OVERLAY_DISCARD_LOCK_CONTENDED`;
    - if `overlay_mounter.is_mounted(merged)` → reuse the live overlay (return the `merged` mount with
      `base=None` and **no** pin write — the holder owns pinning; `base=None` makes the caller defer
      reconcile/reap, the existing safe path);
    - else → `return None` so this provision degrades to the legacy copy this round; a later provision
      (after the holder releases) pins/mounts correctly. `upper` is left intact.
  - **`lock_state == "unavailable"`** (FS could not host the lock): log
    `_CLAUDE_AUTH_OVERLAY_PROVISION_LOCK_UNAVAILABLE` once, then proceed **best-effort exactly as
    today** (discard-if-warranted + mount, unserialized). The race re-opens only under the
    double-fault of (lock-file-uncreatable AND a concurrent provision) — acceptable and logged.
  - **`lock_state == "acquired"`** (the common path; DB-CAS already serialized): restructure the
    discard condition (lines 901–932) into explicit branches so the skip is observable while keeping
    #416's decision and its double `is_mounted` check intact:
    ```
    wants_discard = upper.exists() and _overlay_upper_has_data(upper) \
                    and not _pin_matches_signature(sig_marker, fresh_signature)
    if wants_discard:
        if overlay_mounter.is_mounted(merged):            # broad guard (#416)
            _log.info(... reason_code=_CLAUDE_AUTH_OVERLAY_DISCARD_SKIPPED_LIVE_MOUNT ...)
        elif overlay_mounter.is_mounted(merged):          # last-moment recheck (#416);
            _log.info(... reason_code=_CLAUDE_AUTH_OVERLAY_DISCARD_SKIPPED_LIVE_MOUNT ...)
        else:
            shutil.rmtree(upper, ignore_errors=True)
            shutil.rmtree(work, ignore_errors=True)
            _log.warning(... reason_code=_CLAUDE_AUTH_OVERLAY_UNPINNED_UPPER_DISCARDED_REBUILT ...)
    ```
    Under the held lock the `rmtree` is now atomic vs any other provision's `mount()` (which must also
    take this lock). The second `is_mounted` recheck is retained as #416 defense-in-depth (its TOCTOU
    is now closed by the lock); keeping it avoids reopening the #416 decision and keeps the existing
    race-flip test meaningful.

The `mount/provision` path "honors" the lock because the *real* provision (the lock holder) performs
its `_ensure_shared_claude_base` + `overlay_mounter.mount(...)` only while `lock_state == "acquired"`;
a `contended` duplicate never issues a fresh mount. Thus a discard (always under the held lock) can
never run concurrently with another provision's mount.

  discard + fresh-mount skipped because a concurrent same-workspace provision holds the overlay lock.
- `_CLAUDE_AUTH_OVERLAY_DISCARD_SKIPPED_LIVE_MOUNT = "CLAUDE_AUTH_OVERLAY_DISCARD_SKIPPED_LIVE_MOUNT"`

## Risks & mitigations

- **Re-indent / churn risk.** Wrapping the whole function would balloon the diff; the wrapper +
  renamed `_..._locked` inner keeps the body at its current indentation (signature + a few branches
  change), minimizing diff and review surface.
- **Lock file litter on copy-fallback hosts.** Avoided by keeping `supported()` /
  reserved-char guards *before* `mkdir`+lock in the wrapper, so non-overlay hosts never create
  `.overlay.lock`.
- **`claude_root` not yet existing.** The wrapper `mkdir(parents=True, exist_ok=True)` before opening
  the lock; idempotent and matches the legacy branch's own `mkdir`.
- **Deadlock / blocking the worker.** Acquisition is strictly `LOCK_NB` (non-blocking) — never blocks;
  contention degrades deterministically (reuse-or-defer). Kernel frees the lock on process death, so
  a crashed holder cannot wedge later provisions (same guarantee as the base-build lock).
- **Reopening the #416 decision.** Explicitly avoided: the discard/rebuild *decision* and its double
  `is_mounted` check are preserved; we only add the serializing lock + observability around them.
- **FS that ignores advisory locks** (some network FS). Falls into the `unavailable`/best-effort path
  or silently no-ops the lock; the DB-CAS claim remains the primary guard, so behavior is no worse
  than today and is logged.

## Assumptions

- `claude_root == work_dir/auth/<workspace_id>/claude` is the correct per-workspace serialization
  scope (one overlay per workspace) — confirmed via `_prepare_isolated_claude_auth` (line 477,
  `claude_root=target_root=auth_root/"claude"`).
- The only destructive op in the overlay path is the discard `rmtree(upper/work)`; the mount-failure
  path `rmtree`s only `merged`, and base-build/scratch failures return `None` without touching
  `upper` — so guarding the discard under the lock (plus restricting fresh mounts to the lock holder)
  fully closes the data-loss race (verified by reading lines 933–1102).
- New reason codes are logged-only like their siblings; no `_REASON_TEXT`/catalog entry needed
  (verified `UNPINNED_UPPER_DISCARDED` / `RECONCILE_DEFERRED` are absent from `reasons.py`).
- `_prepare_claude_overlay_mount` has no direct test callers (only a docstring mention in
  `test_provider_readiness_part_002.py`), so the wrapper/inner split is internal-only.

## Non-goals

- Not reopening or altering the #416 discard-vs-rebuild correctness decision.
- Not converting the DB-CAS provisioning claim or adding cross-host/distributed locking — the flock is
  a same-host, same-workspace backstop for the stale-lease window only.
- Not making acquisition blocking, nor adding timeouts/retries.
- Not changing teardown/GC, the reconcile/whiteout subsystem, the shared-base build, or any public
  API / re-export surface.
- No changes outside `auth_mounts_claude.py` and the two overlay test parts.
