## Risks, Assumptions, and Explicit Non-Goals
- **Assumption:** Existing single-status callers for CLI/MCP/REST will continue to pass single values. Pydantic `Query` lists and FastAPI coercion will seamlessly handle single `?status=...` elements as one-item lists, but we type it defensively.
- **Risk:** Unintentional backward incompatibility in MCP if Pydantic strict mode rejects single values for a `list` annotated field. Mitigated by using `list[WorkspaceStatus] | WorkspaceStatus | None` union typing.
- **Non-Goal:** Do not invent a CLI-only `--effort` flag; it remains profile/provider-derived.
- **Non-Goal:** Do not modify PR monitor behavior, scheduling logic, provider readiness, or any core domain behavior. This is strictly a control-surface structural parity effort.
