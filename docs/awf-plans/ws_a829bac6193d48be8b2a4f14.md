## Objective

Lock the public first-run CLI grammar around:

```text
awf setup -> awf start -> awf init <repo>
```

T01 will reserve the new top-level `awf setup` and `awf start` command surfaces, hard-switch no-path `awf init` away from service bootstrap, and keep `awf init <repo>` project onboarding behavior compatible with the current implementation.

## Tests To Write Or Update First

Use strict TDD where practical. First implementation step after creating the repo-local T01 plan will be to add/update tests and run a narrow failing test command.

1. Add `tests/unit/cli/test_setup_commands.py`.
   - `awf setup --help` exits 0 and shows setup-oriented first-run copy.
   - `awf setup` exits non-zero with a stable placeholder reason/code and no traceback.
   - If the placeholder supports `--format json`, assert the JSON shape is stable; otherwise assert the pretty output is stable and intentionally minimal.

2. Add `tests/unit/cli/test_start_commands.py`.
   - `awf start --help` exits 0 and shows start-oriented local Core copy.
   - `awf start` exits non-zero with a stable placeholder reason/code and no traceback.
   - Do not assert real service bootstrap behavior in T01; that belongs to T05.

3. Update init CLI tests before implementation.
   - `awf init` with no path exits non-zero and prints migration guidance for `awf setup`, `awf start`, and `awf init <path>`.
   - `awf init --format json` with no path returns a machine-readable migration payload if the existing `--format` option is retained for compatibility.
   - Old bootstrap-only flags on no-path init, such as `--write-env`, `--no-write-env`, `--timeout-seconds`, `--poll-interval-seconds`, `--skip-agent-runtime-build`, and `--provider`, are removed from help or rejected with the same migration guidance.
   - No-path init must not call `_run_init_service_bootstrap` or service bootstrap internals.
   - `awf init <path>` still performs project onboarding, accepts project-mode flags, and rejects bootstrap-only flags when a path is supplied.
   - Existing obsolete `test_init_without_path_*` cases that only assert the retired service-bootstrap behavior must be rewritten around the migration contract or removed. Do not port them to `awf start` in T01, because that would implement T05.

4. Add/update docs tests before docs edits.
   - Public docs should fail if no-path `awf init` is described as machine/service bootstrap.
   - Public docs should continue to allow `awf init <path>`, `awf init .`, and lower-level `awf service bootstrap` references where they are explicitly framed as service operations rather than the primary no-path init bootstrap path.
   - Update existing Quickstart/project-onboarding docs assertions so the canonical first-run path is `awf setup`, `awf start`, then `awf init <path>`.

## Implementation Approach

1. Create the required implementation plan file `plans/T01_CLI_GRAMMAR_INIT_SWITCH_PLAN.md` with this plan translated into the repo protocol format.
2. Add failing tests for setup/start command registration and placeholder behavior.
3. Update init and docs tests to express the new locked grammar.
4. Implement the smallest CLI changes:
   - Add focused setup/start command modules and register them in `main.py`.
   - Make no-path `awf init` return a clear migration error instead of calling `_run_init_service_bootstrap`.
   - Preserve path-mode onboarding by leaving `_run_init_project_onboarding` and project option handling intact.
   - Keep deprecated bootstrap init flags hidden or explicitly rejected where compatible with Typer; avoid silently accepting them.
5. Update public docs and CLI help text to remove the old no-path init bootstrap contract.
6. Run focused validation only.
7. Create `plans/T01_CLI_GRAMMAR_INIT_SWITCH_VALIDATION.md` comparing the implemented result against this task and the source plan/backlog.
8. Commit local changes with a scoped message. Do not push; AWF owns push/PR creation.

## Risks And Mitigations

- Many existing `test_init_without_path_*` tests encode the old bootstrap behavior. Mitigation: update all affected no-path init tests in touched split files and use `rg 'invoke\(app, \["init"' tests/unit/cli/test_init_parts` during implementation to ensure no obsolete expectations remain.
- Typer option compatibility for hidden/deprecated flags may vary. Mitigation: prefer explicit rejection with stable messaging; if hiding old flags is unsupported, keep parsing compatibility but remove service-bootstrap semantics and ensure help no longer promotes them as no-path init bootstrap flags.
- Public docs mention both `awf service bootstrap` and old no-path `awf init` bootstrap behavior. Mitigation: docs tests should distinguish allowed low-level service bootstrap references from forbidden no-path init-as-bootstrap guidance.
- Placeholder command behavior could be confused with T04/T05 implementation. Mitigation: use explicit placeholder reason text and tests that assert no service bootstrap/system check work happens in T01.
- Removing old no-path bootstrap coverage may reduce coverage for currently retained helper code. Mitigation: keep changes behavior-scoped; do not delete helper internals in T01 unless required. Note any residual coverage gap in the validation doc for AWF/GitHub follow-up.
