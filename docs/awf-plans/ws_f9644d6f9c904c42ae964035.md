# Plan: Manual-Merge PR Monitor Completion And Cleanup

## Goal

Prove and, if necessary, fix the P0 merge-safety slice for manual-merge PR
monitoring: when `auto_merge=false` or the release monitor is used, AWF must
stay in `monitoring_pr` while the PR is open and merge-ready, then complete and
clean up only after GitHub reports the PR as merged. Green gates are readiness
for a human, not a terminal condition.

Initial code read shows the intended shape already exists:

- `decide()` returns `NotifyHuman` for green manual-merge PRs, and
  `ShortCircuitCompleted` when `status.merged` is true.
- `PullRequestMonitorRunner._execute(NotifyHuman)` posts a deduped ready comment,
  sleeps, and returns `False`.
- `_terminate_completed()` transitions with reason code `MONITOR_DONE`, marks the
  merge candidate merged through repository lifecycle sync, runs compose teardown,
  and then runs completed-workspace filesystem GC.

The implementation phase should still write the regression tests first. If they
all pass, keep them as the slice's proof and make no production changes.

## Tests To Write First

Write these as failing tests before any production edit. Prefer a new
`tests/unit/runtime/test_pr_monitor_manual_merge.py` so the contract is easy to
find.

1. `test_manual_merge_green_open_pr_notifies_and_stays_monitoring`
   - Seed a workspace already in `monitoring_pr` with `auto_merge=False`,
     `pr_url`, `pr_number`, compose metadata, a canonical open merge candidate,
     and a successful validation run.
   - Build a runner with `MonitorConfig(auto_merge=False)`.
   - Execute the manual-mode green action either through one direct
     `_execute(decide(...))` call or through a runner iteration helper that does
     not depend on hitting `max_outer_iterations`.
   - Assert:
     - the action is `NotifyHuman`;
     - `_execute()` returns `False`;
     - workspace status remains `monitoring_pr`;
     - candidate remains open and `manual_merge_required=True`;
     - one `gh pr comment` is posted;
     - no `gh pr merge`, no `docker compose down`, and no filesystem GC occur;
     - sleep uses the configured poll interval.

2. `test_manual_merge_external_merge_completes_with_monitor_done_and_cleanup`
   - Full runner loop with two polls:
     - poll 1: green, open PR -> `NotifyHuman`;
     - poll 2: GitHub payload has `merged=True` -> `ShortCircuitCompleted`.
   - Provide a real temporary service layout:
     - `<work_dir>/git/worktrees/<workspace_id>`;
     - `<work_dir>/compose/<workspace_id>`;
     - `<work_dir>/auth/<workspace_id>`;
     - `<work_dir>/logs/<workspace_id>/...` as retained log evidence.
   - Queue successful `docker compose down`.
   - Assert:
     - workspace status is `completed`;
     - latest state-change event has reason code `MONITOR_DONE`;
     - merge candidate status is `merged` and `merged_at` is populated;
     - `docker compose down --remove-orphans --volumes` is called after the
       merged poll, not after the open green poll;
     - worktree, compose, and auth pressure directories are removed while logs
       remain;
     - structured logs include `monitor.action` for `NotifyHuman` and
       `ShortCircuitCompleted`, plus cleanup evidence such as
       `monitor.compose_teardown_ok` and `monitor.filesystem_gc_ok`;
     - no `gh pr merge` is called.

3. `test_manual_merge_closed_unmerged_aborts_without_cleanup`
   - Full runner loop with GitHub payload `closed=True, merged=False`.
   - Assert:
     - decision/action is `Abort(pr_closed_externally)`;
     - workspace transitions to `failed` with the existing abort message/reason;
     - merge candidate is closed, not merged;
     - no human-ready comment is posted;
     - no compose teardown or completed-workspace filesystem GC runs.

4. `test_manual_merge_unresolved_comments_route_to_address_comments_not_completion`
   - Full runner loop where first poll is otherwise green but contains an
     unresolved inline review thread or review comment.
   - Assert:
     - action is `AddressComments`, not `NotifyHuman` or completion;
     - the fake adapter receives the comment prompt and workspace id;
     - the branch is pushed and review thread resolution is attempted only after
       the fake adapter returns a fix verdict;
     - workspace remains non-terminal until a later payload reports
       `merged=True`.

5. `test_manual_merge_policy_blocker_notifies_but_does_not_complete`
   - Payload contains an unresolved review/comment that is classified as a
     policy/checklist blocker (`blocks_merge=True` in the parsed status path, or
     an issue-comment fixture that current parsing turns into such a blocker).
   - Assert:
     - action is `NotifyHuman`;
     - workspace stays `monitoring_pr`;
     - candidate is not merged/completed;
     - later ordinary review comments are still addressable by the monitor.

6. `test_manual_merge_checks_block_ready_until_green`
   - Poll 1 has pending checks or a failing check.
   - Assert:
     - pending checks produce `WaitForCI` and no ready comment;
     - failing checks produce `ReportCiFailure` or the existing CI-fix path and
       no completion;
     - only after checks become green does manual mode post the human-ready
       notification;
     - final completion still requires a later `merged=True` payload.

7. `test_release_monitor_factory_uses_manual_merge_contract` if not already
   redundant
   - Build via `build_release_pr_monitor()` instead of `make_runner()`.
   - Drive the same green-open then merged sequence.
   - Assert no auto-merge command and the same `MONITOR_DONE`/cleanup behavior.

Existing tests to keep as supporting regressions:

- `tests/unit/runtime/test_pr_monitor.py` already covers pure decision behavior
  for merged, closed, green auto-merge, green manual mode, unresolved comments,
  and blocking states.
- `tests/unit/runtime/test_monitor_action_logging.py` already proves
  `NotifyHuman -> ShortCircuitCompleted` and later comments after notification.
- `tests/unit/runtime/test_merge_candidate_lifecycle.py` already checks that
  `NotifyHuman` keeps the candidate open with `manual_merge_required=True`.
- `tests/unit/runtime/test_monitor_completion_gc.py` already covers completed
  monitor filesystem cleanup and skipped GC after teardown failure.

The new suite should consolidate the task-specific proof rather than relying on
readers to infer the contract across these existing files.

## Implementation Steps After Red Tests

1. Add/extend fixtures.
   - If needed, add `auto_merge: bool = True` to
     `seed_monitoring_workspace()` and set `ws.auto_merge`.
   - Keep the default path unchanged so existing tests do not change semantics.

2. Run the first manual-merge open-green test and confirm it is red for the
   intended reason.
   - If it unexpectedly passes, commit no production change for that scenario
     in the implementation phase; keep the test as regression coverage.

3. Fix `NotifyHuman` only if needed.
   - Ensure `_execute(NotifyHuman)` posts a deduped human-ready comment, records
     notification state, sleeps, and returns `False`.
   - It must not transition the workspace, close/merge the candidate, trigger
     compose teardown, run filesystem GC, or call `gh pr merge`.

4. Add the external-merge completion test.
   - If red, fix the `ShortCircuitCompleted` path to call `_terminate_completed`
     with `repo_url`, `base_branch`, `compose_project`, and `compose_file`.
   - Ensure `_terminate_completed()` transitions with `MONITOR_DONE` before
     best-effort cleanup, so cleanup failure cannot leave an actually merged PR
     stuck in `monitoring_pr`.

5. Add closed-unmerged, comments, policy-blocker, and checks tests.
   - If red, fix only `decide()` gate ordering or runner dispatch required for
     the failing gate.
   - Preserve current auto-merge behavior for the same statuses.

6. Add factory coverage only if the focused runner tests did not exercise
   `build_release_pr_monitor()`.
   - Keep release monitor as a thin facade over the generic runner.

7. Run targeted validation, then broader runtime/control-plane validation.

## Risks

- The runner still has `MonitorRunnerConfig.max_outer_iterations` as a safety
  net. Tests that need to prove "wait while open" should assert the
  `NotifyHuman` action is non-terminal directly, not rely on running a fake
  infinite monitor until the safety net fires.
- `Workspace.auto_merge` and `MonitorConfig.auto_merge` can diverge in tests if
  fixtures do not seed both intentionally. Manual-merge candidate readiness
  assertions should seed `Workspace.auto_merge=False`.
- Cleanup is intentionally best-effort after the DB completion transition.
  Tests should assert cleanup is invoked and succeeds in the success fixture,
  while preserving existing behavior that cleanup failure does not mask
  `completed`.
- GitHub payload fixtures must distinguish `closed=True, merged=False` from
  `merged=True`. A merged PR can also be closed by GitHub semantics, but AWF's
  decision core gives `merged` precedence.
- Broad monkeypatching of `_terminate_completed()` or `decide()` would skip the
  behavior under test. Use fake command runner, fake adapter, temporary
  filesystem, and real repository transitions instead.

## Assumptions

- Manual-merge mode is represented by `MonitorConfig(auto_merge=False)` and, for
  persisted readiness/candidate semantics, `Workspace.auto_merge=False`.
- The release PR monitor should remain a configuration wrapper over
  `PullRequestMonitorRunner`; it should not fork monitor logic.
- Existing repository lifecycle sync is the source of truth for marking a merge
  candidate merged when the workspace reaches `completed`.
- Completed-workspace cleanup means compose teardown plus pressure-directory GC;
  durable DB rows, events, logs, and artifacts are retained.

## Explicit Non-Goals

- Do not manually merge PRs or add code that manually merges release PRs.
- Do not change auto-merge behavior except for a shared monitor bug that the
  manual-mode regressions expose and the existing auto-merge tests protect.
- Do not change GitHub branch protection, merge queue policy, stale detection,
  validation tier policy, or review grace timing beyond what is required for
  this manual-merge proof.
- Do not add API or console features for manual merge readiness in this slice.
- Do not lower coverage thresholds, `.awf/workspace.yml` coverage settings,
  `pyproject` gates, or quality checks.
- Do not switch branches, push, rebase, force-push, or commit during this
  planning phase.
