# Plan — Fix #427: false PLAN_ONLY_OUTPUT in validation fix-pass

Workspace: `ws_447618cda7dc44e1b6562536`
Issue: #427 — AWF falsely fails a workspace with `PLAN_ONLY_OUTPUT` during the
validation fix-pass even when the branch already contains real
implementation/test/doc commits.

## Problem (confirmed by reading the code)

`src/awf/control/executor/execution_validation.py` (in `run_validation_and_fix_cycle`):

- Line ~1150: `fix_staged_paths = _git_name_lines(...)` from
  `git diff --cached --name-only` — this is ONLY the latest fix-pass staged delta.
- Lines ~1183-1206: `if fix_staged_paths:` immediately calls
  `self._fail_if_plan_only_paths(changed_paths=fix_staged_paths, expected_status=validating)`
  with **no committed-output guard**. When the agent committed the real
  implementation in EARLIER commits and the final conformance step stages only
  `docs/awf-plans/{ws}.conformance.json`, that staged delta is plan-only →
  false `PLAN_ONLY_OUTPUT` → `_mark_failed` → no PR. It pre-empts the correct
  final gate at `execution_flow.py:1135` (full committed-output check).

The **correct pattern already exists** at the post-agent gate
`execution_flow.py:680-698`: it only fails plan-only when the staged delta is
plan-only AND the net committed output `base..HEAD`
(`self._committed_paths_since(worktree_path, base_commit)`) is ALSO plan-only
(or empty). We mirror that guard at the buggy validation site via a new helper.

Verified in-scope facts:
- `_committed_paths_since` lives in `src/awf/control/executor/git_methods.py:525`
  and runs `git diff --name-only base..HEAD` (NET diff — commit-then-revert nets
  to empty). Reuse it; do not reimplement.
- `changed_paths_are_only_internal_plan_artifacts` lives in
  `src/awf/control/quality_gates.py` and is already imported in
  `quality_methods.py` (line ~59).
- `worktree_path` and `base_commit` are already in scope at the buggy site
  (used at lines ~1208-1212 for the protected-file diff).
- The executor is a thin shell whose methods are wired from sibling modules via
  `mixins.py` (`_fail_if_plan_only_paths` / `_fail_if_plan_only_committed_output`
  are wired at `mixins.py:103-104`).

## Locked design (hold scope — exactly this, nothing more)

### 1. New helper in `src/awf/control/executor/quality_methods.py`

Add next to `_fail_if_plan_only_committed_output` (~line 304):

```python
async def _committed_and_staged_output_is_plan_only(
    self: Any,
    *,
    worktree_path: Path,
    base_commit: str,
    staged_paths: list[str] | tuple[str, ...],
) -> bool:
    """True only when the staged delta is entirely internal plan artifacts AND
    the already-committed net output (base..HEAD) is also plan-only (or empty)
    -- i.e. the workspace has produced no real implementation/test/doc output
    anywhere. Gates PLAN_ONLY_OUTPUT so a fix-pass that stages only the
    conformance artifact cannot false-fail a workspace whose real work is in
    earlier commits. Mirrors the post-agent guard in execution_flow."""
    if not changed_paths_are_only_internal_plan_artifacts(staged_paths):
        return False
    committed_paths = sorted(
        p.as_posix()
        for p in await self._committed_paths_since(worktree_path, base_commit)
    )
    return not committed_paths or changed_paths_are_only_internal_plan_artifacts(
        committed_paths
    )
```

- Short-circuits (no git call) when the staged delta has real content.
- Reuses `_committed_paths_since` and `changed_paths_are_only_internal_plan_artifacts`
  (both already imported in this module).

`src/awf/control/executor/mixins.py`, next to the other plan-only wirings

### 3. Guard the ONE buggy site

`src/awf/control/executor/execution_validation.py` ~line 1183, change:

```python
if fix_staged_paths:
    if await self._fail_if_plan_only_paths(
        workspace_id=workspace_id,
        changed_paths=fix_staged_paths,
        expected_status=WorkspaceStatus.validating,
    ):
        ...  # finish ops PLAN_ONLY_OUTPUT + return stop=True

```

to:

```python
if fix_staged_paths:
    if await self._committed_and_staged_output_is_plan_only(
        worktree_path=worktree_path,
        base_commit=base_commit,
        staged_paths=fix_staged_paths,
    ) and await self._fail_if_plan_only_paths(
        workspace_id=workspace_id,
        changed_paths=fix_staged_paths,
        expected_status=WorkspaceStatus.validating,
    ):
        ...  # existing _finish_pending_validate_operations(... PLAN_ONLY_OUTPUT ...)
             # + return ExecutionValidationResult(stop=True, ...) UNCHANGED
    has_known_non_plan_output = True
    ...  # everything after (protected-file diffs etc.) UNCHANGED
```

Rely purely on the net-diff helper (authoritative git state); do NOT add a
`has_known_non_plan_output` short-circuit on the failure condition.

`and` short-circuits, so when the helper returns False (real work exists),
`_fail_if_plan_only_paths` is never called → no `_mark_failed`. The
`_finish_pending_validate_operations(... PLAN_ONLY_OUTPUT ...)` + `return` block
stays inside the inner `if` unchanged. `has_known_non_plan_output = True` and the
protected-file-diff logic that follow remain unchanged.

## Tests to write FIRST (strict TDD — write, watch fail, then implement)

Follow the existing executor test style. Integration-style tests drive
`execution_validation.run_validation_and_fix_cycle(executor, …)` with a
`SimpleNamespace` executor whose methods are `AsyncMock`s (pattern:
`test_executor_coverage_edges_part_007.py`). Helper unit tests call the helper
directly on a `SimpleNamespace` executor whose `_committed_paths_since` is an
`AsyncMock` (pattern: `test_executor_coverage_edges_part_002.py`).

Helper unit tests for `_committed_and_staged_output_is_plan_only`
(call `quality_methods._committed_and_staged_output_is_plan_only`):
- staged has a real file (`["src/foo.py"]`) → returns `False`; assert
  `_committed_paths_since` is **not** awaited (short-circuit).
- staged plan-only (`["docs/awf-plans/ws_x.conformance.json"]`) + committed has a
  real file (`{Path("src/foo.py")}`) → `False`.
- staged plan-only + committed empty (`set()`) → `True`.
- staged plan-only + committed plan-only (`{Path("docs/awf-plans/ws_x.md")}`)
  → `True`.

Fix-cycle regression tests (drive `run_validation_and_fix_cycle`, fix-pass
branch where `git diff --cached` returns the staged conformance artifact):
- **R1 (critical regression):** net `base..HEAD` committed paths include a real
  file (e.g. `src/foo.py`) and `fix_staged_paths == ["docs/awf-plans/ws_x.conformance.json"]`
  → MUST NOT fail PLAN_ONLY_OUTPUT; `_mark_failed` not awaited with
  PLAN_ONLY_OUTPUT; execution proceeds (downstream `has_known_non_plan_output`
  is True; `_fail_if_plan_only_paths` not awaited / no PLAN_ONLY finish).
- **R3:** net committed output empty AND `fix_staged_paths` plan-only → STILL
  fails PLAN_ONLY_OUTPUT (finish ops + return `stop=True`).
- **R4:** net committed output itself plan-only (only the plan `.md` committed)
  AND `fix_staged_paths` plan-only → STILL fails PLAN_ONLY_OUTPUT.
- **R-revert:** a real file committed then reverted so NET `base..HEAD` is empty,
  `fix_staged_paths` plan-only → STILL fails (proves we read net git state, not a
  stale flag). Modelled by `_committed_paths_since` returning `set()`.

Coverage: the helper's two `return` branches, the short-circuit `return False`,
and both legs of the guarded `if` at the call site are all exercised by the above.

## Risks & assumptions

- **Behavior parity risk:** the guard must mirror `execution_flow.py:680-698`
  semantics exactly (plan-only staged AND plan-only-or-empty committed). The
  helper reuses the identical primitives, so divergence risk is low.
- **`and` short-circuit:** when the helper returns False, `_fail_if_plan_only_paths`
  (which has the `_mark_failed` side effect) must not run — verified by R1.
- **Net-diff semantics:** `_committed_paths_since` uses `base..HEAD`, so a
  commit-then-revert nets to empty → R-revert correctly still fails. Assumption:
  `base_commit` in scope is the same base used by the post-agent gate.
- **Coverage gate:** every new line/branch is covered by the tests above; no
  hollow tests, no exclusions needed (all code is reachable behavior).
- Assumes `worktree_path`/`base_commit` remain in scope at the call site (they
  are — used a few lines later for protected-file diffs).
