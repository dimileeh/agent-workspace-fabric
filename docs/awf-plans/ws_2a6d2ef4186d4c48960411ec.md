# PR Monitor Provider Outage Recovery Plan

## Objective
Implement provider resilience and automated fallback recovery for the PR monitor agent. Ensure that when the monitor agent hits a retryable provider outage, it records metadata, triggers circuit breakers, pauses (retries), or falls back appropriately without repeatedly hammering the exhausted provider/model.

## Intended Files to Touch

- **Source Code:**
  - `src/awf/runtime/pr_monitor_runner.py`: Add handling for `"provider_outage"` in `_invoke_cli_for_verdict` and `_run_fix_cycle`. Terminate the current workspace if a fallback workspace is created.
  - `src/awf/service/provider_recovery.py`: Update `create_provider_recovery_attempt_row` to copy `pr_url`, `pr_number`, `branch_name`, and `monitor_state` fields (`monitor_iter_count`, `monitor_threads_addressed`, `monitor_last_commit_sha`, `monitor_started_at`) from the source to the retried workspace.
- **Tests:**
  - `tests/unit/runtime/test_pr_monitor_runner.py`: Add tests for provider outage and fallback logic during comment resolution and validation fixes.
  - `tests/unit/service/test_provider_recovery.py`: Add a test to verify PR monitor state fields are correctly copied to the fallback workspace.

## Details of Changes

1. **`src/awf/service/provider_recovery.py`**:
   - In `create_provider_recovery_attempt_row`, after creating the `retried` workspace via `repo.create`, copy the following fields from `source` if they exist on the model (e.g. `pr_url`, `pr_number`, `branch_name`, `monitor_iter_count`, `monitor_threads_addressed`, `monitor_last_commit_sha`, `monitor_started_at`).

2. **`src/awf/runtime/pr_monitor_runner.py`**:
   - Add a new exception `ProviderRecoveryFallbackTriggered(Exception)`.
   - Update `Verdict` type alias to include `"provider_outage"`.
   - Modify `_record_provider_agent_run_error` to return `Literal["fallback", "retry", "deterministic"]`:
     - Returns `"fallback"` if `create_provider_recovery_attempt_row` returns a result (meaning a new workspace was created).
     - Returns `"retry"` if it returns `None` but `metadata` was present (meaning `not_before` was set and the circuit breaker took over).
     - Returns `"deterministic"` if `metadata` is `None`.
   - Modify `_invoke_cli_for_verdict`:
     - If `await self._provider_recovery_suppresses_cli(workspace_id)` is true, return `"provider_outage"`.
     - In the `except AgentRunError` block, check the classification.
     - If `"fallback"`, raise `ProviderRecoveryFallbackTriggered`.
     - If `"retry"`, return `"provider_outage"`.
     - If `"deterministic"`, set `cli_failed = True` and return `"agent_failed"`.
   - Modify `_run_fix_cycle`:
     - If `verdict == "provider_outage"`, skip appending to `threads_to_resolve` and `publish_dependent_ids`, and **do not** call `state.mark_addressed(..., verdict)`. This ensures the unresolved comment remains in the pool for the next retry after the cooldown expires.
   - Modify `_run_ci_fix` and `_run_sync_base`:
     - Check the provider error classification. If `"fallback"`, raise `ProviderRecoveryFallbackTriggered`.
     - If `"retry"`, gracefully return a failed push result or exit early so the outer monitor loop can sleep.
   - Modify `run`:
     - Catch `ProviderRecoveryFallbackTriggered`.
     - Log a monitor closing event and cleanly `return` from `run` (terminating the current workspace) since the new fallback workspace will pick up monitoring.

3. **Tests**:
   - Write tests simulating `AgentRunError` with `reason_code="PROVIDER_CAPACITY_EXHAUSTED"` inside `AddressComments`.
   - Verify that `create_provider_recovery_attempt_row` produces a fallback workspace, `ProviderRecoveryFallbackTriggered` is raised, and `pr_monitor_runner.run` terminates.
   - Write tests where the policy demands a `"retry"`. Verify that `"provider_outage"` is returned, `_run_fix_cycle` ignores the comment (does not mark it addressed), and the monitor loop sleeps.
   - Write tests simulating deterministic agent failures to ensure they continue to be marked as `"agent_failed"` and addressed.

## Risks, Assumptions, and Non-Goals
- **Non-Goal:** Implementing the executor no-work fallback (another workspace owns this path).
- **Risk:** Failing to copy all relevant `monitor_` state columns could result in the fallback monitor restarting the PR review process from scratch.
- **Assumption:** Returning from `pr_monitor_runner.run()` gracefully will allow the worker to move the current monitor workspace into a final state, while the fallback workspace is scheduled correctly.
