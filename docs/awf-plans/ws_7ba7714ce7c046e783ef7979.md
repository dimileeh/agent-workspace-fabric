# Plan — issue #424: exclude claude_code `.claude/worktrees/` from the validation-worktree guard

Workspace: `ws_7ba7714ce7c046e783ef7979` (clean retry of the planning phase only).

## Problem

The `claude_code` agent CLI creates `.claude/worktrees/` (nested git worktrees for its
isolated subagents) inside the workspace checkout. This is **agent-runtime state**, not an
AWF artifact (AWF's own worktrees live at `work_dir/worktrees/<id>`;
`grep -r 'claude/worktrees' src/awf` is empty) and not project work.

Since #362 the validation-worktree guard
(`src/awf/runtime/validation_worktree.py:check_validation_worktree_clean`) trusts
`git status --porcelain=v1 --untracked-files=all --ignored=matching`: any untracked,
**non-ignored** path makes the tree "dirty" and AWF refuses to run AWF-owned validation
("refusing to run AWF-owned validation from a dirty tree. Dirty paths:
`.claude/worktrees/`"). When the target repo does not gitignore `.claude/worktrees/`, the
guard trips and the workspace fails (killed ws_df9a6ea504114ab2b46e6e14 / PR #423).

## Approach (fixed by the task — not up for redesign)

1. Declare a per-agent list of **runtime scratch path patterns** *with the agent adapter*
   so AWF core stays generic. For `claude_code` the list is `(".claude/worktrees/",)`;
   every other agent defaults to empty.
2. Before AWF runs the validation guard, append those patterns to the worktree's **local
   git exclude file** — the path returned by
   `git -C <worktree> rev-parse --git-path info/exclude` — inside an idempotent,
   clearly-marked AWF-managed block delimited by sentinels
   (`# >>> awf-managed agent scratch` / `# <<< awf-managed agent scratch`). The block is
   rewritten (never duplicated) on each call.
3. This is git-native, never touches the target repo's committed `.gitignore`, and makes
   `git status --ignored` report the scratch as **ignored**, so the existing guard's policy
   is unchanged — it simply no longer sees the scratch as dirty.
4. If `rev-parse --git-path info/exclude` fails, or the exclude file cannot be read/written,
   log a warning and fall back gracefully (never crash provisioning/validation).

Note: AWF uses per-repo bare mirrors + linked worktrees, so `info/exclude` resolves to the
shared common git dir. That is acceptable and intended — the scratch directory is identical
agent-runtime state for every workspace backed by that mirror, and the block is idempotent.

## Intended files/modules to touch

Production code:

- **`src/awf/adapters/base.py`** — add a default `runtime_scratch_paths` property on
  `AgentAdapter` returning `()` (tuple of glob-free path patterns). Document that these are
  agent-runtime scratch paths AWF excludes from validation cleanliness.
- **`src/awf/adapters/claude_code.py`** — override `runtime_scratch_paths` on
  `ClaudeCodeAdapter` to return `(".claude/worktrees/",)`.
- **`src/awf/runtime/agent_scratch.py`** (new module) — the git-native exclude writer:
  - `AWF_SCRATCH_BLOCK_START = "# >>> awf-managed agent scratch"`
  - `AWF_SCRATCH_BLOCK_END = "# <<< awf-managed agent scratch"`
  - `_strip_managed_block(content: str) -> str` — remove any existing sentinel block
    (inclusive) so repeated calls never duplicate it; tolerant of a missing/partial block.
  - `_render_managed_block(patterns: tuple[str, ...]) -> str` — render the sentinel-wrapped
    block, one pattern per line, deterministic order (dedup preserving order).
  - `async def apply_agent_scratch_excludes(*, run_git, worktree_path, scratch_paths,
    logger=...) -> bool` — no-op + return `False` when `scratch_paths` is empty; else
    `await run_git(["rev-parse", "--git-path", "info/exclude"])`, resolve the path (relative
    paths are joined onto `worktree_path`), strip+rewrite the AWF block, write the file.
    Returns `True` on success. Catches a failed `rev-parse` (`result.ok` is false) and
    `OSError` on read/write, logging `agent_scratch.exclude_*` warnings and returning
    `False`. `run_git` is the existing `GitRunner` type
    (`Callable[[list[str]], Awaitable[CommandResult]]`).
- **`src/awf/control/executor/execution_flow.py`** — wire one call to
  `apply_agent_scratch_excludes` after the adapter is constructed (just after
  `adapter = get_adapter(...)`, before the agent runs and before any
  `check_validation_worktree_clean`), using `adapter.runtime_scratch_paths`,
  `worktree_path`, and an inline worktree git runner mirroring the existing
  `_git_in_worktree` (`git -C <worktree>` with `git_safe_directory_config_args`). Applying
  here (status `running`, both initial and recovery paths) writes the persistent
  `info/exclude` once before the agent can create the scratch dir, covering the executor
  validation cycle and the later PR-monitor pre-push validation on the same mirror.

## Risks & mitigations

- **Linked-worktree shared `info/exclude`.** `rev-parse --git-path info/exclude` resolves to
  the shared common git dir for AWF's linked worktrees. Acceptable per the issue: the scratch
  state is identical for every workspace on that mirror, and the block is idempotent
  (rewritten, never appended). The real-git tests use a standalone repo, so they validate the
  block/idempotency mechanics independent of the mirror layout.
- **Over-broadening the exclude.** Mitigated by test #2 (a genuine stray file still trips the
  guard) and by excluding only the exact agent-declared patterns.
- **Trailing-slash / path-format quirks** in `git status --ignored` output (e.g.
  `.claude/worktrees/`). The existing `_is_under_ignored_path` already normalizes trailing
  slashes; tests assert against real `git status` output rather than hand-built strings.
- **Graceful degradation.** `rev-parse` failure and `OSError` are caught and logged
  (specific exceptions only, never bare `except Exception`), returning `False` without
  raising — provisioning/validation proceeds (and the guard simply behaves as before).
- **Ordering.** The exclude is applied *before* the agent runs, so `.claude/worktrees/` is
  ignored from the moment it can appear; it does not depend on the agent having run first.
- **Coverage of the one executor wiring line.** Covered by test #8 (focused executor part)
  to avoid a coverage regression without coverage-theater.

## Assumptions

- `CommandResult` exposes `.ok` / `.stdout` / `.stderr` (confirmed in
  `awf.common.commands`); the new helper uses the existing `GitRunner` signature already used
  by `validation_worktree`.
- `claude_code`'s only checkout-local scratch path today is `.claude/worktrees/`. If more
  appear later they are added to the adapter tuple — no core change.
- The executor seam after `get_adapter(...)` has `worktree_path` in scope and runs for both
  initial and recovery executions (verified in `execution_flow.py`).

## Non-goals

- No change to the guard's policy in `validation_worktree.py` (it keeps trusting
  `git status --ignored`); only the worktree's `info/exclude` is augmented.
- No reliance on, and no edit to, the target repo's committed `.gitignore` (the
  `.claude/worktrees/` line already on `development` is a stopgap; this AWF-side fix must work
  for any target repo).
- No new abstraction layer, no agent-registry refactor, no changes to other adapters beyond
  the default empty property.
- No broad repo validation / coverage gate run inside the agent phase (AWF + CI own that).
