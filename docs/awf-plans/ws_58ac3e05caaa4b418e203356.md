# T20 — Explicit uv bootstrap contract for `packaging/install.sh`

Workspace: `ws_58ac3e05caaa4b418e203356`
Backlog item: T20 (extends the Lane C installer work; follows T12 `install.sh`).

## 1. Problem and goal

`packaging/install.sh` defaults to `--method uv` and, when `uv` is missing, the
`install_uv()` step aborts late with `MISSING_DEPENDENCY "uv is not installed"`.
There is no way for the installer to bootstrap `uv` itself, and no clear,
authorized path for doing so. T20 adds an **explicit uv bootstrap contract**:

- **Preserve** today's behavior when `uv` is already installed (no bootstrap,
  same `uv tool install` path, same output).
- **Preserve** `--method pipx`: the pipx lane never bootstraps `uv`.
- **Fail clearly** when `uv` is missing and bootstrap was not authorized in
  non-interactive mode (stable shell reason token, actionable message).
- **Support explicit opt-in** via `--bootstrap-uv` (works non-interactively).
- **Allow confirmed interactive bootstrap**: prompt when running on a TTY and
  proceed only on an affirmative answer.
- **Keep `--dry-run` non-mutating**: never fetch/run the uv installer; plan it.
- **Hermetic test seam**: an env var pointing at a local/fixture uv-installer
  script so fixture and unit tests run with no real network or release.

Out of scope: the Python first-run error catalog, `src/awf/host_setup`,
`src/awf/cli`, MCP, and any non-installer runtime/CLI behavior. The installer
emits **shell-level** reason tokens only (it explicitly "does not depend on the
Python first-run error catalog", per the script header), so no
`docs/REASON_CATALOG.md` / `src/awf/...` changes are made here.

## 2. Design

### 2.1 New flags (arg parsing)

Add to `parse_args()` and `usage()`:

- `--bootstrap-uv` — explicit opt-in: install `uv` via the official uv installer
  when it is missing (default off). Sets `BOOTSTRAP_UV=1`.
- `--non-interactive` — never prompt; force the non-interactive decision path
  even when a TTY is present. Sets `NON_INTERACTIVE=1`.

New globals near the other parsed flags: `BOOTSTRAP_UV=0`, `NON_INTERACTIVE=0`.
Support both `--flag` and (for symmetry with existing style) no `=value` form is
needed since these are booleans.

Parse-time guards (mirroring the existing meaningless-combo rejections such as
`--version`/`--uninstall`):

- `--bootstrap-uv` with `--method pipx` → `BAD_USAGE` ("bootstrap-uv only
  applies to --method uv; pipx never bootstraps uv"). This makes the
  "pipx never bootstraps uv" guarantee explicit at the boundary.
- `--bootstrap-uv` with `--uninstall` → `BAD_USAGE` (install-only flag).

`--non-interactive` is accepted broadly (harmless no-op for uninstall/pipx), so
no rejection for it.

### 2.2 New reason tokens (shell-level)

Add to the header comment token list (lines ~15–18) and emit via `fail`:

- `UV_BOOTSTRAP_REQUIRED` — `uv` missing for `--method uv` and bootstrap was not
  authorized (non-interactive without `--bootstrap-uv`, or interactive prompt
  declined). Message names all three recoveries: re-run with `--bootstrap-uv`,
  install `uv` manually (https://astral.sh/uv), or use `--method pipx`.
- `UV_BOOTSTRAP_FAILED` — bootstrap was authorized but the uv installer could
  not be downloaded, exited non-zero, or did not yield a runnable `uv`.

### 2.3 Interactivity helper

```sh
stdin_is_interactive() {
    [ "${AWF_INSTALL_FORCE_INTERACTIVE:-0}" = "1" ] && return 0   # test seam
    [ "$NON_INTERACTIVE" -eq 1 ] && return 1                       # explicit override wins
    [ -t 0 ]                                                       # real TTY detection
}
```

`AWF_INSTALL_FORCE_INTERACTIVE` is a hermetic seam letting the black-box tests
exercise the confirm/decline prompt paths (the harness runs the script with a
piped, non-TTY stdin). `--non-interactive` always beats the seam so the
"explicit non-interactive overrides the prompt" edge is testable.

### 2.4 uv readiness gate (`prepare_install_method`)

Only the `uv` method is affected; pipx is untouched.

```sh
prepare_install_method() {
    [ "$METHOD" = "uv" ] || return 0
    command -v uv >/dev/null 2>&1 && return 0        # preserve existing behavior
    if [ "$BOOTSTRAP_UV" -eq 1 ]; then
        bootstrap_uv                                  # handles --dry-run internally
        return 0
    fi
    if [ "$DRY_RUN" -ne 1 ] && stdin_is_interactive; then
        if confirm_bootstrap_uv; then
            bootstrap_uv
            return 0
        fi
    fi
    fail UV_BOOTSTRAP_REQUIRED "uv is required for --method uv but is not installed; \
re-run with --bootstrap-uv to install it via the official uv installer, install uv \
manually (https://astral.sh/uv), or use --method pipx"
}
```

Called from `run_install()` after `verify_checksum`/"Checksum verified" and
**before** the `--dry-run` branch, so a real install bootstraps before
`install_artifact`, and dry-run still routes through the same gate (failing
clearly or planning the bootstrap) without mutating. `install_uv()`'s existing
`command -v uv … || fail MISSING_DEPENDENCY` stays as a defensive backstop.

### 2.5 Confirmation prompt

```sh
confirm_bootstrap_uv() {
    warn "uv is required for --method uv but is not installed."
    printf '%s' "Install uv now via the official uv installer (https://astral.sh/uv)? [y/N] " >&2
    local reply=""
    IFS= read -r reply || reply=""
    case "$reply" in
        y | Y | yes | YES | Yes) return 0 ;;
        *) return 1 ;;
    esac
}
```

Declined prompt falls through to `UV_BOOTSTRAP_REQUIRED`.

### 2.6 Bootstrap action (`bootstrap_uv`)

```sh
UV_INSTALLER_DEFAULT_URL="https://astral.sh/uv/install.sh"

bootstrap_uv() {
    local src="${AWF_UV_INSTALLER:-$UV_INSTALLER_DEFAULT_URL}"   # hermetic seam
    plan "bootstrap uv via the official uv installer: ${src}"
    [ "$DRY_RUN" -eq 1 ] && return 0                              # non-mutating
    local installer_file="${WORK_DIR}/uv-install.sh"
    fetch "$src" "$installer_file" || fail UV_BOOTSTRAP_FAILED "could not download the uv installer from ${src}"
    [ -s "$installer_file" ] || fail UV_BOOTSTRAP_FAILED "downloaded uv installer is empty: ${src}"
    local uv_bin_dir="${HOME}/.local/bin"
    UV_INSTALL_DIR="$uv_bin_dir" sh "$installer_file" \
        || fail UV_BOOTSTRAP_FAILED "the uv installer exited non-zero"
    case ":${PATH}:" in
        *":${uv_bin_dir}:"*) ;;
        *) PATH="${uv_bin_dir}:${PATH}"; export PATH ;;
    esac
    command -v uv >/dev/null 2>&1 \
        || fail UV_BOOTSTRAP_FAILED "uv is still not on PATH after bootstrap (expected it in ${uv_bin_dir})"
    say "Bootstrapped uv into ${uv_bin_dir}."
}
```

Notes / assumptions:
- Reuses the existing `fetch()` (https-pinned, refuses plain `http://`, supports
  `file://` and local paths for the seam) and `WORK_DIR` from `setup_workdir()`.
- The official uv installer honors `UV_INSTALL_DIR`; we set it to a known dir and
  prepend it to `PATH` so the subsequent `command -v uv` / `uv tool install`
  resolve the freshly installed `uv` within the same process. (Risk noted in §6.)
- `AWF_UV_INSTALLER` is the documented hermetic seam, parallel to
  `AWF_INSTALL_MANIFEST` / `AWF_INSTALL_BASE_URL`.

### 2.7 `usage()` / `--help` text

Document `--bootstrap-uv` and `--non-interactive`, and extend the "Trust"
paragraph with one sentence: by default `uv` is not installed automatically;
bootstrapping requires `--bootstrap-uv` or an interactive confirmation, and
`--method pipx` never bootstraps `uv`.

## 4. Tests to write first (TDD)

Write `test_install_sh_uv_bootstrap.py` (and the syntax-test flag additions)
before editing `install.sh`. Planned cases:

1. **uv present → no bootstrap** (existing behavior preserved): success, no
   "bootstrap uv" plan line, installer-seam script never invoked.
2. **uv present + `--bootstrap-uv` → opt-in is a no-op**: success, no bootstrap.
3. **`--method pipx`, uv missing → never bootstraps**: pipx install succeeds, no
   "bootstrap uv" line, no uv-installer fetch.
4. **uv missing, non-interactive default, no opt-in → `UV_BOOTSTRAP_REQUIRED`**,
   non-zero exit, no `uv tool install`, message names `--bootstrap-uv`/pipx.
5. **uv missing, `--bootstrap-uv` (real) → bootstraps then installs**: fake
   installer via `AWF_UV_INSTALLER` creates uv in `$HOME/.local/bin`; assert
   "Bootstrapped uv", `uv tool install` runs, success; assert `UV_INSTALL_DIR`
   honored (stub created in the expected dir).
6. **uv missing, `--bootstrap-uv --dry-run` → plans, no mutation**: "bootstrap
   uv" plan line present, fake installer NOT run, no uv stub created, no install.
7. **uv missing, no opt-in, `--dry-run` (non-interactive) → `UV_BOOTSTRAP_REQUIRED`**,
   non-mutating.
8. **uv missing, forced-interactive seam + stdin `y` → confirmed bootstrap**:
   installs successfully; prompt fragment on stderr.
9. **uv missing, forced-interactive seam + stdin `n` → declined →
   `UV_BOOTSTRAP_REQUIRED`**, no bootstrap, no install.
10. **`--non-interactive` overrides prompt**: forced-interactive seam +
    `--non-interactive` + stdin `y`, uv missing, no opt-in → still
    `UV_BOOTSTRAP_REQUIRED` (never prompts).
11. **Bootstrap download failure**: `AWF_UV_INSTALLER` points at a missing path →
    `UV_BOOTSTRAP_FAILED`, no install.
12. **Bootstrap yields no uv**: fake installer runs but creates nothing →
    `UV_BOOTSTRAP_FAILED` ("still not on PATH after bootstrap"), no install.
13. **`--bootstrap-uv --method pipx` → `BAD_USAGE`** at parse time; `calls() == []`.
14. **`--bootstrap-uv --uninstall` → `BAD_USAGE`** at parse time; `calls() == []`.
15. **Help lists `--bootstrap-uv` and `--non-interactive`** (extends the existing
    `DOCUMENTED_FLAGS` test).

Each case asserts on stable reason tokens and the recorded stub `calls()` /
filesystem effects, never on incidental wording.

## 6. Risks, assumptions, non-goals

Risks / assumptions:
- **uv installer env knob**: assumes the official uv installer honors
  `UV_INSTALL_DIR` and lands `uv` in that dir; we additionally prepend it to
  `PATH`. If a host installs elsewhere, the post-bootstrap `command -v uv` guard
  fails closed with `UV_BOOTSTRAP_FAILED` rather than proceeding blindly. Tests
  pin this via the hermetic seam, not the real installer.
- **`fetch` reuse**: the default `https://astral.sh/uv/install.sh` flows through
  the existing https-pinned `fetch`; plain `http` is already refused. The seam
  uses `file://`/local paths so no network in tests.
- **Interactivity in tests**: real TTY detection (`[ -t 0 ]`) can't be exercised
  under subprocess pipes, so the `AWF_INSTALL_FORCE_INTERACTIVE` seam stands in;
  the real `[ -t 0 ]` branch is covered indirectly by the non-interactive default.
- **Token/catalog coupling**: new tokens are shell-only; `INSTALLER_*` Python
  catalog entries are intentionally not modified (out of scope). Will confirm no
  test cross-checks shell tokens against the Python catalog before finishing.
- **`set -euo pipefail`**: the `read` in the prompt uses `|| reply=""` and
  pipelines avoid the SIGPIPE-under-pipefail traps already documented in the
  script; new pipelines (if any) follow the same `|| true` discipline.

Non-goals:
- No changes to the Python reason catalog, `host_setup`, CLI, or MCP.
- No automatic Docker/other-tool bootstrapping — `uv` only.
- No change to pipx behavior, checksum/manifest/version/channel/package
  verification, reachability, or uninstall logic.
- No real network calls or real release artifacts in tests.
