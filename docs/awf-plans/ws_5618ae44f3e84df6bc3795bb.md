## 1. Goal & acceptance criteria

Extend the existing release pipeline (`.github/workflows/publish.yml` + `RELEASING.md`),
**without building a parallel release process**, so that:

- **AC1 — drift gate.** The release workflow fails if the generated
  `awf-install-manifest.json` or `python-distribution-sha256.txt` drift from the built
  `dist/*` artifacts (recorded `sha256`, filenames, channel/version/tag, or checksum bytes).
- **AC2 — installer smoke.** A workflow job consumes the release artifacts (or, for local
  runs, fixture artifacts) and runs `packaging/install.sh` so the **downloaded artifact
  checksum is verified before any install mutation** (dry-run; prints "Checksum verified",
  never installs).
- **AC3 — docs.** `RELEASING.md` explains how to verify artifacts manually (drift check +
  installer smoke).
- **AC4 — manual paths stay first-class.** PyPI Trusted Publishing / `uv tool install` /
  `pipx install` paths are unchanged; the `publish` job keeps its manual `workflow_dispatch`
  gate.
- **AC5 — local tests** cover expected workflow jobs, artifact names, manifest/checksum
  fixtures, and release smoke command generation.

  smoke run needs a manifest whose `url` points at the **local** built wheel (`file://`).

## 3. Design

Two new focused scripts (mirroring the one-concern-per-script convention of
`generate_install_manifest.py` / `generate_openapi.py`), plus scoped workflow + docs edits.

### 3.1 `scripts/check_release_artifacts.py` (drift gate — AC1)

- Load the published `awf-install-manifest.json`.
- Re-derive the expected manifest with `generate_install_manifest.build_manifest(...)` using
  the same `dist/`, checksum file, repository URL, version, tag, and channel, pinning
  `generated_at` to the **published manifest's own** `generated_at` so the comparison is
  deterministic (no timestamp churn). Derive version/tag/repository/channel from the published
  manifest where possible; accept explicit `--version`/`--tag`/`--repository-url` flags
  matching the workflow invocation.
- Assert the re-derived manifest equals the published one; on mismatch print a precise,
  field-level diff and exit non-zero. This transitively re-verifies: checksum bytes ↔ dist
  (via `_validate_checksum_content`), checksum coverage/filenames, channel/version/tag, and
  each artifact `sha256`/`url`/`name`.
- Also assert the checksum file exactly covers `dist/*` (re-use `_parse_checksums` +
  `_validate_checksum_coverage`) so a stale/edited checksum file fails independently.
- `main(argv)` returns `0`/non-zero; raises `ManifestError`/`ValueError` mapped to
  `parser.error` like the existing generator.

### 3.2 `scripts/release_smoke.py` (installer smoke command generation — AC2/AC5)

- `build_smoke_manifest(manifest: dict, dist_dir: Path) -> dict`: deep-copy the published
  manifest and rewrite every artifact `url` to `file://{(dist_dir/name).resolve()}` while
  preserving `name`, `kind`, `sha256`, top-level `version`/`package`/`channel`/`source`. This
  lets `install.sh` fetch the **real built wheel bytes locally** and verify the manifest's
  recorded `sha256` before install — proving checksum-before-install on the actual artifacts.
- `smoke_invocation(installer: Path, manifest_path: Path, *, method: str = "uv") ->
  tuple[list[str], dict[str, str]]`: returns argv
  `["bash", str(installer), "--dry-run", "--method", method, "--channel", <manifest channel>]`
  and env `{"AWF_INSTALL_MANIFEST": str(manifest_path)}`. Deriving `--channel` from the
  manifest avoids a spurious `CHANNEL_MISMATCH` on an unpinned prerelease smoke.
- `main(argv)`: flags `--dist-dir`, `--manifest`, `--smoke-manifest-out`, `--method`
  (repeatable; default `uv`), `--installer` (default `packaging/install.sh`), `--run`.
  Writes the smoke manifest, prints the generated command(s); with `--run`, executes each via
  `subprocess.run`, asserting return code `0` and that "Checksum verified" appears with no
  install mutation. Streams hashing through `install.sh`'s real `sha256sum`/`shasum`.

### 3.3 Workflow edits — `.github/workflows/publish.yml` (AC1/AC2/AC4)

- **`build` job:** add one step **"Verify release artifact drift"** after manifest generation
  running `python scripts/check_release_artifacts.py --dist-dir dist --checksums-file
  artifacts/release/python-distribution-sha256.txt --manifest
  artifacts/release/awf-install-manifest.json --version "${VERSION}" --tag "${TAG}"
  --repository-url <repo>`. Fails the release on drift.
- **New `installer-smoke` job** (`needs: build`): `actions/checkout` (for `install.sh` +
  scripts), `actions/download-artifact` `python-distributions` → `dist/` and
  `python-distribution-checksums` → `artifacts/release/`, set up Python 3.12 + uv, then run
  `python scripts/release_smoke.py --dist-dir dist --manifest
  artifacts/release/awf-install-manifest.json --smoke-manifest-out
  artifacts/release/awf-install-manifest.smoke.json --method uv --run` (consumes the real
  uploaded artifacts; proves checksum-before-install). Keep `pipx` optional/secondary.
- **`publish` job:** unchanged (manual `workflow_dispatch` + Trusted Publishing) → AC4.

### 3.4 Docs — `RELEASING.md` (AC3)

Add a short "Verify release artifacts (drift + installer smoke)" subsection: how to run
`scripts/check_release_artifacts.py` and `scripts/release_smoke.py --run` (or the
`install.sh --dry-run` it generates) locally to confirm no manifest/checksum drift and that
the installer verifies the checksum before install. Keep PyPI/uv/pipx text intact; do not
rewrite the README/quickstart (T15 owns broad docs).

## 5. Tests to write first (strict TDD)

Order: write each failing test, then the smallest green implementation.

1. **`test_check_release_artifacts.py`** (manifest/checksum fixtures — AC1/AC5):
   - Consistent dist + checksum + freshly generated manifest → `main(...) == 0`.
   - Tampered recorded `sha256` in the manifest → non-zero + diff names the artifact.
   - Manifest missing an artifact present in `dist` / extra artifact absent from `dist` → fail.
   - Checksum file line edited (wrong digest) → fail independently.
   - Channel/version/tag mismatch in the manifest → fail.
   - Build fixtures with the same paired wheel/sdist/checksum helper used by
     `test_generate_install_manifest.py`.
2. **`test_release_smoke.py`** (release smoke command generation — AC2/AC5):
   - `build_smoke_manifest` rewrites every `url` to `file://…/<name>`, preserves
     `sha256`/`name`/`kind` and top-level `version`/`package`/`channel`/`source`.
   - `smoke_invocation` returns expected argv (`--dry-run`, `--method`, `--channel` from
     manifest) + env (`AWF_INSTALL_MANIFEST`) for `uv` and `pipx`.
   - `main(--run)` against a real fixture wheel: exit `0`, "Checksum verified" present, no
     `uv tool install` / `pipx install` mutation (assert via `install.sh` output / dry-run).
   - Negative: corrupt the fixture wheel bytes so its real `sha256` ≠ manifest → `install.sh`
     fails `CHECKSUM_MISMATCH` **before** install (proves checksum-before-install). May reuse
     `InstallerHarness` or a direct `subprocess` run of `install.sh`.

     `scripts/release_smoke.py` (references `packaging/install.sh`).
   - `{"build", "installer-smoke", "publish"}.issubset(jobs)`; `publish` keeps its
     `workflow_dispatch`/`inputs.publish_target != 'none'` gate (AC4).
   - Existing assertions in `test_publish_workflow_release_artifacts.py` and

## 7. Risks & mitigations

- **Workflow-file push permission.** Editing `.github/workflows/*` can require a token with
  the `workflows` permission. If AWF's push is rejected, **preserve the local work and surface
  the exact permission failure** (do not drop the workflow change) — call it out in the PR/
  validation doc. (Backlog boundary.)
- **Smoke artifact URLs unresolvable in CI.** The real manifest pins `https://…/releases/
  download/…` URLs that do not exist until the release is published. Mitigation: the smoke job
  rewrites URLs to `file://` local dist paths via `build_smoke_manifest`, so it never depends
  on a live release while still verifying the **real** recorded `sha256` against the **real**
  built wheel bytes.
- **`install.sh` channel cross-check on unpinned smoke.** Deriving `--channel` from the
  manifest avoids `CHANNEL_MISMATCH` for prerelease versions; covered by a test.
- **Duplicating generator logic.** Avoided by importing `generate_install_manifest` internals
  for the drift gate rather than re-implementing hashing/parsing.
- **Disturbing existing workflow tests.** Use `issubset` job checks and keep the smoke job in
  `publish.yml`; re-run the existing publish/CI workflow tests in the focused suite.
