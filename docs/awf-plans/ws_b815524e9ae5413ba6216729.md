# ISSUE-304: Cross-workspace host-port collision detection at dispatch time

## Goal

Reject workspace creation with HTTP 409 when a companion's `host_port` is already
mapped by a non-terminal workspace on the same host — before any build or
provisioning begins.

## Intended Files/Modules

| File | What changes |
|---|---|
| `src/awf/service/workspaces.py` | New domain error `WorkspaceCreateHostPortConflictError`; call the cross-workspace check in `WorkspaceService.create()` |
| `src/awf/api/routes/workspaces.py` | Catch the new error in `create_workspace()`, map to 409 with `ErrorResponse` |
| `src/awf/db/repositories/workspace_repository.py` | New repo method `find_host_port_conflicts()` — dialect-aware JSON query |
| `tests/unit/test_host_port_collision.py` | New test module covering all scenarios |

No changes to `schemas_companions.py`, `companion_services.py`, `state_machine.py`,
`enums.py`, or `models.py` — we reuse existing shapes.

## Tests to Write First (TDD)

New file: `tests/unit/test_host_port_collision.py`

1. **collision found → 409**: Dispatch a workspace whose companion declares `host_port=8080` when a non-terminal workspace already maps `8080`. Expect `WorkspaceCreateHostPortConflictError` with the colliding port and workspace ID.
2. **no collision → success**: Dispatch a workspace with `host_port=8080` when no other non-terminal workspace maps that port. Expect normal creation.
3. **terminal workspace with same port → no collision**: A workspace in `completed` (or `failed`, `cancelled`, `destroyed`) with `host_port=8080` does NOT trigger a collision. Expect normal creation.
4. **multiple ports, one collides**: A companion maps `[8000, 8080]`, and another non-terminal workspace maps `8080`. Expect 409 naming port 8080.
5. **multiple companions across workspace**: Two companions on the new workspace, one collides with existing port, the other does not. Expect 409 naming only the colliding port.
6. **same-workspace idempotent replay does not self-collide**: Replaying the same idempotency key with the same payload returns the existing workspace, even though it has the same port. (Existing idempotency path already handles this before the new check runs.)
7. **dialect-aware Postgres query**: Verify the `find_host_port_conflicts()` method produces correct SQL for the Postgres dialect (JSONB path).
8. **dialect-aware SQLite query**: Verify the same method produces correct SQL for the SQLite dialect (`json_extract`).
9. **node_id scoping**: When `node_id` is present on workspace rows, collisions are scoped to the same node. Two workspaces on different nodes with the same `host_port` do NOT collide.

## Implementation Plan

### Step 1: Domain error class

Add to `src/awf/service/workspaces.py`:

```python
class WorkspaceCreateHostPortConflictError(Exception):
    """Raised when a companion host_port is already mapped by a non-terminal workspace."""

    error_code = "COMPANION_HOST_PORT_CONFLICT"
    message = "host port {port} is already mapped by workspace {other_id}"

    def __init__(self, port: int, other_workspace_id: str) -> None:
        self.port = port
        self.other_workspace_id = other_workspace_id
        super().__init__(
            f"host port {port} is already mapped by workspace {other_workspace_id}"
        )
```

Follow the pattern of `WorkspaceCreateIdempotencyConflictError` and
`WorkspaceCreateInsufficientDiskError`: explicit fields, stable `error_code`,
clear human message.

### Step 2: Repository method — cross-workspace port query

Add to `src/awf/db/repositories/workspace_repository.py` (or a new method on `WorkspaceRepository`):

```python
async def find_host_port_conflicts(
    self,
    host_ports: list[int],
    *,
    node_id: str | None = None,
    exclude_workspace_id: str | None = None,
) -> list[tuple[int, str]]:
    """Return (host_port, workspace_id) pairs for non-terminal workspaces
    whose task_policy.companions declare any of the given host_ports.

    Parameter ``exclude_workspace_id`` prevents self-collision for idempotent
    replays (though idempotency is checked before this method is called).

    NOTE: TOCTOU window between SELECT and INSERT is acceptable per issue scope.
    Two truly simultaneous dispatches may both pass this check; the resulting
    compose-up failure is a natural backstop.
    """
```

The implementation needs a dialect-aware JSON query. The existing pattern in
`base.py` shows how to branch on `SESSION_DIALECT_NAME_KEY`:

**Postgres path**: Use `Workspace.task_policy['companions']` JSONB path to
extract host ports from each companion's `ports` array, unnest, and intersect
with the input `host_ports`. The query will look like:

```sql
SELECT ws.id, extracted.host_port
FROM workspaces ws,
     LATERAL (
       SELECT DISTINCT elem->>1 AS host_port
       FROM jsonb_array_elements(ws.task_policy->'companions') AS companion,
            LATERAL jsonb_array_elements(companion->'ports') AS elem
     ) AS extracted
WHERE ws.status NOT IN ('completed', 'failed', 'cancelled', 'destroyed')
  AND extracted.host_port::int = ANY(:host_ports)
  AND (ws.node_id = :node_id OR ws.node_id IS NULL OR :node_id IS NULL)
  AND (ws.id != :exclude_workspace_id OR :exclude_workspace_id IS NULL)
```

**SQLite path**: Use `json_extract` with a different traversal pattern, or
load all non-terminal workspace task policies and filter in Python. Given that
SQLite is only used in tests, a Python-side filter is acceptable and simpler.

The method signature returns `list[tuple[int, str]]` — each element is
`(host_port, workspace_id)`.

### Step 3: Call the check in `WorkspaceService.create()`

In `WorkspaceService.create()`, after the idempotency and disk checks pass and
before `create_workspace_row()`, add:

```python
# Extract companion host_ports from the request payload
companion_host_ports = _extract_companion_host_ports(req)

if companion_host_ports:
    conflicts = await repo.find_host_port_conflicts(
        companion_host_ports,
        node_id=...,  # pass node_id if available on the request/workspace
    )
    if conflicts:
        # Use the first conflict for the error message
        port, other_id = conflicts[0]
        raise WorkspaceCreateHostPortConflictError(port=port, other_workspace_id=other_id)
```

The `_extract_companion_host_ports()` helper extracts `[host_port for (container_port, host_port) in companion.ports for companion in req.task_policy.companions]`
from the `WorkspaceCreateRequest`. It reuses the port shape already validated
by `_validate_ports` in `schemas_companions.py`.

### Step 4: Route-layer mapping to 409

In `src/awf/api/routes/workspaces.py`, extend the `except` block in `create_workspace()`:

```python
except WorkspaceCreateHostPortConflictError as exc:
    return JSONResponse(
        status_code=status.HTTP_409_CONFLICT,
        content=ErrorResponse(
            error_code=exc.error_code,
            message=exc.message,
            detail={
                "host_port": exc.port,
                "conflicting_workspace_id": exc.other_workspace_id,
            },
        ).model_dump(),
    )
```

This mirrors the existing `WorkspaceCreateIdempotencyConflictError` and
`TaskExternalIdConflictError` 409 patterns.

### Step 5: MCP path consistency

The `WorkspaceService.create()` method is shared by REST and MCP. The new
domain error will propagate identically through both paths. Verify in the MCP
tool tests that the same `error_code` and `message` surface.

## Risks, Assumptions, and Non-goals

**Risks:**
- **TOCTOU**: Two near-simultaneous dispatches with the same port could both pass the
  check before either INSERTs. Accepted per issue scope. A DB-level unique
  constraint over JSON would be over-engineering.
- **JSON query correctness**: The Postgres JSONB path traversal is subtle. Tests
  must cover nested arrays (`[container_port, host_port]` pairs) and the
  edge case of an empty companions list.

**Assumptions:**
- Companions are stored in `task_policy` as a JSONB column with shape
  `{"companions": [{"ports": [[cp, hp], ...], ...}, ...]}`. This is confirmed
  by reading `WorkspaceCompanionRequest.ports` and `_companion_spec_from_mapping`.
- The `node_id` column on `Workspace` is the per-host namespace for port collisions.
  A `null` node_id means "local/default host" and should match other `null`
  node_ids. This matches existing resource-reservation scoping patterns in
  `base.py`.

**Non-goals (explicitly deferred per issue):**
- Auto-allocating ephemeral ports when `host_port` is null/`auto` (the "Medium" option).
- Surfacing the port collision inside the `INFRASTRUCTURE_FAILURE` event payload (the "Premium" option, overlaps #299).
