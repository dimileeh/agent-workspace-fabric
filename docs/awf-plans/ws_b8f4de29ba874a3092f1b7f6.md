## Implementation Approach

- Prefer shared REST service builders already used by `src/awf/mcp/server.py`; do not call FastAPI route handlers from MCP tools.
- Preserve response envelopes by returning Pydantic `.model_dump(mode="json")` payloads via `_tool_result`, and use structured MCP errors for invalid cursors/not found cases.
- Keep read responses bounded: list limits stay capped at 500, operation list over-fetches only `limit + 1`, log byte reads remain capped, artifact metadata remains list-only, and no artifact content/download tool is added for this slice.
- Keep AWF generic and project-local: no Aira-specific profile, database, service, branch, or repo assumptions.
- Update docs/backlog only after tests and implementation evidence exist.

## Risks and Assumptions

- Assumption: this slice is read-only operator MCP coverage. Artifact content/download, global event streaming, secret lease status, refresh/rebase controls, and If-Match parity remain separate backlog unless already proven by existing implementation/tests.
- Assumption: the fixed target branch baseline means previous PR-monitor expectation failures are background context only; I will not spend implementation time on them.
- Risk: `awf_get_service_readiness` can perform Docker/provider checks in the default path. Tests should use provider hooks or narrow assertions to avoid environment-dependent failures.
- Risk: metrics include generated timestamps. Tests must normalize volatile fields rather than hard-code current time.
- Risk: artifact metadata currently mirrors REST and includes managed artifact file paths. I will not change the REST/MCP schema unless a test demonstrates actual secret/content leakage; schema changes would be broader than this slice.
- Risk: MCP transport-level authentication is not exercised by in-process `FastMCP.call_tool` tests. This plan focuses on response shape and safety boundaries, while REST auth remains covered by API tests.

## Explicit Non-Goals

- Do not implement arbitrary shell, command-runner, Docker exec, host filesystem browser, secret material, or unbounded artifact read tools.
- Do not implement artifact content/download over MCP in this slice.
- Do not implement new safe operator action tools for refresh, rebase, retry, cancel, stop, destroy, remonitor, or validate beyond reconciling already implemented/test-backed status.
- Do not change branch management, push, rebase, or PR-monitor behavior.
- Do not add Aira-specific runtime/profile assumptions to AWF core.
