# Implementation Plan: Provider Capacity Exhaustion Classification

## Goal
Classify agent CLI failures caused by provider unavailability or quota exhaustion with a structured reason code `AGENT_PROVIDER_CAPACITY_EXHAUSTED` and detailed attributes (`provider`, `model`, `retryable`), avoiding generic `agent_failure` masking.

## Intended Files & Modules to Touch

- `src/awf/adapters/base.py`:
  - Add `_CAPACITY_EXHAUSTED_MARKERS` containing `"resource_exhausted"`, `"model_capacity_exhausted"`, `"retryablequotaerror"`, `"http 429"`, `"rate limit"`, `"quota exhausted"`.
  - Update `_failure_reason_for_result` to map these markers to `"AGENT_PROVIDER_CAPACITY_EXHAUSTED"`.
  - Update `AgentAdapter.run` to populate a `details` dict with `provider`, `model`, `retryable: True`, and `recommended_action: "Retry the workspace later or fallback to a different provider."` when this reason code is detected.
  - Update `AgentRunError.__init__` to accept and store the `details` dict.
  - Add `provider` abstract property to `AgentAdapter`.
- `src/awf/adapters/gemini.py`, `claude_code.py`, `codex.py`, `opencode.py`:
  - Implement the `provider` property (`"google"`, `"anthropic"`, `"openai"`, `"ollama"` respectively).
- `src/awf/control/executor.py`:
  - Update `_run_agent_phase`'s `AgentRunError` catch block to extract `exc.reason_code` and `exc.details` into variables.
  - Pass these variables into `self._mark_failed()` calls, ensuring the executor captures and forwards the structured reason and metadata instead of dropping them in favour of the coarse `FailureReason.agent_failure`.
- `src/awf/api/schemas.py`:
  - Extend `WorkspaceFailureDetailsResponse` to include `provider: str | None = None`, `model: str | None = None`, `retryable: bool | None = None`, and `recommended_action: str | None = None`.
- `src/awf/service/workspaces.py`:
  - Update `workspace_failure_details_payload` to pluck `provider`, `model`, `retryable`, and `recommended_action` from the event payload's `details` block and inject them into the returned dictionary.
- `src/awf/service/metrics.py`:
  - Update `_cluster_failed_workspaces` to map `specific_reason_code == "AGENT_PROVIDER_CAPACITY_EXHAUSTED"` to a specialized `likely_cause` and `action`, bypassing the generic "Unknown Agent Failure".

## Tests to Write First (TDD)

- `tests/unit/adapters/test_adapters.py`:
  - Add tests simulating a provider capacity failure (e.g. mocking CLI stderr with `"RESOURCE_EXHAUSTED"`). Verify `AgentRunError` contains `reason_code="AGENT_PROVIDER_CAPACITY_EXHAUSTED"` and correct `details` (provider, model, retryable).
- `tests/unit/control/test_executor_error_paths.py`:
  - Verify that an `AgentRunError` carrying `AGENT_PROVIDER_CAPACITY_EXHAUSTED` and `details` correctly populates those fields in the final `WorkspaceEvent` payload via `_mark_failed` instead of being swallowed.
- `tests/unit/api/test_failure_analysis.py`:
  - Add a test that seeds a failure with `AGENT_PROVIDER_CAPACITY_EXHAUSTED` and verifies that the `WorkspaceFailureDetailsResponse` correctly surfaces `provider`, `model`, `retryable`, and `recommended_action` fields on the API.

## Risks, Assumptions, and Explicit Non-Goals

- **Non-Goal**: We will **not** implement circuit breakers or fallback dispatch (e.g. auto-switching from Claude to Gemini). We will leave TODO hooks for future classification logic.
- **Risk (Advisory)**: We will touch `src/awf/api/schemas.py` and `src/awf/service/workspaces.py`, which have `OWNED_PATH_OVERLAP_RISK` with `ws_1e79f6b47faf44d0bf8de3f0` and `ws_05365f752ad742abb7c134af`. We assume these overlaps won't create hard conflict barriers if changes are localized to standard schema additions. If they do, AWF's `STALE_OVERLAP` policy will require rebase/revalidation.
- **Assumption**: The existing generic `FailureReason.agent_failure` should be preserved as the coarse failure state to maintain API backward compatibility, relying entirely on the `reason_code` field for structured metadata.
