## Risks
- SQL ordering by computed score can drift from service-layer expectations unless score math is centralized in one helper.
- Fairness logic may change throughput ordering characteristics; guard with strict score formula tests.
- Existing queue-decision consumers may expect creation-time-only persistence; adding dispatch-time records can be noisy unless a single latest-record interpretation is preserved.
- Reason-code taxonomy expansion can affect backward consumers if not additive and defaults are preserved.

## Assumptions
- Existing `QueueDecision` persistence model is sufficient unless a strict new field is missing after implementation review.
- `created_at` is the canonical age source; no new timestamp (like wait-start) is introduced in this slice.
- Existing worker dispatch flow can safely record decisions without requiring a dedicated new write path.
- Operator-readable summaries should avoid sensitive values and bounded text length; exact limits will be introduced in constants.
