# Implementation Plan: Expose Token Usage

## Intended Files to Touch
- `src/awf/service/workspace_observability.py`: 
  Update `workspace_usage_summary` to aggregate token usage (`input_tokens`, `output_tokens`, `total_tokens`, `cost_estimate`) by iterating over `workspace.operations` and extracting the `usage` dictionary from each operation's `result` and/or `payload`.
- `apps/console/components/console-dashboard.tsx`: 
  Update the `UsageSummaryBlock` and relevant list/detail components to conditionally display the prompt (input), completion (output), and total token metrics. If the `status` is `"unavailable"` or the values are absent, it will explicitly mark them as unavailable or hide the grid entirely to keep the view compact.
- `tests/unit/service/test_workspaces_observability.py`: 
  Add/update tests for the token usage aggregation logic.
- `apps/console/components/console-dashboard.spec.tsx` (or similar frontend test files): 
  Add/update tests to ensure the usage grid is conditionally rendered based on the presence of usage metrics.

## Tests to Write First
1. **Backend (`test_workspaces_observability.py`)**:
   - Test that `workspace_usage_summary` correctly aggregates `input_tokens`, `output_tokens`, and `total_tokens` when operations contain valid `usage` metadata.
   - Test that it returns `status="unavailable"` and `None` for token counts when no operations have usage metadata (providers without usage).
   - Test that it safely ignores missing or malformed `usage` dicts, and ensures no sensitive data is leaked or assumed (redaction/no-secret behavior is respected by only pulling explicitly requested keys).

2. **Frontend (`console-dashboard` tests)**:
   - Test that the token usage grid renders correctly when `input_tokens` and `output_tokens` are provided.
   - Test that the component hides the usage grid or displays an "Unavailable" badge when `status === "unavailable"` or when tokens are `null`.

## Validation Commands
- `pytest tests/unit/service/test_workspaces_observability.py -v`
- `npm --prefix apps/console run lint`
- `npm --prefix apps/console test`

## Risks, Assumptions, and Explicit Non-Goals
- **Assumption:** The `usage` metadata is persisted in `workspace.operations` (within the `payload` or `result` JSON columns), and uses keys like `input_tokens`, `output_tokens`, and `total_tokens` as demonstrated by the redaction tests.
- **Assumption:** The frontend `WorkspaceLlmUsageSummaryResponse` schema already supports nullable tokens.
- **Non-Goal:** Calculating or inventing pricing/costs. We will strictly pass through the existing `cost_estimate` and `currency` if available in the metadata, but will not add any new cost-calculation logic.
- **Non-Goal:** Modifying the console's overall layout or styling beyond conditional rendering of the existing `UsageSummaryBlock` components.
