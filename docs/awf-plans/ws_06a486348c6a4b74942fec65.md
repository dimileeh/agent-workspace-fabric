# Plan — Issue #441: persist `awf start --console-port` into the active service env file

GitHub issue: https://github.com/dimileeh/aira-agent-workspace-fabric/issues/441

## Problem statement

`awf start --console-port <port>` injects `AWF_CONSOLE_HOST_PORT=<port>` only into
the **in-memory** `service_env` dict passed to `run_service_bootstrap` for that one
run (`src/awf/cli/start_commands.py:253-254`). Compose starts on the requested port,
but the override is never written to the persisted service `.env`. Later commands
(`awf service status`, doctor, smoke, etc.) re-resolve service settings from that
`.env` via `_resolve_service_runtime_env_files` → `_resolve_existing_service_env_file`,
find no `AWF_CONSOLE_HOST_PORT`, and `_resolve_service_console_url`
(`src/awf/service/config.py:563-593`) falls back to the default console port 3000
(actually `console_url = None`, i.e. no derived port). The console-port override is
therefore not durable.

## Fix (narrow)

When — and only when — an explicit `--console-port` is supplied to `awf start`,
persist `AWF_CONSOLE_HOST_PORT=<port>` into the **active AWF service env file** that
`awf start` selected, before settings resolution. The in-memory injection stays so
the current run is unchanged; persistence makes later commands resolve the same port.

Persistence rules:
- Update an existing `AWF_CONSOLE_HOST_PORT` assignment **in place** (no duplicate
  appended), preserving the `export`/key spelling and all unrelated lines/comments.
- Append a fresh assignment (with a guaranteed newline separator) when the key is
  absent but the file exists, preserving prior content.
- Create the selected env file (and parent dirs) when absent — including the verified
  `--source-checkout` root `.env` case.
- Never write for plain `awf start` (no `--console-port`) or for `--headless`
  (the existing `--headless` + `--console-port` guard already exits 2 before any
  persistence path runs).
- Do not touch `AWF_CONSOLE_URL` or any other key; `AWF_CONSOLE_URL` precedence in
  `_resolve_service_console_url` is unchanged (host env → settings → service-env
  `AWF_CONSOLE_URL` → derived from `AWF_CONSOLE_HOST_PORT`).

### Target env file in each branch of `_resolve_start_bootstrap_inputs`

- **Verified `--source-checkout`**: `verified.root / ".env"` (run persistence *after*
  the existing legacy-env migration so a migrated file is updated, not clobbered).
  After persisting, the file exists, so `read_env_file`/`compose_env_file` resolve to
  `root_env` exactly as today for the populated case.
- **Default discovery (non-verified)**: the `read_env_file` returned by
  `_resolve_service_runtime_env_files(...)` — this is the same active file
  `awf service status` reads, which is the locus of the bug.

## Files / modules to touch

- `src/awf/cli/init_ops.py`
  - Add a focused env-helper `_persist_console_host_port(env_file: Path, console_port: int) -> None`
    next to the existing dotenv helpers (reuses `_ENV_ASSIGNMENT_RE` /
    `_env_assignment_key` / `_env_assignment_key_identity` for case-insensitive,
    `export`-aware key matching). Add a small `_replace_env_assignment_value(line, value)`
    that keeps everything up to and including `=` and substitutes the value, so the
    key spelling and `export` prefix are preserved and any stale value/inline comment
    is replaced. Line-oriented to match the existing merge helpers' contract
    (single-line assignments).
- `src/awf/cli/start_commands.py`
  - In `_resolve_start_bootstrap_inputs`, call `_persist_console_host_port(...)` in both
    branches when `console_port is not None`, before `local_service_environ(...)` /
    `resolve_service_settings(...)`. Keep the existing in-memory
    `service_env["AWF_CONSOLE_HOST_PORT"] = str(console_port)` injection.
  - Import the new helper alongside the existing `from awf.cli.init_ops import (...)`
    blocks.

No changes to `service/config.py`, bootstrap, status, smoke, doctor, or Compose
rendering — the persisted key flows through the existing resolution unchanged.

## Risks & assumptions

- **Line-oriented dotenv editing.** Reuses the codebase's existing single-line
  assignment assumption (`_env_contents_have_multiline_values` exists elsewhere but is
  not needed here — we only rewrite/append one simple `KEY=value` line). Multi-line or
  quoted values for *other* keys are preserved verbatim because we only touch the
  matched `AWF_CONSOLE_HOST_PORT` line and otherwise re-emit lines unchanged.
- **Write target permissions.** For a packaged install whose active env resolves to a
  read-only location, persistence could raise `OSError`. This is an accepted edge: the
  realistic `--console-port` flows are source-checkout / repo-root writable `.env`s.
  No new error-swallowing is added (would hide failures, against project rules); a write
  failure surfaces rather than silently dropping the override. Noted as a follow-up risk
  rather than in-scope handling.
- **Inline comments on the assignment line** are not preserved when replacing the value
  (the value+trailing comment after `=` is rewritten). This matches "preserve unrelated
  comments where practical" — whole-line and separate-line comments are preserved; only
  a same-line trailing comment on the rewritten key is dropped.
- Assumes the in-memory `service_env` injection stays authoritative for the current run,
  so behavior for the active `awf start` invocation is unchanged even before the file is
  re-read.

## Non-goals

- No change to `AWF_CONSOLE_URL` derivation/precedence, API/Postgres host-port handling,
  or any non-console env key.
- No persistence for plain `awf start` or `--headless`.
- No broadening of bootstrap, service status, smoke, doctor, or Compose behavior beyond
  writing the one key.
- No new dotenv parser/abstraction; reuse existing helpers.
- No changes to `awf init` env seeding/merge logic.
- No docs/PRD edits (PR description references and closes #441).
