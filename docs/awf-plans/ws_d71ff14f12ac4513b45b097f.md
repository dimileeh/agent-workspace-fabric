# Plan: Retention-Based Cleanup Eligibility for Completed PR Workspaces

## Goal

Implement the P0 cleanup slice so completed PR workspaces become eligible for
safe cleanup after a configurable retention window, while recent completed
workspaces and failed workspaces remain inspectable.

The cleanup path must:

- select completed/merged PR workspaces older than retention;
- preserve recent completed workspaces;
- preserve failed workspace triage assets by default;
- delete only managed pressure directories: worktree, compose, and auth;
- never delete durable logs, artifacts, workspace rows, events, or operation
  history;
- make repeated cleanup safe after missing paths or partial Docker failures;
- expose clear reason codes and result payloads through service status and the
  CLI.

## Current Code Context

Existing cleanup surfaces to extend:

- `src/awf/service/gc.py`
  - plans and executes filesystem-only GC for terminal workspaces;
  - deletes `<work_dir>/git/worktrees/<workspace>`,
    `<work_dir>/compose/<workspace>` or stored compose parent, and
    `<work_dir>/auth/<workspace>`;
  - already preserves DB rows, events, log streams, and artifacts by omission;
  - currently defaults to all terminal statuses, including `failed`, which
    conflicts with failed triage preservation.

- `src/awf/runtime/pr_monitor_runner.py`
  - marks PR monitor workspaces `completed`;
  - currently tears down Compose after completion and then immediately runs
    filesystem GC. This needs to become retention-aware so recent completed
    workspaces are preserved.

- `src/awf/node/cleanup.py`
  - wraps best-effort Compose teardown and worktree removal for explicit
    destroy operations;
  - already captures partial failures without aborting all cleanup steps.

- `src/awf/service/status.py` and `src/awf/service/orphans.py`
  - report Docker/worktree resources and retention classification for service
    status;
  - can be extended with a policy-aware cleanup readiness check.

- `src/awf/cli/main.py`
  - exposes `awf service gc`;
  - currently uses the hard-coded GC minimum age default.

## Intended Files And Modules To Touch

Production code:

- `src/awf/service/gc.py`
  - Add a policy-aware cleanup planner/result shape.
  - Default automatic eligibility to completed PR workspaces only.
  - Preserve failed workspaces by default with explicit reason codes.
  - Include skipped/preserved rows in dry-run payloads so operators can see why
    recent completed or failed workspaces were not selected.
  - Add structured per-target outcomes: deleted, missing/already removed,
    skipped, failed, and reason code.

- `src/awf/common/config.py`
  - Add configurable defaults, likely:
    `completed_workspace_retention_hours`,
    `workspace_cleanup_scan_interval_seconds`,
    `workspace_cleanup_batch_limit`, and
    `workspace_cleanup_enabled`.

- `src/awf/service/config.py`
  - Carry the new settings into `ServiceSettings`.
  - Include non-secret cleanup settings in `service_config_payload(...)`.

- `src/awf/service/status.py`
  - Add a `workspace_cleanup` check that calls the dry-run planner and reports
    candidate counts, preserved counts, retention hours, examples, and reason
    codes.
  - Keep cleanup-ready candidates operator-visible without making the whole
    service unhealthy solely because old completed workspaces are ready.

- `src/awf/cli/main.py`
  - Make `awf service gc` default retention come from service settings.
  - Keep `--min-age-hours` for compatibility; consider an alias such as
    `--retention-hours`.
  - Emit the structured plan/result, including `reason_code` fields.
  - Exit non-zero only for actual cleanup execution failures, not dry-run
    eligibility.

- `src/awf/runtime/pr_monitor_runner.py`
  - Keep immediate best-effort Compose teardown if needed to release Docker
    networks.
  - Stop immediate filesystem pressure-dir deletion for newly completed
    workspaces unless retention policy explicitly allows it.
  - Log that filesystem cleanup is retention-deferred rather than silently
    skipped.

- `src/awf/control/worker.py` and `src/awf/service/worker.py`
  - If automatic execution is required in this slice, add a periodic cleanup
    sweep dependency using the same policy engine and batch limit.
  - Keep this isolated from provisioning/execution dispatch so cleanup failures
    do not stop normal worker polling.

- `src/awf/node/cleanup.py`
  - Touch only if the retention cleanup runner needs a reusable structured
    Compose teardown result for partial Docker failures.

- `README.md`
  - Update only during implementation, not this planning phase, if new CLI
    flags/settings or result fields need operator documentation.

## Tests To Write First

Write these as red tests before production changes.

1. Completed PR workspace older than retention is selected.

   Location: `tests/unit/service/test_gc.py`

   Setup:
   - Seed a `completed` workspace with PR metadata (`pr_url`/`pr_number` and
     `pr_merge_sha` where available).
   - Set the completion/update time to older than configured retention.
   - Create managed worktree, compose, and auth directories.

   Assertions:
   - Dry-run plan has one candidate.
   - Candidate has reason code like `COMPLETED_PR_RETENTION_EXPIRED`.
   - Candidate reports worktree, compose, and auth paths and estimated bytes.
   - No logs or artifacts paths appear as deletion targets.

2. Recent completed PR workspace is preserved.

   Location: `tests/unit/service/test_gc.py`

   Setup:
   - Seed a `completed` PR workspace newer than retention with pressure dirs.

   Assertions:
   - It is not in cleanup candidates.
   - It appears in a preserved/skipped section with reason code such as
     `WORKSPACE_WITHIN_RETENTION`.
   - Executing cleanup leaves worktree, compose, auth, logs, and artifacts
     intact.

3. Failed workspaces preserve triage assets by default.

   Location: `tests/unit/service/test_gc.py`

   Setup:
   - Seed an old `failed` workspace with worktree, compose, auth, logs, and
     artifacts.

   Assertions:
   - Default cleanup plan does not select it.
   - It is reported as preserved with reason code such as
     `FAILED_WORKSPACE_TRIAGE_PRESERVED`.
   - Execution leaves all triage paths intact.

4. Execution deletes only pressure dirs and preserves durable history.

   Location: `tests/unit/service/test_gc.py`

   Setup:
   - Seed an old completed PR workspace.
   - Add workspace events and a durable log stream row.
   - Create `<work_dir>/logs/<workspace>` and
     `<work_dir>/artifacts/<workspace>` files.

   Assertions:
   - Execution deletes only worktree, compose, and auth.
   - Workspace row remains.
   - Existing events remain.
   - Log stream row and log file remain.
   - Artifact files remain.
   - Result payload has `status: "succeeded"` and per-path reason codes.

5. Cleanup is idempotent after partial Docker failure.

   Location: `tests/unit/service/test_gc.py` or
   `tests/unit/node/test_cleanup.py`, depending on where the Docker teardown
   abstraction lands.

   Setup:
   - Inject a fake Compose teardown that fails on the first run and succeeds on
     the second.
   - Keep the same old completed PR workspace across runs.

   Assertions:
   - First run returns `partial` or `failed` with reason code
     `DOCKER_COMPOSE_DOWN_FAILED` and a clear result payload.
   - No unsafe path deletion happens if Docker state is unknown.
   - Second run succeeds and deletes the eligible pressure dirs.
   - Third run is a no-op/already-cleaned result, not an error.

6. Settings drive retention defaults.

   Location: `tests/unit/service/test_config.py` or
   `tests/unit/cli/test_service_cli.py`

   Assertions:
   - Default retention is the documented value, initially 168 hours unless the
     implementation chooses a different named default.
   - `AWF_COMPLETED_WORKSPACE_RETENTION_HOURS` overrides the value.
   - `awf service gc` uses the configured retention when `--min-age-hours` is
     omitted.

7. Service status exposes cleanup readiness.

   Location: `tests/unit/service/test_status.py`

   Setup:
   - Mock DB/session inputs or use PostgreSQL rows for one old completed PR, one
     recent completed PR, and one failed workspace.

   Assertions:
   - `checks.workspace_cleanup` reports retention hours.
   - It includes candidate and preserved counts.
   - Examples include reason codes explaining selected vs preserved workspaces.
   - Top-level service status remains `ok` when the only issue is eligible
     cleanup work.

8. CLI pretty and JSON output expose reasons.

   Location: `tests/unit/cli/test_service_cli.py`

   Assertions:
   - JSON output includes `policy`, `candidate_count`, `preserved_count`,
     `reason_code`, and per-path outcomes.
   - Pretty output includes the same important keys through the existing
     formatter.
   - Dry-run with candidates exits 0.
   - Execute with cleanup failures exits 1.

9. PR monitor no longer deletes recent completed pressure dirs immediately.

   Location: `tests/unit/runtime/test_monitor_completion_gc.py`

   Update the existing completion cleanup expectation:
   - Compose teardown may still run after merge.
   - Worktree, compose directory, and auth directory remain when the completed

   - A structured log/event indicates filesystem cleanup was deferred by
     retention policy.

10. Worker sweep wiring, if implemented.

   Location: `tests/unit/control/test_worker.py` and
   `tests/unit/service/test_worker.py`

   Assertions:
   - Worker invokes the cleanup sweep at the configured interval.
   - It respects batch limit and node/work-dir configuration.
   - Cleanup failures are logged and do not kill the worker loop.

## Implementation Steps

1. Add cleanup policy/result types in `src/awf/service/gc.py`.
   - Define stable reason-code constants.
   - Keep backwards-compatible fields such as `deleted_paths` and
     `delete_errors` if existing tests or callers depend on them.
   - Add richer `policy`, `candidates`, `preserved`, and per-path outcome
     payloads.

2. Tighten default eligibility.
   - Default candidates should be completed PR workspaces past retention.
   - Treat a completed PR workspace as a completed row with PR metadata
     (`pr_url` or `pr_number`); do not require `pr_merge_sha` for older or
     externally merged rows unless tests show that is reliable.
   - Use the completed transition timestamp if cheaply available; otherwise use
     `Workspace.updated_at` and document that fallback.
   - Exclude active, monitoring, destroying, and failed workspaces from default
     cleanup.

3. Preserve failed triage assets.
   - Default planner reports failed rows as preserved, not candidates.
   - Do not delete failed worktree, compose, auth, logs, or artifacts from the
     retention cleanup path.
   - Leave explicit operator destroy behavior unchanged.

4. Make execution structured and idempotent.
   - Missing pressure dirs are successful `already_removed` outcomes.
   - Symlink, non-directory, and out-of-root protections remain hard skips with
     reason codes.
   - Docker/Compose teardown failures are captured in the result and do not
     raise out of the cleanup run.
   - Re-running cleanup after partial failure retries remaining work and treats
     already removed paths as no-ops.

5. Preserve durable audit data.
   - Keep the deletion roots limited to worktree, compose, and auth.
   - Add regression assertions that `<work_dir>/logs`,
     `<work_dir>/artifacts`, workspace rows, events, and log stream rows
     survive cleanup.
   - Do not delete DB rows.

6. Add configuration.
   - Add pydantic settings with `AWF_` env support.
   - Thread values through `resolve_service_settings(...)`.
   - Use settings defaults in CLI and service status.

7. Add service status visibility.
   - Add a `workspace_cleanup` check payload with `ok`, `status`, `reason`,
     `retention_hours`, counts, and examples.
   - Use reason codes such as `CLEANUP_CANDIDATES_READY`,
     `NO_CLEANUP_CANDIDATES`, and `CLEANUP_PLAN_UNAVAILABLE`.
   - Keep dependency failures visible without hiding DB or Docker issues.

8. Update CLI behavior.
   - Keep dry-run as default.
   - Use configured retention when age is not passed.
   - Include selected and preserved workspaces in JSON.
   - Preserve current explicit `--status` filters where compatible, but do not
     let default cleanup include failed workspaces.

9. Adjust PR monitor completion behavior.
   - Keep completed state transition and durable defer-signal artifact behavior.
   - Keep immediate Compose teardown if required for Docker network pressure.
   - Defer filesystem pressure-dir cleanup until the retention planner selects
     the workspace.

10. Add worker sweep only if needed for this P0 definition.
   - Use the same service GC runner and settings.
   - Run on a bounded interval and batch size.
   - Keep cleanup failures non-fatal to workspace scheduling.

11. Update docs after implementation.
   - Document the retention env var, dry-run output, execute behavior, and
     failed-workspace preservation in `README.md`.

12. Commit during implementation phase.
   - After tests and validation pass, make a local commit with a focused
     message.
   - Do not push; AWF owns push, PR creation, monitoring, and merge.

## Risks And Assumptions

- Retention time source matters. Prefer the completed transition event time if
  available; falling back to `updated_at` is acceptable but cleanup/status code
  must not update the row in a way that accidentally extends retention forever.
- Older completed PR rows may not have `pr_merge_sha`; PR metadata should be
  enough to classify them as PR workspaces unless tests prove otherwise.
- Docker may be unavailable during cleanup. The result should be partial and
  retryable, not silently successful.
- Compose teardown and filesystem deletion should be ordered conservatively so
  AWF does not delete the compose file needed to retry a failed Docker cleanup.
- Existing orphan-resource status uses related retention concepts. The new
  cleanup check should avoid contradictory labels where an existing old
  completed workspace is cleanup-ready but not truly "missing" or unknown.
- All path deletion must keep the existing safe-root, symlink, and directory
  guards.

## Explicit Non-Goals

- Do not delete workspace rows, task attempts, operations, events, durable log
  streams, log files, or artifact files.
- Do not automatically clean failed workspaces in this slice.
- Do not change branch management, PR merge policy, validation policy, or
  staleness policy.
- Do not add cloud/GCP cleanup semantics.
- Do not build console UI changes for this slice.
- Do not add migrations unless implementation proves existing string/JSON
  fields cannot represent the required cleanup history.
- Do not push; AWF handles push and PR lifecycle.
