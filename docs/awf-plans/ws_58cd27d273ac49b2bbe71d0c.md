# Plan — Issue #405: discard unpinned/unverifiable non-empty overlay `upper` rather than mount over a guessed base

Workspace: `ws_58cd27d273ac49b2bbe71d0c`

## Goal (owner decision, verbatim intent)

Resolve the residual #405 edge case that #414 deferred: *"unpinned non-empty upper
remounted over a host-guessed base after reboot when `~/.claude` changed."* The owner
has ruled **wrong-base-correctness WINS over credential-preservation** for an
**unverifiable** base. Implement exactly that:

1. On (re)provision, when there is a **NON-EMPTY** overlay `upper` that is **NOT pinned to
   a VERIFIABLE base** (no pin, OR a pin that cannot be matched to an available/known
   base) **and** no live overlay is still mounted to recover the true base from, **DISCARD
   the upper and rebuild** — mount a fresh empty upper over the base built from the
   **current host** so `~/.claude` (credentials included) is re-derived fresh. From the
   operator's perspective there is **no credential loss** (current host creds are pulled).
2. **Only discard when the base genuinely cannot be verified.** If the upper IS pinned and
   the pin resolves to an available base — or the pin's signature equals the current-host
   signature so a rebuild reproduces exactly that base — **KEEP it** (no behavior change
   for the normal/verified case).
3. Make it **LOUD**: emit a dedicated reason code
   `CLAUDE_AUTH_OVERLAY_UNPINNED_UPPER_DISCARDED_REBUILT` (the owner's suggested
   `OVERLAY_UNPINNED_UPPER_DISCARDED_REBUILT` token, prefixed to match every sibling
   `CLAUDE_AUTH_OVERLAY_*` constant in this module) plus a structured `warning` log, so the
   discard is auditable and never silent. Follows the module's reason-code-as-structured-log
   pattern end-to-end (constant → `reason_code=` log field → re-exported on the stable
   `awf.node.auth_mounts` surface). See "Reason catalog" below — no generated-catalog change.
4. **Update the conflicting regression** `test_overlay_reboot_without_pin_rebuilds_and_repins`
   to encode the decision (discard + rebuild + loud reason code; creds re-pulled from host).
5. **Do NOT regress** `test_crash_before_mount_does_not_pin_stale_base_for_fresh_provision`
   — keep post-mount pinning; introduce **no durable pre-mount pin**.
6. Add a **new regression test** for the decided path (unpinned non-empty upper after a host
   `~/.claude` change → discarded + rebuilt from current host + new reason code).

Non-goal: re-opening #402/#404 work that #414 already landed.

## Where the fix goes (intended files/modules to touch)

- `src/awf/node/auth_mounts_claude.py` — the only production change.
  - Add module constant
    `_CLAUDE_AUTH_OVERLAY_UNPINNED_UPPER_DISCARDED_REBUILT = "CLAUDE_AUTH_OVERLAY_UNPINNED_UPPER_DISCARDED_REBUILT"`
    beside the existing `_CLAUDE_AUTH_OVERLAY_*` constants (with an explanatory comment
    mirroring their style: when/why it fires, the wrong-base > creds trade-off).
  - Add a small private helper `_pin_matches_signature(sig_marker: Path, signature: str) -> bool`
    that returns `True` iff `base.signature` exists and its stripped contents equal
    `signature` (i.e. the pin names exactly the base a current-host rebuild would
    reproduce). `OSError`/absent marker → `False`. This is the "verifiable via matching
    pin" probe distinct from `_pinned_overlay_base` (which proves the pinned base is *on
    disk*). Together they implement owner point 1's two KEEP cases.
  - In `_prepare_claude_overlay_mount`, inside the existing `if base is None:` block (where
    `base = _pinned_overlay_base(...)` returned `None`), **before** `_ensure_shared_claude_base`,
    compute `fresh_signature = _host_claude_signature(host_home)` (already computed there) and
    add the discard guard:
    ```python
    if (
        upper.exists()
        and _overlay_upper_has_data(upper)
        and not _pin_matches_signature(sig_marker, fresh_signature)
        and not overlay_mounter.is_mounted(merged)
    ):
        _log.warning(
            "claude_auth_overlay_unpinned_upper_discarded_rebuilt",
            reason_code=_CLAUDE_AUTH_OVERLAY_UNPINNED_UPPER_DISCARDED_REBUILT,
            workspace_auth_root=str(claude_root),
        )
        shutil.rmtree(upper, ignore_errors=True)
        shutil.rmtree(work, ignore_errors=True)
    ```
    Rationale for each conjunct:
    - `upper.exists() and _overlay_upper_has_data(upper)` — only a NON-EMPTY surviving upper
      carries agent data worth a loud discard; an empty leftover (the `test_crash_before_mount`
      provision-2 case) is a fresh start and must take the silent normal path.
    - `not _pin_matches_signature(sig_marker, fresh_signature)` — KEEP when the pin still
      names the current-host base (the `test_overlay_retry_rebuilds_when_pinned_base_missing`
      case: pinned base reaped but signature == current host, so the rebuild is verified, not
      guessed).
    - `not overlay_mounter.is_mounted(merged)` — when a live overlay survives, the existing
      reuse branch recovers the *real* lowerdir via `_live_overlay_pin_signature`; that base is
      verifiable, so never discard there (keeps every `test_live_mount_reuse_*` test green).
  - After discard, control falls through to the unchanged `_ensure_shared_claude_base`,
    `mkdir(upper/work/merged)` (recreates them empty), mount, and the existing **post-mount**
    `_record_overlay_base_pin(sig_marker, fresh_signature, ...)` — so the durable pin is
    written only after a successful fresh mount (point 5 preserved; no pre-mount pin added).
- `src/awf/node/auth_mounts.py` — add a one-line re-export of the new constant
  (`from awf.node.auth_mounts_claude import _CLAUDE_AUTH_OVERLAY_UNPINNED_UPPER_DISCARDED_REBUILT as ...`)
  alongside the existing `_CLAUDE_AUTH_OVERLAY_*` re-exports, so tests import it from the
  stable surface exactly like the siblings.

No changes to `auth_mounts_claude_reconcile.py` or `auth_mounts_overlay_copy.py`: the discard
happens *before* any reconcile/mount, and the discard scenarios carry no legacy `.claude`
copy, so the reconcile passes are untouched.

## Risks, assumptions, non-goals

**Risks**
- *Over-discarding a recoverable upper.* Mitigated by the three-conjunct guard: only
  non-empty + unverifiable + not-live-mounted uppers are discarded; pinned/verifiable and
  live-mounted uppers are untouched. The trade-off (discard agent overlay mutations when the
  base is unverifiable) is the explicit owner decision; creds are re-pulled from the current
  host so there is no operator-visible credential loss.
- *Second conflicting test* (`test_prepin_upper_mount_failure...`) beyond the one named in the
  task. Surfaced and handled here deliberately; updated to the owner decision while preserving
  its still-valid no-pin/legacy-fallback assertions. Called out explicitly rather than hidden.
- *Combined legacy-copy + non-empty-unpinned-upper* interaction: after discard the caller's
  legacy-edit reconcile still forwards diverging agent edits into the fresh upper (safe,
  edits-only). The owner's named scenarios have no legacy copy, so this is an unchanged,
  benign edge.

**Assumptions**
- "Verifiable base" = pinned base present on disk (`_pinned_overlay_base`) OR pin signature ==
  current-host signature (`_pin_matches_signature`). Both reproduce the exact base the upper
  was built against; anything else is a guess.
- `_host_claude_signature` is already computed once in the `if base is None:` block, so the
  discard probe adds no extra signature walk.
- `FakeOverlayMounter.mount` records lowerdir/upperdir and does not populate `upper`, so the
  "discarded ⇒ upper file absent" assertions are sound under the test fakes.

**Non-goals**
- No durable pre-mount pin (point 5). No change to post-mount pinning, the live-mount reuse
  branch, `_live_overlay_pin_signature`, the #381 edit reconcile, the #402 deletion whiteouts,
  or the #404 host-divergence guard. No re-opening of #402/#404. No new abstractions; reuse
  existing helpers and the established `_CLAUDE_AUTH_OVERLAY_*` reason-code pattern.
