# Plan — Issue #406: Pre-push validation fix pass orphans self-committed repair commits

## Problem (confirmed)

`src/awf/runtime/pr_monitor_runner/pre_push_validation.py::_run_pre_push_validation_fix_pass`:

1. Captures `fix_start_head = await self._rev_parse_head(worktree_path)` (line ~605).
2. Runs the fix-pass adapter.
3. Calls `self._commit_dirty_worktree(...)` (lines ~708-720).

`_commit_dirty_worktree` (in `remote_repair.py`, lines ~239-250) returns `False` when
`git status --porcelain` is **empty** (clean worktree). So when the fix-pass agent
**self-commits** its repair (HEAD advances, worktree becomes clean), `_commit_dirty_worktree`
returns `False`.

The current `if not committed:` branch (lines ~739-749) unconditionally calls
`_rollback_failed_pre_push_validation_fix_pass(..., restore_ref=fix_start_head)`, which runs
`git reset --hard fix_start_head`. That **orphans the agent's valid self-commit** and leaves the
branch on the pre-fix (still-failing) head, so the monitor keeps re-validating the stale state
and blocks the push with `PRE_PUSH_VALIDATION_FIX_FAILED`.

Real-world evidence: awf-cloud `ws_71fbbec52dfc4c79939ea543`/PR55,
`ws_3160e0edae5c4bf398a56b33`/PR56 (valid fix commits `75c5f035`, `432e34da` became unreachable).

## Fix (matches issue Expected Behavior)

In `_run_pre_push_validation_fix_pass`, in the `if not committed:` path, **before** rolling back:

- Re-read HEAD: `current_head = await self._rev_parse_head(worktree_path)`.
- **HEAD advanced** (`current_head is not None and current_head != fix_start_head`): the agent
  self-committed a valid repair. Treat as a successful committed repair — run the **same**
  committed-head cleanup (`_pre_push_validation_cleanup(..., restore_ref=current_head)`) the
  `if committed:` branch uses, and **return `committed=True`** so the caller
  (`_run_pre_push_validation_with_fix_passes`) increments `pass_index` and **reruns** pre-push
  validation on the advanced head (no blind push — the loop re-validates). Do **not** roll back.
- **HEAD did not advance** (`current_head == fix_start_head`, or `current_head is None`, i.e. no
  repair produced / HEAD unreadable): keep existing behavior — roll back to `fix_start_head` and
  return not-committed.

Keep rollback unchanged for all genuine failure paths: agent exception, `ComposeExecCleanupError`,
commit exception. Refactor so the self-commit cleanup and the existing committed-branch cleanup
share one helper rather than duplicating.

### Concrete refactor of `pre_push_validation.py`

1. **Extract** the committed-head cleanup (current lines ~759-775) into a new module-level helper:

   ```python
   async def _cleanup_committed_pre_push_validation_fix_pass(
       self: Any,
       *,
       workspace_id: str,
       worktree_path: Path,
       committed_head: str,
       pass_number: int,
   ) -> str | None:
       """Clean validation side effects against a committed fix head; return failure reason."""
       cleanup = await _pre_push_validation_cleanup(
           self, worktree_path=worktree_path, restore_ref=committed_head
       )
       ok = bool(cleanup.ok)
       log = _log.info if ok else _log.warning
       log(
           "monitor.pre_push_validation_fix_commit_cleanup",
           workspace_id=workspace_id,
           pass_number=pass_number,
           restore_ref=committed_head,
           reason_code=None if ok else cleanup.reason_code,
           cleanup_stderr=(cleanup.cleanup_stderr or "")[:400],
       )
       if not ok:
           return cleanup.reason_code or VALIDATION_WORKTREE_CLEANUP_FAILED
       return None
   ```

2. **Rewrite** the tail of `_run_pre_push_validation_fix_pass` (current lines ~739-776):

   ```python
   if not committed:
       current_head = await self._rev_parse_head(worktree_path)
       if current_head is not None and current_head != fix_start_head:
           # Fix-pass agent self-committed a valid repair (HEAD advanced, worktree clean).
           # Treat as a committed repair: clean side effects against the new head and let the
           # caller rerun pre-push validation on the advanced head. Do NOT roll it back.
           _log.info(
               "monitor.pre_push_validation_fix_self_commit_detected",
               workspace_id=workspace_id,
               pass_number=pass_number,
               fix_start_head=fix_start_head,
               committed_head=current_head,
           )
           cleanup_failure_reason = await _cleanup_committed_pre_push_validation_fix_pass(
               self,
               workspace_id=workspace_id,
               worktree_path=worktree_path,
               committed_head=current_head,
               pass_number=pass_number,
           )
           return True, cleanup_failure_reason
       rollback_failure_reason = await _rollback_failed_pre_push_validation_fix_pass(
           self,
           workspace_id=workspace_id,
           worktree_path=worktree_path,
           restore_ref=fix_start_head,
           pass_number=pass_number,
           reason="commit_failed",
       )
       if rollback_failure_reason is not None:
           return False, rollback_failure_reason
       return False, None

   committed_head = await self._rev_parse_head(worktree_path)
   if committed_head is None:
       _log.warning(
           "monitor.pre_push_validation_fix_commit_head_unavailable",
           workspace_id=workspace_id,
           pass_number=pass_number,
       )
       return True, PRE_PUSH_VALIDATION_INFRASTRUCTURE_FAILED_REASON
   cleanup_failure_reason = await _cleanup_committed_pre_push_validation_fix_pass(
       self,
       workspace_id=workspace_id,
       worktree_path=worktree_path,
       committed_head=committed_head,
       pass_number=pass_number,
   )
   return True, cleanup_failure_reason
   ```

   This replaces the current fall-through `if not committed: ... if committed: ... return committed, None`
   structure with explicit early returns; the `if committed:` block becomes the post-`not committed`
   straight-line path (committed is `True` there).

Behavior preserved: the committed (dirty-worktree) path still re-reads HEAD, treats `None` as
`PRE_PUSH_VALIDATION_INFRASTRUCTURE_FAILED`, and surfaces cleanup failures as
`VALIDATION_WORKTREE_CLEANUP_FAILED` — now via the shared helper.

## Risks & assumptions

- **FakeCommandRunner queue drift (primary risk).** The new pre-rollback `_rev_parse_head` shifts
  queued-result positions for commit-`False` tests. Mitigation: update each affected test and run it
  in isolation; prefer `monkeypatch`-ing `_rev_parse_head` (as the cleanup test does) over fragile
  queue counting where practical for the *new* tests.
- **`_rev_parse_head` failure (`None`) on the self-commit check.** Treated as "no advance" → roll
  back. This is the safe/conservative choice and matches the issue ("current_head is not None and
  current_head != fix_start_head"). It cannot mistake a clean no-op for a self-commit.
- **Caller loop semantics unchanged.** Returning `committed=True` from the self-commit path makes
  `_run_pre_push_validation_with_fix_passes` increment `pass_index` and re-run
  `_run_pre_push_validation` on the advanced head — re-validation, never a blind push. Verified
  against the existing `if committed:` / `pass_index += 1` control flow.
- **Assumption:** a self-committed repair leaves a genuinely clean worktree (`git status
  --porcelain` empty). If the agent self-commits *and* leaves new dirt, `_commit_dirty_worktree`
  returns `True` (committed branch) and behavior is unchanged — also correct.

## Non-goals

- No change to `_commit_dirty_worktree` semantics (clean worktree still returns `False`); the fix is
  entirely in how the fix-pass caller interprets that result.
- No change to rollback behavior for agent-exception, compose-cleanup, or commit-exception paths.
- No change to push gating, merge gates, protected-scope handling, reason-code catalog, or the
  `_run_pre_push_validation` cycle itself.
- No new reason codes, events beyond the single info log, schema, or migration changes.
- AWF/GitHub own broad validation, coverage gate, and merge after the agent phase; this plan runs
  only focused checks.
