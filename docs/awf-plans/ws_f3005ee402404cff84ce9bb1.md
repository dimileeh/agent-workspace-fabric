# Plan: MCP read-only operator parity slice

## Scope

Implement a narrow P1 MCP parity slice for existing read-only operator REST
surfaces. REST remains the canonical API contract; MCP tools should act as a
typed client over the same schemas and service builders, returning
`model_dump(mode="json")` payloads aligned with REST response models and reason
codes.

Target read-only surfaces:

- Merge queue: `/v1/merge-queue`.
- Workspace overview: `/v1/workspaces/overview`.
- Resource/service status: expose resource saturation metrics from
  `/v1/metrics/resources/saturation`; add health only if it stays trivial and
  side-effect-free.
- Validation provenance: `/v1/workspaces/{workspace_id}/validation`.
- Stale reasons: `/v1/workspaces/{workspace_id}/stale-reasons`.
- Artifact metadata: `/v1/workspaces/{workspace_id}/artifacts`.
- Metrics and failure analysis: `/v1/metrics/failures/summary`,
  `/v1/metrics/workspaces/summary`, and `/v1/metrics/slo` where practical.
- Operations: `/v1/operations` and `/v1/operations/{operation_id}`.
- Overlap graph: `/v1/locks/overlap-graph`.

MCP tool names should stay explicit and read-oriented:

- `awf_list_merge_queue`
- `awf_list_workspace_overview`
- `awf_list_workspace_validation`
- `awf_list_workspace_stale_reasons`
- `awf_list_workspace_artifacts`
- `awf_get_failure_analysis_summary`
- `awf_get_workspace_reliability_summary`
- `awf_get_resource_saturation_summary`
- `awf_get_slo_metrics_summary`
- `awf_list_operations`
- `awf_get_operation`
- `awf_get_overlap_graph`

Keep the existing workspace, log, runtime, and operator-control tools working.
For existing MCP tools that currently return a legacy bare list, prefer adding
new parity tools or preserving the old return shape unless strict schema parity
requires changing it with tests.

## Intended Files and Modules to Touch

1. `tests/unit/mcp/test_mcp_operator_surfaces.py` (new)
   - Main TDD contract suite for REST/MCP parity.
   - Build a FastAPI test client and an MCP server over the same in-memory
     PostgreSQL engine/session factory.
   - Compare MCP structured payloads to REST JSON for the same seeded records.

2. `tests/unit/mcp/test_mcp_server.py`
   - Extend registration and input-schema assertions for the new read-only
     tools.
   - Keep existing create/get/list/wait/log/runtime/control tests intact.

3. `src/awf/mcp/server.py`
   - Register the new read-only MCP tools.
   - Use `Field` constraints matching REST query/path parameter constraints.
   - Serialize Pydantic response models with `model_dump(mode="json")`.
   - Return structured MCP errors for REST-style contract errors such as
     invalid cursors using existing `ErrorResponse` reason codes.
   - Do not add any tool that runs arbitrary shell commands or Docker commands.

4. `src/awf/service/merge_queue.py` and `src/awf/api/routes/merge_queue.py`
   - Extract the current route query/serialization logic into a reusable
     service function returning `MergeQueueListResponse`.
   - Keep `_decode_cursor`/invalid cursor behavior and sorting semantics
     unchanged.
   - REST route becomes a thin HTTP wrapper; MCP calls the same service helper.

5. `src/awf/service/workspace_overview.py` or
   `src/awf/service/workspace_observability.py`, plus
   `src/awf/api/routes/workspaces.py`
   - Extract the `/v1/workspaces/overview` response builder into shared code.
   - Preserve cursor encoding/decoding, active-operation selection, lifecycle,
     LLM usage, recovery, and last-event fields.
   - Add a small service method for stale reasons if needed, using
     `StaleReasonRepository` and `StaleReasonListResponse`.

6. `src/awf/service/validation_provenance.py` (new) and
   `src/awf/api/routes/validation.py`
   - Move the existing validation provenance builder into shared service code.
   - Preserve persisted `validation_runs` precedence over legacy log-stream
     inference.
   - Preserve freshness identity fields, tier/status coercion, coverage fields,
     and log stream references.
   - REST maps missing workspace to the existing 404 `NOT_FOUND`; MCP follows
     the existing read-only convention of `null` for missing workspace unless
     a structured error is required by a test.

7. `src/awf/service/artifacts.py` (new),
   `src/awf/api/routes/artifacts.py`, and likely `src/awf/api/schemas.py`
   - Move artifact response models out of the route module if needed so REST
     and MCP can share `WorkspaceArtifactResponse` and
     `WorkspaceArtifactListResponse`.
   - Extract the safe metadata-only artifact listing into shared code.
   - Keep symlink exclusion, root containment checks, deterministic sorting,
     artifact IDs, kinds, and `DEFAULT_ARTIFACT_LIST_LIMIT`.
   - Do not add artifact content download/read tools in this slice.

8. `src/awf/api/routes/metrics.py`, `src/awf/service/metrics.py`, and possibly
   `src/awf/api/schemas.py`
   - Reuse existing metrics summary functions.
   - Move route-local Pydantic response models to shared schemas only if MCP
     cannot cleanly import/use them otherwise.
   - For resource saturation, keep the existing disk/orphan/runtime provider
     seams so tests can inject deterministic providers and MCP does not invent
     new Docker behavior.

9. `src/awf/service/workspaces.py` and `src/awf/api/routes/operations.py`
   - Reuse existing `WorkspaceService.list_all_operations`,
     `WorkspaceService.get_operation`, and `WorkspaceService.list_operations`.
   - Add MCP `awf_list_operations` returning the REST `OperationListResponse`
     envelope.
   - Add MCP `awf_get_operation` returning `OperationResponse` or `null`.

10. `src/awf/service/overlap_graph.py` and `src/awf/api/routes/locks.py`
    - Reuse `build_workspace_overlap_graph` directly for MCP.
    - Preserve filters, compact response, and advisory `blocks_launch=false`
      semantics.

11. `README.md`
    - Update the MCP surface table after implementation so documented tools
      match the new read-only parity surface.
    - Do this only during implementation, not in this planning-only workspace.

## Tests to Write First

Write the MCP contract tests before implementation, run them, and confirm they
fail because the tools or shared builders do not exist yet.

1. `test_operator_parity_tools_registered`
   - Assert all new read-only tools are listed.
   - Assert descriptions say they are read-only/operator observability tools.
   - Assert no tool description implies shell access or Docker exec.

2. `test_merge_queue_tool_matches_rest_payload_and_reason_codes`
   - Seed a workspace, task attempt, merge candidate, validation run, active
     stale reason, and queue blocker/policy state as needed.
   - Compare `GET /v1/merge-queue?...` JSON to
     `awf_list_merge_queue` structured content.
   - Assert `merge_blocker_reason`, `required_next_action`,
     `validation_freshness_status`, `validation_reason_code`, and
     `stale_reasons[*].reason_code` match.

3. `test_workspace_overview_tool_matches_rest_payload`
   - Seed workspace events and a pending/running operation.
   - Compare `/v1/workspaces/overview` to `awf_list_workspace_overview`.
   - Assert lifecycle, recovery, active operation, last event, agent identity,
     and LLM usage fields survive JSON serialization.

4. `test_validation_provenance_tool_matches_rest_payload`
   - Seed both persisted validation-run data and log streams.
   - Compare `/v1/workspaces/{id}/validation` to
     `awf_list_workspace_validation`.
   - Assert tier, command hash, freshness, coverage, stream refs, and status
     fields match.

5. `test_stale_reasons_tool_matches_rest_active_and_resolved_payloads`
   - Seed active and resolved stale reasons for one workspace/candidate.
   - Compare default active-only REST/MCP payloads.
   - Compare `include_resolved=true` REST/MCP payloads.

6. `test_artifacts_tool_matches_rest_metadata_payload`
   - Use a temporary AWF work dir.
   - Seed artifact files, nested files, and ignored symlinks under
     `artifacts/<workspace_id>`.
   - Compare `/v1/workspaces/{id}/artifacts` to
     `awf_list_workspace_artifacts`.
   - Assert the tool returns metadata only, not file contents.

7. `test_failure_analysis_metrics_tool_matches_rest_payload`
   - Seed failed/cancelled workspaces with known `FailureReason` values and
     messages.
   - Compare `/v1/metrics/failures/summary` to
     `awf_get_failure_analysis_summary`.
   - Assert failure groups, latest examples, root-cause clusters, and
     recommended actions match.

8. `test_operations_tool_matches_rest_filters_and_detail`
   - Seed operations across two workspaces.
   - Compare `/v1/operations?workspace_id=...&type=...&status=...` to
     `awf_list_operations`.
   - Compare `/v1/operations/{operation_id}` to `awf_get_operation`.
   - Assert operation reason/failure/log-stream metadata fields are preserved.

9. `test_resource_saturation_tool_matches_rest_payload_with_fake_providers`
   - Use deterministic disk/orphan/runtime provider fakes mirroring the API
     route test seam.
   - Compare `/v1/metrics/resources/saturation` to
     `awf_get_resource_saturation_summary`.
   - Assert admission reason codes and cleanup/runtime health summaries match.

10. `test_overlap_graph_tool_matches_rest_payload`
    - Seed overlapping owned paths across queued/running workspaces.
    - Compare `/v1/locks/overlap-graph` to `awf_get_overlap_graph`.
    - Assert nodes, edges, path match reason codes, and
      `blocks_launch=false` semantics match.

11. `test_invalid_cursors_return_structured_mcp_errors`
    - Cover merge queue and workspace overview invalid cursor inputs.
    - Assert MCP returns `ErrorResponse` structured content with
      `error_code="INVALID_CURSOR"` and the REST message.

## Implementation Steps

1. Add the failing MCP parity tests and run the focused MCP test file to
   capture the expected red state.
2. Extract REST route logic into shared service functions one surface at a
   time, keeping API route responses unchanged and covered by existing API
   tests.
3. Register the corresponding MCP tool after each shared helper exists.
4. Use REST response models as the serialization boundary:
   `response.model_dump(mode="json")`.
5. Add small MCP error helpers for invalid cursor/contract errors; preserve
   `null` for missing workspace/log/operation resources where existing MCP
   read-only tools already use that convention.
6. Run the MCP parity tests after each tool is wired.
7. Run focused existing API tests for every route whose code was extracted.
8. Update README MCP surface documentation only after tests are green.

## Risks

- The active normalized-pagination slice may land before implementation and
  change list response envelopes. Adapt to the landed REST schema rather than
  preserving stale plan assumptions.
- The active overlap-graph slice may modify filters or response fields. Treat
  the current REST endpoint at implementation time as canonical.
- Extracting route-local helper functions can accidentally change cursor,
  ordering, or error behavior. Parity tests should compare full REST/MCP JSON
  payloads for representative seeded data.
- Artifact and resource-status code touches filesystem and Docker-adjacent
  scanners. Tests must use temporary work dirs and existing provider seams to
  avoid environment-dependent failures.
- Existing MCP clients may rely on legacy bare-list payloads for current tools.
  Prefer additive parity tools or explicitly update tests/docs if a return shape
  must change.
- FastMCP wraps primitive/list returns differently from dict/structured
  `CallToolResult` returns. New tools should return structured dict envelopes
  through `_tool_result` to avoid wrapper surprises.

## Assumptions

- REST response schemas and reason codes are the source of truth.
- The task is limited to read-only operator observability parity, except for
  already-existing MCP control tools that are outside this slice.
- Existing service/repository data is sufficient for every planned tool; no new
  DB tables, migrations, scheduling rules, stale policy, or validation policy
  are required.
- Missing workspace behavior can follow current MCP read-only convention
  (`null`) while invalid request contracts return structured MCP errors with
  REST reason codes.
- Resource status means existing resource saturation metrics unless a current
  service-status helper can be reused without new shell/Docker behavior.

## Explicit Non-Goals

- Do not add arbitrary shell, Docker exec, log tail, container inspection, or
  artifact content download tools.
- Do not add new merge policy, stale detection rules, validation freshness
  logic, scheduler behavior, or overlap admission blocking.
- Do not change REST endpoint paths, response schemas, or reason codes except
  for mechanical extraction into shared service functions.
- Do not add console UI work.
- Do not add migrations, lockfile changes, dependency changes, or config
  changes unless implementation discovers a direct schema-sharing blocker.
- Do not push, rebase, switch branches, or commit from this planning workspace.
