# Plan: Issue #412 auth-overlay unmount retry backfill

## Problem Statement

Issue #412 tracks a deferred review gap from PR #410/#399: the runtime retry scan only finds `workspace.terminal_auth_overlay_unmount_pending` markers created after the upgrade. Older `workspace.terminal_runtime_released` events can already have `payload.auth_overlay_unmounted == false` but no overlay-unmount marker, so the existing event-type-only retry scan never sees them. The goal is to perform a one-time, idempotent backfill that makes those historical failed-unmount releases enter the existing retry path without adding JSON-value predicates to the runtime scan.

## Requirements Checklist

- Backfill pre-upgrade failed Claude auth-overlay umount releases into the deferred retry scan.
- Prefer a one-time Alembic data migration that seeds `workspace.terminal_auth_overlay_unmount_pending` markers.
- Keep `_list_pending_terminal_auth_overlay_unmount_candidates` dialect-portable by not adding JSONB/JSON value comparisons to the scan query.
- Backfill only rows whose current effective `workspace.terminal_runtime_released` event recorded `auth_overlay_unmounted: false`.
- Do not touch rows that already have a current-cycle overlay marker (`pending`, `resolved`, or `exhausted`).
- Make the backfill idempotent and safe to re-run.
- Preserve reason-code evidence end-to-end using the existing `TERMINAL_AUTH_OVERLAY_UNMOUNT_PENDING` marker reason code.
- Add focused tests before implementation covering the backfilled retry, existing-marker no-op, idempotence, and dialect behavior where applicable.
- Keep the change scoped; do not reopen the #399 retry state machine.

## Risks And Mitigations

- Risk: inserting a pending marker for an older revoked release would create a false current-cycle retry.
  - Mitigation: target only the latest effective release/revoke event, and skip workspaces whose latest release/revoke event is a revocation.
- Risk: marker scoping depends on `event_order`.
  - Mitigation: reserve a real workspace-local `event_order` by advancing `workspaces.event_sequence`; assert ordering in tests.
- Risk: JSON boolean storage differs between Postgres and SQLite.
  - Mitigation: keep JSON-value checks out of runtime scan SQL; parse payloads in Python or explicitly test any dialect branch.
- Risk: re-running the migration helper could duplicate events.
  - Mitigation: deterministic event IDs plus current-cycle `NOT EXISTS` marker checks; assert idempotence directly.
- Risk: malformed legacy payloads.
  - Mitigation: treat only dictionary payloads with an explicit boolean `False` as qualifying; handle decode errors specifically if string decoding is needed.
