# Implementation Plan: REST Authentication Parity for Operation Read Endpoints

## Goal
Implement the P1 AWF Core readiness slice to close REST authentication parity for operation read endpoints. This ensures that `GET /v1/operations`, `GET /v1/operations/{operation_id}`, and `GET /v1/workspaces/{workspace_id}/operations` require the local AWF bearer token, matching the security boundary of other operator APIs and the MCP tools.

## Target Files to Modify
1. **`src/awf/api/routes/operations.py`**
   - Add `dependencies=[Depends(require_api_token)]` to the `APIRouter` declaration to protect all operation read endpoints consistently.
   - Import `require_api_token` from `awf.api.deps`.

2. **`tests/unit/api/test_operations_listing.py`**
   - Add test-level authentication configuration (setting `AWF_API_TOKEN` via `monkeypatch` and clearing `get_settings.cache_clear()`).
   - Add new tests specifically to verify authentication boundaries: `test_unauthenticated_operation_reads_rejected` and `test_authenticated_operation_reads_accepted`.
   - Update existing tests to pass the expected `Authorization` header to the test client to maintain coverage without regressions.

3. **`docs/MCP_CLIENT_PARITY.md`**
   - Update the "Workspace operations" and "Global operations" rows.
   - Change Status to `MCP implemented`.
   - Update Security Boundary to reflect `require_api_token`.
   - Remove the `TODO§P1-operation-read-auth` backlog slice reference.

## Tests to Write First (TDD Acceptance)
Before modifying the router in `src/awf/api/routes/operations.py`, write failing tests in `tests/unit/api/test_operations_listing.py`:
- `test_unauthenticated_operation_reads_rejected`: Issues `GET` requests to all three operation read paths without an `Authorization` header and verifies a `401 Unauthorized` or `503 Service Unavailable` response.
- Update existing tests in `test_operations_listing.py` to use an authenticated fixture; they will initially pass, but will fail once the router is secured (if the auth logic has regressions or if `get_settings.cache_clear()` isn't handled correctly).

*Note: Adjacent operation write/control endpoints are defined in `controls.py` and have their own isolated router and tests (e.g., `test_workspace_controls_idempotency.py`). Applying `Depends(require_api_token)` to the `operations.py` router strictly scopes the change without risking auth regressions on `controls.py`.*

## Risks, Assumptions, and Explicit Non-Goals
- **Non-Goal**: We are not changing the authentication boundary for workspace creation or listing, nor are we adding `MCP global events`.
- **Assumption**: The existing `require_api_token` dependency correctly supports the local-dev fallback mechanism (either by throwing an actionable `503` if unconfigured, or by correctly verifying the header if configured), preserving local ergonomics.
- **Risk**: Modifying the `client` calls in `test_operations_listing.py` involves many test updates. We must ensure `get_settings.cache_clear()` is used alongside `monkeypatch` to prevent state leakage between tests.
