# Plan: P0 Provider Resilience — Conformance Stall Detection And Recovery

Workspace: `ws_52d8415a02424c4aa4730fa1`.

## Objective

Stop the AWF executor from leaving workspaces indefinitely `running` when an
agent finishes useful implementation work but stalls or loops while generating
the Plan -> Execute -> Compare conformance JSON / report. Today such stalls
either hang on the per-command watchdog and collapse into generic
`agent_failure`, or the workspace appears `running` long after the agent has
gone quiet because the watchdog only sees per-CLI-invocation silence and not
the overall conformance-loop progress.

Required behavior, derived from
`TODO/pre-gke-industrial-readiness.md` "P0 Provider Resilience And Automated
Fallback Recovery":

1. Detect no-output, repeated-output, and over-duration stalls in the
   conformance/report phase and classify them with a structured reason code
   such as `AGENT_STALLED_IN_CONFORMANCE`.
2. Preserve the worktree, local commits, plan artifact, validation logs, and
   conformance evidence/salvage hints when a stall is recorded.
3. If implementation commits already exist on the feature branch and only the
   conformance/report artifact is missing or malformed, recover by retrying
   only the conformance/report phase with an approved fallback model when
   policy allows, or proceed to validation when policy explicitly permits the
   "implementation complete, conformance unknown" path.
4. Emit durable events and operation records that identify the conformance
   phase, reason code, elapsed time / no-output evidence, and chosen recovery
   action so operators can audit the decision.
5. Keep deterministic conformance gaps (`PLAN_CONFORMANCE_UNSATISFIED`) on
   their existing path with actionable gaps; never relabel them as stalls.

This slice intentionally does not touch the provider-capacity classifier
(`src/awf/adapters/provider_failures.py`), the broader fallback-policy /
circuit-breaker code in `src/awf/service/provider_recovery.py`, the worker's
provider cooldown gates, or anything outside the conformance stall path.

## Intended Files And Modules To Touch

### Production code

- `src/awf/runtime/planning.py`
  - Add a new public reason code `AGENT_STALLED_IN_CONFORMANCE`.
  - Add a `ConformanceStallKind` enum with values `no_output`,
    `repeated_output`, `over_duration` and a `ConformanceStallEvidence`
    dataclass capturing the chosen kind, iteration index, elapsed seconds,
    no-output seconds, repeated-output fingerprint count, last `report_text`
    digest, plan/report paths, and a short redacted excerpt of the last agent
    stdout/stderr.
  - Add a pure helper `classify_conformance_stall(...)` that consumes a
    `ConformanceStallPolicy` (thresholds), the per-iteration timing/output
    history, and the latest `AgentRunError`/`AgentRunResult` when present.
    The classifier must:
    - Return `None` when no stall criterion is met (so deterministic
      `needs_iteration` reports keep flowing through the existing
      `PLAN_CONFORMANCE_UNSATISFIED` path).
    - Return a `ConformanceStallEvidence` with `kind=no_output` when the
      latest conformance run raised an `AgentRunError` whose `reason_code`
      is `AGENT_IDLE_TIMEOUT`, or when `AgentRunResult.stdout` was empty for
      consecutive iterations longer than `no_output_seconds`.
    - Return `kind=repeated_output` when the digest of the last
      `report_text` (after `parse_conformance_report`) matches the prior
      iteration's digest at least `repeated_output_threshold` times AND the
      report still says `needs_iteration` AND no committed/dirty path
      changed between iterations.
    - Return `kind=over_duration` when the cumulative time spent in the
      conformance loop exceeds `over_duration_seconds`, regardless of
      iteration count.
  - Add `build_conformance_stall_failure_evidence(...)` mirroring
    `build_conformance_failure_evidence(...)` but emitting the new reason
    code, the stall kind, elapsed/no-output seconds, repeated-output count,
    and a salvage hint object listing which artifacts are present
    (`plan_path`, optional `report_path`, implementation commit count, last
    successful conformance iteration).
  - Add `build_conformance_stall_recovery_prompt(...)` that resumes the agent
    with conformance-only instructions: do not modify implementation files,
    only re-run the compare phase against the existing plan, and write the
    JSON to the existing report path. Include the prior gap list (if any)
    as advisory context.
  - Re-export new symbols at module level so the executor and service can
    import without breaking the existing planning surface.

- `src/awf/profiles/models.py`
  - Extend `ProfilePlanning` with an optional nested `conformance_stall`
    block typed as `ProfileConformanceStallPolicy` (extra="forbid",
    pydantic). Fields: `no_output_seconds: int = 600`,
    `over_duration_seconds: int = 1800`, `repeated_output_threshold: int = 3`
    (>=2), and `recovery_action: Literal["retry_conformance",
    "proceed_to_validation", "fail"] = "retry_conformance"`. Default values
    must keep current behavior unchanged when the profile omits the block.
  - Update existing planning-profile tests under
    `tests/unit/profiles/test_profiles.py` only to assert the new defaults
    round-trip and reject invalid values.

- `src/awf/control/executor.py`
  - Inside `_run_agent_task_with_optional_planning`:
    - Record per-iteration metadata: start/end timestamps, `report_text`
      digest, sanitized stdout/stderr length, whether the conformance step
      raised `AgentRunError`, and whether the worktree changed between
      iterations.
    - Wrap the `adapter.run(... build_conformance_prompt(...))` call in a
      narrow try/except for `AgentRunError`; treat
      `AGENT_IDLE_TIMEOUT`/`AGENT_TIMEOUT` as stall *signals*, not as
      provider-capacity failures, and feed them into the classifier.
    - After every iteration, call `classify_conformance_stall(...)`. If a
      stall is returned:
      - Stop the loop early, build a stall `_PlanningRunFailure` whose
        `reason_code` is `AGENT_STALLED_IN_CONFORMANCE`, whose `details`
        carry both the existing conformance evidence (last report) and the
        new stall evidence under a `conformance_stall` key.
      - Include implementation-commit evidence: `head_sha`, `base_sha`,
        commit count above base, and the list of changed paths so the
        recovery layer can confirm the implementation is non-empty.
    - Keep the existing exhausted-iteration path untouched: if the loop
      exits normally because `max_iterations` was reached and the last
      report is `needs_iteration` with non-empty gaps, still return the
      existing `PLAN_CONFORMANCE_UNSATISFIED` failure. Stalls only fire on
      idle/timeout/repeated-output/over-duration evidence.
  - In `execute(...)`, when a `_PlanningRunFailure` with
    `reason_code=AGENT_STALLED_IN_CONFORMANCE` returns:
    - Mark the workspace failed with `FailureReason.agent_failure` (we keep
      the coarse failure taxonomy stable in this slice) but record the
      structured `reason_code` and `details` so downstream surfaces
      distinguish the stall.
    - Include `salvage=_failure_salvage_payload(...)` so the worktree,
      branch, and remote push branch are preserved.
    - Emit a new `workspace.planning_conformance_stalled` event with the
      stall evidence payload (in addition to the existing
      `workspace.state_changed -> failed` event); reuse the existing
      `add_event` helpers, no new event-store API.

- `src/awf/service/workspaces.py`
  - Add a `_ConformanceStallRecoveryContext` dataclass next to the existing
    `_ConformanceRetryContext` / `_PlanningScopeRetryContext`, carrying the
    stall reason code, evidence, evidence_ref, the chosen recovery action
    (`retry_conformance` / `proceed_to_validation` / `fail`), an optional
    fallback model lookup result, and the implementation-commit summary.
  - Add `_conformance_stall_retry_context(workspace)` that reads the
    workspace's failed-state event payload and returns the context only when
    `details.reason_code == AGENT_STALLED_IN_CONFORMANCE` and
    `details.conformance_stall` is well-formed. Recognize the same approved
    fallback model surface used by `_planning_scope_retry_context` so this
    slice composes with the existing fallback policy without rewriting it.
  - Update `retry_workspace_row(...)` so the precedence order is:
    1. planning-scope retry,
    2. conformance-stall retry (new),
    3. conformance-unsatisfied retry,
    4. plain retry.
    The new branch builds the retry prompt via
    `build_conformance_stall_recovery_prompt(...)` for `retry_conformance`,
    and keeps the original task prompt verbatim for
    `proceed_to_validation` (no agent re-run; the dispatcher routes to the
    existing validate-only recovery path described below).
  - Extend the operation `payload`/`result` and the `workspace.retry_*`
    event payloads with `source_reason_code`,
    `conformance_stall_evidence_ref`, `recovery_action`, and (when
    chosen) `fallback_model` so operators can audit the decision.
  - For `proceed_to_validation`: instead of cloning a new requested
    workspace, create a `OperationType.validate` recovery operation against
    the source workspace using the existing validate-only recovery payload
    shape (`source="operator_api"`, `recovery_mode="validate_only"`,
    `reason_code=AGENT_STALLED_IN_CONFORMANCE`). The executor's existing
    recovery dispatch path then runs validation against the already-pushed
    work without re-running planning or the agent. Reuse
    `create_or_start_monitor_operation` semantics already imported by the
    executor, do not invent a new state.

- `src/awf/api/routes/workspaces.py` and `src/awf/api/schemas.py`
  - Surface the new `recovery_action` and `conformance_stall_evidence_ref`
    fields on the existing retry response/operation surfaces. No new
    endpoint is added; the existing `/v1/workspaces/{id}/retry` endpoint
    handles the new context transparently because the service layer picks
    the right retry context.

- `src/awf/db/repositories.py`
  - No schema change. The new evidence rides on existing
    `workspace.state_changed` event payloads under
    `details.conformance_stall` and on existing `Operation.payload`/`result`
    JSON. We deliberately avoid a new column / migration in this slice to
    keep the PR scoped.

## Risks And Assumptions

- **Risk: false positives that mislabel real conformance gaps as stalls.**
  Mitigation: classifier requires explicit no-output / idle-timeout /
  repeated-digest-without-worktree-change / over-duration evidence; each
  TDD test pins a deterministic `needs_iteration` case that must NOT be
  classified as a stall.
- **Risk: stall recovery that re-enters the full agent path and rewrites the
  plan.** Mitigation: `retry_conformance` reuses the existing
  conformance-only retry prompt machinery, and `proceed_to_validation` goes
  through the existing validate-only recovery dispatch which the executor
  already gates against re-running planning/agent.
- **Risk: stall metadata leaking secrets via long stderr excerpts.**
  Mitigation: reuse `redact_secrets` and `_safe_conformance_text` for all
  excerpts; cap at `MAX_CONFORMANCE_TEXT_CHARS`.
- **Risk: provider/model fallback semantics drifting from the in-flight
  fallback recovery work.** Mitigation: this slice does not invent a new
  fallback structure; it consumes the same `task_policy` fallback shape
  already used by planning-scope retry. If the broader fallback work later
  moves the field, that move updates this slice mechanically.
- **Assumption:** the existing per-CLI-invocation watchdog (`commands.py`)
  is the right primitive for `no_output`. We use its
  `AGENT_IDLE_TIMEOUT`/`AGENT_TIMEOUT` reason codes raised on the
  conformance call as the canonical "no output" stall signal; we do not
  introduce a new watchdog.
- **Assumption:** baseline-SHA + dirty/committed-paths inspection (already
  used by planning-scope detection) is sufficient to decide whether
  implementation commits exist. We do not need to consult the database or
  the validation runner to decide.
- **Assumption:** the executor still owns the stall decision. The PR
  monitor recovery loop is out of scope; if the PR monitor later wants to
  reuse `classify_conformance_stall`, it can import the helper without
  needing executor changes.

## Explicit Non-Goals

- Provider-capacity classifier internals (`provider_failures.py`) and
  fallback policy table changes — the slice composes with what already
  landed but does not modify them.
- Provider/model circuit breakers (`ProviderModelCircuitBreaker`) and
  worker dispatch suppression — out of scope; the conformance stall does
  not page the breaker in this slice.
- New API endpoints, console UI, or schema migrations — all evidence rides
  on existing event/operation JSON.
- Coverage-wrapped pytest classification — owned by a different
  workspace; no changes to `validation.py` here.
- Planning-phase scope violations — already covered by
  `AGENT_PLAN_PHASE_SCOPE_VIOLATION` and intentionally untouched.
- Any change to PR monitor recovery loops; their analogous stall handling
  is a separate slice.
