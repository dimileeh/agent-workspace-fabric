# Plan: P1 Local Secret Lease Lifecycle Records

## Scope

Implement the narrow local control-plane slice for declared workspace secret
leases. AWF will persist lease lifecycle metadata for `WorkspaceProfile.secrets`,
emit audit events for issue, mount-metadata, expiry, and revoke transitions, and
revoke active local lease records when terminal cleanup paths run.

This is a local metadata and audit slice only. It must not fetch secret material,
write secret values to the database, broaden host-home credential mounts, or
pretend to be a cloud secret broker. Existing profile lint remains the boundary
for unsafe secret targets.

## Intended Files And Modules To Touch

    - issue declared leases for a workspace/profile;
    - mark issued leases as mounted at the launch boundary;
    - expire due active leases;
    - revoke active leases for one workspace;
    - list leases for workspace/API callers.
  - Use `WorkspaceRepository.add_event` / `add_events` patterns for audit
    events so `workspace_events` remains the audit trail.

  - Add `new_secret_lease_id()`.

- `src/awf/service/secret_leases.py` (new)

    a best-effort local cleanup step without masking the primary failure.

- `src/awf/node/stack_launcher.py`
  - Touch only if needed to return or expose launch-boundary metadata that the

  - Do not add host-home mounts or secret-value injection.

- `src/awf/service/controls.py`

- `src/awf/service/gc.py`

- `src/awf/runtime/pr_monitor_runner.py`

- `src/awf/api/schemas.py`

  - Expose only non-secret fields: lease id, secret name, kind, target, status,

## Risks

- Secret leakage through row fields, audit payloads, reprs, errors, or test
  fixtures. Mitigation: store only declaration metadata and digests; add tests
  that serialize rows/events and assert fake raw values are absent.
- Ambiguity between "mount metadata recorded" and actual secret injection.
  Mitigation: name and document the local behavior clearly; this slice records
  lifecycle metadata and does not provide secret material.
- Duplicate lifecycle rows/events on provisioning retry. Mitigation: repository
  issue/revoke operations must be idempotent per workspace and declaration.
- Cleanup ordering can create partial-failure edge cases. Mitigation: revoke
  lease records before deleting auth directories, and keep GC retry-safe when
  filesystem cleanup partially fails.
- Alembic migration drift can break local service bootstrap. Mitigation:
  update migration graph tests and verify PostgreSQL upgrade creates the new table.
- Future cloud broker semantics may differ from local metadata semantics.
  Mitigation: keep the service API narrow and explicitly local; do not encode
  provider-specific revoke behavior yet.

## Assumptions

- `WorkspaceProfile.secrets` is the authoritative declaration source for this
  local slice.
- Existing profile lint continues to reject unsafe secret targets and raw
  looking refs before a normal v2 workspace is admitted.
- Provider `ref` values are references, not secret values, but lease records
  should still avoid storing them raw when a digest is sufficient.
- Workspace events are the durable audit trail for lifecycle transitions.
- Local expiry can use a conservative default TTL supplied by the lease service
  because the current profile schema does not carry a lease TTL.
- Existing per-workspace auth directory cleanup remains filesystem cleanup,
  not secret-value lease brokering.

## Explicit Non-Goals

- No cloud secret broker, provider API integration, short-lived credential
  issuance, rotation, or real provider-side revocation.
- No reading, copying, rendering, logging, persisting, or returning secret
  values.
- No new broad host-home mounts and no relaxation of current profile lint or
  service auth mount rules.
- No Docker secrets implementation or new secret-value injection mechanism.
- No provider-specific least-privilege checks for Codex, Claude, Gemini,
  OpenCode/Ollama, GitHub, or Docker.
- No UI/console status panels beyond the service/API status needed by callers.
- No retroactive migration of historical profile snapshots that may already
  contain provider refs.
- No lowering of coverage thresholds, quality gates, profile requirements, or
  validation policy.
