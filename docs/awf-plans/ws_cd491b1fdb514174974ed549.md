## Architecture Decisions

### Naming: `awf smoke run`

The TODO mentions both `awf demo run` and `awf smoke run`. "smoke" is preferred because:
- The existing script is already named `core_release_smoke.py`
- The term "smoke" is used consistently in the TODO and readiness code (`DEMO_PROJECT_READY`, `_smoke_request`, etc.)
- `awf smoke run` follows the existing `awf {noun} {verb}` pattern (`awf service status`, `awf workspace create`)

### Command group pattern

Follows the established convention from `src/awf/cli/main.py`:

```python
smoke_app = typer.Typer(help="DX smoke proof: validate local service, profile, PR path.")
app.add_typer(smoke_app, name="smoke")
```

### Service layer design

A new `collect_smoke_report()` async function in `src/awf/service/smoke.py` that:

1. **Service readiness phase** — hits local API health endpoint (via httpx) or reports `SMOKE_SERVICE_UNREACHABLE` with clear next-action text
2. **Auth/provider readiness phase** — calls `collect_agent_readiness()` from `provider_readiness.py`; summarizes usable/unusable providers with reason codes
3. **Profile preview phase** — uses `preview_project_onboarding()` from `profiles/onboarding.py` on the target project path; falls back to `examples/awf-core-demo` when no project is provided
4. **Validation phase** — extracts validation commands from the profile/phases; reports `SMOKE_VALIDATION_MISSING` if none found
5. **Workspace request phase** — generates a smoke workspace request using `_smoke_request()` from `onboarding.py`; validates shape
6. **PR/monitor phase** — when live GitHub is available: creates workspace via REST API and reports PR URL. In mocked-local mode: emits `SMOKE_PR_MOCKED_LOCAL` with deterministic evidence.
7. **Console links phase** — resolves console URL from configuration; reports `SMOKE_CONSOLE_READY` or `SMOKE_CONSOLE_UNAVAILABLE`

### Output structure

```json
{
  "status": "ok" | "warn" | "fail",
  "project": "/path/to/project",
  "mode": "live" | "mocked_local",
  "phases": [
    {
      "name": "service_readiness",
      "status": "ok",
      "reason_code": "SMOKE_SERVICE_READY",
      "message": "AWF local service health check passed.",
      "evidence": {"api_url": "http://localhost:8000", "status": "ok"},
      "action": "No action required."
    },
    ...
  ],
  "console_links": {
    "ui": "http://localhost:3000",
    "api_docs": "http://localhost:8000/docs"
  },
  "next_actions": ["action text on failure"]
}
```

### Reason codes (self-contained in `smoke.py`)

All reason codes follow the existing `SCREAMING_SNAKE_CASE` convention:

- `SMOKE_SERVICE_READY` / `SMOKE_SERVICE_UNREACHABLE`
- `SMOKE_AUTH_READY` / `SMOKE_AUTH_PARTIAL` / `SMOKE_AUTH_UNAVAILABLE`
- `SMOKE_PROFILE_READY` / `SMOKE_PROFILE_NOT_DETECTED` / `SMOKE_PROFILE_PREVIEW_FAILED`
- `SMOKE_VALIDATION_READY` / `SMOKE_VALIDATION_MISSING`
- `SMOKE_WORKSPACE_REQUEST_READY` / `SMOKE_WORKSPACE_REQUEST_FAILED`
- `SMOKE_PR_MOCKED_LOCAL` / `SMOKE_PR_UNAVAILABLE`
- `SMOKE_CONSOLE_READY` / `SMOKE_CONSOLE_UNAVAILABLE`
- `SMOKE_DEMO_PROJECT_MISSING` (when demo fallback path doesn't exist)

### Mocked-local mode

- Enabled via `--mocked-local` flag or implicitly when GitHub/provider auth is absent
- PR/monitor phase reports `SMOKE_PR_MOCKED_LOCAL` instead of failing
- Auth phase still reports status but doesn't block overall success
- Safe to run repeatedly without side effects
- Produces clear next actions on failure (following the pattern in `readiness.py:_next_actions()`)
