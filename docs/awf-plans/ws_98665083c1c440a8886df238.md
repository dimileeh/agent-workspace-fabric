## Problem Statement

There is broad doc coverage today inside
`tests/unit/docs/test_public_docs_status.py`, but the command-grammar guarantees
(setup/start/init/smoke) are scattered across many large, lane-specific tests and
are not expressed as a single drift contract. T18 asks for a focused drift-test
module that enforces, across all relevant public docs at once:

1. `awf setup`, `awf start`, and `awf init <path>`/`<repo>` are the documented
   first-run grammar.
2. Mocked smoke examples that reference a project path use `awf smoke run
   --project <path> --mocked-local`, never a bare positional project path.
3. Legacy no-path `awf init` presented as *service bootstrap* is rejected
   everywhere (while keeping the legitimate `awf service bootstrap` command
   allowed).
4. The four first-run install lanes are present and the public `curl | bash`
   installer stays release-gated.

## Drift Contract The New Module Enforces

The module centers on a single source-of-truth tuple of first-run public docs so
the contract is read in one place:

```text
FIRST_RUN_DOCS = (
    "README.md",
    "docs/QUICKSTART.md",
    "docs/GETTING_STARTED.md",
    "docs/MCP_SETUP.md",
    "docs/UPGRADE.md",
    "docs/UNINSTALL.md",
    "docs/TROUBLESHOOTING.md",
    "docs/PROJECT_ONBOARDING.md",
)
```

Grammar rules asserted:

- **R1 setup/start present.** README, Quickstart, Getting Started, and MCP setup
  prerequisites each contain standalone `awf setup` and `awf start` invocations.
- **R2 init takes a path.** Every documented `awf init` invocation includes a
  path/repo argument (`<path>`, `<repo>`, `.`, or a quoted path such as
  `"$HOME/awf-eval-project"`). A bare `awf init` command line is forbidden.
- **R3 no-path-init-as-bootstrap rejected.** Across all first-run docs, prose or
  snippets that describe no-path `awf init` as starting/bootstrapping the local
  service are rejected (extends the fixed pattern list already in
  `test_public_docs_status.py`). `awf service bootstrap` as a command remains
  explicitly allowed — the test must not flag it.
- **R4 mocked smoke uses --project.** Any `awf smoke run` example that targets a
  project path uses `--project <path>` together with `--mocked-local`; reject a
  smoke invocation that passes a bare positional path or omits `--project` when a
  project path is referenced in that example.
- **R5 four install lanes + gated curl.** README+Quickstart present the four
  lanes (release-installed/package-manager, source-checkout global tool install,
  source-checkout no-global) and keep `curl -fsSL` / `curl | bash` out of the
  public docs (release-gated language only).

## Tests To Write First (this task *is* tests — TDD via red on a temp fixture)

Because the deliverable is tests, "test-first" means: for each helper I add
(fenced-command extraction, bare-`awf init` detection), write a small unit using
an in-test fixture string / `tmp_path` doc that is known-stale, assert the helper
flags it (red→green on the helper), then run the real-doc assertions. Concretely:

1. `test_helper_flags_bare_awf_init_command()` — feed a fixture markdown with
   `awf init` on its own line; assert the detector reports it; feed `awf init .`
   and `awf service bootstrap`; assert neither is reported.
2. `test_helper_extracts_awf_smoke_invocations()` — fixture with a `--project`
   smoke line and a bare-path smoke line; assert classification.
3. `test_first_run_docs_use_setup_and_start_grammar()` — R1 across docs.
4. `test_documented_awf_init_always_takes_a_path()` — R2 across docs.
5. `test_no_path_init_is_not_described_as_service_bootstrap()` — R3 across docs,
   asserting `awf service bootstrap` is NOT falsely flagged.
6. `test_mocked_smoke_examples_use_project_flag()` — R4 across docs.
7. `test_first_run_install_lanes_present_and_curl_gated()` — R5.

All helpers will be fully exercised by the fixture-driven tests above so no
coverage drop or coverage-exclusion is needed (test-only module; no `src/awf`
lines added).

## Risks And Mitigations

- **Duplication / coverage-theater vs `test_public_docs_status.py`.** Risk the
  new module just re-asserts existing checks. Mitigation: frame the module as the
  single command-grammar contract (shared `FIRST_RUN_DOCS` tuple + R1–R5),
  asserting the *relationship* (init always has a path, smoke always `--project`)
  rather than copying lane-by-lane string checks. The fixture-driven helper tests
  add genuinely new logic, not string duplication.
- **False positives on `awf service bootstrap`.** R3 must allow the legitimate
  command. Mitigation: detector keys on bare `awf init` lines and on prose
  patterns binding `awf init` to bootstrap, and an explicit assertion proves
  `awf service bootstrap` text is not flagged.
- **Fenced-block parsing fragility.** Mitigation: keep extraction simple
  (line-based within ``` fences), exercised by fixture tests; do not try to be a
  full markdown parser.
- **Overlap with `ws_524b726e826f4ece9de01d43`.** Mitigation: new file only; no
  edit to MCP docs unless a test forces it.
- **Doc heading/anchor churn from a future T15 follow-up.** Mitigation: assert on
  command tokens, not on section headings, where possible.
