# Plan: P1 Local Packaging Backup, Upgrade, And Recovery Runbook

## Goal

Add a narrow, practical local-operator runbook for the AWF local
Postgres-backed Docker service. The slice should make it clear how to back up
and restore the AWF control-plane database, rebuild/restart versioned local
images, run migrations during upgrades, roll back a bad local upgrade, recover
from stuck containers, recover or quarantine corrupt work directories, and
understand the current compatibility role of `scripts/run_awf.py`.

This is primarily a documentation and docs-contract-test slice. No helper CLI
is planned unless the implementation proves that the documented Docker/Postgres
commands are too error-prone or cannot be expressed safely with existing
service commands.

## Risks And Mitigations

- Backup/restore commands can be destructive if operators confuse the AWF
  control-plane DB with workspace/project databases. Mitigate with repeated
  wording that the documented Postgres service is control-plane state only.
- Restore instructions can race live API/worker writes. Mitigate by requiring
  API/worker shutdown before restore and status verification after restart.
- Migration rollback may not be generally reversible. Mitigate by documenting
  backup-first rollback and avoiding promises of automatic Alembic downgrade.
- Docker cleanup commands can delete the database volume. Mitigate by making
  non-volume cleanup the default and calling volume removal a last resort only
  after a verified backup.
- Work-dir recovery can lose logs or auth material. Mitigate by documenting a
  quarantine/rename flow first, then selective restore of logs/artifacts/auth
  paths rather than immediate deletion.
- README contract tests can become brittle if they assert prose instead of
  operator contracts. Mitigate by asserting headings and critical command
  fragments, not full paragraphs.

## Assumptions

- The current local-service Compose file remains
  `docker/compose/local-service.yml`.
- The control-plane Postgres Compose service remains named `postgres`.
- The default service DB remains exposed to the host at port `5433` and inside
  Compose as `postgres:5432`.
- `awf service bootstrap` remains the preferred idempotent local-service
  startup and migration path.
- `scripts/run_awf.py` remains supported during this slice but is not the
  strategic always-on service path.

## Explicit Non-Goals

- No production cloud/GKE backup design.
- No image registry, release artifact signing, or remote image publishing.
- No Alembic downgrade framework or automatic migration rollback.
- No changes to database schema, migrations, service worker behavior, PR
  monitor behavior, scheduler policy, or cleanup policy.
- No console UI changes.
- No broad refactor of local-service Compose.
- No reduction in coverage thresholds, quality gates, or validation policy.
