# Implementation Plan: CLI DX Improvements

## Intended Files/Modules to Touch
- `src/awf/cli/main.py`: Update the Typer CLI `help` string arguments for the main `app`, `workspace_app`, `init`, and `service_bootstrap` commands to include detailed text for first-time users, recommended first path, mutation warnings, dry-run behavior, and links to existing docs.
- `tests/unit/cli/test_cli.py`: Write tests that invoke `awf --help`, `awf init --help`, `awf service bootstrap --help`, and `awf workspace --help` to ensure the required help content is emitted.

## Tests to Write First
- Write CLI help assertions in `tests/unit/cli/test_cli.py` using `CliRunner` (which is already configured in that file).
- The assertions will check that the `.stdout` of `runner.invoke(app, ["--help"])` (and subcommands) contains the new key phrases:
  - "Mutates:"
  - "Safety defaults" / "Dry-run"
  - Link to docs (e.g., `docs/CLI_REFERENCE.md`)
  - The recommended first path for first-time users.

## Validation Commands
- `uv run pytest tests/unit/cli/test_cli.py` to verify the new CLI help tests pass after updating `main.py`.
- `uv run ruff check src/awf/cli/main.py tests/unit/cli/test_cli.py` for linting.
- `uv run ruff format --check src/awf/cli/main.py tests/unit/cli/test_cli.py`
- `uv run mypy src/awf/cli/main.py tests/unit/cli/test_cli.py` for type checking.

## Risks, Assumptions, and Explicit Non-Goals
- **Assumptions**: The CLI utilizes Typer's docstring and `help=` argument mechanics. We will use standard Typer docstrings/help to inject this text.
- **Risks**: We may encounter coordination warnings (like `OWNED_PATH_OVERLAP_RISK` in `tests/unit/cli/test_cli.py`) but we are explicitly updating the help text and tests as requested, which should be easily mergeable.
- **Explicit Non-Goals**:
  - Do not change any command implementation logic or actual behavior.
  - Do not create new or wholesale rewrite existing documentation files (like `docs/CLI_REFERENCE.md` or catalog entries).
  - Do not add new command options or flags unless technically required to expose dry-run or safety information.
