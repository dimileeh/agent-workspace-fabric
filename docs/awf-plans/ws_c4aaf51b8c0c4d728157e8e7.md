Addresses deferred issues **#379, #381, #382, #389** in one PR. All concern the shared
read-only `~/.claude` overlay base introduced for the overlay (PR #369), built on top of the

## Issue #379 — duration-independent in-progress lock for staging reap

**Problem:** a pathological >1 h build of a large `~/.claude` base has its own in-progress
staging dir reaped by a concurrent provision because the reaper keys on mtime age ≥ 3600 s.

**Approach (duration-independent `flock`):** an actively-building staging dir holds an exclusive
advisory lock that the kernel releases automatically on process death (OOM/SIGKILL/crash) — so
liveness, not elapsed time, decides reapability.

- In `_ensure_shared_claude_base`, immediately after `mkdtemp`, open `<staging>/.build.lock` and
  acquire `fcntl.flock(fd, LOCK_EX | LOCK_NB)`; hold the fd open across copytree/chown/replace and
  close it in the existing `finally` (releasing the lock) before/around the staging rmtree.
- Rewrite `_reap_stale_claude_base_staging(base_root)` to be age-free: for each
  `*/.claude-base-*`, try to acquire `flock(LOCK_EX | LOCK_NB)` on its `.build.lock`:
  - `BlockingIOError`/`OSError(EAGAIN/EWOULDBLOCK)` → a live builder holds it → **skip** (never
    reap a live build, regardless of duration).
  - lock acquired, or `.build.lock` missing (pre-upgrade orphan / build died before locking) →
    orphan → `rmtree(staging, ignore_errors=True)`.
  - staging dir vanished mid-check (concurrent reap / winning `replace`) → skip (not fatal).
- Remove `_STALE_STAGING_MAX_AGE_SECONDS` and the now-unused `import time` (verify no other use).
  Add `import fcntl`.
- Document the sub-millisecond `mkdtemp → flock` window: a concurrent reaper that hits it only
  forces that provision to rebuild (no data loss); flock is acquired as the first action so the
  window is negligible and, crucially, the *building* state is always lock-protected.

**Why flock over a PID file:** kernel-released-on-death (crash-safe), no PID-reuse hazard, no
duration assumption — exactly the "actively-building base is never reaped" property #379 wants.

## Issue #381 — reconcile fallback edits into the surviving overlay `upper`

**Problem:** when a non-empty `upper` survives but a transient remount failure degrades a provision
to the legacy full copy, the agent mutates that legacy copy; when the surviving `upper` later
remounts, `merged` (upper over lower) shadows the legacy copy and the current code `rmtree`s it,
**dropping the fallback edits**. The reviewer's "prefer legacy when both have data" is unworkable
(a fresh legacy copy always has data) and conflicts with
`test_retry_after_transient_fallback_remounts_surviving_upper`.

**Approach (generation/mtime reconciliation before reaping the legacy copy):**

- Extend `_prepare_claude_overlay_mount` to return the resolved `base` (lowerdir) in its tuple:
  `(merged_mount, upper, work, base)` — `base` is already a valid `Path` in every return branch
  (pinned / freshly built / live-mount reuse / race-reuse). Update the unpack at
  `_prepare_isolated_claude_auth` L797 and all 4 return sites.
- Add `_reconcile_fallback_edits_into_upper(*, legacy: Path, upper: Path, base: Path) -> None`:
  walk the legacy tree; for each regular file `rel`:
  - It is a **fallback edit** iff `base[rel]` is absent OR `legacy[rel].st_mtime_ns >
    base[rel].st_mtime_ns` (the fresh copy preserves host mtimes via `copy2`, so unedited files
    match the base and are skipped — this filters out the whole baseline tree, preserving the
    overlay's disk savings).
  - If a fallback edit and (`upper[rel]` absent OR `legacy[rel].st_mtime_ns > upper[rel].st_mtime_ns`)
    → `copy2(legacy[rel], upper[rel])` (mkdir parents). **`upper` wins ties** (an equal/newer
    upper edit is the agent's authoritative overlay-era change); only a *strictly newer* legacy
    edit overwrites it — the generation/mtime rule.
  - Per-file `OSError` is caught and skipped (best-effort, never blocks provisioning; never logs
    secret contents).
- At the override reap site (L808-809), call the reconcile helper **before** `rmtree(legacy)`.

**Regression preserved:** in `test_retry_after_transient_fallback_remounts_surviving_upper` the host
is unchanged and the legacy copy is fresh, so every legacy file matches the base mtime → reconcile
copies nothing → legacy reaped → `upper`'s `agent-edited` preserved (assertions unchanged).

## Issue #382 — add `st_ctime_ns` to the signature + fix pre-pin revert recovery

**Problem:** the signature keys only size+mtime+mode, so a metadata-preserving edit (`cp -p`,
dotfile manager, backup restore that rewrites content while preserving mtime/size/mode) leaves the
signature unchanged and a stale base is reused.

**DESIGN CALL (documented in the `_host_claude_signature` docstring):**

1. **Add `st_ctime_ns` to every signature entry** (root entry L384 and walk entry L421):
   `rel \0 size \0 mtime_ns \0 ctime_ns \0 mode`. `ctime` is bumped on *any* inode change
   (including a metadata-preserving content rewrite — the final `utime` that restores mtime itself
   bumps ctime), so it catches the missed edits. It is a free field from the same `stat()` call —
   **no extra I/O, no content read** — so the stat-only / no-1.7 GB contract is intact.

2. **Recovery becomes pin-based.** `ctime` is *not* restorable (you cannot set it from userspace),
   so a content-identical *revert* no longer reproduces the old signature/base name. The prior
   pre-pin recovery (`test_prepin_upper_recovers_after_host_reverts_when_mount_failed`) relied on a
   revert reproducing `sig_a` so a **markerless** surviving `upper` could remount against a
   recomputed base. That reproduction is intentionally given up; recovery now flows through the
   `base.signature` **pin** (`_pinned_overlay_base`), which records the exact base a live/surviving
   `upper` belongs to and is **immune to host churn, reverts, and metadata edits** (it never
   recomputes). This is also more *correct*: real overlayfs does not validate that an `upper`
   matches a given lower, so recompute-and-match was only ever best-effort luck.
   - Genuinely **markerless (pre-pin) torn-down** uppers after a host metadata change degrade to
     the legacy copy — documented limitation, **no data loss** (the surviving `upper` stays on
     disk; the legacy fallback preserves working auth). Already covered by
     `test_prepin_upper_mount_failure_does_not_pin_guessed_base`.

3. **Fix the regression test:** replace `test_prepin_upper_recovers_after_host_reverts_when_mount_failed`
   with a **pin-based** recovery test (`test_pinned_upper_recovers_across_host_metadata_change`):
   provision 1 succeeds and pins; provision 2 (overlay torn down) does a metadata-preserving host
   edit, and the surviving `upper` remounts against the **pinned** `base_a` (recovering the agent's
   mutations) — proving recovery is ctime-robust via the pin.

**No-break check:** the live-mount-reuse pin tests (`test_live_mount_reuse_*`) and the
empty-upper / crash-before-mount tests are unaffected (they derive the pin from the live mount table
or assert degrade/no-pin, never from a revert-reproduced signature). The signature-tracking tests
(`mode`, `symlink`, `duplicate_symlinks`, `circular`) assert only "changed → differs", which adding
ctime preserves.

## Issue #389 — GC-B: safe reaper for superseded base signatures

**Problem:** each distinct host signature builds a new `auth/_shared/claude-base/<sig>/.claude`
(~1.7 GB); old ones accumulate forever (terminal GC skips `_shared`). Reap superseded bases while
**preserving** the current signature and any base that is live-mounted or pinned.

**Approach (new focused module `src/awf/service/gc_claude_base.py`, re-exported from `gc.py`):**
keeps `gc.py` under the established first-party split convention (cf. `gc_auth_overlay.py`,
`gc_classify.py`); the documented `awf.service.gc.<name>` surface is preserved via re-export.

- `iter_overlay_lowerdirs(proc_mounts) -> set[Path]` (added to `auth_mounts.py`, generalizing the
  existing `_overlay_lowerdir_from_proc_mounts`; reuses `_unescape_proc_mount_field`) — every live
  overlay `lowerdir=` path.
- `_pinned_base_dirs(work_dir) -> set[Path]` — read each `auth/*/claude/base.signature`, resolve via
  `_shared_claude_base_dir(work_dir, sig)`.
- `reap_superseded_claude_bases(*, work_dir, host_home, proc_mounts=_PROC_MOUNTS, execute=False)
  -> dict` returning an inspectable report (scanned, protected, reaped/planned signatures, errors):
  - `base_root = work_dir/auth/_shared/claude-base`; no-op report if absent.
  - **Protected set** (never reaped): the current signature base
    `_shared_claude_base_dir(work_dir, _host_claude_signature(host_home))` (when `host_home/.claude`
    exists) ∪ live-mounted lowerdir bases (intersect with base dirs) ∪ pinned bases.
  - For each `<sig>/.claude` base dir (skip `.claude-base-*` staging — that is #379's domain): if
    not protected → reap the whole `<sig>` dir. Guard removal: assert the path is within
    `base_root` before `rmtree`; catch `OSError`, classify permission-denied loudly.
  - New reason codes: `CLAUDE_BASE_SUPERSEDED_REAPED`, `CLAUDE_BASE_REAP_PERMISSION_DENIED`,
    `CLAUDE_BASE_REAP_PARTIAL` (a permission-denied reap makes the step `partial`, never a silent
    success). Never logs base contents/secrets.
- **Wiring:** add a flag-gated, host-wide step to `run_service_workspace_gc` mirroring
  `companion_image_prune` — new params `host_home: Path` and `reap_claude_bases: bool = False`;
  include the report in the GC payload (`to_dict`). `POST /v1/service/gc` route passes
  `host_home=settings.host_home` and the new `settings.claude_base_gc_enabled` (default `True`).
  Consistent with #382: recoverable uppers are always pinned, and pinned bases are protected.

## Risks & assumptions

- **`flock` (#379):** Linux-only `fcntl.flock` (fine — control plane is Linux/Docker). Holding the
  build fd open for the whole build is required; ensure the `finally` closes it. Tests exercise real
  flock in `tmp_path` (no mocking) — separate `open()`s in one process are denied under `LOCK_NB`.
- **mtime granularity (#381):** reconciliation compares `st_mtime_ns`; tests set mtimes explicitly
  via `os.utime` to avoid same-tick flakiness. **Known limitation:** if the host changed between the
  overlay's base and the fallback copy, unedited legacy files may be flagged as edits and copied —
  no data loss (upper-newer still wins; the copy is bounded to the small set that differs);
  documented in the helper docstring.
- **ctime non-restorable (#382):** the deliberate trade-off — markerless pre-pin uppers no longer
  recover after a metadata-only host change. Documented; mitigated by pin-based recovery and the
  surviving-`upper` + legacy-fallback safety net (no data loss).
- **GC-B safety (#389):** the protected-set computation must precede any removal; `host_home`
  unavailable/empty ⇒ skip the current-signature protection but **still never reap live/pinned**
  bases. Removal is hard-guarded to paths under `auth/_shared/claude-base`. Wiring adds a setting +
  route param — kept minimal and defaulted to safe (`True`, but only acts under `execute=True`).
- **Assumption:** the overlay-teardown/unmount code from the prior wave is present and unchanged;
  this PR builds on it and does not alter teardown semantics.
