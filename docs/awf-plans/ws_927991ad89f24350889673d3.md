# Plan — Issue #447 (reduced scope): purpose-named `guide`/`instruct` operator control

Workspace: `ws_927991ad89f24350889673d3`
References: GitHub issue **#447** ("Operator-guidance control: instruct a live monitoring
workspace / close the NotifyHuman loop").

## Goal & key finding

AWF **already has the engine** for injecting an operator directive into a live monitoring
workspace:

- the `remonitor` control persists an `OperatorHint(reason=...)` into
  `workspace.monitor_threads_addressed` (the `__awf_pending_operator_hint__` JSON key);
- the pure decision core `decide()` (`src/awf/runtime/pr_monitor.py:874-884`) returns
  `AddressOperatorHint(hint=...)` for a **PENDING** hint, *before* it can reach `Merge`, and a
  non-`pending` hint yields `NotifyHuman`;
- `operator_hint_prompt` (`src/awf/runtime/monitor_prompts.py:230`) builds the agent prompt
  ("Address what the hint says: <reason>"), invoked by `_run_operator_hint_cycle`
  (`src/awf/runtime/pr_monitor_runner/operator_hints.py:63`).

A fresh **pending** hint re-engages the agent even from a prior `needs_human`/`NotifyHuman`
state (the workspace stays in `monitoring_pr`), which is exactly "close the human-wait loop."

**The real gap** is discoverability + semantics: this is hidden behind the `remonitor` name, and
`remonitor --reason` overloads one string as both the *audit reason* and the *agent directive*.

**This change is additive and surface-level**: a new, purpose-named `guide` (alias `instruct`)
control with a **first-class `directive` field distinct from the audit `reason`**, mirroring
`remonitor` 1:1 across service/REST/CLI/MCP, reusing the unchanged `OperatorHint`/`decide()`
engine. We do **NOT** rebuild `decide()`/`MonitorState`.

## Design decisions (scope-bounding)

1. **Eligible states = `monitoring_pr` only.** The #447 scenario is a *live* monitoring
   workspace (deferred findings / `NotifyHuman` keep it in `monitoring_pr`). Restricting to
   `monitoring_pr` keeps `guide` a **no-state-transition** control (it mutates
   `monitor_threads_addressed` + resets the monitor claim, staying `monitoring_pr`) and avoids
   re-implementing remonitor's `failed`-state reset path (`_reset_failed_workspace_for_remonitor`).
   Re-engaging a `failed` workspace remains `remonitor`'s job. This is a deliberate reduction vs.
   the task's optional "[+ failed]"; recorded here with rationale.
2. **No past-settle freeze re-arm.** `decide()` already returns `AddressOperatorHint` for a
   pending hint *before* reaching the `Merge` gate, so a pending directive **already blocks
   auto-merge** until processed. The settle-freeze re-arm in `remonitor_workspace`
   (`controls.py:506-525`) is remonitor-recovery-specific (workspace drifted past settle while
   unmonitored) and is not needed for guide. Keeps the new method small and obviously-correct.
3. **`directive` is the agent prompt; `reason` is audit-only.** `OperatorHint` gains
   `directive: str | None = None`. The prompt path uses `directive` when present, else falls back
   to `reason` (so `remonitor --reason` is unchanged). To satisfy the existing
   `operator_hint_from_threads` invariant (it rejects a hint with empty `reason`), `guide` sets
   `hint.reason = reason_text or directive_text` (always non-empty) and `hint.directive =
   directive_text`.
4. **Backward-compat is sacred.** `remonitor --reason` path (reason → hint → prompt) is
   unchanged; `OperatorHint.directive` defaults `None`; persistence omits `directive` when `None`.
5. **No reason-catalog entry needed.** `OPERATOR_REMONITOR` is *not* in
   `src/awf/service/doctor/reasons.py:_REASON_TEXT` (control audit reason codes are not doctor
   reasons), so `OPERATOR_GUIDE` needs no catalog regeneration. (Will re-confirm; only run
   `scripts/generate_reason_catalog.py` if a diff appears.)

## Risks & assumptions

- **Shared-engine edits.** `OperatorHint`, `operator_hints.py`, `monitor_prompts.py`, and
  `_run_operator_hint_cycle` are on the remonitor hot path. Mitigation: `directive` defaults
  `None`; persistence omits it when absent → remonitor payload is byte-identical; explicit
  remonitor regression tests (#11) and a "directive=None == today" round-trip test.
- **Dropped-directive on status transition.** If `mark_operator_hint_needs_human/agent_failed`
  forget to carry `directive`, a deferred directive is silently lost. Explicitly tested (#1).
- **Concurrent sibling workspaces** edit BitBucket monitor files
  (`pr_creator.py`/`execution_flow.py` for #451; `merge_loop.py`/`fix_cycle.py`/`helpers.py`/
  `loop.py`/`runner.py`/`bitbucket_client.py` for #444/#445/#448). This plan touches **none** of
  those; only `pr_monitor_runner/operator_hints.py` gets a 1-line edit. Base-sync reconciles.
- **Claim reset on a live monitor.** `guide` resets `monitor_claimed_by` (mirroring remonitor) so
  the worker re-engages; consistent with existing remonitor behavior and lease-expiry handling.
- **Assumption:** `OPERATOR_GUIDE` is not a doctor reason (confirmed `OPERATOR_REMONITOR` absent
  from `_REASON_TEXT`) → no `generate_reason_catalog.py` change. Re-confirm; regenerate only if a
  diff appears.
- **Assumption:** Postgres-backed control-plane tests use `$AWF_TEST_DATABASE_URL`
  (`postgres:5432`); no new migration is required (`monitor_threads_addressed` JSON already
  exists; status vocabulary unchanged; `OperationType` is a string literal, not a SQL enum).

## Non-goals (explicit)

- Not rebuilding `decide()`, `MonitorState`, or the `AddressOperatorHint` action — reuse as-is.
- Not adding the issue's "complementary fix" (structured/resumable `NotifyHuman` payload from the
  agent's deferral). Out of this reduced scope; the `guide` control already closes the loop by
  re-arming a pending directive.
- Not changing remonitor's behavior, semantics, or wire format.
- Not making `guide` eligible for `failed` (use `remonitor`); not adding settle-freeze re-arm.
- No free-form chat channel, no bidirectional orchestrator↔agent messaging, no forge-comment
  marker channel.
- No console/UI work.
