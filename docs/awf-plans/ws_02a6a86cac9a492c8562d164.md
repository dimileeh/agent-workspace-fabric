# Implementation Plan: P1 Local Core Feedback / Support Bundle

## Task Summary
Add a telemetry-free, redacted support bundle path for first-time evaluators via `awf service doctor --bundle`. The bundle is an operator-readable local artifact containing service readiness, doctor diagnostics, provider readiness summary, orphan/cleanup posture, recent failure reason summaries, version/config fingerprints, and pointers to relevant logs/artifacts — with all secrets redacted and no raw task prompts or provider outputs.

## Files to Touch
- `src/awf/service/support_bundle.py` — **new** module for bundle collection, redaction, disk write, and repeatability guarantees.
- `src/awf/cli/main.py` — add `--bundle` option to `service_doctor`, wire `support_bundle` collection, print the generated artifact path, and add fail-path guidance pointing to the bundle and the GitHub issue template.
- `tests/unit/service/test_support_bundle.py` — **new** unit tests for bundle shape, redaction, prompt/output scrubbing, repeatability, and degraded-collection behavior.
- `tests/unit/cli/test_cli.py` — add CLI-level tests for `--bundle` invocation, path output, exit codes, and fail-path messaging.

## Tests to Write First (Strict TDD)
1. `test_support_bundle_collects_required_sections` — asserts the bundle dict contains `generated_at`, `version`, `service_status`, `doctor_report`, `provider_readiness_summary`, `orphan_cleanup_posture`, `recent_failure_summary`, `config_fingerprint`, `log_pointers`, `issue_template_pointer`.
2. `test_support_bundle_redacts_secrets` — injects fake secrets into settings, env, and failure examples; asserts no secret values appear in the serialized bundle and `<redacted>` is present where expected.
3. `test_support_bundle_omits_raw_prompts_and_outputs` — injects task prompts, stdout, stderr into failure examples; asserts those keys are stripped and only safe keys (`workspace_id`, `failure_reason`, `reason_code`, `status`, `updated_at`, `count`) remain.
4. `test_support_bundle_writes_readable_artifact` — asserts `write_support_bundle` creates a deterministic file name in the expected directory, returns the absolute path, and prints the path clearly.
5. `test_support_bundle_is_repeatable` — runs collection twice with the same mocked inputs and asserts identical bundle payloads (minus any runtime-only pointers that are deterministic).
6. `test_cli_service_doctor_bundle_flag_writes_file` — invokes `awf service doctor --bundle` with mocked collectors and asserts the CLI prints the artifact path and exits 0.
7. `test_cli_service_doctor_fail_path_points_to_bundle_and_issue_template` — invokes `awf service doctor` (no `--bundle`) with a mocked failing report and asserts the stderr/stdout contains the `--bundle` command suggestion and the relative path `.github/ISSUE_TEMPLATE/bug_report.yml`.

## Risks, Assumptions, and Explicit Non-Goals

### Risks
- **OWNED_PATH_OVERLAP_RISK** with `ws_e90d1b2cf47a45cf920f01a0` on `src/awf/cli/**`, `src/awf/service/status.py`, and tests. We will minimize `main.py` changes to adding the `--bundle` option and a small conditional branch around the existing `service_doctor` body, avoiding any refactor of `service_doctor` internals. If the overlapping workspace lands CLI changes first, AWF stale policy may require rebase.
- `summarize_failure_analysis` requires a reachable DB. If DB is down, the bundle must catch the exception and include a degraded `recent_failure_summary` entry instead of crashing.

### Assumptions
- The GitHub issue template path is static relative to the repo root: `.github/ISSUE_TEMPLATE/bug_report.yml`.
- The bundle artifact will be written to the current working directory with a deterministic name such as `awf-support-bundle-<timestamp>.json` (or `.md` if we choose Markdown). For simplicity and testability we will default to JSON with clear top-level keys and a `log_pointers` section rendered as human-readable strings.
- `service_config_payload` already redacts secrets; we will reuse it directly for the fingerprint.
- Existing `_secret_values` and `_redact_text` from `awf.service.doctor` will be reused for any additional free-text redaction.

### Explicit Non-Goals
- No telemetry upload, no cloud behavior, no external network calls.
- No modification of the doctor diagnostic collection logic itself beyond importing and calling it.
- No changes to `docs/REASON_CATALOG.md` or reason catalog generation scripts.
- No changes to the release-readiness gate (`readiness.py`) beyond reading its public data surfaces.
- No new top-level CLI subcommands; the entry point stays within `awf service doctor --bundle`.
