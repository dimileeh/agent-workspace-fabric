# Plan: Declared Local Secret Lease Mounts

## Goal

Implement the narrow P1 security slice from
`TODO/pre-gke-industrial-readiness.md`: replace broad/default host auth exposure
with profile-declared local secret leases where AWF can do so safely, while
preserving compatibility for providers that still require the existing
per-workspace auth seeding path.

This slice should make the declared `secrets` profile path the default
documented pattern for provider, GitHub, and local auth credentials. It should
not implement a cloud secret broker and must not persist or log raw secret
values.

## Current Shape

- `WorkspaceProfile.secrets` already supports `name`, `kind`, `target`, `mode`,
  `required`, `provider`, and `ref`.
- `SecretLeaseService` already records sanitized issue/mount/expiry/revoke
  metadata for profile-declared secrets.
- `ComposeStackLauncher` still builds agent environment from selected host env
  placeholders and appends `ServiceAuthMountResolver` output when configured.
- `ServiceAuthMountResolver` still resolves/copies local provider auth from
  `AWF_HOST_HOME` into host or per-workspace paths.
- Profile lint already rejects unsafe secret targets and profile-declared broad
  host-home service mounts.

## Intended Files And Modules To Touch

Production:

- `src/awf/node/secret_mounts.py` or `src/awf/node/secret_leases.py` (new)
  - Add the local-mode lease materialization/resolution layer.
  - Convert supported `ProfileSecret` declarations into:
    - read-only bind mounts for `kind: mount`;
    - Compose environment placeholders for `kind: env`;
    - sanitized metadata for provisioner mount recording.
  - Support only local, explicit references in this slice:
    - `provider: env` with `ref: NAME` or `ref: env/NAME`;
    - `provider: github` mapping to `AWF_GITHUB_TOKEN`, `GH_TOKEN`, or
      `GITHUB_TOKEN` placeholders;
    - `provider: local-file` / `provider: host-file` for exact existing files;
    - `provider: local-auth` / `provider: auth` for known local provider auth
      paths where read-only mounting is safe.

    unsupported providers, broad host-home references, writable lease mounts,

## Implementation Sequence

1. Add the failing profile/lint tests for supported declarations and unsafe
   local source refs.
2. Add the failing local lease resolver tests with a temporary expected API.
3. Add the failing stack launcher and compose render tests proving declared
   leases are used before legacy host auth.
4. Add the failing provisioner and worker wiring tests.
5. Implement the local resolver with a small explicit provider map.
   - Normalize env refs but never read env values except to decide whether a
     required source exists.
   - Normalize local-file refs to exact paths and reject roots/broad home refs.
   - Return only `AuthMount`, env placeholder pairs, and sanitized metadata.
6. Wire `ComposeStackLauncher`:
   - start with profile runtime env;
   - add declared lease env placeholders;
   - add legacy env placeholders only for auth not satisfied by declarations;
   - add declared read-only lease mounts;
   - add legacy auth mounts only for unresolved compatibility targets.
7. Preserve existing `ServiceAuthMountResolver` behavior for compatibility and
   update tests that currently expect it to always run.
8. Keep `Provisioner` lease lifecycle order unchanged, but update mount metadata
   to use the resolver's sanitized plan metadata.
9. Update README and onboarding docs to show declared `secrets` as the preferred
   path and legacy host auth as a compatibility fallback.
10. Run focused validation, then the broader Python quality gates.

## Risks

- Existing local dogfood auth may depend on mutable provider state under
  `~/.codex`, `~/.claude`, `~/.gemini`, or OpenCode/Ollama paths.
  - Mitigation: keep legacy per-workspace copied auth as a compatibility path
    and only bypass it when a declared supported lease covers the same target.
- Docker Compose env substitution can accidentally expose raw values if code
  renders env values directly.
  - Mitigation: tests assert generated specs and rendered compose contain only
    `${NAME}` placeholders.
- A "local lease" that copies env secrets into files would create new on-disk
  secret persistence.
  - Mitigation: do not implement env-to-file materialization in this slice;
    env leases remain placeholders, and mount leases bind exact pre-existing
    local files/dirs read-only where supported.
- Overly strict source validation could block legitimate local file secrets.
  - Mitigation: reject roots and auth-like broad paths, but allow exact
    existing files and narrow known auth paths with tests.
- Provider naming could drift without a schema enum.
  - Mitigation: keep the local resolver's supported provider map explicit and
    return structured unsupported-provider errors.

## Assumptions

- `ProfileSecret.provider/ref` is the right contract surface for local lease
  declarations; no broad schema redesign is needed.
- "Do not persist secret values" means no raw values in the database, events,
  logs, generated compose files, or new AWF-owned files. Existing operator-owned
  host credential files may still be mounted read-only by explicit declaration.
- `kind: env` leases are represented in Compose with placeholders, not by
  writing secret files.
- `kind: mount` local leases require an exact local source reference; this slice
  will not fetch secrets from Vault, AWS, GCP, GitHub App APIs, or any cloud
  broker.
- Legacy auth mounts remain necessary for some local CLI OAuth/keychain flows
  until those providers expose safer portable lease formats.

## Explicit Non-Goals

- Do not implement a cloud secret broker or delegated token minting.
- Do not store raw secret values in the DB, events, logs, artifacts, generated
  compose files, or new AWF-managed lease files.
- Do not remove legacy provider auth compatibility in local mode.
- Do not broaden host-home mounts or add new broad credential directories.
- Do not change PR monitor, merge policy, egress enforcement, or cleanup
  semantics beyond using existing lease revocation behavior.
- Do not lower coverage thresholds, lint gates, mypy strictness, or profile
  safety checks.
