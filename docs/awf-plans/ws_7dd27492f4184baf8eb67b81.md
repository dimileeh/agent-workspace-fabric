# Plan: Workspace/auth hardening — API timing-safe token checks and workspace metadata auth

## Current Understanding

`require_api_token` already uses a constant-time `hmac.compare_digest` check against the
configured `AWF_API_TOKEN` and the protected workspace routes currently route through
`APIRouter`-level `Depends(require_api_token)` for workspace/operator metadata and
creation endpoints. The required control/metadata slice therefore appears implemented in
code but lacked workspace-local plan and validation artifacts.

## Intended Files / Modules To Touch

- `src/awf/api/deps.py` (verify/retain constant-time comparison and existing 401/503 envelopes)
- `tests/unit/contracts/test_surface_metadata_alignment.py` (add explicit route-level auth
  regression for sensitive workspace metadata routes)
- `docs/awf-plans/ws_7dd27492f4184baf8eb67b81.md` (this contract artifact)
- `docs/awf-plans/ws_7dd27492f4184baf8eb67b81.validation.txt` (validation evidence/running
  request record)
- callback routes and callback authentication are intentionally out of scope.

## Tests To Write First

1. Add a route-metadata regression that asserts sensitive workspace/operator metadata routes
   declare `require_api_token` in runtime dependency metadata.
   - Routes covered:
     - `POST /v1/workspaces`
     - `POST /v2/workspaces`
     - `GET /v1/workspaces`
     - `GET /v1/workspaces/overview`
     - `GET /v1/workspaces/{workspace_id}`
     - `GET /v1/workspaces/{workspace_id}/events`
     - `GET /v1/workspaces/{workspace_id}/stale-reasons`
     - `GET /v1/workspaces/{workspace_id}/secret-leases`
2. Keep existing tests that verify unauthenticated and wrong-token failures for these
   workspace routes and successful authorized access.
3. Keep existing tests that verify constant-time token checks in `require_api_token` and
   503/401 envelope behavior.

## Implementation Approach

1. Confirm the current `require_api_token` implementation still preserves:
   - 503 behavior when `AWF_API_TOKEN` is not configured.
   - 401 envelope + `WWW-Authenticate: Bearer` on invalid or missing tokens.
   - `hmac.compare_digest`-based constant-time comparison.
2. Add a narrow contract test in `tests/unit/contracts/test_surface_metadata_alignment.py`
   using route metadata introspection so accidental future auth-removal on listed routes
   fails in CI.
3. Keep route surfaces unchanged for callbacks and avoid architecture-level auth dependency
   refactors.
4. Record validation evidence in the workspace validation artifact.

## Risks / Assumptions

- Assumption: contract metadata in `tests/unit/contracts/_introspection.py` still reflects
  router-level dependencies for route-level auth assertions.
- Assumption: local-dev usability remains via `AWF_API_TOKEN` fixture usage in the existing
  API tests.
- Risk: adding route-level contract assertions increases maintenance overhead when routes are
  intentionally made public; route additions must add or update the explicit exception list.

## Explicit Non-Goals

- Callback hardening and callback-route auth work.
- Any rate-limiting or production fail-fast changes unrelated to token timing comparison.
- Response shape changes for workspace listing/create/idempotency/error paths.
- Any global security architecture redesign.
