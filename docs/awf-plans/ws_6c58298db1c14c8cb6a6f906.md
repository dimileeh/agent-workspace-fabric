# Plan: P1 Explicit Workspace Network Postures

## Goal

Make workspace network posture an intentional profile setting with exactly three
resolved postures:

- `restricted`: safe default for newly onboarded projects.
- `offline`: no external network posture for high-security/local-mirror work.
- `open`: trusted local dogfood posture with visible unrestricted internet access.

`open` must remain available, but it should no longer be the silent default. This
slice will not implement destination-level proxy, firewall, DNS, or audit
controls.

## Current Context

- `WorkspaceProfile.security.egress.mode` currently accepts `open`, `offline`,
  `mirrored`, and `allowlist`, and defaults to `open`.
- Local Docker enforcement already maps `open` to the public Compose network and
  maps offline-like modes to an internal Compose network with no host-gateway
  mapping.
- Profile preview returns the full `ProfileResolution.profile` payload, workspace
  API responses return sanitized `requested_profile` and `resolved_profile`, and
  MCP tools generally mirror REST response models.
- `awf profile init` drafts onboarding profiles through
  `src/awf/profiles/onboarding.py`; `.awf/workspace.yml` is AWF's self-dogfood
  profile and should explicitly declare `open` once the schema supports it.

## Intended Files And Modules To Touch

Core profile/schema:

- `src/awf/profiles/models.py`
  - Replace or tighten the public posture enum to the three values
    `offline`, `restricted`, and `open`.
  - Keep the JSON path as `security.egress.mode` unless a smaller helper field is
    needed; this preserves existing profile shape while making `mode` the
    network posture.
  - Change the default posture from `open` to `restricted`.
  - Reject unsupported posture strings such as `allowlist`, `mirrored`, and
    arbitrary values with ordinary Pydantic validation errors.
  - Keep `allowlist` out of the new behavior except as rejected legacy input; do
    not treat it as enforced metadata.
  - Add a resolved `network_posture` field to `ProfileResolution` if needed so
    `awf profile preview` surfaces the posture without operators digging through
    the full profile object.

Local launch/enforcement:

- `src/awf/node/egress_policy.py`
  - Update `local_egress_plan()` to handle `restricted`.
  - Keep `open` as public network + host gateway with a reason code that makes
    unrestricted access obvious.
  - Keep `offline` as internal Compose network + no host gateway.
  - Treat `restricted` conservatively in local Docker as internal Compose network
    + no host gateway, with details explaining that destination-level controls
    are deferred.
  - Remove local allowlist/mirrored branches or turn them into unreachable schema
    guards.

- `src/awf/node/stack_launcher.py`
  - Continue deriving `WorkspaceComposeSpec.network_internal` and
    `host_gateway_enabled` from the resolved posture.

Resolved profile and validation identity:

- `src/awf/runtime/validation_identity.py`
  - Update environment identity inputs to include the resolved network posture
    and stop depending on legacy allowlist semantics.

- `src/awf/service/workspaces.py`
  - Add a small helper that extracts the resolved network posture from a
    workspace's `resolved_profile` safely.
  - Include a top-level `network_posture` on workspace responses where existing
    computed profile metadata patterns already exist.

- `src/awf/api/schemas.py`
  - Add `network_posture: Literal["offline", "restricted", "open"] | None` to
    `WorkspaceResponse` and `WorkspaceOverviewResponse`.
  - Add the same field to runtime/detail projections only if the existing
    response shape already carries profile-derived metadata there.

- `src/awf/service/workspace_observability.py`
  - Populate overview `network_posture` from the resolved profile helper.

Status/doctor output:

- `src/awf/service/orphans.py` and `src/awf/service/status.py`
  - Extend `WorkspaceLifecycleSnapshot` with optional `network_posture` while
    preserving existing tests via a default `None`.
  - Have `_default_workspace_id_lookup()` select `Workspace.resolved_profile` and
    extract posture for active workspaces.
  - Add a non-failing `checks.network_posture` payload with active counts by
    posture, open workspace examples, and explicit reason codes such as
    `NETWORK_POSTURE_NO_ACTIVE_OPEN` and `NETWORK_POSTURE_OPEN_ACTIVE`.

- `src/awf/service/doctor/__init__.py` and possibly
  `src/awf/service/doctor/reasons.py`
  - Add a doctor diagnostic for network posture using the status payload.
  - Render active `open` workspaces as a warning, not a service failure, because
    open is allowed but must be visible.

Onboarding and self dogfood:

- `src/awf/profiles/onboarding.py`
  - Ensure generated profiles and smoke request payloads include or inherit
    `restricted` as the resolved/default posture.

- `.awf/workspace.yml`
  - Add explicit `security.egress.mode: open` for AWF self-development.

Documentation and console compatibility:

- `README.md`
  - Update the local egress/posture section to describe `open`, `restricted`,
    and `offline`, including that local restricted mode does not implement
    destination-level allowlists.

- `docs/PROJECT_ONBOARDING.md`
  - State that generated onboarding profiles default/recommend `restricted` and
    that operators must intentionally choose `open` for trusted local work.

- `apps/console/lib/types.ts`, `apps/console/lib/security-format.ts`, and the
  existing security panel in `apps/console/components/console-dashboard.tsx`
  - Touch only if the backend enum change makes TypeScript or existing security
    display stale. If touched, show open as unrestricted/warning, restricted as
    the default posture, and remove legacy allowlist/mirrored display paths.

No database migration is expected because the posture lives inside profile JSON
and computed response/status projections.

## Risks And Mitigations

- Changing the default from `open` to `restricted` can break local workflows that
  assume package install internet access. Mitigate by making AWF self-dogfood
  explicitly `open`, documenting the operator choice, and making open highly
  visible in status/doctor output.
- Local Docker cannot enforce destination-level restricted egress. Mitigate by
  treating `restricted` as no-public-egress local posture for now and explicitly
  documenting proxy/firewall/audit as a future slice.
- Existing tests and docs mention legacy `allowlist`/`mirrored` modes. Mitigate
  with a focused rename/update, not a broader network-policy refactor.
- Existing console display marks `open` as positive. If the frontend is touched,
  change open to warning/unrestricted language so it cannot be mistaken for a
  safe default.
- Old persisted workspaces may have legacy modes in `resolved_profile`. Helpers
  should handle unknown/malformed posture as `None` or `unknown` for read
  surfaces without crashing, while new profile parsing rejects invalid inputs.
- Adding status checks must not make service health fail just because a trusted
  open workspace is active. Use warning status with `ok: true`.

## Assumptions

- The public profile JSON path can stay `security.egress.mode`; the allowed
  values become the explicit posture contract.
- `restricted` is the safe onboarding default even though local Docker currently
  enforces it as internal-network/no-host-gateway rather than as destination
  allowlisting.
- `open` is still valid for trusted local dogfood and should be declared in the
  repo-local AWF self profile.
- MCP parity is achieved by updating shared REST/service response models rather
  than adding bespoke MCP-only fields.
- No persisted schema change is necessary for this slice.

## Explicit Non-Goals

- No destination-level proxy, firewall, iptables/nftables, DNS filtering,
  Kubernetes `NetworkPolicy`, GCP egress gateway, or audit implementation.
- No package mirror, registry allowlist enforcement, dependency cache, or
  install-script policy work.
- No cloud secret broker or new credential lease behavior.
- No queue, scheduler, merge policy, PR monitor, or stale-detection changes.
- No backlog ledger updates in `TODO/pre-gke-industrial-readiness.md`.
- No quality gate, coverage target, lint, typecheck, or validation weakening.
