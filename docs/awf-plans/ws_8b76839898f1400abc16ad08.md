# Request Admission Rate Limiting Plan

## Problem Statement

Workspace creation and callback registration can currently be burst-abused before later scheduler, disk, or callback persistence protections meaningfully bound host impact. Add a narrow, request-level admission limiter for:

- `POST /v1/workspaces`
- `POST /v2/workspaces`
- `POST /v1/callbacks`

This slice must remain independent from auth hardening, callback SSRF hardening, and scheduler/resource-capacity rewrites.

## Requirements Checklist

- [ ] Bound bursts for v1 workspace creation.
- [ ] Bound bursts for v2 workspace creation before disk admission and workspace row creation.
- [ ] Bound bursts for callback registration before new callback subscription creation.
- [ ] Prefer bearer-token-derived identity when an `Authorization: Bearer ...` header is present and parseable, using only a digest in keys/metadata.
- [ ] Use a fallback identity based on client host and endpoint family when no bearer token is available.
- [ ] Preserve cheap idempotency replay for already-created identical keys where practical, while ensuring bursts of new idempotency keys/payloads are limited before expensive work.
- [ ] Return structured 429 errors with stable reason/error codes and operator-visible limiter metadata.
- [ ] Never expose raw bearer tokens in limiter keys, response metadata, or any log-like metadata helper output.
- [ ] Keep config minimal and local-dogfood friendly.
- [ ] Do not require auth for endpoints that do not currently require it, and do not change callback URL policy or scheduler reservations.

## Intended Files and Modules

- `src/awf/api/request_admission.py` (new): small in-memory fixed-window admission helper with:
  - endpoint-family constants for `workspace_create` and `callback_register`;
  - bearer-token/fallback identity extraction from `Request` without storing raw token values;
  - SHA-256 based identity digests with a static purpose prefix;
  - per-identity, per-endpoint-family fixed-window counters;
  - structured rejection metadata containing endpoint family, identity type, identity digest, limit, window, remaining/retry information, and reason code;
  - a testable clock hook and app-state limiter accessor to avoid cross-test global state.
- `src/awf/common/config.py`: add minimal settings with `Field` descriptions, likely:
  - `request_admission_window_seconds` default `60`;
  - `workspace_create_rate_limit_count` default high enough for local dogfooding and existing tests, likely `120` per window;
  - `callback_register_rate_limit_count` default `240` per window.
- `src/awf/api/routes/workspaces.py`:
  - add admission checks to `create_workspace` and `create_workspace_v2`;
  - perform exact idempotency replay/conflict lookup first when an idempotency key is present;
  - call limiter before `repo.create(...)`, before v2 disk checks, and before `create_workspace_v2_row(...)`;
  - return top-level `ErrorResponse` JSON with `WORKSPACE_CREATE_RATE_LIMITED` on rejection;
  - add 429 response metadata for both create routes.
- `src/awf/api/routes/callbacks.py`:
  - add admission check to `register_callback` after callbacks-enabled and idempotency-key validation;
  - preserve existing idempotent replay by adding a narrow service/repository pre-check before limiter when the idempotency key already exists;
  - raise/return structured 429 with `CALLBACK_REGISTER_RATE_LIMITED` and sanitized metadata;
  - add 429 response metadata.
- `src/awf/service/callbacks.py` if needed:
  - add a small helper for callback idempotency replay lookup using the existing `callback_request_hash` and `CallbackSubscriptionRepository`, so the route can replay existing identical registrations before consuming limiter quota.
- `tests/unit/api/test_workspaces.py`:
  - API tests for v1 and v2 workspace create burst rejection under low test limits;
  - v2 test proving rejection happens before disk admission by installing a disk-check callable that would fail if invoked after the limit is exceeded;
  - idempotency replay test proving an already-created identical key remains cheap while a burst of fresh keys is rejected;
  - structured error payload assertions for workspace rate-limit rejection.
- `tests/unit/api/test_callbacks.py`:
  - API test for callback registration burst rejection under low test limits;
  - idempotency replay test proving an existing identical callback key can replay without duplicate rows even when new keys are limited;
  - structured error payload assertions for callback rate-limit rejection;
  - fallback identity behavior through a client with no `Authorization` header.
- `tests/unit/api/test_deps.py`:
  - small helper-level tests for bearer identity digesting, fallback identity separation, per-token separation, endpoint-family separation, and absence of raw bearer tokens in metadata/log-like fields.
- `docs/awf-plans/ws_8b76839898f1400abc16ad08.validation.md` after implementation:

## Implementation Notes

- Limiter algorithm: in-memory fixed window per app process. This is intentionally narrow and local-runtime friendly; it avoids introducing Redis or another distributed dependency in this slice.
- Limiter key shape should include endpoint family and sanitized identity digest, never raw tokens or full authorization headers.
- Bearer parsing should accept only non-empty `Bearer` credentials case-insensitively. Invalid/non-bearer authorization falls back to client host.
- Fallback identity should use `request.client.host` when present and a stable `unknown-client` fallback otherwise, combined with endpoint family before hashing.
- Structured rejection metadata should be safe for operators and logs:
  - `reason_code`
  - `endpoint_family`
  - `identity_type`
  - `identity_digest`
  - `limit`
  - `window_seconds`
  - `retry_after_seconds`
- Do not emit limiter logs unless needed for tests or existing observability patterns; if added, use only the same sanitized metadata.
- Existing workspace auth dependency remains unchanged. Callback registration remains public/local-dev compatible as it is today.

## Risks and Assumptions

- The first implementation is per-process in-memory, so multiple API worker processes would each have their own bucket. This is acceptable for the narrow local/control-plane slice but should be revisited before horizontally scaled deployments.
- Existing tests create up to 51 workspaces in one test, so defaults must be bounded but high enough not to break normal local dogfooding or current suite behavior. Tests will override settings to low limits for deterministic rejection.
- Idempotency replay requires a DB lookup before limiter. That leaves a small amount of cheap DB work for repeated keys, but prevents duplicate expensive work and preserves current idempotency semantics.
- Concurrent first-use requests with the same new idempotency key may both pass admission before the DB idempotency constraint resolves the duplicate. This is acceptable because duplicate expensive work remains bounded by the request limit and existing idempotency conflict handling.
- `Authorization: Bearer` on unauthenticated callback registration is used only as a quota identity signal, not as authentication or authorization.

## Explicit Non-goals

- No production auth model rewrite.
- No new authentication requirement for create/list/callback routes.
- No callback DNS rebinding, HTTPS-only, or SSRF policy work.
- No scheduler/resource-capacity reservation rewrite.
- No distributed rate limiter or external cache service.
- No broad suite or coverage run locally unless a focused failure requires it.
- No branch switching, pushing, rebasing, or manual PR work.
