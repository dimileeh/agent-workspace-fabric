## Goal

Add compact status panels to the AWF operator console that surface profile secret
policy, lease/audit readiness, unsafe mount lint status, provider credential readiness,
and egress mode/status — without printing secrets. Missing backend fields must render
as "unavailable" rather than throwing. Cards must be compact, no nested cards, and
preserve mobile layout.

---

## Approach: Console-Only, Conservative Fallbacks

The backend already surfaces most of the needed data in the `Workspace` detail
endpoint (specifically: `secret_leases`, `resolved_profile.secrets`,
`resolved_profile.security.egress`, `resolved_profile.security.host_home_auth_mounts`,
and `policy_findings`). The data exists in `resolved_profile` (a
`Record<string, unknown> | null`) and `secret_leases` (a typed array already in the
Python schema but **not yet in the TS types**). No backend behavior changes are needed
beyond a tiny compatibility addition: adding `secret_leases` to the TS `Workspace`
interface.

The approach:
1. Extract typed helpers for profile security/secret/egress fields from the untyped
   `resolved_profile` / `requested_profile` objects, with full fallback for missing or
   partial payloads.
2. Add TS interfaces for `WorkspaceSecretLease`, `ProfileSecret`, `ProfileEgress`,
   and `ProfileSecurity` so the contract is type-checked.
3. Render two compact panels in the workspace detail view:
   - **Security & Egress panel** — shows egress mode, host-home auth mount policy,
     and any unsafe mount lint findings derivable from existing data.
   - **Secrets & Leases panel** — shows declared secrets from profile, lease/audit
     readiness from `secret_leases`, and provider credential readiness status (derived
     from lease provider and secret declarations).
4. Add lib-level formatting helpers with unit tests.
5. Add type-contract tests for new TS interfaces.

No new API endpoints. No backend behavior changes beyond ensuring `secret_leases`
is included in the API response (it already is — see `WorkspaceResponse.secret_leases`
in `schemas.py:503`).

## Detailed Design

### 1. New TypeScript interfaces (`types.ts`)

```typescript
export interface WorkspaceSecretLease {
  lease_id: string;
  secret_name: string;
  kind: string;
  target: string;
  status: string;
  provider: string | null;
  ref_digest: string | null;
  issued_at: string;
  mounted_at: string | null;
  expires_at: string | null;
  revoked_at: string | null;
}

export interface ProfileSecret {
  name: string;
  target: string;
  kind: "mount" | "env";
  mode: "ro" | "rw";
  required: boolean;
  provider: string | null;
}

export interface ProfileEgress {
  mode: "open" | "allowlist" | "offline" | "mirrored";
  allowlist: string[];
}

export interface HostHomeAuthMountPolicy {
  mode: "block" | "warn";
}

export interface ProfileSecurity {
  egress: ProfileEgress;
  host_home_auth_mounts: HostHomeAuthMountPolicy;
}
```

Add to `Workspace` interface:
```typescript
secret_leases: WorkspaceSecretLease[];
```

### 2. Formatting helpers (`security-format.ts`)

All helpers must handle `null`/`undefined`/partial payloads gracefully.

**`extractProfileSecrets(profile: Record<string, unknown> | null | undefined): ProfileSecret[]`**
- Read `profile?.secrets`; if missing or not an array, return `[]`.
- Map each element, picking only the typed fields. If `name`/`target`/`kind`/`mode`/`required` are wrong type, use defaults. Skip the `ref` field entirely (never expose it).
- Never throw.

**`extractProfileEgress(profile: Record<string, unknown> | null | undefined): ProfileEgress`**
- Read `profile?.security?.egress`. If missing, return `{ mode: "open", allowlist: [] }` (safe default).
- Validate `mode` against known literal union; fall back to `"open"` if unrecognized.
- Validate `allowlist` is `string[]`; default to `[]`.

**`extractProfileSecurity(profile: Record<string, unknown> | null | undefined): ProfileSecurity`**
- Combine `extractProfileEgress(profile)` and `extractHostHomeAuthMountPolicy(profile)`.

**`extractHostHomeAuthMountPolicy(profile: Record<string, unknown> | null | undefined): HostHomeAuthMountPolicy`**
- Read `profile?.security?.host_home_auth_mounts`. If missing, return `{ mode: "block" }` (safe default).
- Validate `mode` against `"block" | "warn"`; fall back to `"block"`.

**`summarizeSecretLeaseReadiness(leases: WorkspaceSecretLease[]): { ... }`**
- Returns: `{ total: number, issued: number, mounted: number, expired: number, revoked: number, allReady: boolean, missingRequired: boolean }`.
- Count leases by status. `allReady` = all required leases are `mounted`. `missingRequired` = any required lease not issued/mounted.

**`summarizeEgressStatus(egress: ProfileEgress): { label: string, tone: string, detail: string }`**
- Map mode to display labels: `"open"` → tone `"good"`, `"allowlist"` → tone `"warn"`, `"offline"` → tone `"info"`, `"mirrored"` → tone `"neutral"`.
- Detail includes allowlist count when applicable.

**`formatHostHomeMountPolicy(policy: HostHomeAuthMountPolicy): { label: string, tone: string }`**
- `"block"` → `"blocked"` / `"good"`; `"warn"` → `"allowed (warn)"` / `"warn"`.

**`summarizeProviderCredentialReadiness(secrets: ProfileSecret[], leases: WorkspaceSecretLease[]): { ... }`**
- Cross-reference declared secrets with leases to determine which providers have issued leases.
- Return `{ declared: number, leased: number, missingProviders: string[], label: string, tone: string }`.

## Risks

1. **`secret_leases` may not flow through the BFF proxy.** The console's Next.js API routes in `apps/console/app/api/` need to pass through the `secret_leases` field. If the BFF route strips it, the field will be `undefined` in the client. Mitigation: verify the BFF proxy passes through all top-level fields (it likely does since `resolved_profile` is already passed through); the `extract*` helpers default gracefully to "unavailable".

2. **`policy_findings` not on console `Workspace` type.** Currently the TS `Workspace` interface does not have `policy_findings`. Adding it is a types-only change, but if the API route doesn't return it, the field will be `undefined`. The plan adds it to the TS type and renders it conditionally (only shown if present and non-empty).

3. **`resolved_profile` shape varies.** Since it's `Record<string, unknown> | null`, the `extract*` helpers must be defensive against any shape. The test suite covers null, undefined, missing keys, wrong types, and valid shapes.

4. **Mobile layout regression.** The new panels must use the existing responsive grid patterns (`sm:grid-cols-2`, `xl:grid-cols-N`) and must not nest `Panel` components inside each other. Use `Fact`/`QueueChip` grids only.

5. **Coordination overlap with ws_a41728907dc740d6a1ae7092 on `tests/unit/api/test_workspaces.py`.** Our plan does NOT touch Python backend tests, so no real conflict. The overlap is advisory only.

## Assumptions

1. The `GET /v1/workspaces/{id}` API already returns `secret_leases` and `policy_findings` (confirmed by reading `schemas.py` lines 490-503).
2. The Next.js BFF API route at `apps/console/app/api/awf/workspaces/[workspaceId]/route.ts` (or similar) passes through the full API response without stripping `secret_leases` or `policy_findings`.
3. No new backend endpoints or fields are needed. The only backend-adjacent change is adding `secret_leases` and `policy_findings` to the TS `Workspace` interface to match the actual API response.
4. The `ref` field on `ProfileSecret` is already stripped by the backend's `_sanitize_profile_value()` function (confirmed), so it will never appear in the console data. Our extraction helpers also explicitly omit it for defense-in-depth.
5. Provider credential readiness is derived from cross-referencing declared secrets with lease status — not from a dedicated endpoint.

1. **No new backend API endpoints or fields.** The only backend-adjacent change is to the TS type definitions in the console.

6. **No nesting of `Panel` components.** Each security/lease section is a `Panel` containing flat `Fact`/`QueueChip` grid items only.
7. **No reduction in coverage.** Tests are additive. No existing tests are modified.
