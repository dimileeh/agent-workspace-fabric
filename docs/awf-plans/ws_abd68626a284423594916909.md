# Plan: P1 Log Secret Redaction

## Scope

Implement a focused security hardening slice for workspace log data. The change
should introduce one central text redactor for common token shapes and route
workspace log persistence plus live log broadcasts through it before any
operator-facing log data is stored or streamed.

The main choke points are `WorkspaceLogSink.write()` for durable log files and
`LogBroadcaster.publish()` for live frames. Existing API response shapes should
not change: log read responses and WebSocket frames keep the same fields, with
only sensitive value bodies replaced by a stable marker.

## Intended Files And Modules To Touch

Production modules:

- `src/awf/common/redaction.py` (new)
  - Add a central `REDACTION_MARKER`, likely `"<redacted>"`.
  - Add `redact_secrets(text: str) -> str`.
  - Cover:
    - GitHub tokens such as `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `gha_`,
      and `github_pat_...`;
    - OpenAI-style `sk-...` and `sk-proj-...` keys;
    - Anthropic-style `sk-ant-...` keys;
    - Gemini / Google API key style `AIza...` values;
    - generic `Bearer <value>` tokens;
    - `Authorization: Bearer <value>` and `Authorization: Basic <value>`
      header values while preserving the header name and auth scheme;
    - basic-auth URL credentials such as `https://user:pass@example.com/...`
      while preserving the scheme and host context;
    - `AWF_API_TOKEN=...`, `AWF_GITHUB_TOKEN=...`, and similar
      `*_API_TOKEN` / `*_AUTH_TOKEN` assignment-style values while preserving
      the key and separator.
- `src/awf/runtime/logs.py`
  - Redact data before appending bytes in `WorkspaceLogSink.write()`.
  - Update metadata byte and line counts from the redacted text actually
    written to disk.
  - Broadcast the same redacted text that was persisted.
  - Also redact inside `LogBroadcaster.publish()` so direct live-frame callers
    cannot bypass the redactor.
  - Keep frame offsets based on the persisted redacted log file for sink-backed
    streams.

Likely no production changes:

- `src/awf/api/routes/logs.py`, `src/awf/api/routes/ws.py`, and
  `src/awf/service/workspaces.py`
  - Reads should naturally return redacted data because new writes are redacted
    before persistence.
  - Touch only if tests show a live initial-tail path can bypass the log sink.
- `src/awf/runtime/pr_monitor_operations.py`,
  `src/awf/runtime/pr_monitor_runner.py`, `src/awf/runtime/pr_creator.py`, and
  `src/awf/service/provider_readiness.py`
  - Existing specialized redactors can remain for their structured payloads.
  - Consider follow-up consolidation only if the implementation stays small and
    does not broaden this slice.

Test modules:

- `tests/unit/runtime/test_log_redaction.py` (new)
  - Focused tests for the central redactor and representative fake secret
    patterns.
- `tests/unit/runtime/test_logs.py`
  - Regression coverage for persisted workspace log redaction and live frame
    redaction.
  - Add a direct `LogBroadcaster.publish()` regression to prove live frames are
    sanitized even when not produced by `WorkspaceLogSink`.

## Tests To Write First

1. Add central redactor tests in `tests/unit/runtime/test_log_redaction.py`.
   - Use synthetic, non-real values that match known token formats.
   - Assert useful context remains:
     - `Authorization: Bearer <redacted>`;
     - `Authorization: Basic <redacted>`;
     - `AWF_API_TOKEN=<redacted>`;
     - `https://<redacted>@github.com/example/repo.git`.
   - Assert raw fake token bodies are absent from the result.
   - Expected red: `awf.common.redaction` does not exist.

2. Add a `WorkspaceLogSink.write()` regression in `tests/unit/runtime/test_logs.py`.
   - Write a line containing fake GitHub, OpenAI/Anthropic/Gemini, bearer, URL
     credential, and AWF token values.
   - Subscribe to the broadcaster during the write.
   - Assert the persisted file and live frame contain the stable marker and do
     not contain any fake secret body.
   - Assert non-secret surrounding text remains readable.
   - Expected red: current sink writes and broadcasts raw text.

3. Add a direct `LogBroadcaster.publish()` regression.
   - Publish a frame containing `Authorization: Bearer fake-token-value`.
   - Assert the queued frame is redacted.
   - Expected red: current broadcaster enqueues raw `data`.

4. Optional hardening test if the implementation uses a buffered streaming
   redactor.
   - Split a fake token across two `WorkspaceLogSink.write()` calls and assert
     the file and emitted frame do not leak either full token body.
   - If this materially complicates the slice, document chunk-boundary
     redaction as residual risk rather than expanding beyond the requested P1.

5. Implement the smallest production change needed.
   - Add the common redactor.
   - Thread it through the log sink and broadcaster.
   - Keep all public response models and field names unchanged.

## Risks

- Regex redaction can over-match or under-match. Keep patterns targeted to
  known token shapes and assignment/header contexts rather than broad words
  like `token` in ordinary prose.
- Chunk boundaries can split a secret across writes. A stateful buffered
  redactor would reduce that risk but may delay partial-line log streaming and
  change metadata timing. Decide explicitly during implementation based on test
  complexity and blast radius.
- Redaction changes byte length. Metadata and offsets should describe the
  redacted file bytes, not the raw process output bytes.
- Existing historical log files written before this change are not retroactively
  scrubbed by this slice.
- Centralizing all existing specialized redactors could create unnecessary
  churn. This task should harden workspace logs first and avoid broad unrelated
  refactors.

## Assumptions

- "Persisted logs" refers to workspace log files written through
  `awf.runtime.logs.LogStore` / `WorkspaceLogSink`.
- "Streamed log frames" refers to `LogFrame` payloads emitted through
  `LogBroadcaster` and then sent by the workspace WebSocket route.
- Replacing only the sensitive value body with `"<redacted>"` satisfies the
  stable marker requirement.
- Fake test values that match token formats are safe to place in tests and do
  not represent real credentials.
- No database schema, migration, API response field, or CLI contract change is
  needed.

## Explicit Non-Goals

- Do not scan or rewrite existing historical log files.
- Do not add artifact redaction or uploaded-file scanning.
- Do not redesign the WebSocket protocol, log metadata schema, or log read API.
- Do not lower coverage thresholds, workspace coverage requirements, quality
  gates, or validation policy.
- Do not log real secrets in tests, fixtures, comments, or failure messages.
- Do not switch branches, push, rebase, force-push, or manually manage the AWF
  PR lifecycle.
