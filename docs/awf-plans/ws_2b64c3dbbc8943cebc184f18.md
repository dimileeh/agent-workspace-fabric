# Plan: Artifact Read And Download API Slice

## Objective

Implement the narrow P1 artifact API contract beyond metadata while preserving
the existing artifact list response. AWF should expose token-protected artifact
downloads from the existing local artifact root only:

`<AWF_WORK_DIR>/artifacts/<workspace_id>/...`

The implementation should not allow arbitrary filesystem reads, symlink escapes,
or path traversal outside the workspace artifact directory. The current list
endpoint already returns a cursor-ready envelope (`items`, `next_cursor`,
`has_more`, `limit`, `cursor`), so this slice should keep that shape compatible
and add only backward-compatible fields if needed.

## Current Context

- `src/awf/api/routes/artifacts.py` owns the current API route and local
  Pydantic response models.
- `GET /v1/workspaces/{workspace_id}/artifacts` already requires
  `require_api_token`, validates workspace existence, scans
  `<work_dir>/artifacts/<workspace_id>`, skips symlinks/non-regular files, and
  returns a cursor-ready list envelope.
- Existing artifact metadata includes `artifact_id`, `workspace_id`, `name`,
  `relative_path`, `path`, `kind`, `size_bytes`, and `modified_at`.
- Existing tests are concentrated in `tests/unit/api/test_artifacts.py`.
- Public API schemas generally live in `src/awf/api/schemas.py` for
  console-neutral reuse, but artifact schemas are currently route-local.

## Intended Files And Modules To Touch

  - Extend metadata/list compatibility assertions only additively.

- `tests/unit/service/test_artifacts.py` (new)

- `tests/unit/runtime/test_validation.py`
  - Do not change runtime capture behavior unless implementation reveals a real

### Production Code

- `src/awf/service/artifacts.py` (new)
  - Centralize artifact-root resolution, safe relative-path validation,
    metadata listing, content-type guessing, and downloadable artifact lookup.
  - Define narrow service errors such as `ArtifactPathError` and
    `ArtifactNotFoundError` so route code maps failures to structured HTTP
    responses without catching broad filesystem exceptions.

- `src/awf/api/routes/artifacts.py`
  - Keep `GET /v1/workspaces/{workspace_id}/artifacts` compatible.
  - Add a token-protected download route, planned shape:
    `GET /v1/workspaces/{workspace_id}/artifacts/download?path=<relative_path>`.
  - Return a `FileResponse` or equivalent streaming response with standard
    download headers: `Content-Length`, `Content-Type`, and
    `Content-Disposition` with the artifact filename.
  - Keep workspace-missing and artifact-missing errors structured.

- `src/awf/api/schemas.py`
  - Move or duplicate the artifact response models here only if needed to keep
    the OpenAPI/console contract neutral and reusable.
  - Preserve all existing metadata fields. Additive candidates:
    `download_url` and `content_type`.

- `README.md` or `docs/PLAN_MVP.md`
  - Add a short API note for listing artifacts and downloading one artifact only
    if this implementation slice changes the documented contract. Do not add
    product narrative outside the API contract.

## Tests To Write First

1. API authentication and compatibility:
   - Existing list endpoint still returns the current envelope and existing item
     fields.
   - Download endpoint requires the local bearer token when `AWF_API_TOKEN` is
     configured.

2. Happy-path download:
   - Create a workspace, write an artifact under
     `<work_dir>/artifacts/<workspace_id>/logs/stdout.txt`, then call:
     `GET /v1/workspaces/{workspace_id}/artifacts/download?path=logs/stdout.txt`.
   - Assert status `200`, body bytes match the file, `Content-Length` matches
     byte count, `Content-Type` is appropriate for `.txt`, and
     `Content-Disposition` uses `stdout.txt`.

3. Missing workspace:
   - Download for `ws_missing` returns structured `404` with `error_code:
     NOT_FOUND`, matching the existing list endpoint style.

4. Missing artifact:
   - Existing workspace plus absent relative path returns structured `404`
     without leaking a host path.

5. Path traversal and unsafe paths:
   - `path=../secret.txt`, `path=/tmp/secret.txt`, empty path, and backslash
     variants return structured `400` with a path-specific error code such as
     `INVALID_ARTIFACT_PATH`.
   - A symlinked artifact file and a symlinked intermediate directory are
     rejected or treated as not found; neither may serve bytes outside the
     managed artifact root.

6. Service-level resolver tests:
   - Safe nested relative path resolves and reports stat/content metadata.
   - Root missing or root symlink is handled without filesystem escape.
   - Deleted-during-stat and permission/OSError cases fail closed.

7. List shape add-ons, if implemented:
   - `download_url` and `content_type` are additive and do not remove or rename
     any existing list fields.
   - `next_cursor`, `has_more`, `limit`, and `cursor` remain present.

After adding these tests, run the focused artifact tests and confirm the new
download/path-safety tests fail before implementation.

## Implementation Steps

1. Add the failing API and service tests described above.

2. Extract artifact filesystem logic into `src/awf/service/artifacts.py`:
   - Build the workspace artifact root from `Path(settings.work_dir) /
     "artifacts" / workspace_id`.
   - Reject absolute paths, `.` / `..` segments, empty paths, NUL-like invalid
     values, and backslash-separated traversal attempts.
   - Resolve the artifact root with `strict=True`, reject symlink roots, and
     ensure the final resolved file remains under the resolved root.
   - Walk every relative path component and reject symlink components before
     serving bytes.
   - Serve only regular files.

3. Update the list endpoint to call the service while preserving response
   compatibility. If adding `download_url` or `content_type`, make those fields
   additive and leave `path` untouched for this compatibility slice.

4. Add the download endpoint:
   - Reuse `_require_workspace` before any filesystem lookup so missing
     workspace behavior remains deterministic.
   - Map invalid path to `400 INVALID_ARTIFACT_PATH`.
   - Map absent/non-regular/rejected artifact to `404 NOT_FOUND` or
     `ARTIFACT_NOT_FOUND` consistently with the existing API taxonomy.
   - Use `FileResponse` with `filename=<basename>` and explicit media type from
     `mimetypes.guess_type`, falling back to `application/octet-stream`.

5. Add or move artifact Pydantic schemas into `src/awf/api/schemas.py` only if
   the route needs new public fields or OpenAPI reuse. Keep route-local adapter
   functions small if the service returns dataclasses.

6. Add minimal docs for the authenticated download URL and safety constraints if
   new fields/routes are visible to clients.

7. Run focused tests, then lint/type checks, then the broader unit surface if
   the schema/service extraction touches shared API behavior.

## Risks

- `FileResponse` header formatting can vary by media type and Starlette
  version; tests should assert contract-relevant header values without
  overfitting harmless formatting.
- The current list response exposes an absolute `path`. Removing it would be a
  breaking change, so this slice should keep it even though the new download
  route should be the preferred retrieval contract.
- Symlink handling must fail closed. Allowing symlink files or symlinked parent
  directories would weaken the "AWF-managed artifact paths only" guarantee.
- Moving route-local schemas to `schemas.py` can affect OpenAPI snapshots or MCP
  imports indirectly; keep the move minimal and additive.
- Query-parameter path downloads need careful URL encoding in docs and generated
  `download_url` fields.

## Assumptions

- Local artifact storage remains filesystem-backed under `AWF_WORK_DIR`; no
  remote object store or durable artifact DB index exists in this slice.
- The authenticated download endpoint is acceptable instead of signed expiring
  URLs for this P1 slice because `require_api_token` is already the local
  operator security boundary for artifact metadata.
- Missing artifact roots for existing workspaces continue to mean an empty list;
  attempting to download from a missing root returns a missing-artifact response.
- Artifact `relative_path` values are POSIX-style paths as produced by the
  existing listing code.

## Explicit Non-Goals

- No signed URL service, expiring token minting, or external artifact store.
- No range requests, resumable downloads, archive generation, or directory
  downloads.
- No artifact upload API.
- No secret scanning, redaction, quarantine, or classification of artifact
  contents.
- No removal or renaming of existing artifact metadata fields.
- No console UI changes beyond schemas/OpenAPI compatibility.
- No database migrations or persistent artifact metadata table.
