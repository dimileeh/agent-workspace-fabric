## Problem

AWF has a full FastAPI REST API with 30+ endpoints, but:

1. **No stable OpenAPI artifact** — The spec is served dynamically at `/openapi.json` but never dumped, validated, or checked in. CI has no step that verifies the spec is structurally valid or complete.
2. **No regression protection** — Nothing prevents the spec from drifting, losing endpoints, or breaking backward compatibility.
3. **Incomplete API examples** — `docs/REST_API_REFERENCE.md` covers only 7 of 30+ endpoint paths. No copy-paste `curl` examples exist for: retry, remonitor, cancel, stop, destroy, refresh, rebase, validate, merge-queue, tasks, operations, logs (detail), locks, overlap-graph, callbacks, runtime, metrics, readiness, release-readiness, stale-reasons, secret-leases, validation provenance.
4. **No validation commands** for OpenAPI spec regressions.

## Acceptance Criteria (from TODO)

- `openapi.json` can be generated or verified in CI/local validation
- Linked from docs
- Paired with copy-paste `curl` examples for: create workspace, list status, read logs/events, request validation, remonitor, retry, and release readiness
- Regression tests/docs checks that keep the artifact/examples from drifting

## Implementation Plan

### 1. Create OpenAPI spec generation script

**File:** `scripts/generate_openapi.py`

- Module that imports `create_app` from `awf.api.app`, calls `app.openapi()`, and writes the result to `openapi.json` in the repo root.
- CLI invocation: `python scripts/generate_openapi.py` (writes `openapi.json`)
- Also usable as a test helper: `from scripts.generate_openapi import get_openapi_spec`
- No external dependencies beyond what's already in the project (FastAPI, Pydantic). The `app = create_app(use_lifespan=False)` call already works without DB/lifespan.
- The script must be idempotent: running it again produces the same output if endpoints have not changed (modulo version bumps).

### 2. Add `openapi-spec-validator` dev dependency

**File:** `pyproject.toml`

- Add `openapi-spec-validator>=0.7.0` to `[project.optional-dependencies] dev`.
- This is a lightweight, widely-used package for OpenAPI spec validation with no heavy transitive deps.
- Used by the regression test to validate structural correctness of the spec.

### 3. Write regression tests first (TDD)

**File:** `tests/unit/api/test_openapi_artifact.py`

Test cases:

1. **Spec generation succeeds** — `create_app(use_lifespan=False).openapi()` returns a valid dict with `openapi`, `info`, `paths` keys.
2. **Spec is valid OpenAPI 3.x** — Uses `openapi_spec_validator` to validate the full spec structure.
3. **All route prefixes are present** — Asserts that the expected path prefixes (`/healthz`, `/readyz`, `/release-readiness`, `/v1/workspaces`, `/v2/workspaces`, `/v1/events`, `/v1/tasks`, `/v1/callbacks`, `/v1/merge-queue`, `/v1/operations`, `/v1/metrics`, `/v1/locks`) appear in the generated spec's `paths`.
4. **Key endpoint methods exist** — For each of the acceptance-criteria endpoints (create workspace POST, get workspace GET, list workspaces GET, list events GET, list logs GET, request validation POST, remonitor POST, retry POST, release-readiness GET), assert the method+path exists in the spec.
5. **No duplicate operation IDs** — Collect all `operationId` values; assert uniqueness.
6. **All response models have schemas** — For each endpoint's declared response model in the spec, assert the model schema exists in `components/schemas`.
7. **Spec round-trips to JSON and back** — `json.loads(json.dumps(spec))` succeeds without error, proving the spec is fully JSON-serializable (no unserializable types like `datetime` objects leaking in).

### 6. Add docs drift regression test

**File:** `tests/unit/api/test_docs_drift.py`

## Risks

| Risk | Mitigation |
|------|------------|
| `openapi-spec-validator` may flag valid FastAPI patterns | Test locally first; if needed, pin version or use `openapi_spec_validator.validate_spec` which is widely compatible with FastAPI-generated specs |
| OpenAPI spec may contain non-serializable types | Test #7 (JSON round-trip) catches this; FastAPI/Pydantic models should already be JSON-safe |
| Docs drift test may be too brittle for small wording changes | Only check for path prefix presence and curl URL paths, not exact wording |
| Overlap with `ws_72055a2cbe8148b4a7d1468e` owned paths (`tests/unit/api/**`, `src/awf/api/**`) | New test files only; no modification to existing API route or schema code. The overlap is advisory and these are new files that don't conflict with existing test structure. |
| Checked-in `openapi.json` will show diffs on version bumps | The `--check` mode should treat the version field as a known-expected-drift field, or we generate and compare without the `info.version` key. Simpler: regenerate and compare the full file; version changes are intentional and should be committed. |

## Assumptions

1. `create_app(use_lifespan=False)` produces a complete OpenAPI spec without needing DB/Docker dependencies — verified by existing test pattern in `test_app_lifespan.py` and `test_deps.py`.
2. `openapi-spec-validator` is compatible with FastAPI 0.115+ generated specs — this is standard usage.
3. The existing `docs/REST_API_REFERENCE.md` structure can be expanded in-place without breaking existing links.
4. `scripts/generate_openapi.py` can be a standalone script without needing complex packaging — it just imports `awf.api.app:create_app`.
