## Problem Statement

Complete the narrow P1 low-risk security cleanup slice from the 2026-05-14 architecture/security review without overlapping the separate auth posture, callback SSRF, request admission/rate-limit, or production-config guardrail workstreams.

The work has three focused outcomes:

1. Remove fragile SQL interval string interpolation from PostgreSQL scheduler scoring while preserving workspace ordering semantics.
2. Ensure selected workspace create/idempotency/conflict 409 payloads avoid unnecessary internal field names such as `task_external_id`, while keeping stable error codes and useful operator guidance.
3. Prove doctor/support-bundle known-secret sets are used only for redaction and never emitted in collected output, including API token and database credential sentinels.

## Risks and Assumptions

- PostgreSQL `make_interval` is acceptable because this expression is only used in the PostgreSQL-specific scheduler age boost builder. SQLite behavior should remain unchanged.
- SQL string snapshots can be brittle across SQLAlchemy versions; tests should assert targeted properties instead of a full query string.
- `external_id` is a public API request field and should remain available in conflict detail. The internal legacy/database name to exclude from selected payloads is `task_external_id`.
- Existing doctor/support redaction may already handle API tokens and database passwords. If so, implementation should keep the source unchanged and retain added proof tests.
- Active workspace overlap warnings mention `src/awf/api/routes/workspaces.py` and `tests/unit/api/test_workspaces.py`; implementation should re-read these files immediately before editing and keep changes minimal to reduce stale-overlap risk.
- Documentation updates are only needed if a documented response body changes, not for wording adjustments that are undocumented.
