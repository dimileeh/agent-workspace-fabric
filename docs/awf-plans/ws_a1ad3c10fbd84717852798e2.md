# Plan — Harden Claude auth overlay fallback reconciliation & base-pin (#402, #404, #405)

Workspace: `ws_a1ad3c10fbd84717852798e2`
Deferred follow-ups from PR #401. One PR addressing **#402**, **#404**, **#405**.

## Guiding invariant (overrides all tactical choices below)

**Credential safety is paramount.** A wrong reconciliation must NEVER hide or drop a
still-valid credential. Every branch added here resolves ambiguity by *failing safe
toward keeping the credential visible*:

- #402: when a fallback-era deletion cannot be confidently attributed to the agent
  (vs a host-side change), do **NOT** create a whiteout — the file stays visible.
- #404: when a newer legacy mtime cannot be confidently attributed to an agent edit
  (vs an unedited host-changed copy), do **NOT** overwrite an existing `upper` edit.
- #405: a base-pin write failure must **NOT** hard-fail provisioning (keep the live,
  correct overlay); the residual wrong-base risk is mitigated on the *next* provision.

## Background / current behavior (verified by reading source)

Core file: `src/awf/node/auth_mounts_claude.py`
(`_reconcile_fallback_edits_into_upper`, `_prepare_claude_overlay_mount`,
`_record_overlay_base_pin`, `_live_overlay_pin_signature`, `_pinned_overlay_base`).
Symlink-safe write primitives: `src/awf/node/auth_mounts_overlay_copy.py`
(`_safe_mtime_ns`, `_safe_overlay_copy`). `src/awf/node/auth_mounts.py` re-exports
every public name; tests reference `awf.node.auth_mounts.<name>`.

- `_reconcile_fallback_edits_into_upper(legacy, merged, upper, base)` walks files that
  *exist* under `legacy`, forwards a file when it is a "fallback edit"
  (`base[rel]` absent OR `legacy_mtime > base_mtime`) and `upper` does not already hold
  an equal-or-newer entry ("upper wins ties"). Copies route through the live `merged`
  mount via `_safe_overlay_copy` (O_NOFOLLOW fd descent on both source and dest).
- It does **not** observe deletions (os.walk only yields existing files) → #402.
- Its edit-forwarding rule is mtime-only with no host comparison → #404.
- `_record_overlay_base_pin` logs `CLAUDE_AUTH_OVERLAY_BASE_PIN_WRITE_FAILED` and
  returns (keep-live) on `OSError`; the live-mount-reuse branches already re-pin from
  `/proc/mounts` while the mount is still up. The only unhandled window is
  **mount gone (reboot) + no pin + host changed** → #405.

Capability probe pattern exists: `_has_cap_sys_admin` reads `CapEff` from
`/proc/self/status` (bit 21). We mirror it for CAP_MKNOD (bit 27).

## Design

### #404 — host-origin vs agent-origin newer legacy mtime (do first; smallest, unblocks shared param)

Thread the **live host** `~/.claude` path into the reconcile so it can distinguish an
*agent fallback edit* from an *unedited host-changed copy*.

Key fact: the legacy copy is produced by `copytree(symlinks=False)` using `copy2`, which
preserves host `st_mtime_ns`. So for any file:
- **unedited** legacy file ⟺ `legacy_mtime_ns == host_mtime_ns` and same `st_size`
  (host-origin; agent never touched it),
- **agent-edited** legacy file ⟹ `legacy` diverges from host (newer mtime / different
  size = agent-origin).

New rule (scoped to protecting an **existing `upper` regular file**, exactly the
reviewer's ask — "an existing upper regular file should not be replaced solely because
the fallback copy has a newer host mtime"):

- When `upper[rel]` exists as a **regular file**, forward the legacy file over it ONLY
  when the legacy file **diverges from the live host** (proves an agent edit) AND the
  existing strictly-newer rule (`legacy_mtime_ns > upper_mtime_ns`) holds.
- When `upper[rel]` is absent / a whiteout / non-regular, keep the existing
  fallback-edit behavior (documented acceptable limitation; nothing to protect).

This preserves the tested fallback re-edit forwarding (agent-edited legacy diverges from
host → still forwarded) and fixes the regression (unedited host-changed legacy that is
byte/mtime-identical to host → not forwarded over the agent's older `upper` edit).

`host_claude` becomes a **required keyword param** of
`_reconcile_fallback_edits_into_upper`. Production caller `_prepare_isolated_claude_auth`
passes `host_home / ".claude"`. (No default: a default risks silently re-introducing the
bug; tests are in scope and updated.)

### #402 — forward fallback-era deletions as overlayfs whiteouts (fail-safe)

After the existing existing-file walk, add a second pass: walk `base`, find entries
present in `base` but **absent in `legacy`** = deletion candidates. For each candidate
`rel`:

1. Skip if `upper[rel]` already exists (any type) — the agent's overlay state is
   authoritative; do not double-handle. Skip usage-history dirs (already absent from
   base, kept for symmetry).
2. **Host-divergence disambiguation** (using the same live `host_claude` from #404):
   - host **lacks** `rel` → ambiguous (host may have removed it; legacy's absence is
     then host-explained, not agent-attributable) → **do NOT whiteout** (fail safe;
     base's copy stays visible = credential kept).
   - host **has** `rel` and host matches `base` (same `st_mtime_ns` + `st_size`) →
     host unchanged for this path, so legacy's absence is a confident **agent
     deletion** → eligible to whiteout (this mirrors normal overlay semantics: an
     agent deletion through `merged` hides the lower's copy).
   - host **has** `rel` but differs from `base` (host re-added/changed it) → ambiguous
     → **do NOT whiteout** (fail safe).
3. **Whiteout creation** via new `_safe_overlay_whiteout(upper, rel)`:
   - Primary: `os.mknod(char dev 0,0, mode=S_IFCHR|0o000, makedev(0,0))` written into
     `upper` via O_NOFOLLOW dir-fd descent (symmetric to `_safe_overlay_copy`; create
     intermediate parent dirs in `upper` as plain merged dirs). Requires **CAP_MKNOD**.
   - **Capability fallback**: if CAP_MKNOD is absent (probe) or `mknod` raises `EPERM`/
     `ENOSYS`/any `OSError` → **do NOT whiteout**, log, return False. A misclassified or
     un-creatable whiteout therefore can NEVER hide a credential — the failure mode
     degrades to "deletion not forwarded" = credential kept.
   - Whiteouts must live in `upper` (overlayfs reads them there); they cannot be
     expressed as a write through `merged`. Reconcile runs at provision time *before*
     the agent attaches, and a not-yet-coherent whiteout merely fails to hide (safe
     direction), so direct `upper` creation is acceptable here.

New helpers:
- `_has_cap_mknod(proc_status=_PROC_SELF_STATUS) -> bool` in `auth_mounts_claude.py`
  (mirror `_has_cap_sys_admin`, bit `_CAP_MKNOD_BIT = 27`), re-exported via
  `auth_mounts.py`.
- `_safe_overlay_whiteout(upper: Path, rel: Path) -> bool` in
  `auth_mounts_overlay_copy.py` (re-imported by `auth_mounts_claude.py`), reusing the
  O_NOFOLLOW descent pattern.
- New reason code `_CLAUDE_AUTH_OVERLAY_WHITEOUT_FAILED` (and/or
  `_CLAUDE_AUTH_OVERLAY_DELETION_AMBIGUOUS`) for fail-safe skips. Run
  `scripts/generate_reason_catalog.py` mentally / regenerate `docs/REASON_CATALOG.md`
  if a new operator-facing reason code is added (confirm gate — see Risks).

### #405 — base-pin write failure: keep-live + next-provision re-pin / rebuild

**Keep** `_record_overlay_base_pin` non-fatal (do not overturn
`test_overlay_signature_write_oserror_keeps_live_overlay`). Mitigate the residual
cross-reboot wrong-base risk on the **next** provision:

- Confirm/strengthen: when `upper.exists()` and `_pinned_overlay_base` returns `None`
  (pin missing OR pinned base no longer on disk = "stale/absent pin") and the overlay is
  still **live**, the existing live-mount-reuse branches recover the true base from
  `/proc/mounts` and re-pin (already implemented — extend the regression test to assert
  this second-provision re-pin, per "extend it; don't overturn it").
- For the **mount-gone** sub-case (reboot): when remounting a surviving `upper` against a
  base recomputed from the *current* host, after a successful mount record the pin to
  that freshly computed signature (already done) so future remounts are consistent, and
  ensure a **stale pin pointing at a vanished base** triggers a rebuild + fresh re-pin
  rather than being trusted (`_pinned_overlay_base` `is_dir()` guard already returns
  `None`; add an explicit test). No hard-fail path is introduced.

This keeps keep-live intact and makes the pin durable on the very next provision instead
of demanding fail-over at write time.

> delta is whatever the new test proves is missing (it may be test-only + a small guard).

## Risks & mitigations

- **Hiding a still-needed credential (catastrophic).** Mitigated by the fail-safe default
  in every ambiguous branch (#402/#404) and the CAP_MKNOD fallback; whiteout failures
  degrade to "not hidden". Adversarial tests assert no credential is hidden on
  ambiguity.
- **Direct whiteout write into a live overlay `upper`.** Reconcile runs pre-agent-attach;
  an incoherent whiteout merely fails to hide (safe). Documented; considered alternative
  (`unlink` through `merged`, which auto-whiteouts without CAP_MKNOD) rejected because
  the task prescribes mknod/CAP_MKNOD + capability fallback — but noted as the contingency
  if mknod-into-live-upper proves unreliable under a real overlay test.
- **Overturning `test_overlay_signature_write_oserror_keeps_live_overlay`.** Explicitly
  *extended*, not changed; keep-live and no-hard-fail assertions remain.
- **Signature churn on `_reconcile_fallback_edits_into_upper`.** New required `host_claude`
  kwarg updates ~30 direct-call tests in part_003; mechanical but reviewed for correctness.
- **mtime+size equality as the host-vs-legacy/base signal.** Relies on `copy2`-preserved
  mtimes (already the module's contract). Coincidental-equality false-negatives only ever
  *keep* a credential/upper edit (safe). Documented as a deliberate, conservative limit;
  content compare considered but rejected to honor the stat-only ethos for large trees
  (per-file small-set content compare may be added if a test demands it).
- **New reason code drift gate.** If added, regenerate `docs/REASON_CATALOG.md` before push.

## Assumptions

- CAP_MKNOD is capability bit 27; `/proc/self/status` `CapEff` parsing mirrors
  `_has_cap_sys_admin` exactly.
- The production worker holds CAP_MKNOD (it already holds CAP_SYS_ADMIN); the capability
  fallback exists for capability-less contexts and hardened hosts.
- #405's mount-gone+no-pin path may already re-pin correctly after a successful remount;
  a failing-first test determines whether the code delta is test-only plus a guard, or a
  behavioral change. Either way: keep-live preserved, no hard-fail introduced.
- Whiteouts belong in `upper`; there is no `merged`-routed equivalent.

- No fail-over / unmount-on-pin-write-failure (the reviewer's #405 suggestion is
  deliberately declined; keep-live wins).
- No content-hash-based signature/reconciliation (stat-only design preserved).
- No changes to `bootstrap.py`, `cleanup.py`, `pre_push_validation.py` (parallel tasks).
- No change to the shared-base build/reap, teardown, or GC paths beyond what the three
  issues strictly require.
- No new abstractions beyond the two small helpers (`_safe_overlay_whiteout`,
  `_has_cap_mknod`); reuse existing patterns.
