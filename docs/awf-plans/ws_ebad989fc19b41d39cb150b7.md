## 1. Summary

Expose `ProviderRecoveryDecision` state and related observability through existing API surfaces so console operators can see reason codes, cooldown windows, fallback targets, circuit breaker state, and recommended actions. Add structured event payloads for provider recovery lifecycle events. Ensure merge queue and metrics surfaces reflect recovery state as a first-class concept, not generic failure noise. Add contract-style unit tests for schema compatibility and reason-code stability.

## 4. Detailed Design

### 4.1 `ProviderRecoveryStateResponse` (new schema in `schemas.py`)

```python
class ProviderRecoveryStateResponse(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    action: Literal["retry", "fallback", "terminal"] | None = None
    reason_code: str | None = None
    source_provider: str | None = None
    source_model: str | None = None
    retry_attempt_number: int | None = None
    fallback_attempt_number: int | None = None
    cooldown_until: datetime | None = None
    next_eligible_at: datetime | None = None
    fallback_target: FallbackTargetResponse | None = None
    source_workspace_id: str | None = None
    source_attempt_id: str | None = None
    recommended_action: str | None = None
    terminal: bool | None = None


class FallbackTargetResponse(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    agent: str
    provider: str | None = None
    model: str
```

`action` is nullable so workspaces not in a recovery flow get `None`. All fields are optional for console schema tolerance (requirement 4).

### 4.2 Extensions to `WorkspaceFailureDetailsResponse`

Add `provider_recovery_state: ProviderRecoveryStateResponse | None = None` alongside the existing unstructured `provider_recovery: dict[str, Any] | None = None`. The structured field gives console consumers a typed contract; the existing dict field remains for backward compatibility.

### 4.3 Extensions to `WorkspaceResponse` and `MergeQueueItemResponse`

Add `provider_recovery_state: ProviderRecoveryStateResponse | None = None` to both schemas, defaulting to `None`. The workspace service and merge queue service will populate this by calling `provider_recovery_state_for_workspace()`.

### 4.4 Reason-code constant registry in `provider_recovery.py`

Export an explicit frozenset `PROVIDER_RECOVERY_REASON_CODES` containing all stable reason code strings:

```python
PROVIDER_RECOVERY_REASON_CODES: frozenset[str] = frozenset({
    "PROVIDER_MODEL_CIRCUIT_OPEN",
    "PROVIDER_RETRY_DELAYED",
    "PROVIDER_FALLBACK_SELECTED",
    "REPEATED_PROVIDER_FAILURE_FINGERPRINT",
    "NON_RETRYABLE_PROVIDER_FAILURE",
    "PROVIDER_RECOVERY_ATTEMPTS_EXHAUSTED",

```

This enables the stability test (test 4) and documents the contract.

### 4.6 Event payload structure

Provider recovery events already emit structured payloads (see `provider_recovery.py` lines 318-336). The plan establishes that **event payloads must include** the following keys in every `workspace.provider_recovery_*` event:

| Event type | Required keys |
|---|
| `workspace.provider_recovery_requested` | `source_workspace_id`, `new_workspace_id` (if applicable), `provider_recovery.action`, `provider_recovery.decision_reason_code`, `provider_recovery.target_agent`, `provider_recovery.target_provider`, `provider_recovery.target_model`, `provider_recovery.fallback_attempt_number`, `provider_recovery.retry_attempt_number` |
| `workspace.provider_recovery_cooldown` | `source_workspace_id`, `provider_recovery.action`, `provider_recovery.decision_reason_code`, `provider_recovery.not_before` |
| `workspace.provider_recovery_terminal` | `provider_recovery.action` (always "terminal"), `provider_recovery.terminal_reason` |
| `workspace.provider_recovery_created` | `source_workspace_id`, `new_workspace_id`, `provider_recovery.action`, `provider_recovery.decision_reason_code` |

These are **already present** in the existing `_decision_payload()` output. This plan adds a **contract test** (test 11) that validates the event payload shape against these requirements, so future refactors can't silently drop fields.

### 4.7 Merge queue enrichment

`_item_from_candidate()` in `merge_queue.py` will call `provider_recovery_state_for_workspace(workspace)` to populate the `provider_recovery_state` field on `MergeQueueItemResponse`. For workspaces in a provider recovery state, the recovery reason appears as a structured field rather than buried in the generic `merge_blocker_reason`.

No change to merge eligibility logic — only the **projection**.

### 4.8 Metrics enrichment

Add `ProviderRecoveryStateSummary` to `metrics.py`:

```python
@dataclass(frozen=True)
class ProviderRecoveryStateSummary:
    in_cooldown: int
    pending_retry: int
    pending_fallback: int
    terminal_no_loop: int
    terminal_exhausted: int
    circuit_breakers_open: int
```

Populated by querying `ProviderModelCircuitBreakerRepository.list_open()` for circuit breaker counts and scanning in-flight workspaces with `provider_recovery_state` in their task_policy for recovery-state counts.

Add `provider_recovery_state_summary` to `ResourceSaturationSummary`.

In `FailureAnalysisSummary`, enrich `FailedWorkspaceExample` and `RootCauseCluster` with a structured `provider_recovery` sub-field (using `ProviderRecoveryStateView` or `None`).

### 4.9 Workspace observability enrichment

In `workspace_observability.py`, `WorkspaceRecoverySummary` and `WorkspaceRecoveryPayload` will include:

```python
provider_recovery: ProviderRecoveryStateView | None = None
```

The `workspace_recovery_summary()` function will detect provider-recovery events and populate this structured field. If the workspace is in a provider recovery cooldown phase, the `reason_code` and `action` will reflect the recovery reason (e.g., `PROVIDER_RETRY_DELAYED`) rather than the generic workspace failure reason.

## 6. Risks, Assumptions, and Non-Goals

### Risks

1. **Overlap with ws_3434c0301e7744d6aefbd315 and ws_2a6d2ef4186d4c48960411ec** on `src/awf/service/provider_recovery.py`. This plan adds extraction/view functions, not modifications to the decision logic. Coordinate to merge additive changes; our functions are pure projections and shouldn't conflict with behavioral changes the other workspaces make.

2. **Overlap with ws_52d8415a02424c4aa4730fa1** on `src/awf/service/metrics.py`. This plan adds `ProviderRecoveryStateSummary` and extends `ResourceSaturationSummary`, which may conflict. Coordinate so that additive dataclasses are merged first, then both workspaces extend them.

3. **Overlap on `docs/awf-plans/**`** is advisory; both this and the listed workspaces may create plan files concurrently. No code conflict.

4. **Schema backward compatibility** — Adding `provider_recovery_state` as an `Optional` field with `None` default to existing schemas preserves backward compatibility. The unstructured `provider_recovery` dict field in `WorkspaceFailureDetailsResponse` remains.

### Assumptions

1. The `provider_recovery_state` dict in `task_policy` is the authoritative source for current recovery state. We read it; we don't write it in this slice.

2. `ProviderModelCircuitBreakerRepository.list_open()` is available and returns current open circuit breakers.

3. The event types `workspace.provider_recovery_requested`, `workspace.provider_recovery_cooldown`, `workspace.provider_recovery_terminal`, and `workspace.provider_recovery_created` are already emitted and their payload structure is stable.

4. Pydantic v2 model validation with `from_attributes=True` works with the new `ProviderRecoveryStateView` dataclass.

### Explicit Non-Goals

1. **No changes to core retry/fallback execution logic** — `decide_provider_recovery()`, `create_provider_recovery_attempt_row()`, `_retry_delay_seconds()`, `_select_fallback_target()`, `_record_provider_circuit_breaker()` are owned by other workspaces. We only add **read-side projection functions**.

2. **No new DB migration or model** — All new API fields are computed from existing `task_policy` JSON and event payloads.

3. **No PR monitor behavioral changes** — This plan does not touch `pr_monitor.py` or `pr_monitor_runner.py`.

4. **No worker dispatch changes** — `worker.py` cooldown logic is out of scope.

5. **No console UI changes** — This is backend-only; the console app will consume the new API fields.

6. **No deletion of the unstructured `provider_recovery` dict field** in `WorkspaceFailureDetailsResponse` — it remains for backward compatibility; the new `provider_recovery_state` field is additive.
