# Plan: P1 Operator Console — Estimated Cost with Reliable Pricing Metadata

## Objective

Implement an explicit pricing metadata contract so that cost estimates are
never fabricated from unknown pricing. Cost is shown only when **both** token
usage data and trusted pricing metadata exist. When pricing is missing, stale,
or unknown, the API and console clearly explain that pricing is unavailable.

This is a **pricing-metadata slice only** — it does not build token plumbing,
live billing calls, or hard-coded provider pricing tables.

## Implementation Steps

1. **Define `PricingMetadata` model** in `src/awf/profiles/pricing.py`.
   - Fields: `provider: str`, `model: str`, `currency: str`, `unit: str`,
     `timestamp: datetime`, `version: int | None = None`.
   - Validation: all string fields required and non-empty; timestamp must be
     UTC-aware.
   - Helper `is_current(now: datetime | None = None, max_age_days: int = 90)`
     returns `bool`.
   - Constant `PRICING_MAX_AGE_DAYS = 90` as a configurable module-level
     default.

2. **Add `ProfilePricing` model** and wire into `WorkspaceProfile` in
   `src/awf/profiles/models.py`.
   - New class: `class ProfilePricing(BaseModel)` with one field:
     `pricing: PricingMetadata`. Uses `ConfigDict(extra="forbid")`.
   - Add to `WorkspaceProfile`: `pricing: ProfilePricing | None = None`.
   - Profile loading (`resolver.py`) reads the `pricing` key from the YAML
     dict and passes it through.

3. **Add `PricingMetadata` to service layer** in
   `src/awf/service/workspace_observability.py`.
   - `workspace_pricing_metadata(workspace: Workspace) -> PricingMetadata | None`
     reads from `workspace.resolved_profile` (the `WorkspaceProfile` object).
   - `compute_cost_estimate(usage: LlmUsageSummary, pricing: PricingMetadata | None, now: datetime | None = None) -> tuple[float | None, str | None]`
     pure function. Returns cost only when: (a) usage has at least one
     non-`None` token count, (b) pricing is not `None`, (c)
     `pricing.is_current()` is `True`. Returns `(None, reason)` otherwise.
   - Update `workspace_usage_summary()` to accept `pricing` parameter and
     compute `cost_estimate` via `compute_cost_estimate()`.
   - Update `usage_payload()` to include `pricing` dict in the returned
     payload.

4. **Add API schemas** in `src/awf/api/schemas.py`.
   - Add `WorkspacePricingMetadataResponse` Pydantic model matching
     `PricingMetadata`.
   - **Do NOT modify** the existing `LlmUsageSummaryResponse` structure (to
     preserve backward compatibility with the token-usage workspace). Instead,
     add a new top-level field `pricing` to `WorkspaceResponse`,
     `WorkspaceOverviewResponse`, and `TaskResponse` that carries pricing
     metadata. The `cost_estimate` field on `LlmUsageSummaryResponse` remains
     nullable and is only populated when the service layer can compute it.
   - The `pricing` field is `WorkspacePricingMetadataResponse | None`.

5. **Wire pricing into workspace API routes.**
   - In `src/awf/api/routes/workspaces.py`, call
     `workspace_pricing_metadata(ws)` and include result in response body
     alongside existing fields.
   - In `src/awf/api/routes/tasks.py`, same for task rows.
   - In `src/awf/api/routes/ws.py` (WebSocket snapshots), include pricing
     metadata if available (optional — may skip if snapshot cost exceeds).

6. **Update console types and display.**
   - Add `PricingMetadata` TypeScript interface in `apps/console/lib/types.ts`.
   - Add optional `pricing: PricingMetadata | null` to `LlmUsageSummary`.
   - In `apps/console/lib/format.ts`, update `fallbackLlmUsage()` to preserve
     `pricing`; add `formatCostWithAvailability()` that returns a value with
     availability context.
   - In `apps/console/components/console-dashboard.tsx`, modify
     `UsageSummaryBlock` to:
     - Show a pricing badge when `pricing` is not null.
     - Show cost only when `cost_estimate` is not null and `pricing` is not
       `null`.
     - Show explanatory text ("pricing not configured", "pricing stale") when
       pricing is missing or stale.

## Risks

- **Profile contract change**: Adding a `pricing` field to `WorkspaceProfile`
  with `extra="forbid"` means ALL existing profiles continue to work (field is
  optional). Risk is low.
- **Staleness threshold**: 90 days is a reasonable default but may need tuning.
  Parameterized via constant — easy to adjust.
- **Token-usage workspace overlap**: This plan adds pricing *alongside* the
  existing `LlmUsageSummaryResponse` structure without modifying its existing
  fields. The cost estimate field remains nullable. A separate token-usage
  workspace that populates `input_tokens`/`output_tokens`/`total_tokens` is
  fully compatible — this plan only adds the pricing condition that gates cost
  computation.
- **No console JS test harness**: Console validation is limited to `lint`,
  `typecheck`, and `build` — documented in existing plan format.

## Assumptions

- `Workspace.resolved_profile` (a `WorkspaceProfile` object) is available at
  API-serving time and carries the parsed YAML.
- Profile resolver already handles YAML loading and can ingest a `pricing`
  key without breaking.
- The `LlmUsageSummary` dataclass shape (input/output/total tokens) is the
  stable token contract from the prior observability work.
- Cost computation formula: given pricing `per_1k_tokens`, compute
  `(input_tokens * input_price + output_tokens * output_price)` — however, this
  plan keeps pricing metadata as a *single* model-level unit (not split per
  direction) because the PRD does not demand split pricing. The cost estimate
  is simply a placeholder: the exact formula is deferred to when token usage is
  populated. For now, the cost helper computes `(input_tokens + output_tokens)
  / 1000 * <unit_price_from_pricing_when_added>` or returns `None` with a
  reason.

## Explicit Non-goals

- Do not add token usage data (tokens come from a separate workspace).
- Do not add database migrations for pricing — config-only.
- Do not call external pricing APIs or billing endpoints.
- Do not hard-code provider pricing tables in source code.
- Do not change workspace lifecycle, PR monitor, merge policy, or branch
  management.
- Do not add a new JS test harness; rely on existing `lint`/`typecheck`/`build`.
