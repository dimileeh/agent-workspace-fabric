## Problem And Scope

T14 needs an end-to-end smoke harness that proves the first-run installation lanes work without requiring a published release by default, while still allowing release-artifact lanes to be enabled explicitly when artifacts exist.

The harness should cover four lanes:

1. Release installer fixture/dry-run: use local fixture or local release artifacts with `packaging/install.sh --dry-run` so checksum and manifest handling are exercised without mutating installs.
2. Tool install lane: exercise `uv tool install` or `pipx install` in an isolated temporary tool home/bin directory, never the operator's global tool directories.
3. Source checkout global tool install: from a temp copied checkout, run `uv tool install . --force` into isolated tool directories, then run AWF commands from outside the checkout.
4. Source checkout no-global lane: from a temp copied checkout, run `uv run --python 3.12 --extra dev awf ...` from outside normal developer-shell assumptions and prove `setup --source-checkout` plus setup/start/help command surfaces work.

The implementation should build on the existing T12/T13 assets already present:

- `packaging/install.sh` has fixture seams via `AWF_INSTALL_MANIFEST`, `--dry-run`, and `--method uv|pipx`.
- `scripts/release_smoke.py` already rewrites release manifests to local `file://` artifact URLs and verifies checksum-before-install.
- `tests/unit/cli/test_clean_install_smoke.py` already has wheel/help smoke coverage; T14 should add the lane harness rather than replace that guard.

## Tests To Write First

1. Unit test: fixture installer lane is local and non-mutating.
   - Build a temp fake wheel and manifest with `file://` URLs.
   - Run or construct the installer dry-run path for `--method uv` and `--method pipx`.
   - Assert `--dry-run`, manifest env, method, manifest-derived channel, and checksum verification expectations.
   - Assert the lane does not call a real package install command.

2. Unit test: release-gated lane is disabled unless artifacts are explicit.
   - Without the release gate/env and artifact paths, the harness should skip/report the release lane as disabled, not hit GitHub/PyPI/network.
   - With explicit `--release-dist-dir` and `--release-manifest`, assert it delegates through the release smoke path and still uses local artifact URLs.

3. Unit test: tool-install environments are isolated.
   - For `uv`, assert `UV_TOOL_DIR`, `UV_TOOL_BIN_DIR`, temp `HOME`, and PATH are pinned under the temp smoke root.
   - For `pipx`, assert `PIPX_HOME`, `PIPX_BIN_DIR`, temp `HOME`, and PATH are pinned under the temp smoke root.
   - Assert the harness never uses the user's home tool directories by default.

4. Unit test: source checkout copy preserves required markers and excludes heavy/dev state.
   - Copy from the repo root to a temp checkout.
   - Assert source-checkout markers such as `pyproject.toml`, `src/awf/__init__.py`, `docker/control-plane.Dockerfile`, and `docker/compose/local-service.yml` exist.
   - Assert `.git`, `.venv`, caches, and build output directories are not copied.

5. Integration test: source no-global lane from outside the checkout.
   - Create a temp copied checkout.
   - Run `uv run --python 3.12 --extra dev awf --help`, `awf setup --help`, and `awf start --help` from a cwd outside both the source copy and the original checkout.
   - Run `uv run --python 3.12 --extra dev awf setup --dry-run --source-checkout <temp-checkout> --format json` with a temp `HOME` and scrubbed `PYTHONPATH`.
   - Treat ordinary host-readiness blockers, such as missing Docker, as acceptable for the smoke, but fail if the output reports `SOURCE_CHECKOUT_INVALID`, cannot parse JSON, or does not identify the selected source checkout.

6. Integration test: source global `uv tool install . --force` lane.
   - Install from the temp copied checkout into isolated `UV_TOOL_DIR`/`UV_TOOL_BIN_DIR`.
   - Run the installed `awf` binary from outside the checkout and exercise root/setup/start help plus the same source-checkout dry-run proof.
   - Skip only for environmental setup gaps (`uv` unavailable or dependency resolution unavailable offline). Fail non-environmental install, entry-point, or source-checkout regressions.

7. Optional integration test: package tool install lane using a local built wheel.
   - If the existing packaging helper can build a local wheel, install it into isolated uv/pipx tool dirs and run help surfaces from outside the checkout.
   - Skip environmental dependency fetch failures using the existing packaging skip patterns; fail malformed wheel/entry-point regressions.

## Risks And Mitigations

- Tool install lanes can require dependency resolution. Mitigate by keeping default fixture/source lanes runnable without a published release, isolating tool directories, and skipping only clearly environmental offline/unavailable cases while failing non-environmental package or entry-point regressions.
- `awf setup --dry-run` can return blocked on machines without Docker or with occupied ports. The source-lane smoke should validate source-checkout correctness independently of host-readiness status and fail only on source-checkout/CLI regressions.
- Copying the source checkout can be slow or accidentally include large dev state. Mitigate with a deterministic ignore list for `.git`, virtualenvs, caches, dist/build output, node modules, and pytest artifacts while preserving AWF source markers.
- Release lanes could accidentally hit network or mutable latest artifacts. Mitigate with explicit release gating and required artifact paths; default local runs use fixture/local `file://` artifacts only.
- Docs paths have an advisory overlap with another workspace. Avoid broad docs edits; if a minimal docs smoke reference is necessary, keep it to `docs/SMOKE_COMMAND.md` and record the reason.
- The harness may expose earlier T05/T10/T12/T13 bugs. Keep fixes minimal and regression-tested; if the bug belongs in a dependency slice but blocks T14 acceptance, document the narrow fix in the validation artifact.
