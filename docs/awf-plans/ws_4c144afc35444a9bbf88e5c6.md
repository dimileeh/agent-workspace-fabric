## 1. Problem statement and scope

T01 registered `awf setup` as a real Typer command (`app.command("setup")(setup_command)`
in `src/awf/cli/main.py`, body in `src/awf/cli/setup_commands.py`) that currently emits a
reserved **placeholder** payload (`AWF_SETUP_PLACEHOLDER`, exit 1). T04 replaces that
placeholder with the first real capability of the one-time machine setup wizard: a
**read-only host system-readiness pass** that verifies the machine can run AWF Core
**without starting Core and without writing any secret**.

In scope for T04:

- Replace the `setup_command` placeholder with the real option surface and dispatch:
  `--provider PROVIDER` (repeatable), `--dry-run/--no-dry-run`, `--non-interactive`,
  `--allow-plain-secrets`, `--source-checkout PATH`, `--format json|pretty`.
- Add focused, bounded, **dependency-light** host system checks in a new
  `src/awf/host_setup/system_checks.py`: Docker (CLI + daemon), Compose, Git, `gh`,
  Python/runtime, ports, disk, shell/PATH, and local capacity — all read-only,
  **no Core start**.
- Aggregate the checks into a first-run readiness payload and render it through the T03
  rendering layer (status, blockers, warnings, docs links, next command), in both
  `json` and `pretty`.
- Write only **safe, non-secret** config updates when **not** in dry-run mode (reuse the
  T02 `HostSetupConfig` + `write_host_setup_config`); never write in dry-run.
- Validate and **forward** (not consume) the `--provider` selector and
  `--allow-plain-secrets` consent so T06 (credential backends) and T07 (provider
  orchestration) can act on them later.

Out of scope (owned by later tasks — do not implement here): credential storage backends
(**T06**), provider auth/network probing + orchestration (**T07**), Claude/Codex client
config writers (**T08**), `awf start` bootstrap (**T05**), MCP setup tools (**T09**),
packaging/installer/docs/release (**T11–T18**).

## 5. Design — `src/awf/host_setup/system_checks.py`

### 5.1 Types

```python
class SetupCheckLevel(str, Enum):
    OK = "ok"; WARNING = "warning"; BLOCKED = "blocked"

@dataclass(frozen=True)
class SetupCheckResult:
    name: str                 # "docker", "compose", "git", "gh", "python", "ports", ...
    level: SetupCheckLevel
    summary: str
    detail: str
    fix: str | None = None
    docs_link: str | None = None
    data: Mapping[str, Any] = field(default_factory=dict)   # non-secret facts only

class SetupCheckError(RuntimeError):
    """Hard, reason-coded setup failure (usage/validation/short-circuit)."""
    def __init__(self, message: str, *, reason_code: str,
                 details: Mapping[str, Any] | None = None): ...
```

`SetupCheckError` is raised for `SETUP_PROVIDER_UNKNOWN` and `INTERACTIVE_INPUT_REQUIRED`.
Individual checks **return** a `SetupCheckResult` — a missing tool is a result, never an
exception.

Severity/reason mapping (reuse T03 codes; do **not** invent new reason codes or touch
`doctor/reasons.py`/`REASON_CATALOG.md`):

- Any `BLOCKED` check → contributes a `FirstRunIssue(severity="blocked",
  reason_code=SETUP_READINESS_FAILED, problem/cause/fix/docs from the check)`.
- Any `WARNING` check → `FirstRunIssue(severity="warning",
  reason_code=SETUP_READINESS_FAILED, …)`.
- Source-checkout invalid → `FirstRunIssue(severity="blocked",
  reason_code=SOURCE_CHECKOUT_INVALID, details={missing_markers})`.
- Unknown provider → raise `SetupCheckError(SETUP_PROVIDER_UNKNOWN)`.
- Interactive-required → raise `SetupCheckError(INTERACTIVE_INPUT_REQUIRED)`.

### 5.2 Checks (each bounded, read-only, never starts Core)

Every subprocess probe uses a hard `timeout=` and catches `FileNotFoundError` /
`subprocess.TimeoutExpired` / `OSError` specifically (never bare `except Exception`, never
a hidden retry — AGENTS.md).

- `check_docker()` — `shutil.which("docker")` missing → BLOCKED (install fix); else
  `docker info`/`docker version` (short timeout) non-zero/timeout → BLOCKED (start-daemon
  fix). Distinct detail/fix per sub-case. Never runs containers.
- `check_compose()` — `docker compose version`, fall back to `docker-compose version`;
  neither → BLOCKED.
- `check_git()` — `shutil.which("git")` + `git --version`; missing → BLOCKED.
- `check_gh()` — `shutil.which("gh")`; missing → **WARNING** (PR flow needs it eventually;
  T04 does not block, and does not run `gh auth status` — provider auth is T07).
- `check_python_runtime()` — compare `sys.version_info` to the 3.12 floor; below → BLOCKED.
- `check_ports(port)` — bind a `socket` to `127.0.0.1:<api_host_port>` (default from
  `HostSetupConfig.api.host_port`); in use (`OSError`) → WARNING with the port in `data`
  (reconfigurable at start, hence warning).
- `check_disk(path)` — `shutil.disk_usage(path)` on the work dir / home; below a few-GB
  threshold → WARNING with free bytes in `data`.
- `check_shell_path()` — is the dir of the running `awf` / `sys.executable` scripts on
  `$PATH`? detect shell from `$SHELL`; not reachable → WARNING with a zsh/bash/fish fix.
  Read-only; never edits rc files.
- `check_local_capacity()` — **host-local** estimate from `os.cpu_count()` and best-effort
  memory/disk; clearly inadequate (e.g. <2 usable CPUs / under a memory floor) →
  WARNING/BLOCKED. Must **not** touch the DB, API, or any control-plane capacity service.

### 5.3 Aggregation / provider validation / interactive guard

- `KNOWN_SETUP_PROVIDERS: frozenset[str]` + `normalize_provider(name) -> str` (alias
  handling, e.g. `codex`↔`openai`, `claude`↔`anthropic`, `opencode`↔`ollama`, plus
  `github`, `gemini`, `awf-cloud`); unknown → `SetupCheckError(SETUP_PROVIDER_UNKNOWN)`.
  Provider names overlap the existing `validate_provider_names` vocabulary where possible.
- `run_system_checks(*, config, port=None, work_dir=None) -> list[SetupCheckResult]` —
  runs every check in a stable order.
- `build_setup_readiness_payload(results, *, selected_providers, allow_plain_secrets,
  dry_run, source_checkout_invalid=None) -> FirstRunPayload` — maps results to
  `FirstRunIssue`s (via `first_run_issue_from_reason_code`), assembles non-secret
  `details` (`selected_providers`, `allow_plain_secrets`, `dry_run`, resolved
  `source_checkout` root, per-check `data`), always includes a `next_steps` "next command"
  (fix-blockers guidance when blocked, else `awf start`), and calls the new
  `first_run_report_payload(...)` to derive `status`/`reason_code`.
- `require_interactive(non_interactive: bool, what: str) -> None` — raises
  `SetupCheckError(INTERACTIVE_INPUT_REQUIRED)` when `non_interactive` and an interactive
  prompt for `what` would be required.

## 6. Design — `src/awf/cli/setup_commands.py` (CLI dispatch)

Replace the placeholder body. Options on `setup_command`:

- `provider: list[str] = typer.Option([], "--provider", help=…)` (repeatable).
- `dry_run: bool = typer.Option(False, "--dry-run/--no-dry-run", help=…)`.
- `non_interactive: bool = typer.Option(False, "--non-interactive", help=…)`.
- `allow_plain_secrets: bool = typer.Option(False, "--allow-plain-secrets", help=…)`.
- `source_checkout: Path | None = typer.Option(None, "--source-checkout", help=…)`.
- `fmt: OutputFormat = typer.Option(OutputFormat.pretty, "--format", help=…)`.

Flow:

1. Normalize/validate `--provider` (`normalize_provider`) → unknown raises
   `SetupCheckError(SETUP_PROVIDER_UNKNOWN)`.
2. `read_host_setup_config()` for defaults (api host port, work dir).
3. If `--source-checkout` given: `validate_source_checkout(path)`; on
   `SourceCheckoutError` record a `SOURCE_CHECKOUT_INVALID` blocker.
4. `run_system_checks(...)` → `build_setup_readiness_payload(...)`.
5. **If not dry-run:** write only safe non-secret config via `write_host_setup_config`
   (verified `source_checkout` metadata, `api.host_port`, and
   `consent.plain_file_secrets=True` when `--allow-plain-secrets`). Never writes secrets.
   Under `--non-interactive`, any step needing an interactive prompt calls
   `require_interactive(...)` → `INTERACTIVE_INPUT_REQUIRED`.
6. **If dry-run:** skip step 5 entirely (no writes, no Core start).
7. Render: `fmt == json` → `_emit(render_first_run_json(payload), fmt)` (stdout);
   `pretty` → `typer.echo(render_first_run_pretty(payload), err=True)` (stderr). This
   matches the placeholder/test convention (pretty on stderr, json on stdout).
8. Exit codes:
   - `status in {success, warning}` → `0` (warnings are advisory, like A7's "warnings").
   - `status in {blocked, failed}` → `typer.Exit(code=1)`.
   - `SetupCheckError` for `SETUP_PROVIDER_UNKNOWN` / `INTERACTIVE_INPUT_REQUIRED` →
     render the reason-coded diagnostic, then `typer.Exit(code=2)` (usage/input error,
     consistent with `awf init` migration errors).

All output flows through the T03 renderer, whose redaction guarantees no token-shaped or
provider-ref value leaks in either format.

- **mypy strictness** — `system_checks` is fully typed; frozen dataclasses + explicit
