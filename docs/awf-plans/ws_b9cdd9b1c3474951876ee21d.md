# Plan: Harden Postgres/asyncpg connection resilience

## Goal

Make long-running local AWF API and worker processes tolerate stale or closed
asyncpg connections without converting transient database disconnects into
workspace terminal failures or lost active-execution ownership. Keep the public
API shape stable except for narrow diagnostic reason/detail additions on existing
health/status payloads.

## Current Implementation Notes

- `src/awf/db/session.py` is the central async engine/session factory. It
  already enforces `postgresql+asyncpg://`, strips AWF-only query params, supports
  test search paths/null pools, and has connect retry only for initial asyncpg
  connects.
- `ControlWorker.run_once()` in `src/awf/control/worker.py` opens fresh sessions
  for scheduler reads, stale-active scans, claim refresh/release, and queue
  decision writes. The heartbeat loops currently stop after any DB exception,
  which can let an active execution claim expire after a one-off closed
  connection.
- Workspace list/detail API paths in `src/awf/api/routes/workspaces.py` use one
  request session from `awf.api.deps.get_db_session`, so a closed connection in a
  read cannot be replayed today.
- `/readyz` in `src/awf/api/routes/health.py` and `awf.service.status` already
  surface DB failures as structured diagnostics; they should classify closed
  asyncpg connections more specifically while preserving the existing response
  envelope.

## Intended Files / Modules To Touch

- `src/awf/db/session.py`
  - Configure async SQLAlchemy engines with asyncpg/Postgres liveness defaults:
    `pool_pre_ping=True`, bounded `pool_recycle`, and bounded `pool_timeout`.
  - Preserve existing `awf_search_path`, `awf_null_pool`, and connect retry query
    behavior.
- `src/awf/db/resilience.py` (new, if a small helper module is cleaner than
  growing `session.py`)
  - Add closed-connection classification for SQLAlchemy/asyncpg exceptions.
  - Add bounded retry helpers for idempotent DB read operations and claim
    heartbeat updates.
  - Add session rollback/invalidation helper that never hides the original
    exception.
- `src/awf/api/deps.py`
  - Harden rollback/close after transient disconnects so cleanup failures do not
    replace the request error.
  - Expose/use session-factory based read retry where needed.
- `src/awf/api/routes/workspaces.py`
  - Move `list_workspaces` and `get_workspace` reads through bounded retry using
    fresh sessions per attempt.
  - Keep response schemas unchanged.
- `src/awf/api/routes/health.py`
  - Classify closed asyncpg connections with a stable diagnostic reason such as
    `DB_CONNECTION_CLOSED` while retaining `DB_CONNECTION_FAILED` for generic DB
    failures if existing tests require it.
- `src/awf/service/status.py`
  - Mirror the same DB diagnostic classification used by `/readyz`.
- `src/awf/mcp/server.py`
  - Only update if tests show the MCP readiness mirror does not inherit the
    health-route helper changes cleanly.
- `src/awf/control/worker.py`
  - Retry transient closed-connection failures around scheduler read paths,
    stale-active scan reads, and execution/monitor claim heartbeat refreshes.
  - Ensure transient DB failures in stale-active scan bookkeeping abort that scan
    with a diagnostic log/event when possible, not workspace cleanup/failure.
  - Keep non-idempotent writes conservative: retry only when the transaction is
    known invalidated before commit; otherwise log/diagnose and let the next poll
    reconcile.
- Tests listed below. No migrations are expected.

## Tests To Write First

Use existing PostgreSQL-backed fixtures from `tests/postgres.py`; do not add
SQLite or fake persistence. Simulated failures can be injected by raising
SQLAlchemy/asyncpg-shaped closed-connection exceptions from a PostgreSQL-backed
session path, and at least one engine-level test should terminate a real backend
connection.

1. `tests/unit/db/test_session_scope.py` or new
   `tests/unit/db/test_connection_resilience.py`
   - `test_make_engine_configures_asyncpg_liveness_pool_options`: monkeypatch
     `create_async_engine`, call `make_engine()`, and assert `pool_pre_ping`,
     recycle, timeout, and existing connect args/query stripping are preserved.
   - `test_closed_pooled_postgres_connection_is_replaced_on_next_checkout`:
     create a real pooled engine from `postgres_empty_test_url()`, warm the pool,
     terminate the checked-in backend with `pg_terminate_backend`, then assert a
     fresh `SELECT 1` succeeds.
   - `test_closed_connection_classifier_matches_asyncpg_interface_error_names`:
     assert helper classification covers `sqlalchemy.exc.InterfaceError`,
     `DBAPIError(connection_invalidated=True)`, asyncpg-style orig class names,
     and the known message text `connection is closed`.

2. `tests/unit/control/test_worker.py`
   - `test_run_once_retries_scheduler_read_after_closed_connection`: with real
     PostgreSQL data, inject one transient closed-connection failure in the first
     scheduler list/read, assert the same `run_once()` retries and dispatches or
     claims the eligible workspace, and assert the worker keeps polling.
   - `test_execution_claim_refresh_retries_closed_connection_without_losing_owner`:
     seed a ready/running workspace owned by the worker, inject one closed
     connection into `_refresh_execution_claim`, and assert the retry preserves
     `execution_claimed_by` and extends `execution_claim_expires_at`.
   - `test_stale_active_scan_closed_connection_does_not_terminal_fail_workspace`:
     seed an active workspace that would otherwise be inspected by the
     stale-active scan, inject a transient closed DB failure in the scan read or
     post-inspection bookkeeping, run the scan/run_once, and assert the workspace
     remains active with its execution ownership intact. If a subsequent session
     is available, assert a diagnostic workspace event/log reason such as
     `DB_CONNECTION_CLOSED` or `DB_CONNECTION_TRANSIENT_RECOVERED` is recorded.

3. `tests/unit/api/test_workspaces.py`
   - `test_list_workspaces_retries_once_after_closed_connection`: seed a real
     workspace, inject one closed-connection failure into the list read path, and
     assert `GET /v1/workspaces` returns 200 with the workspace instead of 500.
   - `test_get_workspace_retries_once_after_closed_connection`: same pattern for
     `GET /v1/workspaces/{workspace_id}`, including validation provenance loads.
   - Assert no new response fields are required for the workspace payloads.

4. `tests/unit/api/test_health.py`
   - Add a closed-connection diagnostic case for `_check_db`/`/readyz`, asserting
     the response remains structured, returns 503 for an unhealthy DB probe, and
     carries the specific closed-connection reason/detail without crashing
     orphan-resource classification.

5. `tests/unit/service/test_status.py`
   - Add the same closed-connection diagnostic coverage for
     `awf.service.status.check_database` / `collect_service_status`.

6. Optional only if coverage or implementation shape requires it:
   - `tests/unit/mcp/test_mcp_operator_surfaces.py` for MCP readiness if the MCP
     copy does not reuse the route/status helpers.
   - A focused staleness service test only if `StalenessRefreshService` needs the
     generic read-retry helper directly; the required stale-active scan coverage
     should live in worker tests.

Expected pre-implementation failures: engine option assertions fail, real stale
pooled connection reuse fails or raises an asyncpg/SQLAlchemy disconnect error,
worker/API retry tests return/log an exception instead of recovering, and
heartbeat ownership can be lost after a single transient DB exception.

## Implementation Steps

1. Add the failing tests above, starting with DB helper/engine tests, then worker
   and API regression tests.
2. Add central DB resilience helpers:
   - `is_transient_closed_connection_error(exc)` for SQLAlchemy `InterfaceError`,
     invalidated `DBAPIError`, asyncpg connection exception class names, and the
     known closed-connection message text.
   - `invalidate_or_rollback_session(session, exc)` to invalidate closed sessions
     where possible and fall back to rollback/close safely.
   - `run_db_read_with_retry(factory, operation, attempts=2, ...)` for idempotent
     read paths using a fresh session per retry.
3. Update `make_engine()` with Postgres asyncpg liveness defaults. Keep overrides
   minimal and AWF-query-param compatible; do not change the required URL scheme.
4. Route API workspace list/detail through the retry helper using the session
   factory, not a single injected session. Keep create/update/control endpoints
   unchanged unless tests show dependency cleanup can mask closed-connection
   errors.
5. Harden worker DB paths:
   - Wrap scheduler reads (`_list_by_status`, provider-recovery suppression
     reads, `_filter_current_status`) in bounded retry.
   - Wrap stale-active candidate scans and workspace-scoped scan bookkeeping so a
     transient DB disconnect logs/records diagnostics and skips the current scan
     rather than failing or cleaning up a workspace.
   - Retry execution and monitor claim heartbeat refreshes on transient closed
     connections before declaring claim loss. Persistent DB outage may still lead
     to lease expiry, but one stale pooled connection must not.
   - Keep ambiguous post-commit failures out of automatic replay; let the next
     poll reconcile those rows.
6. Update readiness/status DB checks to use the classifier for closed-connection
   diagnostics. Prefer existing response fields (`reason`, `detail`) over schema
   expansion.
7. Re-run focused tests after each small implementation step, then the broader
   validation surface below.

## Risks And Assumptions

- Assumption: the production local control plane uses SQLAlchemy's asyncpg
  dialect with pooled connections; tests using `awf_null_pool=1` are for schema
  isolation and should not drive production pool behavior.
- Assumption: retrying read-only operations and claim heartbeat updates is safe;
  replaying writes after an ambiguous commit is not safe and should be avoided.
- Risk: SQLAlchemy wraps asyncpg closed-connection failures differently across
  versions. The classifier should prefer stable signals (`connection_invalidated`,
  SQLAlchemy `InterfaceError`, asyncpg class names) and use message matching only
  as a fallback.
- Risk: worker stale-active scans perform runtime inspection between DB reads.
  A DB disconnect after inspection must not be interpreted as permission to
  clean up or terminally fail a workspace.
- Risk: broad route-level retries can accidentally replay non-idempotent API
  actions. Scope retries to workspace list/detail reads for this slice.
- Risk: readiness helpers are duplicated between API, CLI status, and MCP
  surfaces. Reuse helpers where practical and test whichever mirror is touched.
- Risk: very long DB outages can still cause leases to expire because AWF cannot
  refresh ownership without a database. This slice guarantees resilience to
  stale/closed pooled connections and bounded transient disconnects, not
  indefinite DB unavailability.

## Explicit Non-Goals

- Do not modify terminal runtime cleanup policy.
- Do not redesign stale-active execution causality preservation beyond avoiding
  transient DB disconnects becoming workspace terminal failures.
- Do not add SQLite, in-memory persistence, or fake repository behavior.
- Do not change public workspace response contracts unless a narrow diagnostic
  addition is proven necessary.
- Do not add unbounded retries, retry loops that hide reason codes, or retries
  around ambiguous committed writes.
- Do not change AWF branch management, push/rebase behavior, PR monitor merge
  policy, or cleanup/retention policy. AWF will handle push and PR workflow
  after local implementation work is complete.
