# Plan — AWF #361 follow-up: run overlay teardown where the mount is visible

Workspace: `ws_dd44d20ee5094381a155d975`
Closes review findings: **#374, #375, #376, #380, #383, #388** (one PR).

## Problem (single root cause)

Per-workspace `~/.claude` overlay mounts are created by the **worker** container,
which alone holds `CAP_SYS_ADMIN` and binds the work dir `:rshared`
(`docker/compose/local-service.yml`). But `awf service gc` runs from the **CLI**
(host) or the **API** container via `POST /v1/service/gc` — neither has
`CAP_SYS_ADMIN` nor shares the worker's mount namespace. When GC reaps a
**terminal** (failed/cancelled/destroyed/superseded) workspace,
`teardown_workspace_auth_overlay` sees `os.path.ismount(merged) == False` (the
worker's mount is invisible in this namespace), returns a **silent no-op**, and
then `rmtree(auth/<id>)` either strands the still-live overlay mount + `upper`
inodes (worker ns) or fails `EBUSY`. The no-op is reported as success.

A second, related defect (#376/#388): the worker work-dir bind is hard-coded
`:rshared`. On hosts whose work dir is a **private** mount, Docker refuses to
start the worker; on **non-propagating** hosts (Docker Desktop / virtiofs /
grpcfuse) the `:rshared` flag is accepted but the worker's overlay never
propagates into the sibling agent container, so the agent gets an **empty
`~/.claude`** with no signal.

## Locked design (do NOT re-litigate)

1. **Worker-routed terminal teardown.** The SYS_ADMIN-capable worker unmounts a
   terminal workspace's overlay in its **terminal-runtime-release** sweep
   (after compose-down releases the agent container's bind), *before* GC removes
   the auth dir — i.e. in the namespace where the mount is visible.
2. **GC path fails loudly, never silently no-ops.** When the GC process cannot
   guarantee the unmount (lacks `CAP_SYS_ADMIN`, mount invisible) it must emit a
   reason code and surface a `partial` result instead of rmtree-ing into a leak
   and reporting success — consistent with the gc-as-root work merged in #372.
3. **Bootstrap rshared preflight.** `awf service bootstrap` ensures
   `${AWF_HOST_WORK_DIR}` is an `rshared` host mount, or detects a
   non-propagating host and gates the `:rshared` flag + forces the copy fallback
   so the worker neither fails to start nor silently provisions an empty
   `~/.claude`.

### Core behaviour
- `src/awf/node/auth_mounts.py` — **teardown path only** + mounter force-copy gate:
  - New reason-code/marker constants: `_CLAUDE_AUTH_OVERLAY_UNMOUNT_INCAPABLE`,
    `_OVERLAY_UNMOUNTED_MARKER = ".overlay-unmounted"`,
    `_CLAUDE_AUTH_FORCE_COPY_ENV = "AWF_CLAUDE_AUTH_FORCE_COPY"`.
  - New error type `OverlayUnmountUnverifiableError(RuntimeError)` carrying
    `reason_code`.
  - Rework `teardown_workspace_auth_overlay(...)`:
    - capability-aware (inject a `capability_probe: Callable[[], bool]` defaulting
      to `_has_cap_sys_admin`, so tests don't need real caps):
      - if `mounter.is_mounted(merged)` → `mounter.unmount(merged)` (raises loud
        on failure, unchanged), then write the `.overlay-unmounted` marker.
      - else (not visibly mounted in this namespace):
        - **capable** (worker / root+SYS_ADMIN): write the marker (records that a
          capable process verified teardown) and return.
        - **incapable** (CLI/API): if overlay scratch (`upper`) exists **and** no
          marker is present → raise `OverlayUnmountUnverifiableError`
          (`reason_code=_CLAUDE_AUTH_OVERLAY_UNMOUNT_INCAPABLE`) — the worker has
          not yet released this overlay, so removal would strand a live mount.
          If the marker exists (worker already released) or there is no overlay
          scratch (legacy full-copy workspace) → no-op, return.
  - `_SubprocessOverlayMounter.supported()` / `default_overlay_mounter()`: also
    return the copy-fallback posture (`supported() == False`) when
    `AWF_CLAUDE_AUTH_FORCE_COPY` is truthy in the env. Self-contained, additive,
    far from the sibling's region.

- `src/awf/service/gc.py` — loud-failure GC path:
  - `_unmount_candidate_auth_overlay`: call `teardown_workspace_auth_overlay`
    with capability awareness. On `OverlayUnmountUnverifiableError` **or** a
    genuine umount `(OSError, subprocess.SubprocessError)`, **return a structured
    failure** (reason code + message) instead of swallowing.
  - `_delete_gc_plan_paths`: when the unmount step reports failure, append a
    `WorkspaceGCDeleteError(kind="auth_overlay_unmount", reason_code=...)` and
    **skip** deleting the `auth` path (record it as a `skipped`
    `WorkspaceGCPathOutcome` with the same reason code) so we never rmtree over a
    possibly-live mount. Other paths (worktree/compose) proceed. The delete error
    makes `_gc_result` return `status="partial"` /
    `reason_code=CLEANUP_EXECUTION_PARTIAL` — the loud signal.

- `src/awf/control/worker/cleanup.py` — worker terminal-runtime-release path:
  - In `_release_terminal_runtime_for_candidate`, after a successful runtime
    cleanup (`cleanup.ok`, i.e. compose stack stopped), call
    `teardown_workspace_auth_overlay(work_dir=self._auth_overlay_work_dir,
    workspace_id=candidate.workspace_id)` via `asyncio.to_thread` (blocking
    `umount`). The worker is capable, so this unmounts in the right namespace and
    writes the `.overlay-unmounted` marker. A genuine umount failure is logged
    with `reason_code=CLAUDE_AUTH_OVERLAY_UNMOUNT_FAILED` and **does not** block
    port reclaim (the release still records `terminal_runtime_released`); GC's

    auditability.

### Bootstrap preflight (#376/#388)
- `src/awf/service/bootstrap.py` — new preflight before the `api_worker` stage:
  - New module-level helper `ensure_work_dir_mount_propagation(host_work_dir,
    *, run_subprocess, environ, mountinfo_path=Path("/proc/self/mountinfo"))`
    returning a small dataclass `WorkDirPropagationResult(propagation: str,
    force_copy: bool, reason_code: str, detail: str)`:
    - Parse `/proc/self/mountinfo` to find the mount backing `host_work_dir` and
      read its propagation (`shared:` vs none). If shared → `rshared`, no force.
    - If private but the host is Linux and `mount` is available → attempt
      `mount --bind <dir> <dir>` (idempotent self-bind to make it a mountpoint)
      then `mount --make-rshared <dir>`; re-probe. Success → `rshared`.
    - If non-propagating / cannot be made shared (no `/proc/self/mountinfo`,
      Docker Desktop / non-Linux, virtiofs/grpcfuse fs type, or
      `--make-rshared` fails) → `propagation="rprivate"`, `force_copy=True`,
      reason `SERVICE_BOOTSTRAP_WORK_DIR_PROPAGATION_UNAVAILABLE`.
  - In `run_service_bootstrap`, run the preflight, fold the result into
    `subprocess_env`/`service_env` as `AWF_WORK_DIR_BIND_PROPAGATION` and
    `AWF_CLAUDE_AUTH_FORCE_COPY`, and record a
    `ServiceBootstrapStageResult(stage="work_dir_propagation", ...)` so the
    decision is visible in `awf service bootstrap` output. New reason codes:
    `SERVICE_BOOTSTRAP_WORK_DIR_PROPAGATION_ENSURED`,
    `SERVICE_BOOTSTRAP_WORK_DIR_PROPAGATION_UNAVAILABLE`. A preflight that cannot
    even probe is non-fatal: default to the safe copy fallback, never crash
    bootstrap.

- `docker/compose/local-service.yml`:
  - Worker work-dir bind becomes propagation-gated:
    `- ${AWF_HOST_WORK_DIR:-${HOME}/.awf/service}:${AWF_HOST_WORK_DIR:-${HOME}/.awf/service}:${AWF_WORK_DIR_BIND_PROPAGATION:-rshared}`.
  - Add to the shared `x-awf-environment` (so the worker sees it):
    `AWF_CLAUDE_AUTH_FORCE_COPY: ${AWF_CLAUDE_AUTH_FORCE_COPY:-false}`.
  - Update the inline comment to explain the preflight gating.

## Risks & assumptions

- **Worker work-dir wiring** touches `service/worker.py` (out of strict scope) by
  one line, or we read it from the runtime cleaner. Resolve before coding.
- **Marker semantics**: the `.overlay-unmounted` marker is the cross-namespace
  signal that lets a capability-less GC distinguish "worker already released"
  from "still mounted elsewhere", avoiding both false-success and
  perpetual-`partial`. Marker lives under `auth/<id>/claude/`, removed with the
  dir.
- **Force-copy gate** lives in `default_overlay_mounter()`/`supported()` (mounter
  region), not the sibling's base/signature functions — low conflict risk, but
  coordinate if the sibling also edits the top of the file.
- **mountinfo parsing / `mount --make-rshared`** is Linux-specific and best
  effort; non-Linux/Docker-Desktop hosts intentionally land on the copy fallback.
  Assumes the host CLI running bootstrap can run `mount` (root or passwordless);
  if not, we fall back to copy rather than failing bootstrap.
- Reason codes are plain log/event string literals (like the existing
  `CLAUDE_AUTH_OVERLAY_UNMOUNT_FAILED`); the doctor `_REASON_TEXT` catalog is not
  required for them, so no `REASON_CATALOG.md` drift.

## Non-goals

- Re-architecting GC to run inside the worker; we keep GC where it is and make it
