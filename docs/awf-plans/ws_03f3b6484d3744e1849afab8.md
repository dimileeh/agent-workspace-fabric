# Plan: P0 Workspace Control Idempotency and Concurrency

## Scope

Implement the PRD v2.2 slice for mutating workspace controls:

- `POST /v1/workspaces/{id}/cancel`
- `POST /v1/workspaces/{id}/stop`
- `DELETE /v1/workspaces/{id}` (`destroy` operation)
- `POST /v1/workspaces/{id}/remonitor`
- `POST /v1/workspaces/{id}/refresh`
- `POST /v1/workspaces/{id}/validate`

The contract is: same `Idempotency-Key` plus the same effective payload returns the same operation; same key plus any different effective payload returns `409` with `IDEMPOTENCY_CONFLICT`; stale `If-Match` returns `409` with `VERSION_CONFLICT`; accepted expected-version data is visible in operation payloads and related workspace events without changing public top-level response shapes.

## Intended Files and Modules

Tests first:

- `tests/unit/api/test_workspace_controls_idempotency.py`
  - Extend API-level coverage for all six actions.
  - Cover same-key replay, same-key mismatched payload, same-key mismatched `If-Match`, stale `If-Match`, and no duplicate operations/events/side effects.
- `tests/unit/service/test_controls_lifecycle.py`
  - Add service-level regression tests for shared idempotency and optimistic concurrency behavior, especially refresh/validate active-operation coalescing and stale version ordering.
- `tests/unit/service/test_controls.py`
  - Add narrow helper/error mapping tests only if new control errors or route helpers are introduced.
- `tests/unit/runtime/test_pr_monitor_runner_coverage_edges.py`
  - Add focused tests proving stale PR monitor terminal callbacks cannot move `cancelled`, `destroying`, or `destroyed` workspaces to `completed` or `failed`.
- `tests/unit/control/test_executor_monitor_recovery.py` or `tests/unit/control/test_executor_error_paths.py`
  - Add only if inspection shows an executor callback gap not already covered by existing stale-status tests.
- `tests/unit/db/test_models.py`, `tests/unit/db/test_repository_coverage.py`, and migration tests only if the implementation requires a schema/index change.

Implementation:

- `src/awf/service/controls.py`
  - Centralize effective idempotency payload construction for each action.
  - Ensure replay is checked before optimistic concurrency, so exact same-key retries still replay after the workspace version changes.
  - Ensure optimistic concurrency is checked before active-operation coalescing for fresh keys, so a stale `If-Match` cannot be hidden by an existing pending refresh/validate operation.
  - Include `expected_version` consistently in operation payloads and accepted event payloads when supplied.
  - Preserve existing messages and response models.
- `src/awf/api/routes/controls.py`
  - Keep token dependency and idempotency requirements intact.
  - Touch only if helper behavior or structured conflict mapping needs adjustment.
- `src/awf/db/repositories.py`
  - Touch only if a small repository helper is needed for locked idempotency lookup or optional event payload support.
- `src/awf/runtime/pr_monitor_runner.py`
  - Guard monitor terminal transitions with current-status checks so stale monitor callbacks respect operator cancel/destroy.
- `src/awf/db/models.py` and `migrations/versions/*`
  - Not intended initially. Add a partial unique index or migration only if tests expose duplicate operation creation that cannot be solved through the service lock path.

## TDD Sequence

   - Parametrize cancel, stop, destroy, remonitor, refresh, and validate.
   - Assert same key plus same payload returns the same operation id and does not add rows or repeat stop/cleanup side effects.
   - Assert same key plus different body, query option, requested tier, or `If-Match` returns structured `IDEMPOTENCY_CONFLICT`.
   - Assert stale `If-Match` returns structured `VERSION_CONFLICT` and creates no operation or event.
   - Assert accepted operation payloads include `expected_version` when `If-Match` was supplied.

2. Add failing service tests in `test_controls_lifecycle.py`.
   - Verify `_prepare_operation` semantics directly through the public service methods.
   - Cover the subtle ordering case: a fresh key with stale `If-Match` must not coalesce onto an active refresh/validate operation; the original idempotency key must still replay.
   - Verify operation/event payload visibility for expected-version data.

   - In PR monitor tests, seed a workspace, move it to `cancelled`, `destroying`, or `destroyed`, invoke `_terminate_completed` and `_terminate_failed`, and assert the terminal operator state remains unchanged.

   - Add PR monitor terminal-transition guards.

5. Run targeted tests and then the broader validation surface.
   - Fix only behavior required by failing tests and PRD contract.

6. Commit in the implementation phase after validation passes.

## Risks and Assumptions

- The API idempotency key is treated as a global operation key, matching the existing `OperationRepository.get_by_idempotency_key` behavior.
- PostgreSQL unit tests cannot fully prove PostgreSQL advisory-lock concurrency. The implementation should keep the existing Postgres advisory lock path and rely on deterministic service tests for behavior.
- Adding keys inside `operation.payload` or `workspace_event.payload` is considered backward-compatible; changing top-level `WorkspaceControlResponse` or `OperationResponse` fields is not.
- Existing active-operation coalescing for refresh/validate should remain for fresh keys without a stale `If-Match`.
- `delete` in the task maps to the existing destroy endpoint and `OperationType.destroy`.
- Existing token protection on `src/awf/api/routes/controls.py` must remain unchanged.

## Non-Goals

- Do not implement `start` or `rebase` idempotency in this slice.
- Do not broaden API permissions, weaken `require_api_token`, or add unauthenticated control paths.
- Do not change public response shapes beyond already exposed payload contents.
- Do not redesign operation retention, operation lifecycle events, merge policy, scheduler admission, or PR monitor review policy.
- Do not switch branches, push, rebase, or manually drive AWF PR handling.
