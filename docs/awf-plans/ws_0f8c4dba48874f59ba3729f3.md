## Risks And Assumptions

- Risk: the preserved migration revision collides with the current base. The
  migration must be recreated with a new revision id rather than cherry-picked
  verbatim.
- Risk: the preserved branch is based on older repository state. Cherry-picking
  whole commits may try to delete or overwrite unrelated current files. Apply
  callback-specific hunks and inspect conflicts before staging.
- Risk: callback wildcard semantics can accidentally expose internal event type
  names. Prefer a shared public allowlist for both request validation and
  matching.
- Risk: raw workspace events and operation rows can contain sensitive data.
  Envelope builders must remain allowlist-based and regression tests must keep
  obvious fake secrets in source rows.
- Assumption: this recovery remains the local-service callback foundation from
  the preserved plan; it does not need a continuously running background
  dispatcher to satisfy conformance.
- Assumption: callback delivery is at-least-once. Stable delivery idempotency
  keys are the receiver-side dedupe mechanism.
- Assumption: exact public callback event types are a deliberately curated
  public contract, not every string currently written to `workspace_events`.
