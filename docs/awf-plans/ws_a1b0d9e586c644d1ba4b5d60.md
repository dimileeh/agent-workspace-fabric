# CI Evidence Repro Command Fallback Plan

## Scope
Implement a narrow hardening fix so PR-monitor CI evidence always includes a focused pytest repro command when GitHub Actions evidence exposes pytest node IDs, even when no usable pytest invocation was extracted from the log.

This planning phase is limited to this artifact. Implementation will happen in a later phase.

## Intended Files and Modules to Touch

- `src/awf/runtime/ci_failure_evidence.py`
  - Primary implementation target.
  - Locate the code that extracts pytest node IDs and builds `suggested_repro_commands`.
  - Preserve the existing extracted-command behavior.
  - Add a generic fallback command when pytest-looking node IDs exist but no pytest command prefix is available.
  - Use the existing maximum repro node count and `shlex.quote` for each node ID.

- `tests/unit/runtime/test_ci_failure_evidence.py`
  - Primary test target.
  - Add regression tests for fallback command creation and bounded/quoted multi-node behavior.
  - Preserve existing coverage for extracted pytest commands, non-test failures, missing logs, redaction, provider-neutral check names, and prompt ordering.

- `src/awf/common/github_client.py`
  - Touch only if investigation shows CI evidence shaping or node ID extraction currently lives here or needs a small structured-field pass-through adjustment.

- `tests/unit/common/test_github_client.py`
  - Touch only if `github_client.py` changes or existing tests must be updated to preserve behavior.

- `src/awf/runtime/monitor_prompts.py`
  - Touch only if the prompt payload drops `suggested_repro_commands` or otherwise needs a narrow adjustment for the fallback to reach repair prompts.

- `tests/unit/runtime/test_monitor_prompts.py`
  - Touch only if prompt rendering/ordering needs explicit regression coverage for the fallback command.

- `src/awf/runtime/pr_monitor_runner.py`
  - Touch only if the operation payload path filters or omits fallback repro commands.

- `tests/unit/runtime/test_pr_monitor_runner.py`
  - Touch only if runner payload coverage is needed to prove the fallback reaches agents.

## Tests to Write First

1. Add a failing unit test in `tests/unit/runtime/test_ci_failure_evidence.py` for a GitHub Actions log that contains pytest-style `FAILED ...::test_name` lines but no extractable `Run pytest` command.
   - Expected `suggested_repro_commands` should include:
     - `uv run --python 3.12 --extra dev pytest <quoted node id> -q`
   - The test should use provider-neutral check/job names and not rely on `python-full-coverage`.

2. Add a failing unit test in `tests/unit/runtime/test_ci_failure_evidence.py` for multiple pytest node IDs.
   - Include parametrized node IDs containing spaces and shell metacharacters.
   - Assert every included node ID is quoted with `shlex.quote` semantics.
   - Assert the command includes no more than the existing maximum repro node count.
   - Assert the command ends with `-q`.

3. Run or adjust existing tests for extracted pytest commands after the first failures are established.
   - Confirm that when an extractable pytest command prefix exists, AWF still uses that prefix and appends quoted bounded node IDs plus `-q`.

4. Add or adjust prompt/runner tests only if investigation shows the fallback command is built but not passed through to monitor prompts or operation payloads.
   - Keep these tests narrow and structured-evidence focused.

## Implementation Approach

1. Inspect `ci_failure_evidence.py` to identify the existing flow for:
   - failed log parsing;
   - pytest node ID extraction;
   - extracted pytest command detection;
   - maximum repro node count;
   - command quoting/redaction behavior.

2. Introduce the fallback at the point where node IDs are already known and `suggested_repro_commands` would otherwise be empty because no pytest command prefix was extracted.

3. Reuse existing constants/helpers where present.
   - If no helper exists, add a small local helper for building a focused pytest repro command.
   - Preferred fallback prefix:
     - `uv run --python 3.12 --extra dev pytest`

4. Build commands generically from evidence contents only.
   - Do not branch on GitHub Actions job/check names.
   - Do not add broad coverage commands or full-suite commands.

5. Preserve current behavior for extracted pytest commands.
   - Existing extracted prefix wins.
   - Append bounded `shlex.quote(node_id)` values and `-q`.

6. Keep changes narrow.
   - Avoid monitor runner or prompt changes unless tests prove the structured evidence path drops the fallback.

## Risks and Mitigations

- Risk: Existing tests may assert an empty repro command list when no command is extracted.
  - Mitigation: Update only tests where pytest node IDs are present; non-test failures and missing logs should keep existing behavior.

- Risk: Quoting expectations may differ from current command construction.
  - Mitigation: Use `shlex.quote` consistently for fallback and preserve the same quoting path used by extracted pytest commands if one already exists.

- Risk: The maximum node count constant may be private or embedded in existing logic.
  - Mitigation: Reuse the existing constant/helper rather than introducing a second limit.

- Risk: Fallback command could accidentally encourage broad local runs.
  - Mitigation: Include only known node IDs, bounded to the repro limit, and append `-q`; do not add full coverage or suite-wide commands.

- Risk: The fallback may be generated correctly but omitted from repair prompts or operation payloads.
  - Mitigation: Add prompt/runner tests only if the evidence path lacks existing pass-through coverage.

## Assumptions

- Pytest node IDs are already extracted into a structured `test_node_ids` or equivalent field before repro command construction.
- There is an existing maximum repro node count used by current extracted-command behavior.
- The AWF dev runtime convention `uv run --python 3.12 --extra dev pytest` is valid for focused local pytest repros in this repository.
- `shlex.quote` is acceptable for shell-safe command rendering in monitor payloads.

## Explicit Non-Goals

- No changes to GitHub Actions workflow policy.
- No changes to coverage thresholds.
- No provider-specific or AWF-check-name-specific branching.
- No broad PR-monitor rewrite.
- No local broad/full coverage command suggestion merely to rediscover known failures.
- No branch switching, pushing, rebasing, force-pushing, or manual PR operations.
