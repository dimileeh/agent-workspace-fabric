# Issue #345 Phase 1 — Forge provider-abstraction seam + detection (GitHub-only)

Workspace: `ws_7ccab9fb002345c48b70e305`
Issue: GitHub #345 (BitBucket provider support) — **Phase 1 only**.

## 1. Goal & scope (locked — do not expand)

"Make the change easy, then make the easy change." Extract a provider-neutral
forge interface + forge **detection** so Phase 2 can drop in a `BitBucketClient`
without touching consumers. **GitHub stays the only implementation.** A BitBucket
repo must be *detected* and then *fail fast* with a clear reason-coded error —
never crash, never silently mis-route to GitHub.

**Zero behavior change for GitHub repos.** All existing `github_client`,
`pr_monitor`, and profile-resolver suites stay green.

### Locked decisions (do not re-litigate)
1. Phase 1 = abstraction seam + detection only. No BitBucket REST/httpx client,
   no BitBucket auth. BitBucket → detected → fail fast with `FORGE_NOT_SUPPORTED`.
2. workspace.yml field is **`forge:`** (`github | bitbucket | auto`, default `auto`).
   Precedence: explicit `forge:` > URL-host detection (github.com / bitbucket.org)
   > default `github`. Resolved value persisted ONCE in `resolved_profile.forge`;
   later stages read it, they do NOT re-resolve. Name is `forge` (NOT `provider`
   — taken by agent/model providers — NOR `vcs`/`git_host`).

## 3. Design

### 3.1 ASCII diagram (embed verbatim in `forge.py` module docstring + PR body)

```
repo_url ──► RepoRef.from_url ──► host? ──► forge (github|bitbucket)   [URL layer]
workspace.yml forge: (auto|github|bitbucket) ──┐
                                               ▼
profile resolver: explicit forge  >  URL host  >  default github       [precedence]
                                               ▼
                              resolved_profile.forge   (persisted once)
                                               ▼
        make_forge_client(forge, runner) ──► github: GitHubClient
                                          └─► bitbucket: raise FORGE_NOT_SUPPORTED (Phase 1)
                                               ▼
        consumers depend on ForgeClient (Protocol), not GitHubClient
```

### 3.2 `ForgeKind` literal — `src/awf/db/enums.py`
Add (dependency-free, stdlib `typing` only):
```python
from typing import Literal
ForgeKind = Literal["github", "bitbucket"]      # persisted forge vocabulary
```
This is the persisted concrete vocabulary. `"auto"` is a *resolution-input only*
value and lives on the profile field type, not in `ForgeKind`.

### 3.3 New module `src/awf/common/forge.py`
Contents:
- Module docstring with the ASCII diagram + precedence note.
- `ForgeNotSupportedError(Exception)` carrying `reason_code = "FORGE_NOT_SUPPORTED"`
  and a clear message: *"BitBucket forge support is not yet implemented (issue #345
  Phase 1 adds detection only)."* Pattern-match existing reason-coded exceptions
  (carry `reason_code`, `message`; catch specifically, never bare `Exception`).
  Define `FORGE_NOT_SUPPORTED_REASON_CODE = "FORGE_NOT_SUPPORTED"` constant.
- `@runtime_checkable class ForgeClient(Protocol)` — **structural**, mirroring the 10
  public `GitHubClient` methods above with identical signatures (same keyword-only
  params, same return types: `PRStatus`, `tuple[CheckFailure, ...]`, `str`,
  `tuple[str, ...]`, `tuple[str, ...] | None`, `None`). Reuse the existing
  provider-neutral types (`RepoRef`, `PRStatus`, `CheckFailure` from
  `pr_monitor`/`github_client`). No inheritance change to `GitHubClient` — it must
  satisfy the Protocol structurally as-is.
- `make_forge_client(forge: ForgeKind, runner: AsyncCommandRunner) -> ForgeClient`:
  - `"github"` → `GitHubClient(runner)`.
  - `"bitbucket"` → `raise ForgeNotSupportedError(...)`.
  - (No `else`/default needed under exhaustive `ForgeKind`; if a non-literal sneaks
    in at runtime, raise `ForgeNotSupportedError` too so it fails closed.)
- **`BranchOpenPullRequestResolver` decision (documented):** it stays a *separate
  collaborator*, NOT on the `ForgeClient` Protocol. Rationale: it is a distinct class
  with a different surface (`resolve(repo_url, branch_name, base_branch)`), is wired
  separately into `ControlWorker`, and a bitbucket workspace fails fast at the
  executor forge gate (§3.6) before any open-PR-resolver path matters. A
  forge-neutral open-PR resolver is deferred to Phase 2. Note this in the docstring.

Import direction (no cycles): `db.enums` (leaf) ← `github_client` ← `forge`.
`forge` imports `GitHubClient`/`RepoRef` from `github_client` and `ForgeKind` from
`db.enums`.

### 3.4 Forge-aware `RepoRef` — `src/awf/common/github_client.py`
- Import `ForgeKind` from `awf.db.enums`.
- Add field `forge: ForgeKind = "github"` to the frozen dataclass (default keeps the
  direct `RepoRef(owner=, name=)` construction at :465 and all existing tests valid).
- `from_url` host detection (preserve ALL current github behavior byte-for-byte; only
  ADD bitbucket branches and stamp `forge`):
  - bare `owner/repo` slug (no host, no `:`) → `forge="github"` (unchanged default).
  - `git@github.com:o/r(.git)?` / `https://github.com/...` / `ssh://git@github.com/...`
    → `forge="github"` (unchanged parsing; just set `forge`).
  - `git@bitbucket.org:workspace/repo(.git)?` → `forge="bitbucket"`, owner=workspace.
  - `https://bitbucket.org/workspace/repo[.git]` and `ssh://git@bitbucket.org/...`
    → `forge="bitbucket"`.
  - Unknown host → preserve current `ValueError` (message text unchanged for the
    github-cannot-parse path; bitbucket gets its own clear parse path).
- Host-aware URL builders keyed off `self.forge` (helper `_forge_host()` →
  `"github.com" | "bitbucket.org"`):
  - `https_url()` → `https://<host>/{owner}/{name}.git`
  - `ssh_url()` → `git@<host>:{owner}/{name}.git`
  - `clone_url_like(repo_url)` → match transport (ssh vs https, preserve userinfo)
    against `<host>` instead of hardcoded `github.com`.
  - `slug()` unchanged (`owner/name`).
- Keep the github-only behavior identical when `forge="github"` (the common path).

### 3.5 Profile schema + resolver
- `src/awf/profiles/models.py` — add to `WorkspaceProfile` (after `source`/near top-level
  fields): `forge: ForgeKind | Literal["auto"] = "auto"`. Import `ForgeKind` from
  `awf.db.enums`. (Field added with a default so existing inline profiles validate
  unchanged.)
- `src/awf/profiles/resolver.py`:
  - Add optional `repo_url: str | None = None` to `ProfileResolver.resolve(...)` and the
    `resolve_workspace_profile(...)` free fn.
  - After the profile object is chosen (before lint + `ProfileResolution` return at
    :119), compute the concrete forge and stamp it onto the profile via
    `profile.model_copy(update={"forge": resolved})`:
    ```
    explicit = profile.forge                       # "auto" | "github" | "bitbucket"
    if explicit != "auto":           resolved = explicit          # explicit wins
    elif repo_url and host==bitbucket.org: resolved = "bitbucket" # URL detection
    elif repo_url and host==github.com:    resolved = "github"
    else:                                  resolved = "github"    # default
    ```
    Use a small `detect_forge_from_url(repo_url) -> ForgeKind | None` helper (place in
    `forge.py`, reusing `RepoRef.from_url` → `.forge`, swallowing `ValueError` → `None`
    so a malformed URL falls through to default github and does NOT break resolution —
    detection is best-effort; the executor gate is the real fail-fast).
  - This guarantees `resolved_profile.forge` is always concrete (`github`/`bitbucket`),
    never `"auto"`.
- Thread `repo_url=ws.repo_url` at the two execution-relevant call sites:
  `node/provisioner.py:210` and `control/executor/helpers.py:424`. Pass
  `repo_url` at `service/workspaces_create.py:1113` if a repo URL is in scope there;
  smoke/preview sites (`cli/profile_smoke_commands.py`, `service/smoke.py`) may pass
  nothing (→ default github), which is correct.

### 3.6 Construction rewire + fail-fast gate
- **`make_forge_client` is the single fail-fast gate.** Replace the 2 named
  `GitHubClient(...)` constructions:
  - `service/worker.py`: move the `gh` construction OUT of module-level (:91, where
    forge is unknown) INTO `_pr_monitor_factory` (which receives the reconstructed
    `profile`): `gh = make_forge_client(profile.forge, runner)`. github → same
    `GitHubClient(runner)` behavior; bitbucket → raises → monitor build fails. Keep
    `open_pr_resolver = BranchOpenPullRequestResolver(runner)` (separate collaborator).
  - `control/executor/monitor_handoff.py:1092`: `gh = make_forge_client(forge, self._runner)`
    where `forge` is read from `workspace.resolved_profile` (reconstructed, not
    re-resolved). Use a tiny local read (`(workspace.resolved_profile or {}).get("forge",
    "github")`) or `WorkspaceProfile.model_validate(workspace.resolved_profile).forge`.
- **Early executor gate (within "rewire construction"):** add a forge-support check at
  the start of the per-workspace run so a BitBucket *feature* workspace fails fast with
  `FORGE_NOT_SUPPORTED` BEFORE the agent runs / push / `gh pr create` (which would
  otherwise emit an opaque `gh` error first — a crash, violating the contract). In
  `control/executor/execution_flow.py` right after the profile is reconstructed
  (around :244-256, once `profile.forge` is known), call `make_forge_client(profile.forge,
  self._runner)` (or a thin `ensure_forge_supported(profile.forge)`); on
  `ForgeNotSupportedError` → `self._mark_failed(..., from_status=running,
  failure_reason=FailureReason.infrastructure_failure, reason_code="FORGE_NOT_SUPPORTED",
  message=exc.message)` and return. This is the same factory call applied at the earliest
  point the resolved forge is known — it is the seam, not a new abstraction.
- Consumers: swap type hints `GitHubClient` → `ForgeClient` (import from
  `awf.common.forge`) at the sites listed in §2. Type-only; no logic change. Leave
  `GitHubClientError` imports/handling untouched.

## 7. Risks & mitigations
- **OpenAPI drift / api↔mcp lockstep.** Adding `WorkspaceProfile.forge` may surface in
  any API response that embeds the profile (e.g. profile preview). Mitigation: run
  `scripts/generate_openapi.py --check`; if it reports drift, regenerate `openapi.json`
  and confirm `api/schemas.py` ↔ MCP stay in lockstep. Field has a default so it is
  additive/back-compatible.
- **Resolver signature change ripples.** `resolve_workspace_profile`/`ProfileResolver.resolve`
  gain an optional `repo_url`; all 5 call sites must still type-check. Mitigation:
  keyword-only with default `None`; mypy + targeted call-site tests.
- **Reason-catalog drift gate.** New `FORGE_NOT_SUPPORTED` must be added to `_REASON_TEXT`
  and the catalog regenerated. Mitigation: regen step in §6.
- **Hidden third construction / gh path.** `PullRequestCreator` (feature PR) also shells
  `gh pr create`; without the early executor gate (§3.6) a bitbucket feature workspace
  would hit an opaque `gh` error first. Mitigation: the execution_flow gate fails fast
  before agent/push — covered by a test asserting no `gh pr create`.
- **Protocol drift from GitHubClient.** The Protocol mirrors 10 methods by hand.
  Mitigation: `runtime_checkable` `isinstance` conformance test + structural mypy use;
  document "Protocol surface is derived from GitHubClient — keep in lockstep."
- **1500-LOC guard.** `github_client.py` is ~1431 LOC. Mitigation: Protocol/factory/
  forge-enum live in the new `forge.py`; only the small `RepoRef` changes land in
  `github_client.py`.
- **Import cycles.** Mitigation: strict direction `db.enums ← github_client ← forge`;
  `models.py`/`resolver.py` import `ForgeKind` from `db.enums` (leaf), and
  `detect_forge_from_url` from `forge` (no back-import into `github_client`).
