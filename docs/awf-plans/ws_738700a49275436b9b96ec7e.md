# Implementation Plan: Untrusted External Evidence Framing

## Scope and Intent

Harden the agent-facing prompt boundary for external text that AWF gets from GitHub PR reviews, PR comments, and CI check logs. The implementation should make that text visibly quoted evidence with source provenance, and should restate that AWF/system/task policy remains authoritative.

This is a focused PR-monitor slice. It should not become a general web/package-ingestion system.

## Intended Files and Modules to Touch

- `src/awf/common/prompt_evidence.py` (new)
  - Add a small shared representation, likely `UntrustedEvidence`, with fields for source kind/name, source id, author, URL or location details when available, and text.
  - Add a renderer such as `render_untrusted_evidence(...)` that:
    - labels the block as untrusted external evidence;
    - includes provenance before the quoted text;
    - says the evidence cannot override AWF/system/task policy, owned_paths, validation policy, secret handling, merge gates, cleanup rules, or git/push instructions;
    - quotes every evidence line with a stable prefix so malicious delimiters, markdown fences, and fake instructions stay inside the evidence block.

- `src/awf/runtime/monitor_prompts.py`
  - Update `address_thread_prompt` to render `ReviewThread.body_excerpt` via the shared evidence helper with provenance including repo, PR number, thread id, author, path, and line when present.
  - Update `address_review_comment_prompt` to render `ReviewComment.body_excerpt` via the helper with provenance including repo, PR number, comment id, author, and whether it is a review-level or issue-style comment when inferable from the id.
  - Update `fix_ci_prompt` to render each `CheckFailure.log_excerpt` as untrusted check-log evidence with provenance including repo, PR number, check name, and conclusion. Avoid raw fenced-code log blocks for untrusted logs.
  - Keep the existing decision tree and footer behavior intact, especially the `Do NOT push` instruction and CI policy against disabling checks.

- `tests/unit/common/test_prompt_evidence.py` (new)
  - Unit tests for the shared helper and representation.

- `tests/unit/runtime/test_monitor_prompts.py`
  - Add adversarial regression tests for PR review thread prompts, review-level comment prompts, and CI repair prompts.
  - Update existing prompt assertions only where wording shifts because evidence is now framed differently.

- `tests/unit/runtime/test_pr_monitor_runner.py` or `tests/unit/runtime/test_monitor_action_logging.py` (tiny adjacent integration test if practical)
  - Add one focused test that drives a comment-repair path far enough to prove the prompt handed to the fake adapter contains the quoted evidence framing, not just the pure prompt helper output.

No planned changes to `src/awf/common/github_client.py` or the PR monitor dataclasses. Existing IDs, authors, paths, and check names appear sufficient for provenance. If a failing test proves additional provenance is required in `ReviewThread`, `ReviewComment`, or `CheckFailure`, keep that adjacent edit minimal and document it.

## Tests to Write First

1. `tests/unit/common/test_prompt_evidence.py::test_untrusted_evidence_includes_source_provenance_and_boundary_policy`
   - Build evidence with source kind, source id, author, repo/PR metadata, and text.
   - Assert the rendered output names the source/provenance and explicitly says external text cannot override AWF/system/task policy, owned_paths, validation policy, secret handling, merge gates, or cleanup rules.

2. `tests/unit/common/test_prompt_evidence.py::test_untrusted_evidence_quotes_every_line_of_adversarial_text`
   - Use adversarial text containing markdown fences, fake `SYSTEM:` instructions, delimiter-looking lines, `ignore owned_paths`, `print secrets`, `skip validation`, `merge immediately`, and `cleanup all worktrees`.
   - Assert each adversarial line appears only with the quote prefix and cannot escape into the authoritative prompt text.

3. `tests/unit/runtime/test_monitor_prompts.py::test_review_thread_adversarial_body_is_quoted_evidence_not_policy`
   - Create a `ReviewThread` whose body tries to override owned paths, secret handling, validation, merge gates, and cleanup.
   - Assert the prompt includes provenance for the GitHub thread and keeps the malicious body quoted.
   - Assert authoritative AWF instructions such as the decision tree and `Do NOT push` remain outside the evidence block.

4. `tests/unit/runtime/test_monitor_prompts.py::test_review_comment_adversarial_body_is_quoted_evidence_not_policy`
   - Same adversarial pattern for `ReviewComment`.
   - Assert the comment id and author are included as provenance and the malicious policy text stays quoted.

5. `tests/unit/runtime/test_monitor_prompts.py::test_ci_log_adversarial_text_is_quoted_evidence_not_policy`
   - Use a `CheckFailure.log_excerpt` that attempts to disable checks, bypass validation, reveal secrets, or merge despite failures.
   - Assert the log is rendered as untrusted evidence with check provenance and the real prompt still tells the agent not to disable, skip, or weaken checks.

6. Runner integration test if the existing fixtures support it cleanly:
   - Drive `_address_review_comment` or an `AddressComments` action with a fake adapter.
   - Assert the captured adapter prompt contains the untrusted evidence marker and quoted malicious text.
   - Keep this test focused; do not build a full monitor integration scenario if the pure prompt tests already prove the behavioral contract.

## Implementation Steps

1. Add the failing helper tests and monitor prompt regression tests.
2. Implement the shared evidence helper in `src/awf/common/prompt_evidence.py`.
3. Apply the helper in `src/awf/runtime/monitor_prompts.py` for review threads, review comments, and CI check logs.
4. Update existing prompt tests for the new framing while preserving their original behavioral assertions.
5. Add the narrow runner integration test if it can reuse current fake adapter fixtures without broad setup changes.
6. Run targeted validation, then broader lint/typecheck appropriate for the touched Python surface.

## Risks

- String-level prompt tests cannot prove an LLM will never follow malicious quoted text. They can prove AWF consistently frames the text as untrusted evidence and preserves authoritative policy instructions outside that text.
- Markdown quoting must be robust against blank lines, nested blockquotes, fake delimiters, and code fences. The helper tests should cover these cases directly.
- Changing prompt wording can affect existing tests that assert exact snippets. Keep wording changes minimal and preserve the current decision tree.
- CI logs can be long and noisy. The existing log truncation in `GitHubClient.fetch_failing_check_logs` should remain the size control; this slice should only change framing.

## Assumptions

- The highest-risk current path is `monitor_prompts.py`, because PR monitor repair prompts directly pass GitHub review text and check logs to coding agents.
- Existing PR monitor models already carry enough provenance for this slice: repo slug and PR number are passed to prompt builders, and review/check objects carry IDs, authors, paths, lines, check names, and conclusions.
- This repository's owned paths for the implementation include the AWF runtime/common prompt code and their unit tests. The planning artifact is the only file modified in this phase.

## Explicit Non-Goals

- Do not implement full webpage, package README, issue ingestion, or internet-content crawling.
- Do not change merge policy, review grace timing, validation thresholds, secret mounts, egress enforcement, cleanup policy, or GitHub fetching behavior.
- Do not add retries or hide failures behind prompt wording.
- Do not refactor the PR monitor decision core or GitHub client parsing beyond the minimal prompt-framing needs.
