# Implementation Plan: Orphan Resource Detection And Cleanup Readiness

## Intended Files/Modules To Touch

1. `src/awf/service/orphans.py` (new)
   - Add the read-only orphan resource detector as the single service-level implementation.
   - Define dataclasses for:
     - workspace lifecycle snapshots: workspace id, status, updated_at, compose project name;
     - detected resource examples: `resource_kind`, resource id/name, workspace id when derivable, reason code, classification, suggested action;
     - summary payload: total counts, counts by kind, retained/expected counts, warning counts, examples, and top-level status/reason.
   - Detect Docker resources with injected subprocess fakes:
     - containers via `docker ps -a --filter label=com.docker.compose.project --format ...`;
     - networks via `docker network ls --filter label=com.docker.compose.project --format ...`;
     - volumes via `docker volume ls --filter label=com.docker.compose.project --format ...`, with a conservative name/project fallback if labels are missing from the formatted output.
   - Detect managed worktrees by scanning `<work_dir>/git/worktrees/<workspace_id>` for immediate `ws_*` directories only.
   - Classify resources as:
     - expected for active workspace statuses;
     - retained/expected for `completed` workspaces still inside the existing retention window;
     - actionable orphan/cleanup-ready for missing DB rows or terminal resources outside retention;
     - warning/unavailable for Docker CLI/daemon failures or malformed Docker output.
   - Reuse `awf.service.gc.DEFAULT_MIN_AGE_HOURS` as the initial retention policy source so completed resources inside the current GC retention window are not flagged as unsafe or unexpected.

2. `src/awf/service/status.py`
   - Replace the current inline container-only orphan logic with the new detector.
   - Keep the service status integration read-only.
   - Preserve the existing operator surface as much as practical by continuing to expose the check under `checks["orphan_workspaces"]`, while adding resource-oriented fields such as `resource_counts`, `orphan_counts_by_kind`, and examples with `resource_kind`.
   - Keep Docker-unavailable orphan detection as `ok=True`, `status="unavailable"` or `status="warn"` so the orphan detector itself does not crash service status. The separate Docker health check may still fail overall service readiness.

3. `tests/unit/service/test_orphans.py` (new)
   - Add focused pure-detector tests using fake Docker subprocess results and temp directories.
   - Avoid real Docker entirely.

4. `tests/unit/service/test_status.py`
   - Update/extend integration-level service status tests to prove `collect_service_status` includes the new resource summary and still handles cancellation/failure paths.

5. `tests/unit/cli/test_cli.py` and/or `tests/unit/cli/test_service_cli.py`
   - Update only if pretty output expectations need to reflect new resource-oriented fields while preserving current CLI behavior.

6. `README.md` (only if the implementation changes documented status payload/action text)
   - Update the existing `awf service status` orphan-resource paragraph from container-only wording to containers/networks/volumes/worktrees.

## Tests To Write First

Write the failing tests before implementation, then confirm the expected failures.

1. `test_no_orphans_reports_zero_counts`
   - Active workspace resources plus unrelated non-AWF resources produce `NO_ORPHANS`, zero orphan counts, and empty examples.

2. `test_orphan_container_missing_workspace_is_structured`
   - A fake AWF-labeled container for `ws_ghost` with no active/known workspace produces one example with `resource_kind="container"`, `workspace_id="ws_ghost"`, reason `WORKSPACE_MISSING`, and a non-empty suggested action.

3. `test_orphan_network_missing_workspace_is_structured`
   - Same shape for an AWF Compose network.

4. `test_orphan_volume_missing_workspace_is_structured`
   - Same shape for an AWF Compose volume, including the fallback path when the volume listing only supplies an AWF-prefixed name.

5. `test_orphan_worktree_missing_workspace_is_structured`
   - A temp `<work_dir>/git/worktrees/ws_ghost` directory with no active/known workspace is reported as `resource_kind="worktree"`.

6. `test_docker_unavailable_is_actionable_warning_not_crash`
   - Fake Docker command failure or `FileNotFoundError` returns an unavailable/warning summary with reason `DOCKER_UNAVAILABLE` or `DOCKER_CLI_NOT_FOUND`, zero Docker orphan counts, and still allows worktree scanning.

7. `test_malformed_docker_output_records_warning_and_keeps_valid_rows`
   - Bad JSON lines do not raise; valid rows are still classified; malformed lines increment warning details with reason `DOCKER_OUTPUT_MALFORMED`.

8. `test_completed_workspace_within_retention_not_flagged`
   - A `completed` workspace whose `updated_at` is newer than `DEFAULT_MIN_AGE_HOURS` may have containers/networks/volumes/worktrees present, but they are counted as retained/expected, not orphan/unsafe.

9. `test_completed_workspace_past_retention_is_cleanup_ready`
   - A completed workspace older than retention is reported as actionable cleanup-ready without deleting anything.

10. Service status regression tests
    - `collect_service_status` includes the detector output.
    - Service status fails when real orphans are present, remains non-crashing when Docker orphan enumeration is unavailable, and preserves existing disk/provider behavior.

## Risks

- Docker CLI formatting differs slightly by resource kind and Docker version, especially for volume labels. The detector should use label filters where possible, tolerate missing label fields, and fall back to AWF Compose naming only for clearly managed resources.
- There is an inherent race between a detector snapshot and an active cleanup/provisioning transition. The detector should report current evidence with reason codes, not mutate state or promise that a resource is still present after the status command returns.
- Treating completed resources inside retention as expected depends on `DEFAULT_MIN_AGE_HOURS` being the correct local retention policy. If a profile-specific retention policy is added later, this detector should accept that setting rather than hard-coding the default.
- Worktree detection should only scan the managed AWF root. Following symlinks or recursively scanning arbitrary paths would raise safety and false-positive risk.

## Assumptions

- Managed Docker resources are created by Docker Compose and carry `com.docker.compose.project` labels or AWF project names with `awf_ws_*` / `awf-ws_*`.
- Managed worktrees live under `<settings.work_dir>/git/worktrees/<workspace_id>`.
- Active statuses are the existing non-terminal workspace lifecycle states; terminal status retention behavior can reuse the same terminal status set used by service status/GC.
- This slice can satisfy the API/status exposure requirement through `awf service status`, because that surface already owns Docker dependency probing and read-only local health reporting.

## Explicit Non-Goals

- Do not delete containers, networks, volumes, worktrees, compose directories, auth directories, logs, artifacts, or DB rows in this slice.
- Do not add a new destructive cleanup command or change `awf service gc` deletion semantics.
- Do not require real Docker in unit tests.
- Do not lower coverage thresholds, `.awf/workspace.yml`, `pyproject` quality gates, or validation policy.
- Do not update the console UI in this slice.
- Do not check off or edit `TODO/pre-gke-industrial-readiness.md` as part of this implementation unless a later task explicitly asks for checklist maintenance.
