# WS-B2 — Reap orphaned per-workspace filesystem / docker state (issue #361)

## Problem & scope

AWF leaks ~188 GB of per-workspace disk. WS-B1 (merged, PR #372) gave us the *reclaim
engine*: deletion routed through the **root** control-plane, post-merge immediate
pressure-dir reclaim, and a volume-removing `compose_teardown` callback. But that engine
selects candidates **by DB row**. Per-workspace directories whose `workspaces` row no
longer exists (`auth/<id>`, `git/worktrees/<id>`, `compose/<id>`) are unreachable by GC
and orphan forever. Separately `service/orphan_resources.py` already *detects and
classifies* orphans but is hard-wired `dry_run_only=True`, so it never reaps.

This workstream (WS-B2) adds two things, **building directly on WS-B1 — reusing its
deletion primitives and `compose_teardown`, not re-implementing them**:

1. **Filesystem-vs-DB reconciler** — a bounded, logged, idempotent sweep (run by the
   worker, deleting as root through WS-B1's in-control-plane path) that scans the `auth/`,
   `git/worktrees/`, `compose/` roots, cross-references the `workspaces` table, and reaps
   directories whose row no longer exists. Orphaned `compose/` dirs also get a
   stack + volume teardown via WS-B1's `compose_teardown` path first.
2. **Readiness-driven reaper** — make `orphan_resources` `cleanup_ready` / `terminal`
   classification able to drive an *actual* reap (compose down + filesystem removal) behind
   a config flag `auto_cleanup_orphans` (**DEFAULT OFF**). Flag off ⇒ behavior unchanged
   (report only, `dry_run_only=True`).

### Out of scope / non-goals (explicit)
- **No edits to `src/awf/node/auth_mounts.py`** (that is WS-A).
- **No preserved-failed age cap and no worktree-remove idempotency fix** (those are WS-B3,
  running in parallel). In particular **do not touch `_classify_workspace_for_gc`** in
  `gc.py`. Any change to `gc.py` lands in *new* functions / a clearly separated section.
- Do not re-implement WS-B1's deletion-through-root, `_delete_gc_path`, or
  `_service_gc_compose_teardown` / `ComposeManager.teardown_project` — call them.
- No new REST/CLI/MCP surface is required (the sweep is worker-internal); the existing
  `POST /v1/service/gc` is untouched. (If a manual trigger is later wanted it is a
  follow-up, not this PR.)

## Reused WS-B1 / existing mechanisms (do not duplicate)
- `awf.service.gc_classify._delete_gc_path(target, work_dir=...)` → permission-aware,
  safe-root-checked deletion returning `(deleted, error, failure_reason_code)` with reason
  codes `PATH_DELETED` / `PATH_ALREADY_REMOVED` / `PATH_DELETE_PERMISSION_DENIED` /
  `PATH_DELETE_FAILED`. This already gives us the **loud permission-denied failure**
  (never a silent success) and idempotent already-removed handling required by the task.
- `awf.service.gc_classify._gc_path` / `WorkspaceGCPath` / `_is_safe_gc_path` — path
  modelling + the safety guard that refuses to delete outside the three GC roots / symlinks
  / non-dirs.
- `awf.node.compose_manager.ComposeManager.teardown_project(project_name, compose_file,
  workspace_id, remove_volumes=True)` — the exact primitive WS-B1's
  `_service_gc_compose_teardown` uses to reap per-workspace docker volumes.
- `awf.service.orphan_resources` scanning + classification (`_classify`,
  `build_orphan_resource_summary`, `workspace_id_view_from_session`).
- Worker periodic-scan pattern: `self._next_<x>_scan_at = 0.0` in `__init__`, a
  `_maybe_<x>()` guard in `run_once` that checks `monotonic()` against the interval, and an
  interval on `self._config` (mirrors `_maybe_release_terminal_runtime`).

## Design

### A. `src/awf/service/gc_reconcile.py` (new module)
Pure scan/classify split from I/O reaping so the core is unit-testable without a DB.

Dataclasses (frozen):
- `OrphanDirTarget(kind: Literal["auth","worktree","compose"], workspace_id, path: Path,
  age_seconds: float)`.
- `OrphanDirReconcileResult(reaped: list[...], errors: list[...], compose_teardowns: dict,
  scanned_count, orphan_count, reaped_count, cap_limit, capped: bool, dropped_count,
  status, reason_code)` with `to_dict()` for structured logging.

Functions:
- `scan_orphan_workspace_dirs(work_dir, known_workspace_ids, *, now, min_age_hours, limit)`
  → **pure**. For each of the three roots, list `ws_*` directory entries. Map a
  companion-worktree dir name back to its parent id via
  `parent_workspace_id_from_companion_worktree_id` (same helper the detector uses) so a
  companion worktree of a *live* parent is **not** mis-classified as orphaned. A dir is an
  orphan candidate iff its (parent) id ∉ `known_workspace_ids` **AND** its directory mtime
  is older than `now - min_age_hours` (the **grace** that protects an in-flight,
  still-provisioning workspace whose row write lags the dir creation). Sort deterministically
  (oldest first), apply `limit`; if more candidates than `limit`, set `capped=True` and
  `dropped_count` — **never silently truncate**.
- `reconcile_orphaned_workspace_dirs(session_factory, *, work_dir, compose_teardown=None,
  now=None, min_age_hours=DEFAULT_MIN_AGE_HOURS, limit, execute)` → I/O entrypoint.
  - Loads the full id set: `SELECT id FROM workspaces` over **all** statuses (any existing
    row ⇒ not orphaned — deliberately broader than terminal-only so we never race a row in
    a transitional state).
  - Calls `scan_orphan_workspace_dirs`.
  - `execute=False` ⇒ plan/report only (this is the path used when `auto_cleanup_orphans` is
    off): returns the result with `status="dry_run"` and logs what *would* be reaped.
  - `execute=True` ⇒ for each compose orphan, first call `compose_teardown(target)`
    (defaulting to a small closure over `ComposeManager.teardown_project(...,
    remove_volumes=True, project_name=f"awf_{ws_id}", compose_file=<dir>/compose.yml)`),
    skipping fs deletion for that target on a non-ok teardown (record the error, mirror
    WS-B1). Then delete each target via `_delete_gc_path` (run in `asyncio.to_thread`).
    Permission denial surfaces as `PATH_DELETE_PERMISSION_DENIED` and makes the run
    `partial` — **loud, never silent success**.
  - `log()` (structlog) a single structured line summarising scanned / orphan / reaped /
    capped / dropped and one line per reaped path and per error, all carrying reason codes.
  - Idempotent: already-absent dirs return `PATH_ALREADY_REMOVED` (no-op); re-running after
    a full reap yields zero orphans.

New reason codes (added to the module + regenerated catalog):
`ORPHAN_DIR_REAP_OK`, `ORPHAN_DIR_REAP_PARTIAL`, `ORPHAN_DIR_REAP_DRY_RUN`,
`ORPHAN_DIR_REAP_CAP_HIT`. Per-path outcomes reuse the existing `PATH_*` codes.

### B. `src/awf/service/orphan_resources.py` (flip dry-run behind the flag)
- Thread an `auto_cleanup_orphans: bool = False` parameter through
  `build_orphan_resource_summary(...)` so the emitted `CleanupReadiness.dry_run_only`
  becomes `not auto_cleanup_orphans` (default `True` ⇒ unchanged) and the `action` string
  reflects whether reaping is enabled. All existing call sites keep the default ⇒ no
  behavior change unless explicitly opted in.
- Add `reap_classified_orphans(summary, *, work_dir, compose_teardown, enabled)` that, when
  `enabled` (flag on) and `summary.cleanup_readiness` is not blocked-on-unknown, reaps the
  `terminal` / `missing` classified records: compose `down` (containers/networks/volumes)
  via the same `ComposeManager.teardown_project` path and filesystem removal of `worktree`
  records via `_delete_gc_path`. When `enabled=False` it is a no-op returning a
  report-only result. Default off everywhere.
- Keep the deletion + teardown helpers shared with module A (import, don't copy).

### C. Worker wiring
- `ControlWorker.__init__`: accept an optional
  `orphan_dir_reconciler: Callable[[], Awaitable[OrphanDirReconcileResult]] | None = None`
  and init `self._next_orphan_reconcile_scan_at = 0.0`. (Injecting a prebuilt callback —
  rather than passing `work_dir`/`compose` — keeps the worker generic and the sweep
  trivially unit-testable with a fake.)
- Add `_maybe_reconcile_orphan_dirs(self)` in `control/worker/cleanup.py` mirroring
  `_maybe_release_terminal_runtime`: interval-gated, transient-DB-connection aware (warn +
  reschedule), specific-exception handling (no bare `except Exception` swallow that hides
  reason codes), reschedules `self._next_orphan_reconcile_scan_at` after each attempt.
  Call it from `run_once` next to the other `_maybe_*` calls. No-op when the callback is
  `None`.
- `WorkerConfig`: add `orphan_reconcile_scan_interval_seconds: float = 3600.0`,
  `orphan_reconcile_max_per_scan: int = 50`, `orphan_reconcile_min_age_hours: float =
  DEFAULT_MIN_AGE_HOURS`, `auto_cleanup_orphans: bool = False`.
- `ServiceSettings` + `Settings` (`common/config.py`) + `resolve_service_settings`: add the
  same fields (env-driven, validated `gt=0` / `ge=0`), default off.
- `service/worker.py build_worker_runtime`: build the reconciler callback closing over
  `session_factory`, `work_dir`, the existing `ComposeManager`, and the flag/limits, and
  pass it (+ the new `WorkerConfig` fields) into `ControlWorker`. When
  `auto_cleanup_orphans` is off the callback runs `execute=False` (report/log only); when on
  it runs `execute=True`.

**Single kill-switch decision (assumption, documented):** `auto_cleanup_orphans` (default
OFF) gates *actual deletion* for **both** the worker reconcile sweep (A) and the
readiness-driven reaper (B). With the flag off, the sweep still runs but in report/dry-run
mode so operators get visibility into what would be reaped (the locked "report only"
behavior); with it on, both actually reap. This is the safest reading of "DEFAULT OFF" and
avoids surprising default-on disk deletion. Alternative (sweep always-executes, only B
gated) is noted under Risks.

## Tests to write first (strict TDD — red before green)

New: `tests/unit/service/test_gc_reconcile.py`
1. **Reaps a row-less dir** — create `work_dir/auth/ws_X`, `git/worktrees/ws_X`,
   `compose/ws_X/compose.yml` with old mtime; `known_workspace_ids` empty; `execute=True`,
   fake `compose_teardown` returning ok. Assert all three dirs deleted, compose teardown
   called once with `remove_volumes=True`, status ok, reason `ORPHAN_DIR_REAP_OK`.
2. **Leaves a dir with a live/provisioning row** — id ∈ `known_workspace_ids`: not reaped.
   Separately, a **row-less but too-young** dir (mtime within grace): not reaped even though
   row-less (proves the provisioning race is safe). Companion-worktree dir of a live parent:
   not reaped.
3. **Permission denied is loud** — monkeypatch `_delete_gc_path` (or use a 0500 parent on a
   non-root test) to raise/return `PATH_DELETE_PERMISSION_DENIED`; assert the result is
   `partial` with `ORPHAN_DIR_REAP_PARTIAL` and the error carries
   `PATH_DELETE_PERMISSION_DENIED` — never reported as success.
4. **Bounded / logged cap** — more orphan dirs than `limit`: `capped=True`,
   `dropped_count>0`, only `limit` reaped, `ORPHAN_DIR_REAP_CAP_HIT` logged (assert via
   caplog/structlog capture); nothing silently dropped.
5. **Idempotent** — run twice; second run finds zero orphans / `PATH_ALREADY_REMOVED`,
   status ok.
6. **Dry-run** — `execute=False`: nothing deleted, `status="dry_run"`,
   `ORPHAN_DIR_REAP_DRY_RUN`, planned targets still listed.
7. **Compose teardown failure** — fake teardown returns non-ok: compose fs dir is skipped,
   error recorded, run `partial`.

`tests/unit/service/test_orphan_resources.py` (extend)
8. **Flag off (default)** — `build_orphan_resource_summary(...)` ⇒
   `cleanup_readiness.dry_run_only is True` (unchanged); `reap_classified_orphans(enabled=
   False)` is a no-op (no deletion calls).
9. **Flag on** — `dry_run_only is False`; `reap_classified_orphans(enabled=True)` reaps the
   terminal/missing worktree + compose records (teardown + `_delete_gc_path` invoked),
   leaves `expected`/`unknown` untouched, and surfaces a permission-denied as a loud error.

`tests/unit/control/test_worker_parts/` (new part, mirroring the terminal-runtime tests)
10. **Interval gating** — `_maybe_reconcile_orphan_dirs` invokes the callback only when
    `monotonic() >= _next_orphan_reconcile_scan_at`, then reschedules; no-op when callback
    is `None`.
11. **Transient DB error** — callback raising a transient DB-connection error ⇒ warn +
    reschedule, no raise; a non-transient error is logged with reason code and re-raised
    (no bare-Exception swallow).

Config tests (extend existing `tests/unit/.../test_config*` for service/common):
12. New settings parse from env, defaults are off / sane, and `build_worker_runtime` passes
    them into `WorkerConfig` and only builds an executing reconciler when
    `auto_cleanup_orphans` is true (otherwise report-only).

Coverage: every new branch (reap, leave-live, leave-young, perm-denied, cap, dry-run,
teardown-fail, flag on/off, interval gate, transient vs fatal) is covered by the tests
above. Genuinely unexecutable defensive lines (e.g. a `TYPE_CHECKING` import or an
unreachable `else`) get a documented `# pragma: no cover` rather than a hollow test.

## Risks & assumptions
- **Destructive sweep.** Mitigated by: row-less-only, all-statuses id set (any row ⇒ keep),
  minimum-age grace, `_is_safe_gc_path` root guard, `auto_cleanup_orphans` default-OFF
  kill-switch, and bounded+logged batches. Worst case with flag off is logging only.
- **Provisioning race** (dir created before row commits) — handled by the grace window;
  test #2 proves a young row-less dir is left alone.
- **Single kill-switch decision** — gating the worker sweep behind the same default-off flag
  means the 188 GB leak is not auto-fixed until an operator opts in. Accepted as the safe
  default; the report-only mode still surfaces the leak. If review prefers the sweep to
  always execute (only B gated), that is a one-line change to the wiring.
- **Compose-file path for row-less dirs** — assume `<work_dir>/compose/<id>/compose.yml`
  and project `awf_<id>` (the standard layout WS-B1 already relies on); a missing compose
  file makes teardown a safe no-op skip before the fs removal.
- **Multi-node** — like the existing terminal-runtime sweep, this assumes single-node
  (Phase 1). The scan operates on the local `work_dir`; a comment notes the multi-node
  follow-up.
- **Reason-catalog gate** — new codes must be registered/regenerated or CI's catalog drift
  check fails; included in validation.
