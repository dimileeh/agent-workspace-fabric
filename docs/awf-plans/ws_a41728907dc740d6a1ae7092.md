# Implementation Plan: P1 API Contract Slice (v1 Compatibility)

## Goal
Implement a narrow P1 API contract slice to maintain legacy (v1) API compatibility while preparing for a documented v2 cutover. We will use strict TDD to guarantee that existing endpoints continue to return their expected response envelopes, fields, and idempotency behavior.

## Intended Files/Modules to Touch
- **Tests:**
  - `tests/unit/api/test_v1_compatibility.py` (New file for contract tests)
  - `tests/unit/api/test_v1_idempotency.py` (New or existing, depending on layout)
- **Implementation:**
  - `src/awf/api/schemas/` (or equivalent location for Pydantic/response models)
  - `src/awf/api/endpoints/` (API endpoint implementations, adding schema defaults/guards)
  - Existing v1 route modules to add/ensure compatibility guards.

## Tests to Write First (TDD)
We will implement failing tests that verify legacy response envelopes, backward-compatible fields, and idempotency behavior for the following endpoints:
1. `create`: Assert legacy response envelope.
2. `list`: Assert legacy response envelope and pagination.
3. `status`: Assert legacy response envelope and status enum.
4. `detail`: Assert legacy response envelope and required fields.
5. `logs`: Assert legacy response envelope.
6. `operations`: Assert legacy response envelope.
7. `merge-queue`: Assert legacy response envelope.
8. **Idempotency tests**: Verify idempotent behavior for mutable endpoints where applicable (e.g., `create`, `operations`).
9. **v1/v2 expectations**: Documented v1/v2 compatibility expectation tests confirming backwards-compatible defaults are preserved.

## Validation Commands
```bash
uv run --python 3.12 --extra dev ruff check src/awf tests/unit/api
uv run --python 3.12 --extra dev mypy src/awf
uv run --python 3.12 --extra dev pytest tests/unit/api -q
```

## Risks, Assumptions, and Explicit Non-Goals
### Risks
- Accidental changes to legacy Pydantic schemas might break downstream v1 clients.
- Misunderstanding of legacy vs. v2 envelope expectations could cause test fragility.

### Assumptions
- The application uses Python 3.12 and modern typing (e.g., FastAPI, Pydantic, mypy).
- Existing `uv` configuration is intact and able to run test tools.
- Idempotency mechanisms currently exist or can be asserted at the API contract level without full backend implementations.

### Explicit Non-Goals
- **Do not** remove fields from existing clients.
- **Do not** begin a v2 API cutover (all work is isolated to ensuring v1 remains stable).
- **Do not** lower test coverage, `fail_under` thresholds, workspace coverage requirements, or PRD quality gates.
- **Do not** modify un-requested domains or make architectural changes beyond strict API contract compatibility.
