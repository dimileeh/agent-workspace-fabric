# Plan: Local Resource Reservation Accounting

## Objective

Finish the local scheduler accounting slice for CPU, memory, disk, and DinD
pressure without introducing multi-node or GKE scheduling. The implementation
should persist per-workspace reservations, compute active steady/peak usage and
available local capacity truthfully, expose pressure reasons through the API and
console, and release reservations idempotently when workspaces reach terminal
cleanup. Owned-path overlap must remain advisory and must not become an
admission blocker.

## Intended Files And Modules To Touch

### Production

- `src/awf/db/models.py`
  - Extend `ResourceReservation` with a local DinD pressure dimension, likely
    `dind_slots: int` with default/backfill `0`.
  - Include `dind_slots` in `Workspace.active_resource_reservation`.

- `migrations/versions/<new>_resource_reservation_dind_slots.py`
  - Add the `resource_reservations.dind_slots` column.
  - Backfill existing rows to `0` and keep downgrade symmetrical.

- `src/awf/db/repositories.py`
  - Accept and persist `dind_slots` in `ResourceReservationRepository.create`.
  - Keep `release_active_for_workspace` idempotent; add explicit coverage for
    repeated release calls and terminal/destroy cleanup paths.

- `src/awf/common/config.py` and `src/awf/service/config.py`
  - Add local capacity settings used as the truth source when configured:
    `local_capacity_cpu_cores`, `local_capacity_memory_gb`, and
    `local_capacity_dind_slots`.
  - Add or document the existing disk truth source as `DiskCheck.free_bytes`;
    do not invent host disk capacity when the check is unavailable.
  - Add a default logical disk reservation setting only if required for legacy
    rows; otherwise leave omitted `disk_mb` as "not reserved".

- `src/awf/service/workspaces.py`
  - Extend `ResourceReservationPlan` and `resource_reservation_plan()` with
    `disk_mb` and `dind_slots`.
  - Derive `dind_slots=1` from an explicit or inline profile whose
    `docker.mode` is `dind`; use `0` when the profile is known non-DinD.
  - For `profile_ref="auto"` rows where DinD is not known until provisioning,
    mark the queue-decision resource summary as `dind_mode="unknown"` and let
    provisioning update the active reservation once the profile is resolved.
  - Include request, active capacity snapshot, and pressure reason fields in
    durable `QueueDecision.resource_summary`.
  - Keep `QueueDecision.decision="admitted"` for owned-path overlap; overlap
    must stay in `overlap_risk_summary`.

- `src/awf/node/provisioner.py`
  - After resolving an `auto` profile, update or replace the active reservation
    to reflect the resolved DinD requirement before transitioning to `ready`.
  - Keep this update idempotent if a provisioner retry sees the same resolved
    profile again.

- `src/awf/service/metrics.py`
  - Extend `ReservedResources` to include `disk_mb` and `dind_slots`.
  - Add a capacity/pressure summary that reports, per dimension:
    `limit`, `reserved`, `available`, `available_after_next_default`, and
    `reason_code` when saturated or unknown.
  - Preserve steady and peak CPU/memory separately.
  - Continue excluding released reservations and terminal workspaces; keep the
    "latest active reservation per workspace" rule.

- `src/awf/api/schemas.py` and `src/awf/api/routes/metrics.py`
  - Serialize `dind_slots` in workspace reservation responses.
  - Add typed response models for the expanded resource capacity and pressure
    summaries.
  - Keep existing disk admission failure shape, while adding richer pressure
    reasons to the metrics endpoint.

- `src/awf/api/routes/workspaces.py`
  - Pass the already-collected disk check into v2 creation so the queue-decision
    resource summary can record disk pressure context without re-checking.
  - Preserve idempotent replay behavior under disk pressure.

- `apps/console/lib/types.ts`
  - Add TypeScript fields for `dind_slots`, disk reservations, capacity
    dimensions, and pressure reasons.

- `apps/console/components/console-dashboard.tsx`
  - Extend the existing Resource / Capacity panel to show reserved and
    available CPU, memory, disk, and DinD slots.
  - Surface pressure reason badges using existing compact panel patterns.

   profile resolution.

## Risks And Assumptions

- Assumption: this slice keeps the current local queue model. A workspace may
  be accepted into `requested` while pressure is visible; this plan does not add
  a new `queued` workspace status or worker deferral loop.
- Assumption: configured local CPU, memory, and DinD limits are the truthful
  source for those dimensions. If unset, AWF must report availability as
  unknown instead of guessing from the host.
- Assumption: disk availability comes from the existing `DiskCheck` free-byte
  result. Disk reservations are logical scheduler reservations, not measured
  per-workspace disk usage.
- Assumption: `dind_slots=1` is sufficient for this narrow local slice; future
  weighted DinD accounting can build on the integer field.
- Risk: `profile_ref="auto"` cannot know DinD mode until the worktree exists.
  The provisioner reconciliation test should prevent long-lived false
  accounting after profile resolution.
- Risk: adding a migration requires updating both SQLAlchemy models and Alembic
  graph tests; keep the schema diff to the one new column.
- Risk: capacity payload shape changes may require careful console type updates
  to avoid TypeScript drift.
- Risk: old active rows without the new reservation dimensions need conservative
  fallback behavior. Report fallback counts where possible rather than hiding
  them.

## Explicit Non-Goals

- Do not implement multi-node placement, GKE scheduling, node pools, or bin
  packing.
- Do not add fairness, starvation prevention, human boost, retry-aware scoring,
  or a new scheduler queue state in this slice.
- Do not make owned-path overlap block workspace submission, provisioning, or
  execution.
- Do not implement explicit exclusive resource locks.
- Do not replace the existing disk admission guard or hide disk failures behind
  retries.
- Do not add real-time cgroup/container telemetry; this is reservation
  accounting, not runtime metering.
- Do not lower coverage targets, ruff, mypy, or console quality gates.
- Do not touch unrelated docs, lockfiles, branch management, push behavior, or
  PR monitor merge policy.
- Do not commit during the planning phase.
