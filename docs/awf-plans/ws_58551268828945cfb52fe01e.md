# Implementation Plan: Workspace Services Compose Execution

## 1. Intended files/modules to touch

*   **Node Layer:**
    *   `src/awf/node/compose_manager.py`: Enhance compose file copy/rendering, project directory handling, service environment and port propagation, health wait behavior, and deterministic cleanup.
*   **Profiles Layer:**
    *   `src/awf/profiles/compose.py`: Update profile handling for docker compose to map the required context, ports, and environment correctly.
*   **Runtime Layer:**
    *   Target runtime orchestration paths (e.g. `src/awf/runtime/workspace_services.py` if present, or wherever profiles are invoked in `src/awf/runtime`) to gracefully handle Docker-unavailable skips and structured failure reason codes.

## 2. Tests to write first (TDD Approach)

*   **`tests/unit/node/test_compose_manager.py` & `tests/unit/node/test_compose_manager_subprocess.py`:**
    *   Add failing tests for:
        *   **Compose file copy/rendering:** Ensure templates/variables are properly substituted and copied into the correct workspace subpath asynchronously or via asyncio.to_thread to avoid blocking the event loop.
        *   **Project directory handling:** Assert that the compose execution context runs in the specified working directory.
        *   **Service environment and port propagation:** Verify environment variable passthrough and mapped port configurations.
        *   **Health wait behavior:** Ensure timeout/health checks on compose services are verified before returning success.
        *   **Deterministic cleanup:** Verify all related docker resources are torn down regardless of execution success or failure.
        *   **Docker-unavailable skips:** Ensure a graceful skip (not a catastrophic crash) when the Docker socket is missing.
        *   **Structured failure reason codes:** Ensure `ComposeExecutionError` or similar exceptions expose parsable exit codes/reasons.
*   **`tests/unit/runtime/test_workspace_services_compose.py`:**
    *   Add tests to confirm runtime properly routes DinD execution for workspace-services profiles.

## 4. Risks, Assumptions, and Explicit Non-Goals

*   **Risks:**
    *   *Cleanup Collisions:* Deterministic cleanup of compose resources might inadvertently stop or prune containers from other concurrently running services if labels/project names are not uniquely scoped per workspace/run.
    *   *Health Check Hangs:* Improper health wait behavior could cause zombie processes or hang the pipeline indefinitely if not bounded by strict timeouts.
*   **Assumptions:**
    *   The environment running these paths acts as a DinD (Docker-in-Docker) host, meaning `/var/run/docker.sock` is either mounted or the `DOCKER_HOST` environment is available, unless testing the unavailable skip branch.
    *   The `uv` commands run in a Python 3.12 environment with dev extras as specified.
*   **Explicit Non-Goals:**
    *   No Aira-specific assumptions; AWF core must remain completely generic.
    *   Do not decrease overall test coverage, `fail_under` metrics, or bypass PRD quality gates.
    *   No modifications to non-relevant areas (lockfiles, migrations, unrelated configuration).
    *   Do not push or commit directly (handled by AWF post-agent).
