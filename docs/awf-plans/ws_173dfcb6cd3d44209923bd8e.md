# Plan: P0 Stranded Workspace Recovery

## Goal

Implement a narrow P0 recovery slice for active workspace rows whose managed
runtime has disappeared or whose agent container is no longer running. The
implementation must detect this without crashing operator-facing status,
metrics, workspace runtime, or workspace detail surfaces, and must make the
safe recovery decision:

- `monitoring_pr` workspaces with an open PR stay recoverable and eligible for
  remonitor/resume.
- Pre-PR workspaces become `failed` with an actionable structured reason unless
  an explicit retry policy is present.
- Logs, worktrees, compose files, volumes, and PRs are preserved.

## Current Anchors

- Runtime snapshots are produced by `src/awf/runtime/inspection.py`.
- Workspace runtime/detail is served through `src/awf/service/workspaces.py`,
  `src/awf/api/routes/runtime.py`, and `src/awf/api/schemas.py`.
- Service status already gathers DB workspace snapshots and Docker resource
  inventory in `src/awf/service/status.py`, `src/awf/service/orphans.py`, and
  `src/awf/service/orphan_resources.py`.
- Metrics capacity accounting lives in `src/awf/service/metrics.py` and
  `src/awf/api/routes/metrics.py`.
- The worker already has a stale active execution recovery loop in
  `src/awf/control/worker.py`; extend this path rather than adding a second
  mutating watchdog.
- Remonitor recovery already exists in `src/awf/service/controls.py` via
  `WorkspaceControlService.remonitor_workspace`.

Implementation:

- `src/awf/service/workspace_runtime_health.py` (new)
  - Add the small shared classifier and dataclasses:
    `WorkspaceRuntimeFinding`, `WorkspaceRuntimeDecision`,
    `WorkspaceRuntimeHealthSummary`.
  - Reason codes:
    `STRANDED_WORKSPACE`, `AGENT_CONTAINER_MISSING`,
    `AGENT_CONTAINER_EXITED`, and `RUNTIME_INSPECTION_UNAVAILABLE`.
  - Decision values:
    `none`, `fail_workspace`, `remonitor_workspace`, and `defer_retry_policy`.
  - Classify from a DB workspace snapshot plus either a `RuntimeSnapshot` or a
    Docker resource inventory row.
  - Treat `requested` rows with no persisted compose metadata as not yet
    provisioned, not stranded; once a compose project or post-requested status
    exists, missing runtime resources are actionable.
- `src/awf/runtime/inspection.py`
  - Preserve current Docker CLI behavior, but return enough structured data to
    distinguish no containers, agent service missing, and agent service
    non-running.
  - Keep CLI failures as non-crashing `unavailable` snapshots.
- `src/awf/api/schemas.py`
  - Add a compact optional runtime health response model and expose it on
    `WorkspaceRuntimeResponse`.
  - If feasible without per-request Docker scans, expose the latest persisted
    runtime finding on `WorkspaceResponse` as `runtime_health`; otherwise keep
    workspace detail coverage to persisted failure/event data and put live
    inspection on the runtime endpoint.
- `src/awf/service/workspaces.py`
  - Use the classifier in `get_runtime()`.
  - Include structured `reason_code`, decision, status, message, and services
    in the runtime response.
  - Do not mark workspaces failed from read-only runtime/detail calls.
- `src/awf/service/status.py`
  - Extend `_default_workspace_id_lookup()` snapshots with `pr_url` and enough
    compose metadata for runtime classification.
  - Add a `stranded_workspaces` check alongside existing orphan checks.
  - Keep orphan resource cleanup readiness separate from active-workspace
    stranding.
- `src/awf/service/orphans.py` or `src/awf/service/orphan_resources.py`
  - Reuse existing Docker list parsing where practical, adding service/state
    fields only if the shared classifier needs them.
- `src/awf/service/metrics.py`
  - Add runtime health counts to the resource saturation summary, such as
    `stranded_count`, `recoverable_count`, and `reason_counts`.
  - Keep existing `active_total` semantics backed by DB status; pre-PR rows
    leave active accounting once the worker marks them failed.
- `src/awf/api/routes/metrics.py`
  - Serialize the new runtime health metrics if service models change.
- `src/awf/control/worker.py`
  - Replace the current stale-active-execution-only runtime logic with the
    shared classifier.
  - Extend detection to the requested statuses from the task:
    `requested`, `provisioning`, `ready`, `running`, `validating`, `pushing`,
    and `monitoring_pr`.
  - For `fail_workspace`, transition to `failed` with
    `FailureReason.infrastructure_failure`, clear stale execution/monitor
    claims, and write a `workspace.runtime_stranded_detected` event carrying the
    structured reason. Do not stop or remove containers/worktrees/logs.
  - For `remonitor_workspace`, leave the workspace in `monitoring_pr`, record an
    event, clear stale monitor claims if needed, and let the existing monitor
    resume/remonitor path pick it up.
  - Add a narrow retry-policy hook that defaults to false. If a future explicit
    policy is present, record `defer_retry_policy` rather than failing.
- `src/awf/db/enums.py`
  - Not expected to change. Use `FailureReason.infrastructure_failure` plus
    event `reason_code` for the new structured runtime codes.
- `src/awf/db/models.py` and migrations
  - Not expected to change. Prefer events and existing failure fields over new
    columns for this slice.

   - Add a summary input or provider for runtime health findings.
   - Assert resource saturation output includes stranded/recoverable counts and
     reason counts.
   - Assert active DB counts remain unchanged in read-only metrics, while
     pre-PR rows marked failed by the worker are no longer active.

5. Worker recovery tests in `tests/unit/control/test_worker.py`.
   - A stale `running` workspace with missing compose/agent transitions to
     `failed`, stores `failure_reason="infrastructure_failure"`, includes the
     runtime reason code in `failure_message`/event payload, and preserves
     compose/worktree metadata.
   - A stale `monitoring_pr` workspace with `pr_url` records a recoverable
     runtime event, clears stale claims, remains `monitoring_pr`, and can be
     claimed for monitor resume.
   - A `monitoring_pr` workspace without `pr_url` follows the failure path.

## Implementation Sequence

1. Add the failing tests above, starting with the pure/service classifier tests.
2. Implement the shared runtime health dataclasses and classifier.
3. Update runtime inspection/serialization so missing and exited agent states
   produce structured findings without raising.
4. Wire the classifier into `WorkspaceService.get_runtime()`.
5. Add status aggregation using existing Docker list helpers and the expanded
   DB workspace snapshot.
6. Add metrics aggregation and response fields only after the service status
   path is green.
7. Refactor `ControlWorker` to call the shared classifier and make the safe
   recovery decision for stale active rows.
8. Keep recovery mutations minimal: fail only pre-PR cases, preserve all
   runtime artifacts, and reuse the existing monitor resume/remonitor flow for
   PR workspaces.
9. Run targeted validation, then full unit/lint/typecheck.
10. Commit locally in the implementation phase with a conventional commit
    after validation passes. No commit is made during this planning phase.

## Risks And Assumptions

- There is no implemented automatic retry policy for active runtime stranding
  today. The default behavior should therefore fail pre-PR rows with actionable
  infrastructure failure metadata; the classifier should leave a small explicit
  hook for future retry policy.
- A brand-new `requested` workspace with no compose metadata is normal queue
  state, not a stranded runtime. Detection should become actionable for
  `requested` only when persisted compose/runtime metadata says AWF had already
  created a managed stack.
- Docker can be unavailable while status or metrics are requested. This must
  produce `RUNTIME_INSPECTION_UNAVAILABLE` or scanner-unavailable payloads, not
  exceptions or destructive recovery.
- A running sidecar does not prove the agent is alive. If the compose project
  exists but the `agent` service is missing or exited, classify it as stranded.
- Existing orphan cleanup checks classify resources with no live DB owner. The
  new detector classifies live DB rows with no healthy runtime. These are
  related but distinct and should remain separate in operator payloads.
- Worker recovery should be conditional on stale/missing claims so it does not
  race an actively heartbeating executor or monitor.
- Adding optional response fields is acceptable; changing or removing existing
  fields is not.

- Do not remove containers, networks, volumes, logs, worktrees, compose files,
  or artifacts as part of this recovery slice.
- Do not add a broad cleanup policy, secret broker behavior, scheduler rewrite,
  or merge queue redesign.
- Do not introduce a new failure enum unless existing `FailureReason` cannot
  carry the terminal failure; prefer structured event reason codes.
- Do not change branch management, run git checkout/switch, push, rebase, or
  force-push.
- Do not lower coverage, ruff, mypy, or validation thresholds.
