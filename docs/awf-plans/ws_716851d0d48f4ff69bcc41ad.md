# AWF Self-Dogfood Parallel Final Coverage Determinism Plan

Workspace: `ws_716851d0d48f4ff69bcc41ad`

## Problem Statement

AWF needs deterministic workspace-local full coverage support for AWF self-dogfood fallback and for future projects that opt into local full gates, without making ordinary targeted edit validation run full coverage. The specific regression to protect is a parallel coverage command such as:

```bash
pytest -n 3 --dist=loadscope --cov=awf --cov-report=term-missing
```

reporting coverage above the configured 99% threshold while pytest exits nonzero with test errors/timeouts. AWF must classify that as validation/test failure with failing node IDs/evidence when available, not as infrastructure failure, stale execution, cleanup failure, or a pure coverage-threshold failure.

GitHub Actions remains the authoritative full coverage gate for PR-monitored AWF work. This slice only keeps AWF Core capable of explicit workspace-local final coverage gates.

## Requirements Checklist

- Diagnose current xdist/local runtime determinism gaps for AWF self-profile coverage.
- Prefer root-cause fixture/runtime-helper fixes over broad skips.
- Use explicit serial grouping/locking only for genuinely shared Docker/Postgres/global-state tests, with a test-level reason and regression coverage.
- Preserve the 99% AWF coverage target.
- Keep full coverage out of ordinary targeted edit validation.
- Ensure coverage-at-threshold plus pytest nonzero is recorded as validation/test failure with reason metadata and evidence.
- Preserve GitHub Actions final gate semantics for PR-monitored workspaces.
- Keep changes narrow; do not rewrite scheduler, PR monitor, provider recovery, merge queue, profile parsing, or unrelated dependency behavior.

   - Capture failing node IDs and classify each failure as fixture cleanup, Postgres schema lifecycle, Docker/global-state, timeout, or parser/classification issue.
   - Do not add skips. For each failing node, either make fixture cleanup deterministic, isolate the shared resource with an explicit reason, or document why it is already covered by an existing helper.

2. Add the failing regression tests listed above before implementation changes.
   - Prefer helper-level tests first because they are fast and narrow.
   - Add a persistence/fix-cycle test only if helper-level coverage does not prove validation-run classification end to end.

3. Tighten coverage failure parsing/classification in `src/awf/runtime/validation.py`.
   - Recognize xdist pytest `FAILED` and `ERROR` summary forms, including timeout/error lines that carry node IDs.
   - Preserve bounded fallback evidence for worker crashes/timeouts when node IDs are unavailable.
   - Keep coverage percent parsing and provider fail-under parsing authoritative.
   - Ensure a nonzero pytest coverage command with passing coverage records pytest failure evidence and sets the command result reason to `PYTEST_TEST_FAILURE`.

4. Tighten executor local-final-gate semantics in `src/awf/control/executor.py`.
   - Ensure targeted edit validation continues to call profile phases with `include_coverage=False`.
   - Ensure local full coverage is executed only for explicit workspace-local coverage final gates with a declared coverage command.
   - Ensure validation-run reason codes and user-facing failure messages prioritize pytest failure evidence over coverage success or baseline debt.

7. Validate against the saved plan.

## Risks And Assumptions

- The active coordination warning overlaps `src/awf/runtime/validation.py`, `src/awf/control/executor.py`, and `tests/unit/runtime/test_validation.py`; keep edits narrow to reduce stale-overlap risk.
- Docker may be unavailable in this workspace. Docker-dependent failures should be isolated only when tests actually require Docker, not skipped broadly.
- The AWF-provided Postgres service is shared by tests through `$AWF_TEST_DATABASE_URL`; schema allocation and cleanup must remain deterministic under xdist.
- Some xdist failures may be real product/test bugs outside the initial suspected files. Fix the smallest root cause that makes the failing test deterministic.
- Full local coverage may take significantly longer than focused validation. GitHub Actions remains the final authority for PR-monitored AWF full coverage.
- Existing parser behavior already handles some coverage-wrapped pytest failures; the likely implementation is tightening edge cases and persistence semantics, not rewriting validation.

## Explicit Non-Goals

- Do not add dependency workarounds unrelated to pytest-xdist/coverage determinism.
