## Implementation Plan: P1 MCP artifact content/download parity slice

### Goal
Add a bounded MCP tool `awf_read_workspace_artifact` that reads the bytes of a single workspace artifact and returns them safely inside a JSON envelope, reusing the existing filesystem validation already used by the REST download endpoint. Update the parity matrix and contract registry so the gap is closed.

### Out of scope
- Changing REST artifact download behavior (`GET /v1/workspaces/{workspace_id}/artifacts/download`).
- Adding shell/exec, unbounded streaming, or BlobContent transport.
- Modifying workspace artifact storage layout.

### Files/modules to touch
1. `src/awf/service/artifacts.py`
   - Add `MAX_ARTIFACT_CONTENT_BYTES = 1_048_576` constant.
   - Add `ArtifactOversizedError(ValueError)` exception.
   - Add `get_workspace_artifact_content(*, workspace_id, artifact_dir, relative_path, limit_bytes)` → reads validated artifact bytes, raises `ArtifactPathError`, `ArtifactNotFoundError`, or `ArtifactOversizedError`.
2. `src/awf/api/schemas.py`
   - Add `WorkspaceArtifactReadResponse` Pydantic model:
     - `workspace_id: str`
     - `relative_path: str`
     - `name: str`
     - `content_type: str`
     - `size_bytes: int`
     - `content: str` (base64-encoded bytes; generic and safe for text or binary)
3. `src/awf/mcp/server.py`
   - Import new symbols from `awf.service.artifacts` and `WorkspaceArtifactReadResponse`.
   - Register `awf_read_workspace_artifact` tool with arguments:
     - `workspace_id: str` (required)
     - `path: str` (required, relative POSIX path)
     - `limit_bytes: int` (default 65_536, ge=1, le=MAX_ARTIFACT_CONTENT_BYTES)
   - Tool logic:
     - Open DB session, check workspace existence via `WorkspaceRepository.exists`; if missing return `_error_result("NOT_FOUND", ...)`. This mirrors the artifact list tool pattern.
     - Call `get_workspace_artifact_content` inside `asyncio.to_thread`.
     - Map `ArtifactPathError` → `_error_result("INVALID_ARTIFACT_PATH", ...)`.
     - Map `ArtifactNotFoundError` → `_error_result("NOT_FOUND", ...)`.
     - Map `ArtifactOversizedError` → `_error_result("ARTIFACT_OVERSIZED", ...)`.
     - On success return `_tool_result(WorkspaceArtifactReadResponse(...).model_dump(mode="json"))`.
4. `docs/MCP_CLIENT_PARITY.md`
   - Update "Artifact content/download" row:
     - MCP tool name: `awf_read_workspace_artifact`
     - Status: `MCP implemented`
     - Backlog Slice: `—`
     - Schema / Error-Code Contract: add `ARTIFACT_OVERSIZED`
5. `tests/unit/contracts/_capabilities.py`
   - Update `workspace_artifact_download` capability:
     - `mcp_tool="awf_read_workspace_artifact"`
     - `parity_status="MCP implemented"`
     - `parity_backlog_slice="—"`
     - `error_codes`: add `"ARTIFACT_OVERSIZED"`
     - `mcp_request_fields=frozenset({"workspace_id", "path", "limit_bytes"})`
     - `mcp_required_fields=frozenset({"workspace_id", "path"})`
     - `response_fields=frozenset({"workspace_id", "relative_path", "name", "content_type", "size_bytes", "content"})`
6. `tests/unit/mcp/test_mcp_server.py`
   - Add tests for `awf_read_workspace_artifact` in the existing `TestToolRegistration` / behavior suites.
   - Tests (happy path + guards):
     - tool is registered and schema declares bounded `limit_bytes`.
     - reads a safe small file and returns base64 `content` plus metadata.
     - returns `NOT_FOUND` for missing workspace.
     - returns `NOT_FOUND` for missing file.
     - returns `NOT_FOUND` for symlink-escaped file.
     - returns `INVALID_ARTIFACT_PATH` for traversal paths (`../`, absolute, empty, backslash).
     - returns `ARTIFACT_OVERSIZED` when `size_bytes > limit_bytes`.
     - respects the `limit_bytes` ceiling (e.g. refuses 2 MiB request even if file is smaller).

### Risks and assumptions
- **Risk**: `tests/unit/contracts/_capabilities.py` cross-validation is strict; both the registry row and the parity matrix markdown must be updated in lock-step or collection-time assertions will fail.
- **Risk**: Absolute host paths must never leak through MCP error messages or response payloads; the tool must use `relative_path` and `name` only.
- **Assumption**: Base64 encoding inside a JSON `structuredContent` dict is the correct bounded-content transport for MCP in this codebase. Every other MCP tool uses `_tool_result` with a dict payload and `TextContent`, so returning a base64 string in a field keeps the transport uniform.
- **Assumption**: `WorkspaceRepository.exists` inside the MCP tool is acceptable for the DB check, mirroring the existing artifact list tool pattern.

### Explicit non-goals
- No streaming or `BlobContent` transport changes.
- No CLI command addition.
- No modification of `FileResponse` REST behavior.
- No shell, exec, or arbitrary filesystem access tools.
