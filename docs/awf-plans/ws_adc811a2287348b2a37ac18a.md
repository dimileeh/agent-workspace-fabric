# Plan — Issue #347: consolidate duplicated workspace-create orchestration

## Goal

Extract the **shared core** of the two duplicated workspace-creation code paths —
`workspace_create_profile_snapshots(...)` → `check_host_port_conflicts(...)` →
`create_workspace_row(...)` — into one helper in
`src/awf/service/workspaces_create.py`, and have **both** entry points call it.

Pure DRY refactor. **Zero behavior change**, zero error-semantics change, zero HTTP
status-code change. PR #328 confirmed both paths are independently correct; this only
removes the divergence risk flagged by Cursor Bugbot.

## Current state (what is being consolidated)

Both call sites today run the identical 3-step sequence inline:

- **REST route** — `src/awf/api/routes/workspaces.py:324-341`, inside a handler that
  *also* does rate limiting, durable idempotency replay, a disk-admission check, and the
  `try/except` HTTP error mapping (`ProfileResolutionError` → 422 `INVALID_PROFILE`,
  `TaskExternalIdConflictError` → 409, host-port conflicts → 409,
  `WorkspaceProviderReadinessBlockedError` → blocked response). Passes
  `excluding_workspace_id=None` and `node_id=effective_worker_node_id(settings)`.
- **Service** — `src/awf/service/workspaces.py:592-610`, inside `WorkspaceService.create()`,
  which *also* does the `idempotency_key` lock + `workspace_create_payload_matches` replay,
  the disk check, and the `s.commit()`. It **raises** the domain exceptions; the MCP/CLI
  layer maps them.

The 3-step core (snapshot → port-check → `create_workspace_row`) is byte-for-byte the same
in both places; that duplication is the divergence risk #347 targets.

## Design of the new helper

Add to `src/awf/service/workspaces_create.py` (next to `create_workspace_row` and
`workspace_create_profile_snapshots`):

```python
async def create_workspace_row_checked(
    session: AsyncSession,
    repo: WorkspaceRepository,
    payload: WorkspaceCreateRequest,
    *,
    idempotency_key: str | None = None,
    settings: Settings | None = None,
    disk_check: DiskCheck | None = None,
    node_id: str | None = None,
    excluding_workspace_id: str | None = None,
) -> Workspace:
    """Resolve profile snapshots once, guard host-port conflicts, and persist the row.

    Shared core of the REST route handler and ``WorkspaceService.create``. Raises the
    same exceptions the inline code did (``check_host_port_conflicts`` /
    ``create_workspace_row``); callers keep their own HTTP/exception mapping.
    """
    requested_profile, resolved_profile = workspace_create_profile_snapshots(payload)
    # Lazy import: ``awf.service.workspaces`` imports this module at load time, so a
    # top-level import here would be a cycle (matches the existing lazy-import pattern
    # used throughout this file with ``# noqa: E402``).
    from awf.service.workspaces import check_host_port_conflicts  # noqa: E402

    await check_host_port_conflicts(
        repo,
        payload.companions,
        resolved_profile=resolved_profile,
        excluding_workspace_id=excluding_workspace_id,
        node_id=node_id,
    )
    return await create_workspace_row(
        session,
        payload,
        idempotency_key=idempotency_key,
        settings=settings,
        disk_check=disk_check,
        requested_profile=requested_profile,
        resolved_profile=resolved_profile,
    )
```

Rationale for the signature: it accepts exactly what both call sites need (session, repo,
payload, idempotency_key, settings, disk_check, the already-resolved `node_id`, and
`excluding_workspace_id`) and returns the created `Workspace`. Computing the snapshot once
inside the helper and forwarding it to **both** `check_host_port_conflicts` and
`create_workspace_row` (via `requested_profile=/resolved_profile=`) keeps `create_workspace_row`
from recomputing it — the redundant double-resolution the issue calls out.

Notes:
- `check_host_port_conflicts` lives in `awf.service.workspaces`; import it **lazily** inside
  the helper to avoid the module-load import cycle (consistent with the dozens of existing
  `# noqa: E402` lazy imports in `workspaces_create.py`).
- Name `create_workspace_row_checked` is a proposal; if adjusted, keep it descriptive and
  update the re-export + `__all__` accordingly.

## Risks & mitigations

- **Import cycle**: `awf.service.workspaces` imports `workspaces_create` at module load, so the
  helper must import `check_host_port_conflicts` lazily inside the function body
  (`# noqa: E402`). Mitigated by following the file's established lazy-import pattern.
- **Unused-import lint failure in the route** after removing the three inlined imports — verified
  each is referenced only in the block being replaced; drop them in the same edit.
- **`node_id` parity**: route computes `effective_worker_node_id(settings)`, service computes it
  from `resolved_settings`; both are forwarded as the helper's `node_id` arg, preserving today's
  exact values. The helper does not compute `node_id` itself, so neither path changes.
- **`excluding_workspace_id`**: route passes `=None` explicitly today; preserved by passing
  `excluding_workspace_id=None` at that call site (service omits it → default `None`, same value).
- **Coverage**: the helper's success path and the early-raise path are both exercised by the new
  focused tests, so no new uncovered lines; no coverage-exclusion pragma needed.
- **OpenAPI drift**: untouched request/response schemas ⇒ the drift gate is unaffected.

## Assumptions

- Both paths are already behaviorally correct (per #328 deferral); this change must not alter
  observable behavior, only de-duplicate structure.
- The helper belongs in `workspaces_create.py` (next to its collaborators), re-exported through
  `awf.service.workspaces` so the route keeps importing create helpers from one place.

## Non-goals

- No change to rate limiting, durable idempotency replay, disk-admission, the idempotency-key
  lock/payload-match, or the session commit — those stay in their respective call sites.
- No change to error types, HTTP status codes, response payloads, or the OpenAPI contract.
- No renaming/restructuring beyond introducing the one helper and rewiring the two call sites.
- No move of `check_host_port_conflicts` out of `awf.service.workspaces`.
