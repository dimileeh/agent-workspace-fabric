# Implementation Plan

## Goal
Add a searchable reason-code and error-code catalog to document common API/CLI/MCP failures, likely causes, and operator fixes, ensuring future codes do not silently lack documentation.

## Intended files/modules to touch
1. `docs/REASON_CATALOG.md`: The new searchable Markdown catalog for reason and error codes.
2. `src/awf/service/doctor/reasons.py`: Enhance `_ReasonText` to include `likely_cause`, `related_command`, and `docs_link` to fulfill public catalog requirements while reusing the existing taxonomy. Update existing doctor codes with required values.
3. `tests/unit/docs/test_catalog_coverage.py`: A new pytest to enforce that all "public" reason codes have corresponding entries in `docs/REASON_CATALOG.md`.
4. `src/awf/service/readiness.py`: Update if needed to hook the catalog coverage into the `PRD_SLO_THRESHOLDS` or generic release readiness checks, or rely on the pytest for "docs-status coverage" depending on project conventions.

## Tests to write first
1. `tests/unit/docs/test_catalog_coverage.py`:
   - Write a failing test that extracts known public reason codes (keys from `_REASON_TEXT`, values from `FailureReason`, and possibly a regex/AST extraction of `reason_code="..."` assignments).
   - Assert each code is documented in `docs/REASON_CATALOG.md` (e.g., has a `### <CODE>` heading).
   - Implement a bounded allowlist for codes that are intentionally omitted, requiring a rationale string for each.

## Validation commands
- `pytest tests/unit/docs/test_catalog_coverage.py`
- `pytest tests/unit/` (to ensure `_ReasonText` changes don't break existing tests)
- `ruff check src/awf/service/doctor/reasons.py tests/unit/docs/`
- `mypy src/awf/service/doctor/reasons.py tests/unit/docs/`

## Risks, assumptions, and explicit non-goals
- **Assumption**: The catalog will be a static Markdown file (`docs/REASON_CATALOG.md`) which is easily searchable on GitHub/docs sites, rather than an API-generated dynamic page.
- **Risk**: Extracting reason codes via regex/AST could result in a large number of internal constants. The test will prioritize `_REASON_TEXT` and `FailureReason` enums and explicitly listed codes. A bounded allowlist will manage the remainder.
- **Non-goal**: Broadly rewriting CLI help output. The task specifies to "avoid broad CLI rewrites" and only expose stable docs links or helper text.
