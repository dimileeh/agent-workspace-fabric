# Plan: P0 Provider Resilience And Automated Fallback Recovery

## Objective

Implement the provider/model recovery foundation for AWF with strict TDD. This
slice should turn retryable agent-provider outages into structured recovery
decisions instead of generic terminal `agent_failure`, add provider/model
cooldowns so exhausted models are not hammered by worker or PR-monitor recovery,
and create fallback retry attempts only when the workspace policy explicitly
allows them.

This builds on the landed provider-capacity classification and no-work idle
cleanup work. It intentionally does not implement the coverage-wrapped pytest
classification bug; that is owned by another workspace.

## Intended Files And Modules To Touch

- `src/awf/adapters/base.py`
  - Extend existing provider-capacity classification to emit richer structured
    metadata for auth, quota, capacity, usage-limit, timeout, idle-timeout, and
    no-work/provider failure cases.
  - Preserve secret redaction by storing sanitized fingerprints and short stderr
    evidence only.

- New `src/awf/adapters/provider_failures.py`
  - Centralize provider/model stderr fingerprint matching so adapter-time and
    persisted-failure recovery use the same reason-code vocabulary.
  - Include existing reason codes such as `AGENT_AUTH_FAILED`,
    `AGENT_PROVIDER_CAPACITY_EXHAUSTED`, `AGENT_TIMEOUT`, and
    `AGENT_IDLE_TIMEOUT`.

- New `src/awf/service/provider_recovery.py`
  - Add dataclasses/functions for `ProviderFailureClassification`,
    `ProviderRecoveryMetadata`, fallback policy parsing, cooldown/backoff
    calculation, deterministic/no-loop decisions, and fallback target selection.
  - Analyze persisted workspace failure events/details and failure messages, not
    only fresh `AgentRunError` objects.

- `src/awf/db/models.py`
  - Add durable provider/model circuit breaker state, likely a
    `ProviderModelCircuitBreaker` table keyed by provider/model with fields for
    state, failure count, opened/cooldown-until timestamps, last reason code,
    last sanitized fingerprint, and last workspace/attempt evidence.
  - Prefer storing per-workspace recovery metadata in existing event and
    operation payload JSON, not new workspace columns, unless tests show query
    surfaces need a small indexed field.

- `src/awf/db/repositories.py`
  - Add repository helpers for circuit breaker recording, lookup, expiration,
    and provider/model dispatch suppression.
  - Add helpers for creating provider fallback retry attempts that preserve
    task/attempt/canonical-attempt lineage.

- `migrations/versions/<new>_provider_model_circuit_breakers.py`
  - Create/drop the circuit-breaker table and indexes.

- `src/awf/api/schemas.py`
  - Add v2 creation schemas for per-workspace provider fallback policy:
    approved fallback agent/provider/model entries, max fallback attempts,
    cooldown/backoff settings, and optional retry-after caps.
  - Extend failure details with recovery metadata: reason code, provider, model,
    retry eligibility, retry-after/cooldown, fingerprint, recommended action,
    fallback allowed/selected, and deterministic/no-loop terminal reason.

- `src/awf/service/workspaces.py`
  - Store fallback policy in `task_policy` during v2 creation while keeping

  - Extend `workspace_failure_details_payload()` to compact provider recovery

  - Extend retry/fallback creation so superseding attempts preserve repo/base

- `src/awf/control/executor.py`

  - Mark source workspaces failed with structured evidence, then create delayed

  - Keep deterministic no-work/non-provider agent failures terminal.

- `src/awf/runtime/pr_monitor_runner.py`

  - Stop monitor recovery loops from repeatedly invoking an exhausted model;

- `src/awf/control/worker.py`

- `src/awf/service/metrics.py` and `src/awf/api/routes/metrics.py`

## Tests To Write First

1. Provider failure fingerprint classification:
   - Auth: Gemini missing `GEMINI_API_KEY`, generic 401/unauthorized, existing
     `AGENT_AUTH_FAILED` reason code.
   - Quota/capacity: `RESOURCE_EXHAUSTED`, `MODEL_CAPACITY_EXHAUSTED`,
     `RetryableQuotaError`, HTTP 429, retry-after text, rate-limit and quota
     markers.
   - Usage-limit: Codex Spark style usage-limit messages and model-switch
     guidance.
   - Timeout/idle timeout: existing command timeout reason codes become
     retryable provider recovery metadata when provider/model is known.
   - Non-provider deterministic CLI failures remain non-retryable and have no
     fallback decision.

2. Recovery metadata derivation from persisted failures:
   - Seed failed workspace state-change events with only existing reason codes
     and stderr/message fingerprints; assert derived metadata includes reason
     code, provider, model, retryable flag, retry-after/cooldown, sanitized
     fingerprint, recommended action, and fallback eligibility.
   - Assert token-looking values are redacted or omitted from fingerprints.

3. Delayed retry/backoff/fallback decisions:
   - A retryable provider no-work failure with no fallback policy creates a new
     requested retry attempt with a not-before/cooldown policy and source
     evidence, or records a delayed retry decision if max attempts are exhausted.
   - The same failure with an approved fallback entry creates a requested
     fallback attempt using the fallback agent/model and records why that target
     was selected.
   - Max fallback attempts and repeated identical fingerprints produce terminal
     no-loop decisions.

4. Circuit breaker suppression:
   - Repeated transient capacity failures for the same provider/model open the
     circuit for a configurable cooldown window.
   - Ready/requested work using that provider/model is not dispatched while the
     breaker is open.
   - Different models or approved fallback providers remain dispatchable.
   - The breaker expires deterministically after the cooldown.

5. Non-transient failures remain terminal:
   - Plain no-work with no provider failure reason, syntax/import failures,
     validation failures, policy failures, and profile resolution failures do
     not create retry/fallback attempts and do not loop.

6. Fallback attempt inheritance and lineage:
   - Fallback attempts preserve repo URL, base branch, task title/prompt,
     external ID, task class, owned paths, validation commands, requested and
     resolved profile snapshots, `auto_merge`, review grace, task kind, monitor
     policy, planning/profile metadata, and failure evidence.
   - New `TaskAttempt` rows set `parent_attempt_id` and
     `redispatch_from_attempt_id` to the failed source attempt and supersede the
     old canonical attempt only according to existing canonical rules.

7. PR monitor recovery loop suppression:
   - A provider-capacity failure during review-comment or CI recovery records a
     provider recovery event/operation and does not repeatedly re-invoke the same
     exhausted adapter in the next monitor loop.
   - With approved fallback policy, the monitor prepares a superseding fallback
     attempt preserving monitor/review-grace policy.

8. API and metrics visibility:
   - Workspace get/list responses expose provider recovery metadata in
     `failure_details`.
   - Failure-analysis clusters classify provider auth/quota/capacity/usage-limit
     failures separately with actionable retry/fallback guidance.
   - Metrics include open circuit breaker counts/details where the current
     metrics API already has failure-analysis/capacity surfaces.

## Implementation Sequence

1. Write the adapter/provider recovery classification tests and make them fail.
2. Add the shared provider-failure classifier and wire `AgentAdapter.run()` to
   attach structured, redacted details.
3. Write service-level decision tests for persisted failure analysis,
   retry-after/backoff, fallback selection, max attempts, and deterministic
   no-loop behavior.
4. Implement `provider_recovery` policy parsing and decision logic using
   existing `task_policy` as the backwards-compatible storage for fallback
   policy and per-attempt recovery metadata.
5. Add circuit-breaker model/repository/migration and tests for open, suppress,
   expire, and per-model isolation.
6. Extend v2 API schemas and `create_workspace_v2_row()` to accept and persist
   provider fallback policy without changing legacy v1/v2 requests.
7. Extend retry/fallback attempt creation in `WorkspaceService`/repositories to
   preserve lineage and metadata, then add inheritance assertions.
8. Wire executor no-work provider failures into the recovery service. Source
   workspaces should fail with structured evidence; the recovery service creates
   a delayed retry or approved fallback attempt when allowed.
9. Wire PR monitor `AgentRunError` paths into the same recovery service so
   recovery loops defer or fallback instead of hammering an exhausted model.
10. Update worker requested/ready listing to skip attempts cooling down due to
    per-attempt retry-after or open provider/model circuit breakers, recording
    events/queue details for operator visibility.
11. Extend workspace response, failure-analysis metrics, and any existing API
    response projections to include provider recovery metadata.
12. Run focused validation, then ruff/mypy on touched Python code. In the PR
    description, explicitly call out that coverage-wrapped pytest
    classification is outside this slice.

## Risks And Assumptions

- Provider stdout/stderr varies by CLI and version. The first implementation
  should keep matchers conservative, test the incident fingerprints, and include
  generic markers only when they are clearly provider related.
- Retry-after parsing may be absent or ambiguous. Use bounded defaults from
  fallback policy/settings when no explicit retry-after exists.
- Circuit-breaker suppression must not starve unrelated providers/models or
  unrelated non-agent scheduler behavior.
- Fallback attempts should be fresh workspace attempts, not mutation of the
  failed workspace, to preserve auditability and lineage.
- PR monitor fallback from an already-open PR is inherently conservative. This
  slice should stop provider hammering and prepare a superseding attempt; it
  should not try to transplant partially repaired PR-monitor work across
  providers.
- Existing API clients without fallback policy must continue to create
  workspaces successfully and should see no behavior change unless a retryable
  provider failure is detected.
- Secret redaction is mandatory: fingerprints and events may contain reason
  text, provider, model, and hashes, but must not persist raw tokens or auth
  headers.

## Explicit Non-Goals

- Do not implement the coverage-wrapped pytest classification bug.
- Do not change unrelated scheduler fairness, resource reservation, overlap, or
  merge-queue behavior beyond provider cooldown dispatch suppression.
- Do not introduce unapproved global model routing; fallbacks must come from the
  workspace/task policy.
- Do not silently retry deterministic agent failures forever.
- Do not auto-merge, manually push, or manually resolve PR monitor feedback.
- Do not weaken validation, coverage, stale detection, review grace, or merge
  policy gates.
