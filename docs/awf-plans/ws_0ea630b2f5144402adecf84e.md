## 2. Design

New module `src/awf/host_setup/credentials.py` providing a small, injectable
backend abstraction. Nothing in this module ever prints; it returns data and
raises reason-coded errors. It never logs or returns raw secret values.

### 2.1 Backend kinds and reason codes

- Backend kinds: `"keyring"`, `"env_ref"`, `"plain_file"` (string constants,
  plus a `CREDENTIAL_BACKENDS` tuple).
- Reuse reason codes from `rendering.py` (no new codes):
  - `CREDENTIAL_BACKEND_UNAVAILABLE` — no usable backend / plain-file rejected on
    a non-Linux or non-headless host.
  - `CREDENTIAL_PLAIN_FILE_CONSENT_REQUIRED` — plain-file requested without the
    `--allow-plain-secrets` flag and/or recorded consent.
  - `CREDENTIAL_REF_INVALID` — malformed env var name, unsafe ref, or a value
    that looks like a raw secret.
  - `INTERACTIVE_INPUT_REQUIRED` — a secret/env-var input is required but absent
    in a non-interactive run (we never prompt in this module).

### 2.2 Types

- `CredentialError(RuntimeError)` — mirrors `HostSetupConfigError` /
  `SourceCheckoutError`: `reason_code`, `message`, secret-free `details`,
  `to_dict()`. Its `details` are constructed to never contain secret material.
- `CredentialRef(BaseModel, frozen, extra="forbid")` — `backend`
  (Literal of the three kinds) and `ref` (the `keyring://` / `env://` /
  `plain-file://` string). Helper `to_provider_config_fields(status=...)`
  returning the kwargs to build/update a `ProviderConfig` (so config stays the
  single writer of persisted state).
- `HostCredentialCapabilities(frozen model)` — `os_name: str`,
  `is_headless: bool`, property `supports_plain_file` (== Linux **and**
  headless). `detect_host_credential_capabilities(*, system=None, environ=None)`
  derives it from `platform.system()` and absence of `DISPLAY`/`WAYLAND_DISPLAY`
  on Linux; both inputs injectable for deterministic tests.
- `CredentialRequest(frozen model/dataclass)` — `provider: str`,
  `account: str = "default"`, `env_var: str | None`,
  `secret_source: Callable[[], str | None] | None`, `non_interactive: bool`.
  `secret_source` is a lazy callable so a value is only pulled when a backend
  actually needs it (keyring/plain_file); env_ref never pulls a value.

### 2.3 Backend protocol + implementations

`CredentialBackend(Protocol)`: `kind: str`, `is_available() -> bool`,
`create_ref(request: CredentialRequest) -> CredentialRef`.

- `KeyringCredentialBackend`
  - Lazy/optional `import keyring` (injectable `keyring_module` parameter for
    tests; never touches the real OS keychain in tests).
  - `is_available()`: import succeeds **and** the resolved keyring is not a
    null/fail backend (guarding headless Linux where keyring resolves to a
    no-op). Import failure / fail backend → `False`.
  - `create_ref()`: pulls the secret from `secret_source`; if missing and
    `non_interactive` → `INTERACTIVE_INPUT_REQUIRED`; otherwise
    `keyring.set_password(service, account, secret)` and returns
    `keyring://<service>/<account>` (service/account contain only provider/awf
    identifiers, never the secret).
- `EnvRefCredentialBackend`
  - `is_available()` → always `True` (a name pointer needs no backend).
  - `create_ref()`: requires `env_var`; if absent and `non_interactive` →
    `INTERACTIVE_INPUT_REQUIRED`. Validates the name against
    `^[A-Z][A-Z0-9_]*$` and rejects names that look like secret values (reuse
    token detection) → `CREDENTIAL_REF_INVALID`. Returns `env://<NAME>` and
    **stores no value** (e.g. `env://OPENAI_API_KEY`, `env://GH_TOKEN`).
- `PlainFileCredentialBackend`
  - Constructed with `capabilities`, `allow_plain_secrets`, `consent`, and an
    injectable `secrets_dir` (default `~/.awf/secrets`).
  - `is_available()` → `allow_plain_secrets and consent and
    capabilities.supports_plain_file`.
  - `create_ref()`: enforces, in order, (a) consent+flag else
    `CREDENTIAL_PLAIN_FILE_CONSENT_REQUIRED`; (b) Linux+headless else
    `CREDENTIAL_BACKEND_UNAVAILABLE` (details note plain-file is headless-Linux
    only — no secret); (c) pulls the secret (missing + non_interactive →
    `INTERACTIVE_INPUT_REQUIRED`); then writes the secret to
    `secrets_dir/<provider>` creating the dir `0700` and the file `0600`
    (atomic write via temp file + `os.open(..., 0o600)` + `replace`, mirroring
    `config.write_host_setup_config`). Returns `plain-file://<abs-path>`.

### 2.4 Selection / orchestration

`select_credential_backend(*, preferred, capabilities, allow_plain_secrets,
plain_file_consent, keyring_backend=None, env_backend=None,
plain_file_backend=None) -> CredentialBackend`:

- `preferred="keyring"` or `None` (auto): keyring if available, else env_ref
  (the safe default fallback). This makes **keyring the default when available**
  and gives **headless Linux without keychain an env-ref offer** without writing
  any raw secret.
- `preferred="env_ref"`: always env_ref.
- `preferred="plain_file"`: only via the gated `PlainFileCredentialBackend`
  (consent/flag/platform checks), else the matching reason-coded
  `CredentialError`.
- Unknown `preferred` → `CREDENTIAL_BACKEND_UNAVAILABLE` (or
  `CREDENTIAL_REF_INVALID`) with a secret-free detail listing valid kinds.

Thin convenience `store_provider_credential(request, *, preferred,
capabilities, allow_plain_secrets, plain_file_consent, backends...) ->
CredentialRef` = select + `create_ref`. Backends are injectable so tests use
fakes end-to-end and never hit the real keychain/OS.

### 2.5 Config metadata (minimal, backward-compatible)

In `src/awf/host_setup/config.py`, add an **optional** `backend: str | None`
field to `ProviderConfig` (validated against the three kinds when present;
default `None` preserves existing construction such as
`ProviderConfig(credential_ref=..., source=..., status=...)`). This records
*which* backend produced the ref as non-secret metadata. No new top-level
config fields; consent already lives in `ConsentConfig.plain_file_secrets`.
`CredentialRef.to_provider_config_fields()` returns `credential_ref` + `backend`
(+ caller-supplied `status`). Re-export new public symbols from
`src/awf/host_setup/__init__.py`.

### 2.6 Redaction posture (hooks needed here only; T17 owns the rest)

- The module returns only refs/metadata and reason-coded errors; it builds
  `details` from non-secret fields exclusively.
- Existing `redact_first_run_value` already redacts `keyring://`/`env://`/
  `plain-file://` refs and token shapes, so structured output is covered.
- T06 hook: ensure any internal logging (if added) routes through
  `awf.common.redaction.redact_secrets`, and add a focused regression test
  proving token-shaped inputs never surface in refs, `CredentialError.details`,
  `to_dict()`, or captured stdout/stderr. Deeper support-bundle / plain-file
  path-disclosure hardening is **T17** and out of scope here.

## 4. Tests to write first (strict TDD)

New file `tests/unit/service/test_host_setup_credentials.py`, `@pytest.mark.unit`,
using fakes (`FakeKeyringBackend`, fake keyring module, injected capabilities +
`secrets_dir=tmp_path`). All assertions check for the **absence** of a fixed
fake token such as `_FAKE_TOKEN = "sk-proj-" + "a"*48` / `"ghp_" + "b"*36`.

1. **Keyring default when available** — auto selection with an available keyring
   backend returns the keyring backend; `create_ref` yields a `keyring://…` ref.
2. **Backend unavailable → env_ref fallback** — keyring `is_available()` False
   ⇒ auto selection returns env_ref; ref is `env://<NAME>` (headless-Linux
   no-keychain path offers env ref).
3. **Env ref stores only a variable name** — `create_ref` with
   `env_var="OPENAI_API_KEY"`/`"GH_TOKEN"` returns `env://OPENAI_API_KEY`; no
   value stored; passing a token-shaped string as the env var name →
   `CREDENTIAL_REF_INVALID`; lowercase/invalid names rejected.
4. **Plain-file consent/flag gating** — `preferred="plain_file"` without
   `allow_plain_secrets` and/or `consent` → `CREDENTIAL_PLAIN_FILE_CONSENT_REQUIRED`.
5. **Plain-file permissions** — with flag+consent on a faked headless-Linux
   capability, the secret file is `0600` and `secrets_dir` is `0700`; ref is
   `plain-file://<path>`; file contents hold the secret but the returned
   ref/metadata/`details` do not.
6. **Non-Linux rejection** — `os_name="Darwin"`/`"Windows"` with flag+consent →
   `CREDENTIAL_BACKEND_UNAVAILABLE` (no file written).
7. **Non-headless rejection** — Linux but `is_headless=False` (e.g. `DISPLAY`
   set) with flag+consent → `CREDENTIAL_BACKEND_UNAVAILABLE` (no file written).
8. **Non-interactive enforcement** — keyring/plain_file with absent
   `secret_source`, and env_ref with absent `env_var`, under `non_interactive`
   → `INTERACTIVE_INPUT_REQUIRED`; module never prompts.
9. **Redaction** — token-shaped inputs never appear in the ref,
   `CredentialError.details`, `to_dict()`, or `capsys` stdout/stderr; a
   `CredentialRef`/error rendered through `redact_first_run_value` contains no
   token.
10. **Capabilities detection** — `detect_host_credential_capabilities` with
    injected `system`/`environ` classifies headless Linux, desktop Linux, macOS,
    and Windows correctly.
11. **Config integration** — `CredentialRef.to_provider_config_fields()` builds
    a `ProviderConfig`; `write_host_setup_config` → `read_host_setup_config`
    round-trips the new `backend` metadata and still rejects a raw secret value
    placed in `credential_ref` (regression for existing guard).

Adjust/extend `tests/unit/service/test_host_setup_config.py` only if the new
optional `ProviderConfig.backend` field needs explicit coverage.

## 6. Risks and mitigations

- **R1 — keyring dependency & lockfile regen.** `keyring` is absent and adding
  it edits `pyproject.toml` + `uv.lock`, which needs `uv lock`/`uv sync`
  (possibly network). *Mitigation:* the backend uses **lazy optional import +
  dependency injection**, so the code and the full test suite work whether or
  not keyring is installed (tests use fakes). If lockfile regen is infeasible in
  this workspace, fall back to **not declaring the dependency** and rely on the
  optional import (`is_available()` returns False when import fails); record the
  decision in the validation doc. Either way no behavior/test depends on the
  real library.
- **R2 — `ProviderConfig.backend` compatibility.** A new required field would
  break existing construction and persisted configs. *Mitigation:* keep it
  `Optional` with default `None`; add round-trip + back-compat tests.
- **R3 — owned-path overlap.** `OWNED_PATH_OVERLAP_RISK` flags
  `ws_4c144afc35444a9bbf88e5c6` also owning `src/awf/host_setup/__init__.py`.
  *Mitigation:* keep `__init__.py` edits purely additive (new exports only),
  keep host-capability detection **inside** `credentials.py` (no new shared
  host module), and let tests import from `awf.host_setup.credentials` directly
  to reduce coupling. Accept possible `STALE_OVERLAP` rebase if the other
  workspace merges first.
- **R4 — secret leakage.** The whole point of the task. *Mitigation:* module
  never prints/logs secrets; errors built from non-secret fields only; explicit
  `capsys` + redaction regression tests; lean on existing
  `redact_first_run_value` for any rendered output.
- **R5 — plain-file atomic write / perms portability.** *Mitigation:* reuse the
  exact pattern from `config.write_host_setup_config`
  (`os.open(..., 0o600)` + temp + `replace`, best-effort `chmod`), and gate
  plain-file to Linux only, sidestepping non-POSIX perm quirks.

## 7. Assumptions

- T02/T03 contracts (config schema, reason codes, rendering/redaction) are
  stable on `development` and are reused as-is. No new reason codes are needed.
- H02 is locked: plain-file is an opt-in fallback for Linux/headless only, after
  explicit `--allow-plain-secrets` + recorded consent; keyring and env refs are
  preferred. "Headless" = Linux with no `DISPLAY`/`WAYLAND_DISPLAY`.
- Credential *resolution* (reading values back for provider readiness) and any
  interactive prompting belong to T04/T07, not T06. T06 produces refs/metadata
  and enforces non-interactive failure for missing input.
- `keyring://` service/account identifiers use AWF/provider names only and carry
  no secret.
