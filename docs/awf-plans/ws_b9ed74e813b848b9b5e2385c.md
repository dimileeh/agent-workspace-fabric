## TDD Sequence

1. Regenerate and inspect branch coverage:
   - `uv run --python 3.12 --extra dev pytest --cov=awf --cov-branch --cov-report=term-missing`
   - Keep the failing coverage output as the source for exact uncovered lines.

2. WebSocket/log observability tests first:
   - Missing DB factory: create an app without `configure_database`, connect
     with a valid token, assert WebSocket closes with `WS_1011_INTERNAL_ERROR`.
   - Missing workspace: connect with a configured DB to an unknown workspace,
     assert an error frame with `NOT_FOUND` and policy-violation close.
   - No-events channel path: seed workspace, events, and agent/validation/service
     streams; connect with `channels=agent` and assert snapshot plus selected log
     tail only.
   - Backlog filtering: assert absent files, empty files, unselected sources, and
     source names `agent`, `validation`, `service`, and custom sources are handled
     as the route contract says.
   - Live path: use small deterministic queues/fakes to assert heartbeat frames,
     duplicate event IDs are suppressed, and selected log frames are emitted.

3. Workspaces route tests:
   - V2 idempotency replay returns the existing workspace and warnings when the
     payload matches.
   - V2 idempotency conflict catches changed nested fields including validation
     tier, agent model, out-of-scope policy, profile ref/body, auto-merge, and
     review grace.
   - Invalid profile resolution returns 422 `INVALID_PROFILE`.
   - Overview includes latest event by `occurred_at`, active operation from
     newest pending/running operation, and `None` when both are absent.
   - Retry missing and not-allowed paths return the structured 404/409 response.
   - Stored profile/policy helper behavior is covered through request/response
     where possible, with narrow helper tests only for malformed persisted
     metadata.

4. Validation provenance tests:
   - Persisted validation run with empty `commands` yields the fallback unknown
     command item.
   - Malformed command records produce safe defaults for phase, index, command,
     and stream IDs.
   - Current target SHA prefers latest merge candidate `head_sha`, then monitor
     SHA, then `None`.
   - Stream-derived provenance covers stdout-only, stderr-only, legacy `cmd_N`,
     trailing-number labels, setup prefix stripping, stream-name phase fallback,
     invalid stream kinds, open stream running/failed status, successful terminal
     status, and failed-record inference from command text or phase.
   - Malformed `resolved_profile` falls back without crashing.

5. Merge queue tests:
   - Invalid cursor values return 400 `INVALID_CURSOR` for non-base64, malformed
     JSON, missing `u`/`id`, non-string ID, and empty ID.
   - Pagination over candidate and legacy rows returns deterministic ordering,
     `has_more`, and a usable `next_cursor`.
   - Candidate responses cover blocker priority: completed,
     failed/cancelled, not canonical, policy blocked by stored flag or active
     blocking finding, stale validation tier, stale docs scope, generic stale,
     manual merge, waiting for monitor, older-candidate blocker, ready, and
     workspace-not-terminal.
   - Readiness returns `ready=false` when an active blocking policy finding
     exists, even if the candidate ready flag is true.
   - Legacy workspace responses cover monitoring with auto-merge, monitoring
     manual merge, pushing, completed, failed/cancelled, and non-terminal.

6. Smaller route/dependency tests:
   - Tasks: `GET /v1/tasks/{task_ref}/attempts` missing task 404, limit 422, and
     attempt response with/without merge candidate readiness.
   - Controls: missing/blank `Idempotency-Key`, valid weak/quoted `If-Match`,
     invalid `If-Match`, missing workspace, remonitor without PR URL, remonitor
     invalid state, idempotency conflict, and version conflict.
   - Deps: invalid/non-PostgreSQL/isolated PostgreSQL URLs, missing PostgreSQL file
     identity, no database URL fast path, unchanged identity fast path, factory
     refresh under the reconnect lock, session rollback on exception, and token
     not configured/unauthorized paths. Use explicit temporary environment
     management with `try/finally`; do not introduce pytest monkeypatch usage.
   - Artifacts: artifact root missing, root symlink, root `OSError`, extensionless
     file kind, unreadable/deleted files, escaping symlink skip, and sorted
     recursive metadata.
   - Health: DB factory absent, factory raises, session execute raises, session
     execute times out if practical with a small fake, close error suppressed,
     command runner fallback injection, docker missing binary, timeout, generic
     exception, non-zero output truncation, and success version extraction.

7. Run each new test narrow first and confirm it fails for the expected reason
   before any implementation edits. If a test covers already-correct behavior
   and passes immediately, keep it only if it asserts a real uncovered branch
   from the fresh coverage report.

8. Implement only the minimum production change needed for any genuine bug
   exposed by a red test. Otherwise, keep the change test-only.

9. If implementation work is allowed in the next phase, commit a red-test
   commit first where practical, then a green commit. Do not push.

## Risks and Mitigations

- WebSocket tests can hang if they wait for live frames without a deterministic
  publish/close path. Use bounded receives, direct small fakes for internal live
  streaming loops where necessary, and cancel background tasks in `finally`.
- Environment-backed token settings are cached. Manage `os.environ` and
  `get_settings.cache_clear()` explicitly with `try/finally`; do not add pytest
  monkeypatch usage.
- Merge queue setup can become brittle because candidate state depends on
  task/attempt/workspace relationships. Prefer existing repository helpers and
  explicit DB assertions after seeding.
- Some uncovered branches may be defensive or unreachable through public API
  routes. Cover them through narrow helper tests only when the helper has a real
  behavior contract; otherwise document why the branch remains.
- Full coverage may reveal lower-priority non-API gaps outside this scope. Keep
  this campaign focused on requested API route and observability modules.
- The repo declares a 99% coverage target, but this slice may not reach 99% by
  itself if unrelated modules remain uncovered. The goal is to materially reduce
  the requested API route gaps without weakening coverage settings.

## Assumptions

- Existing `client` and `engine` fixtures remain the primary path for request
  tests because they provide fresh isolated PostgreSQL state.
- File-system behavior can be tested with `tmp_path` and real files/symlinks.
- Small explicit fake collaborators are acceptable when they model real
  behavior and assert calls, such as a fake command runner or recording
  WebSocket object.
- Existing route dependencies and repository seams are sufficient for most
  coverage; production edits should be rare.

## Non-Goals

- Do not change `.awf/workspace.yml`, coverage configuration, `fail_under`, or
  branch coverage settings.
- Do not add fake/import-only/superficial tests or tests without meaningful
  behavioral assertions.
- Do not introduce pytest monkeypatch usage.
- Do not add broad mocks that bypass the behavior under test.
- Do not add `# pragma: no cover` except for genuinely unreachable defensive
  branches, with a specific explanatory comment.
- Do not refactor control, runtime, service, database, migration, frontend, or
  lockfile code as part of this coverage slice unless a red API test exposes a
  real route integration bug.
- Do not switch branches, push, rebase, force-push, or commit during this
  planning phase.
