# Plan — Issue #430: guard post-agent repair plan-only check with committed-output helper

## Problem

The post-agent **pre-commit semantic repair** flow in
`src/awf/control/executor/quality_methods.py` (function
`_run_post_agent_semantic_precommit_repair`, the plan-only check at ~line 970)
judges "plan-only output" from `repair_staged_paths` — the *latest staged delta*
(`git diff --cached --name-only` after the repair re-stage) — with **no
committed-output guard**.

This is the same bug class as #427 (fixed in the validation fix-pass at
`execution_validation.py:1184`). False-fire scenario: the agent **self-commits**
real implementation in earlier commits, and the post-agent semantic repair then
re-stages **only** an AWF plan/conformance artifact. The repair diff then looks
plan-only and raises `_PostAgentCommitStepError(reason_code=PLAN_ONLY_OUTPUT_REASON_CODE,
failure_reason=agent_failure)` — even though the branch's net `base..HEAD` output
contains real code. Result: a false-positive agent failure and no PR.

## Chosen policy

Apply the same committed-output guard #427 introduced, exactly as the issue's
verified prescription states. Gate the existing `_fail_if_plan_only_paths` call
behind `_committed_and_staged_output_is_plan_only` (helper at
`quality_methods.py:304`, wired via `mixins.py:104`). The helper:

- short-circuits to `False` (no git call) when the staged delta has any non-plan
  content — so the common success path is unchanged and adds zero git calls;
- when the staged delta is all-internal-plan, issues `git diff --name-only
  base..HEAD` (via `_committed_paths_since`) and returns `True` only when the
  net committed output is empty or also plan-only.

This resolves the issue's two cases correctly and does **not** weaken the genuine
gate, addressing Codex's "mask a no-op repair" caution:

- **R6** (repair removed real impl / nothing real committed): `base..HEAD` empty
  → helper `True` → STILL raises (unchanged terminal behavior).
- **R5** (real impl self-committed earlier): `base..HEAD` has real code → helper
  `False` → does NOT raise; the branch has a real PR. The "mask a no-op repair"
  worry does not apply because a no-op repair with no committed real output lands
  in R6 and still fails.

## Risks & assumptions

- **Risk: hidden queued-sequence breakage.** Any existing test that reaches the
  post-agent semantic repair plan-only check with an all-plan staged delta now
  consumes one extra runner result and will fail without it. Mitigation: run the
  whole `test_executor_post_agent_commit_parts` dir; fix only the missing-queue
  failures with the one-line empty-`base..HEAD` insertion; do not alter their
  assertions.
- **Assumption:** `_refresh_supply_chain_policy_for_workspace` (called between the
  after-repair cached diff and the plan-only check) does not consume a queued
  runner result for these all-plan inputs — confirmed by the existing
  `plan_only_change_is_blocked` test passing today without a supply-chain queue
  entry. The new `base..HEAD` diff is therefore the next queued item.
- **Assumption:** the protected-quality-gate check after the plan-only gate issues
  no runner calls for a plain plan artifact (not a protected/owned path), so R5
  proceeds straight to commit retry + rev-list. Verify when wiring R5's queue.
- **Assumption:** `worktree_path` / `base_commit` are in scope at the call site —
  confirmed (function params, used at the protected-file diff a few lines below).
