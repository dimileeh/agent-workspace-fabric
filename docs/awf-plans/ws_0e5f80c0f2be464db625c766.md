# Plan: Operator Console Filters Completion

## Goal
Add filtering for all supported agents (including `opencode`) and exact models to the AWF operator console dashboard. Ensure these filters compose correctly with existing status, search, and repo filters, and are responsive on various screen layouts. Provide Playwright test coverage for the new filters.

## Intended Files/Modules to Touch
1. `apps/console/components/console-dashboard.tsx`:
   - Add `modelFilter` state to `ConsoleDashboard`.
   - Compute `availableModels` using `useMemo` from `overview` data (`Array.from(new Set(overview.map(w => w.agent_model).filter(Boolean))).sort()`).
   - Pass `modelFilter`, `onModelFilter`, and `availableModels` into `<WorkspaceFilters />`.
   - Update `WorkspaceFilters` prop types to include the new fields.
   - Within `WorkspaceFilters`, add `"opencode"` to the list of `Agent` options.
   - Within `WorkspaceFilters`, update the grid layout (e.g., `<div className="grid grid-cols-2 sm:grid-cols-3 gap-2">`) to display a new `<Select />` for `Model` containing `["all", ...availableModels]`.
   - Update `workspaceFilterSummary` function signature and logic to append `model ${modelFilter}` to the filter summary text when it's not "all".
   - Update `filteredOverview` logic within `ConsoleDashboard` to apply client-side exact model filtering (`filtered.filter(item => item.agent_model === modelFilter)`) if `modelFilter !== "all"`.
   - Ensure the new `modelFilter` is added to the `useMemo` dependency array for `filteredOverview`.

2. `apps/console/tests/dashboard-filters.spec.ts` (New file):
   - Add Playwright tests to cover the dashboard filters behavior.
   - Mock the API similar to `theme-accessibility.spec.ts`.
   - Mock workspace data to have different agents (`opencode`, `codex`) and exact models (`gemini-3.1-pro-preview`, `ollama/glm-5.1:cloud`).
   - Validate that changing the agent filter selects the right dropdown option.
   - Validate that changing the model filter correctly limits the displayed items in the list.

## Risks, Assumptions, and Explicit Non-Goals
- **Assumption:** The `agent` filter is currently already processed locally and in the backend. "Exact model" filter is strictly client-side over the fetched 100 workspaces (i.e. "generated from workspace data"). We do not need to plumb the `agent_model` query parameter to the control plane `/api/awf/workspaces/overview` API.
- **Risk:** Filter layout breaking on very narrow screens.
  - **Mitigation:** We will use responsive Tailwind grid classes (`grid-cols-2 sm:grid-cols-3` or `grid-cols-1 sm:grid-cols-3`) to gracefully stack the Select elements.
- **Explicit Non-Goal:** Exposing `modelFilter` as a backend filtering capability in `src/awf/api/routes/workspaces.py` or modifying the control-plane data access layer.
