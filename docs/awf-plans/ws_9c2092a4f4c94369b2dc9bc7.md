# Plan — AWF #361 WS-B3: preserved-failed age cap + idempotent worktree remove

Branch: `awf/ws_9c2092a4f4c94369b2dc9bc7` · Issue: #361 (workstream WS-B3 of 4)

## Goal

Two focused, independent robustness fixes that cap per-workspace disk growth.
Reuse WS-B1's reclaim engine for any actual deletion — do **not** re-implement it.

- **FIX 1 (P2#5) — preserved-failed age cap.** Failed workspaces with preserved
  work are classified `FAILED_WORKSPACE_TRIAGE_PRESERVED` and kept *indefinitely*.
  Add a configurable `max_preserved_failed_hours` (default 720 h / 30 d). Once a
  preserved-failed workspace is older than the cap, reclaim its **pressure dirs**
  (auth, worktree, compose stack + volumes — via the existing candidate reclaim /
  `compose_teardown` path) while **keeping the durable record** (DB row,
  `WorkspaceEvent` audit log, logs). Emit a **new reason code** distinct from the
  168 h idle cleanup so the two are auditable separately.
- **FIX 2 (P2#6) — idempotent worktree remove.** `GitManager.remove_worktree`
  errors with `'is not a working tree'` when the directory exists but git
  metadata is stale, which makes GC mark the cleanup `partial`. Treat that
  specific already-removed condition as **success** (the existing
  `git worktree prune` clears the stale metadata); only a *genuine* removal
  failure should still error.

## Key findings from investigation (grounding the design)

- **GC never deletes the `Workspace` DB row.** `run_terminal_workspace_gc` /
  `run_workspace_filesystem_gc` only reap filesystem pressure dirs, compose
  stacks/volumes, reservations, and secret leases (confirmed: no `session.delete`
  / row delete anywhere in `src/awf/service`). Therefore routing an aged-out
  preserved-failed workspace into the **candidate** path automatically satisfies
  "reap pressure dirs, keep the durable record." No new "keep row" flag is needed.
- `_classify_workspace_for_gc` (`src/awf/service/gc.py:1318`) returns
  `FAILED_WORKSPACE_TRIAGE_PRESERVED` on two symmetric branches: `status ==
  failed` (line ~1373) and `status == "superseded"` (line ~1396), both when
  `_failed_terminal_workspace_has_no_work(...)` is `False` (work is preserved).
  The age cap is inserted *before* each of those `WorkspaceGCPreserved` returns.
- The bulk planner `plan_terminal_workspace_gc` fetches **all** failed/superseded
  rows via `_workspace_gc_preserved_predicate` (no age filter for default-policy
  failed/superseded — lines 589-592), so aged rows are already loaded and reach
  `_classify_workspace_for_gc`. **No SQL predicate change is required**; the age
  gate is applied in Python inside classify.
- `_classify_workspace_for_gc` has exactly two callers to thread config through:
  `plan_terminal_workspace_gc` (bulk sweep, line ~510/527) and
  `run_workspace_filesystem_gc` (single post-merge, line ~882).
- Reason-code catalog (`scripts/generate_reason_catalog.py`) is generated only
  from `awf.service.doctor.reasons._REASON_TEXT`. Existing GC reason-code strings
  (`FAILED_WORKSPACE_TRIAGE_PRESERVED`, etc.) are **not** registered there, so
  adding a new plain reason-code string needs **no** doc/catalog change.
- FIX 2 seam: `GitManager.remove_worktree`
  (`src/awf/node/git_manager.py:362`). It already guards
  `if worktree_path.exists()` then runs `git worktree remove --force`, then
  `git worktree prune`. `_run` raises `GitOperationError` (carries `stderr`,
  `reason_code`) on non-zero exit. GC's `default_worktree_remover`
  (`src/awf/service/gc_worktrees.py:152`) wraps the call in `except Exception`
  and downgrades to `partial` (line 175) — so fixing `remove_worktree` to not
  raise on the already-gone case removes the spurious `partial` without touching
  `gc_worktrees.py`.

## Files to touch (only these)

   - New module constant `DEFAULT_MAX_PRESERVED_FAILED_HOURS = 720` (near
     `DEFAULT_MIN_AGE_HOURS = 168`).
   - New reason-code constant
     `PRESERVED_FAILED_AGE_CAP_RECLAIMED = "PRESERVED_FAILED_AGE_CAP_RECLAIMED"`
     (near the other reason-code constants ~line 70-78).
   - `_classify_workspace_for_gc`: add keyword param
     `preserved_failed_cutoff_at: datetime | None = None`. On **both**
     `FAILED_WORKSPACE_TRIAGE_PRESERVED` branches (failed and superseded), before
     returning the preserved record: if `preserved_failed_cutoff_at is not None
     and updated_at <= preserved_failed_cutoff_at`, return
     `_candidate_for_workspace(..., reason_code=PRESERVED_FAILED_AGE_CAP_RECLAIMED)`
     instead. (Factor the shared `updated_at <= cutoff` candidate-return into a

     localized to this function.)
   - Minimal config plumbing: add
     `max_preserved_failed_hours: float = DEFAULT_MAX_PRESERVED_FAILED_HOURS`
     param to `plan_terminal_workspace_gc`, `run_terminal_workspace_gc`, and
     `run_service_workspace_gc`; compute
     `preserved_failed_cutoff_at = current_time - timedelta(hours=max_preserved_failed_hours)`
     in the planner and pass it into both `_classify_workspace_for_gc` calls.
     Keep `run_workspace_filesystem_gc` passing the default/None (post-merge path
     targets completed-merged workspaces, not preserved-failed) — pass the cutoff
     there too for consistency so the cap is honored uniformly, defaulting from
     the same constant.
   - **Do not** edit any other gc.py section (avoid colliding with WS-B2's
     reconciler being added in parallel).

2. `src/awf/node/git_manager.py` — FIX 2 only:
   - In `remove_worktree`, wrap the `git worktree remove --force` `_run` call in a
     `try/except GitOperationError`. Re-raise unless the failure is the specific
     already-removed condition — match `"is not a working tree"` (case-insensitive)
     in `exc.stderr` (git's `fatal: '<path>' is not a working tree`). On match:
     log a debug/info structured line and fall through to the existing
     `git worktree prune` (which clears the stale metadata). Catch the specific
     `GitOperationError` + matched stderr only — **not** bare `Exception`, and
     **not** all `GitOperationError`s.

## Risks & assumptions

- **Reusing the candidate reclaim path is sufficient for "keep the record."**
  Verified: GC reaps only pressure dirs/compose/reservations/leases and never
  deletes the `Workspace` row or its events. Risk: if WS-B2 later adds row
  deletion for some reaper, the cap must not be routed through it — mitigated by
  using the existing candidate path, which is row-preserving by construction.
- **stderr text match for "is not a working tree".** Git's wording is stable
  across modern versions; matching the substring case-insensitively on
  `exc.stderr` is robust to the leading `fatal:` / quoted path. Risk: a future
  git localization could change wording — acceptable, and a genuine miss would
  surface as a (rare) `partial`, the pre-fix behavior, not a regression.
- **Default cap 720 h (30 d).** Chosen per issue guidance; configurable so
  operators can tune. It is far above the 168 h idle window so the two paths
  stay distinct and auditable via separate reason codes.
- **Param threading touches three planner functions.** This is the "minimal
  config plumbing" explicitly permitted by the issue; edits stay additive
  (defaulted kwargs) to avoid colliding with WS-B2's separate reconciler section.
