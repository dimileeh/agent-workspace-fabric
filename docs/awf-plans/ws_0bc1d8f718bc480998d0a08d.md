# Plan: Docs Search/Readability Checks for Public Docs

## Scope

Implement the P1 docs-status/readability slice with strict TDD. The implementation should add deterministic unit tests that prove public guides are discoverable, documented AWF commands still exist in the Typer CLI surface, and copy-paste-marked snippets remain syntactically valid. Keep docs edits minimal and only adjust index/reference links needed to satisfy the new checks.

2. Add `test_awf_commands_mentioned_in_public_docs_exist_in_cli_help_tree`.
   - Extract AWF command invocations from public docs code fences and inline command mentions, normalizing prefixes like `uv run --python 3.12 --extra dev awf ...` to `awf ...`.
   - Ignore placeholders and shell syntax that are not CLI commands, and avoid executing mutating commands.
   - Validate command paths against Typer metadata from `src/awf/cli/main.py` (`app`, nested Typer groups, registered commands) or bounded `CliRunner` help invocations only; do not run the actual commands.
   - Cover key documented commands such as `awf init`, `awf service bootstrap`, `awf service status`, `awf service readiness`, `awf service logs`, `awf service gc`, `awf smoke run`, `awf profile preview`, `awf profile init`, `awf workspace create/show/list/events/runtime/operations/logs/log`, `awf workspace remonitor/retry/adopt-pr`, and `awf locks list` when present in docs.

3. Add `test_copy_paste_marked_snippets_are_syntactically_valid`.
   - Detect sections/docs explicitly marked copy-paste, currently especially `docs/PROJECT_ONBOARDING.md` and references from `docs/GETTING_STARTED.md`.
   - Validate fenced snippets by language without running them: `json` via `json.loads`, `yaml` via the project YAML parser if available, `python` via `ast.parse`, and `bash`/`sh` via `bash -n` on temporary script text after filtering prompt-only prose if necessary.
   - For `text` copy-paste prompts, assert fence balance and non-empty content rather than parsing as executable code.
   - Keep checks deterministic and fast; no Docker, network, GitHub, service startup, or destructive command execution.

4. Confirm the first test run fails for the current gap before implementation, then make the smallest docs/test changes to pass.

## Implementation Approach

- Write small parsing helpers in the test module:
  - Markdown link extraction that resolves relative links from README and `docs/*.md` to repo-relative paths.
  - Fenced-code extraction with language and nearby heading/context.
  - AWF command extraction that handles multiline shell continuations and strips env assignments / `uv run ... awf` prefixes.
  - Typer command-tree extraction from `awf.cli.main.app` and subcommands, preferring structural inspection over executing commands.
- Define public docs conservatively:
  - Start with README Documentation links and README “See” reference links.
  - Expand only through public guide/reference pages that are already linked from README or the docs index.
  - Recognize `docs/TROUBLESHOOTING.md` when present, but do not require new troubleshooting content.
- Keep docs fixes link-only unless a snippet is objectively malformed.
- Avoid adding a standalone script unless the test helpers become reusable for CI outside pytest; the acceptance can be met by unit tests.

## Risks and Mitigations

- Markdown parsing can become too broad and classify internal docs as public. Mitigation: anchor the public set to README/docs-index links and explicitly exclude `docs/awf-plans/**`, generated conformance/validation files, and internal planning artifacts unless README names them as references.
- CLI extraction can produce false positives from examples, placeholders, or explanatory prose. Mitigation: parse only `awf` command paths, normalize common prefixes, stop at options/placeholders, and assert against command path existence rather than full invocation semantics.
- Bash syntax validation can reject intentionally partial snippets. Mitigation: apply `bash -n` only to fences in explicitly copy-paste contexts, preserve multiline continuations, and treat prompt-only `text` fences as non-executable.
- Active docs workspaces may land overlapping README/docs changes first. Mitigation: keep implementation edits narrow and re-run docs tests after any stale refresh/rebase AWF performs.
- Typer internals may be awkward to inspect directly. Mitigation: fall back to `CliRunner` help for bounded, non-mutating command paths if structural inspection is brittle.

## Assumptions

- `README.md` currently acts as the public docs index unless a dedicated `docs/README.md` is introduced by another slice.
- Public docs are Markdown files that are discoverable from README/docs-index links, not every Markdown file under `docs/`.
- Syntax validity for copy-paste snippets means parseable/non-malformed, not semantically runnable against a live AWF service.
- The troubleshooting guide may be a stub or may be expanded by another workspace; this slice should recognize/link-check it but not write that content.

## Explicit Non-Goals

- Do not rewrite public docs for style or readability prose beyond link/snippet fixes required by tests.
- Do not run documented AWF, Docker, GitHub, curl, service, or workspace commands as part of docs-status validation.
- Do not add broad CI wiring unless existing pytest coverage is insufficient for acceptance.
- Do not modify AWF CLI behavior, API routes, MCP tools, console code, migrations, or lockfiles.
- Do not duplicate the troubleshooting-guide slice or invent new troubleshooting content.
