# Plan: workspace agent identity, lifecycle timing, and LLM usage observability

## Objective

Expose operator-ready observability for each AWF workspace without changing the
event timeline contract:

- show the effective agent runtime, model, and effort even when the caller used
  the default model policy from `src/awf/adapters/defaults.py`;
- project lifecycle stage start/end/duration from workspace state events;
- add a durable API/console shape for LLM token and cost summaries while
  returning explicit unavailable/null values until reliable adapter usage data
  exists.

This is an API/console projection slice. It should not invent token numbers,
provider prices, or new workspace lifecycle events.

## Tests To Write First

1. Effective agent identity service tests:
   - Empty policy plus `AgentRuntime.codex` returns model `gpt-5.5`, effort
     `xhigh`, and source `default`.
   - Empty policy plus `gemini`, `claude_code`, and `opencode` returns the
     central defaults:
     `gemini-3-pro-preview`, `claude-opus-4-7`, and
     `ollama/kimi-k2.6:cloud`.
   - Explicit nonblank `task_policy["agent_model"]` wins for model while effort
     still comes from defaults.
   - Blank/malformed model policy falls back to defaults.

2. Workspace/task API identity tests:
   - Create a v2 workspace without `task.model`; assert
     `/v1/workspaces/{id}`, `/v1/workspaces`, `/v1/workspaces/overview`, and
     `/v1/tasks` expose the effective model and effort.
   - Create a v2 workspace with `task.model`; assert all same endpoints expose
     the override model and default effort.
   - Create a legacy v1 workspace; assert defaults are still exposed so older
     rows do not show only `agent`.
   - If effective identity snapshots are stored in `task_policy`, assert v2
     idempotency replay with no requested model still succeeds and compares the
     requested model, not the derived snapshot.

3. Lifecycle summary service tests:
   - Given `workspace.created` and ordered `workspace.state_changed` events,
     assert each reached stage has `started_at`, `ended_at`,
     `duration_seconds`, and `completed`.
   - Given a workspace currently in `running`, pass a fixed `now` and assert
     the running stage is `active`, `ended_at` is null, and duration uses
     `now - started_at`.
   - Given a transition from `validating` to `failed`, assert later stages are
     `terminal_skipped` and the validating stage is closed at the failure
     event.
   - Given a newly created workspace, assert `requested` is active and future
     stages are pending.

4. Lifecycle API tests:
   - Seed deterministic events through the repository or direct event rows and
     assert `/v1/workspaces/{id}` and `/v1/workspaces/overview` include the
     lifecycle array.
   - Assert active stage duration is nonnegative and updates from the current
     server time.
   - Assert terminal failed/cancelled workspaces expose skipped future stages.

5. Usage summary tests:
   - Assert workspace detail, overview, and task rows include usage fields:
     `input_tokens`, `output_tokens`, `total_tokens`, `cost_estimate`,
     `currency`, `status`, `source`, and `reason`.
   - For current adapters/logs, assert values are null and status is
     `unavailable` with a reason such as `usage_not_reported`.
   - Before implementing parser code, grep current adapter/log contracts. Only
     add parser tests if a real structured usage line exists.

6. Console static/type coverage:
   - There is no Jest/Vitest test script in `apps/console/package.json`, so the
     console change will be covered by TypeScript types, ESLint, and Next build
     checks rather than a new JS test harness.

Per AWF TDD rules, commit the failing tests first in the implementation phase,
then implement the smallest green change. Do not commit during this planning
phase.

## Implementation Steps

1. Add the observability projection helper.
   - Define lightweight dataclasses or pure functions for:
     `effective_agent_identity(workspace_or_agent, task_policy)`,
     `workspace_lifecycle_summary(workspace, now=None)`, and
     `workspace_usage_summary(workspace)`.
   - Normalize model policy by accepting only nonblank strings.
   - Preserve server-side model IDs as-is; compacting `ollama/` remains a
     console display concern.
   - Treat effort as default-derived unless a future stored policy key exists.

2. Add API schema fields.
   - Keep existing `agent_model` for backwards compatibility, but make it the
     effective model rather than only the requested override.
   - Add `agent_effort`, `agent_model_source`, and `agent_effort_source`.
   - Add `lifecycle: list[WorkspaceLifecycleStageResponse]`.
   - Add `llm_usage: WorkspaceLlmUsageSummaryResponse`.
   - Prefer flat fields for list/task rows and a nested `llm_usage` object for
     usage to keep null/unavailable semantics explicit.

3. Wire workspace routes through shared response builders.
   - Replace raw `WorkspaceResponse.model_validate(ws)` calls in workspace
     list/get/service paths with a helper that overlays computed fields.
   - Update overview item construction to call the same identity, lifecycle,
     and usage helpers.
   - Keep `/v1/workspaces/{id}/events` unchanged.

4. Wire task routes.
   - Update `_task_from_attempt` and `_task_from_workspace` to expose the same
     effective model/effort and usage summary.
   - Keep readiness, candidate, and task attempt behavior unchanged.

5. Optionally persist new-workspace identity snapshots.
   - If tests and implementation show value without idempotency risk, store
     derived keys such as `effective_agent_model`, `effective_agent_effort`,
     and source labels in `task_policy`.
   - Do not overload `task_policy["agent_model"]`; it currently represents the
     requested override and is used by idempotency checks.
   - For legacy rows without snapshots, always fall back to
     `DEFAULT_AGENT_DEFAULTS` at projection time.

6. Update the console.
   - Extend `WorkspaceOverview`, `Workspace`, and task-related types.
   - Make `formatAgentLabel` use effective model and `formatAgentTitle` include
     effort/source.
   - Pass API lifecycle summaries into `LifecycleRail`; show compact
     `start`, `end`, and duration text per stage.
   - For active stages, rely on existing polling to refresh duration naturally.
   - Add a small usage summary in workspace detail that shows token/cost values
     when present and `unavailable` plus reason when absent.

7. Verify parser availability.
   - Search current adapter stdout/stderr/log stream contracts for structured
     token usage.
   - If none exists, keep `workspace_usage_summary` as unavailable/null and
     leave parser implementation as an explicit future extension.

## Risks

- If effective defaults are only projected, historical workspaces may display a
  newer default after `DEFAULT_AGENT_DEFAULTS` changes. Snapshotting new rows in
  `task_policy` mitigates this, but must not break idempotency semantics.
- Lifecycle summaries depend on event ordering and transition event quality.
  The helper must tolerate legacy or malformed events and avoid mutating the
  event timeline.
- Terminal transitions can be ambiguous for the interrupted stage. This plan
  closes the interrupted stage at the terminal transition and marks later
  stages `terminal_skipped`.
- Active duration values are time-dependent. Tests should inject `now` at the
  helper layer and use loose/nonnegative assertions at the HTTP layer.
- Token usage output varies by CLI/provider and may be absent, noisy, or
  unstable. Parsing should be added only for documented or clearly structured
  output.
- Console detail receives WebSocket snapshots as `Workspace` objects; if route
  snapshots keep using raw `model_validate`, live updates could drop computed
  fields.

## Assumptions

- `DEFAULT_AGENT_DEFAULTS` is the authoritative default model/effort policy.
- Existing `Workspace.task_policy` can carry optional derived identity snapshot
  keys without a migration.
- Existing `Workspace.events` contains enough `workspace.created` and
  `workspace.state_changed` data to derive lifecycle timing for current rows.
- The console has no dedicated JS test runner today; lint, typecheck, and build
  are the supported static validation surface.
- Usage/cost observability can start as a stable null/unavailable contract until
  adapters provide reliable usage data.
