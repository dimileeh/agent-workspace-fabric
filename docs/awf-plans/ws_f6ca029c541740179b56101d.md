# Plan: Persist + Surface Bootstrap Work-Dir/Auth Posture (#398 + #400)

## Summary

Two deferred issues from #397:

- **#398**: Bootstrap sets `AWF_WORK_DIR_BIND_PROPAGATION` and
  `AWF_CLAUDE_AUTH_FORCE_COPY` at preflight time, but the choice is only
  in-process env — it is never durably persisted. A later non-bootstrap
  `docker compose up` (recreate) silently reverts to the compose-file
  defaults (`:rshared` / `force_copy=false`), which is wrong on
  non-propagating hosts (Docker Desktop / virtiofs / grpcfuse).

- **#400**: `awf service status` / doctor cannot see the effective
  force-copy / propagation posture because the post-bootstrap runtime
  has no durable record of what the preflight decided. Status and
  provider readiness run outside bootstrap and cannot re-derive the
  posture (they would need mountinfo + mount(8) logic that only the
  bootstrap preflight is authorized to run).

## Approach

1. **Persist the posture** by writing `AWF_WORK_DIR_BIND_PROPAGATION`
   and `AWF_CLAUDE_AUTH_FORCE_COPY` into the compose env-file
   (`.env` adjacent to the compose file) at the end of a successful
   bootstrap preflight. The compose env-file is the single source of
   truth that Docker Compose reads on every `up`/`recreate`, so a
   plain `docker compose up` without bootstrap will pick up the
   persisted values.

2. **Handle staleness**: the persisted posture includes a
   `AWF_WORK_DIR_PROPAGATION_TIMESTAMP` so a future bootstrap can
   detect that the persisted value is stale (host may have changed
   between bootstraps) and re-derive it. A non-bootstrap `compose up`
   trusts the persisted value (it cannot re-derive — that requires
   the preflight).

3. **Surface the posture** in `collect_service_status` by reading the
   persisted values from the compose env-file (or the passed environ)
   and adding a `mount_propagation` check payload. Provider readiness
   in `provider_readiness.py` already reads
   `AWF_CLAUDE_AUTH_FORCE_COPY` from the passed environ — extend it
   to also report `AWF_WORK_DIR_BIND_PROPAGATION`.

## Detailed Design

### 1. Persisting the posture (`bootstrap.py`)

New dataclass:

```python
@dataclass(frozen=True)
class PersistedPropagationPosture:
    propagation: str           # "rshared" or "rprivate"
    force_copy: str             # "true" or "false"
    timestamp: str              # ISO-8601 UTC
```

New function `_persist_work_dir_propagation_result`:
- Takes: `env_file: Path`, `result: WorkDirPropagationResult`
- Reads the existing env-file values (if file exists) using
  `compose_env_file_values()` from `environment.py`.
- Compares existing `AWF_WORK_DIR_BIND_PROPAGATION` with
  `result.propagation` — only rewrites if changed (minimizes file
  churn).
- Writes three keys to the env-file:
  - `AWF_WORK_DIR_BIND_PROPAGATION=<propagation>`
  - `AWF_CLAUDE_AUTH_FORCE_COPY=<true|false>`
  - `AWF_WORK_DIR_PROPAGATION_TIMESTAMP=<ISO-8601>`
- Uses `redact_audit_text()` from `common/audit` on all values
  before logging (the propagation values themselves are not secrets,
  but the function must be called on any file content that could
  contain adjacent secrets from other operators editing the `.env`).
- Writes atomically: write to a temp file in the same directory, then
  `os.replace()`.
- **Best-effort**: `OSError` on write is caught and logged (via
  `redact_audit_text`-redacted detail), never fatal.

Staleness handling in `run_service_bootstrap`:
- Before running the preflight, check if the compose env-file already
  has `AWF_WORK_DIR_PROPAGATION_TIMESTAMP`.
- If it does, parse the timestamp. If it is within a reasonable
  window (the preflight is idempotent — always re-run it during
  bootstrap; staleness is only relevant for non-bootstrap `compose up`
  which cannot re-run it), the persisted value survives for compose
  to read.
- **In bootstrap, always re-run the preflight** (it is idempotent and
  the source of truth). The persisted value is primarily for the
  non-bootstrap `docker compose up` recreate path.
- After preflight, always persist (overwriting any stale value).

### 2. Surfacing the posture (`status.py`)

New function `_mount_propagation_check_payload`:
- Reads `AWF_WORK_DIR_BIND_PROPAGATION` and
  `AWF_CLAUDE_AUTH_FORCE_COPY` from, in order:
  1. The passed `environ` (which bootstrap folds the preflight result
     into — this is the live-truth source).
  2. The compose env-file (when status runs outside bootstrap).
- Returns a check payload:
  ```python
  {
      "ok": True,
      "status": "ok" | "unknown",
      "reason": "MOUNT_PROPAGATION_AVAILABLE" | "MOUNT_PROPAGATION_UNKNOWN",
      "propagation": "rshared" | "rprivate" | None,
      "force_copy": True | False | None,
      "detail": "...",
  }
  ```
- When neither source has the keys, reports status `"unknown"` with
  reason `"MOUNT_PROPAGATION_UNKNOWN"` — not a failure, just
  diagnostic drift (same as today, but now explicitly surfaced).

Wire into `collect_service_status`:
- Add `"mount_propagation": _mount_propagation_check_payload(...)` to
  the `checks` dict.

### 3. Provider readiness (`provider_readiness.py`)

In the `_claude_code_readiness` function (around line 937):
- The `environ` dict already carries `AWF_CLAUDE_AUTH_FORCE_COPY`
  when bootstrap provides it. Add `AWF_WORK_DIR_BIND_PROPAGATION` to
  the same readiness environ dict so the readiness payload surfaces
  both posture values.

## Risks and Assumptions

### Risks

1. **Env-file write races**: Two concurrent bootstraps could race on
   the env-file. Mitigated by atomic write (`os.replace`) and the fact
   that both bootstraps will compute the same posture on the same host.

2. **Env-file location may not exist**: The compose env-file path
   (`LOCAL_SERVICE_COMPOSE_ENV_FILE = Path(".env")`) may not exist
   (first bootstrap). Mitigated by creating it if absent. If the
   parent directory is unwritable, `OSError` is caught — best effort,
   non-fatal.

3. **Secrets in env-file**: The env-file may contain adjacent secrets
  (API tokens). The persist function only writes/overwrites the three
  posture keys, preserving all other entries. Logs use
  `redact_audit_text()` for any env-file content that enters logs.

4. **Stale posture on host change**: A host that was propagating at
  bootstrap time may become non-propagating after a Docker Desktop
  upgrade. The `AWF_WORK_DIR_PROPAGATION_TIMESTAMP` enables future
  staleness detection by bootstrap. Non-bootstrap `compose up`
  cannot detect staleness and must trust the persisted value — this
  is documented as a known limitation. The next bootstrap will
  refresh the posture.

### Assumptions

1. The compose env-file format is compatible with
   `compose_env_file_values()` for reading and simple `KEY=VALUE`
   line appending for writing.

2. `AWF_WORK_DIR_BIND_PROPAGATION` and `AWF_CLAUDE_AUTH_FORCE_COPY`
  are not secrets — they are host-capability flags. Writing them to
  the env-file is safe even though the env-file may also contain
  secrets.

3. Bootstrap always has authority to re-derive the posture. The
  persisted value is only for non-bootstrap compose operations.

### Explicit Non-Goals

1. **Do not touch `auth_mounts.py`**, `cleanup.py`, or
   `pre_push_validation.py` — separate parallel tasks.

2. **Do not change the compose file** (`local-service.yml`) defaults
   — they remain `rshared` / no force_copy as compose-file defaults;
   the env-file overrides take precedence.

3. **Do not implement auto-refresh for non-bootstrap compose ups**
   — these must trust the persisted posture. Only bootstrap can
   refresh it.

4. **Do not encrypt the env-file** — the posture values are not
   secrets. Other entries in the env-file may be secrets, but
   encrypting the entire file would break Compose's env-file parser.
   Standard file permissions (0600) are sufficient.

5. **Do not add mount-propagation re-derivation to `awf service
   status`** — it would require mount(8) and potentially root
   privileges. Status only reads the persisted/env posture.

6. **Do not change the `_apply_work_dir_propagation_env` function
   signature or the `WorkDirPropagationResult` dataclass** — these
   are stable public API used by the bootstrap loop and tests.
