# Plan: SDK Stance Decision and Documentation

## Intent
We will adopt the explicit-doc stance regarding a Python SDK for the v0.1 release, as the codebase does not currently have a natural client abstraction ready to ship without conflicting with active REST/CLI/MCP parity work. The stance is that REST, CLI, and MCP are the supported client surfaces for v0.1.

## Intended Files to Touch
1. `README.md` - Add an explicit section about the SDK stance and supported client surfaces.
2. `docs/CLIENT_SURFACES.md` - Create or update this file to state the SDK stance prominently and warn against importing internal Python modules.
3. `docs/MCP_CLIENT_PARITY.md` - Update the role contract or introductory section to reflect that no Python SDK is provided for v0.1.
4. `tests/unit/docs/test_sdk_stance_docs.py` - Create this new test file to enforce the presence of the SDK stance documentation.

## Tests to Write First
- `tests/unit/docs/test_sdk_stance_docs.py`:
  - A test that reads `README.md`, `docs/CLIENT_SURFACES.md`, and `docs/MCP_CLIENT_PARITY.md`.
  - Assert that each file contains an explicit statement that "REST, CLI, and MCP are the supported client surfaces for v0.1" (or equivalent phrasing).
  - Assert that each file explicitly warns integrators not to import internal AWF modules (e.g., "do not import internal modules").

## Risks, Assumptions, and Explicit Non-goals
- **Assumptions**: A natural client abstraction does not exist in `src/awf/client`, so we are opting for the explicit-doc stance as advised by the acceptance criteria.
- **Explicit Non-goals**: We will not implement any broad SDK or API client code in this slice. We are purely documenting the supported surfaces (REST, CLI, MCP) for v0.1.
- **Risks**: We overlap with `ws_f598e969bed54d17be999e62` which also touches `docs/CLIENT_SURFACES.md` and `README.md`. We will keep our additions contained to dedicated "SDK Stance" or "Client Surface" sections to minimize merge conflicts.
