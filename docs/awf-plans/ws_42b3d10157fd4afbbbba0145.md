# Plan: P0 Planning Phase Scope Enforcement

## Objective

Finish the remaining P0 planning-phase scope-enforcement slice with strict TDD.
The current code already detects some extra plan-phase file edits, but it
returns plain failure strings and surfaces them as generic `agent_failure`.
This slice will make the planning contract explicit in prompts, persist
structured planning-scope failure evidence, expose precise operator-facing
details, and add a conservative recovery path that does not accidentally promote
premature implementation work.

The prior branch `origin/awf/ws_90f9152eefb54c899fccbd9b` is useful for prompt
and failure-detail ideas, but it should not be merged wholesale. It did not
complete recovery behavior and it failed validation on a prompt assertion.

## Risks And Assumptions

- Command-level detection is limited by current `AgentRunResult`, which exposes
  stdout/stderr but not a reliable list of commands run inside the agent. The
  first implementation should always identify offending paths and include
  `offending_commands` only when trustworthy metadata exists.
- Automatic salvage promotion is intentionally risky because the preserved branch
  may contain implementation produced before planning approval. The default must
  be fresh retry or explicit salvage only.
- The retry path must not overwrite user/operator task policy except for an
  explicit approved fallback model field.
- Existing conformance failure retry behavior must keep working and should not
  be conflated with planning-scope violations.
- API schema additions should be backward-compatible optional fields.
- The prior branch's prompt idea should be adapted carefully so assertions match
  rendered text.

## Explicit Non-Goals

- Do not merge broad unrelated churn or old plan/conformance artifacts from
  `origin/awf/ws_90f9152eefb54c899fccbd9b`.
- Do not lower coverage thresholds, profile validation requirements, or PRD
  gates.
- Do not add provider-wide fallback scheduling beyond this planning-scope
  recovery path.
- Do not auto-push, auto-open PRs, or auto-merge preserved premature
  implementation branches.
- Do not change AWF branch ownership, push/rebase behavior, or PR monitor
