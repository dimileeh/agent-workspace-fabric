# Plan: Document And Demo Existing-PR Monitor Adoption

Workspace: `ws_e332a1d013c54928863320f0`
Backlog slice: `Document and demo PR monitor adoption for an already-open PR`

## Current Findings

- First-class adoption is already implemented as `POST /v1/workspaces/adopt-pr`, `awf workspace adopt-pr`, and MCP tool `awf_adopt_pull_request_monitor`.
- `docs/REST_API_REFERENCE.md` has only a short adoption example and currently says adoption requires `Idempotency-Key`; the implemented REST/CLI tests show the caller does not supply this header. AWF derives deterministic idempotency from normalized repo/PR identity.
- `README.md` has a short adoption paragraph, `docs/MCP_CLIENT_PARITY.md` has the parity row, and `docs/MCP_REFERENCE.md` currently omits the adoption tool from its tool table.
- The console already supports inspection surfaces for an adopted workspace: workspace details, validation provenance, operations, events, durable logs, merge queue, and remonitor/refresh/revalidate controls. It does not currently provide a console form to initiate adoption, so docs must not imply that.
- Terminal-row idempotency hardening is active in a separate workspace. During implementation, verify whether that slice has landed and document either the landed behavior or the current behavior precisely.
