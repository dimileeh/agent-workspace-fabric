# Plan — Bounded retry for failed worker-side Claude auth-overlay umount (issue #399)

Workspace: `ws_d5e96857c77340e6820fe0e1`
Deferred from PR #397 → tracked as issue **#399**.

## Problem

`src/awf/control/worker/cleanup.py` releases a terminal workspace's runtime on the
periodic terminal-runtime-release sweep. When the Compose stack comes down cleanly
(`cleanup.ok`), the worker — the **only** context that holds `CAP_SYS_ADMIN` and shares
the agent container's mount namespace — unmounts the per-workspace Claude auth overlay via
`_teardown_terminal_auth_overlay()`, then records `workspace.terminal_runtime_released`.

That release event makes the workspace *effectively released*
(`terminal_runtime_effectively_released_expr`), so `_list_terminal_runtime_candidates`
**permanently excludes it** from future sweeps. The capability-less API-container GC can only
detect-and-skip (no `CAP_SYS_ADMIN`, raises `CLAUDE_AUTH_OVERLAY_UNMOUNT_INCAPABLE`). Net:
the overlay umount gets **exactly one attempt**. A transient *or* persistent umount failure
on that single attempt leaks the overlay mount + auth dir **forever**.

## Design tension (must preserve)

The single-attempt-then-record-released behavior is deliberate: releasing the runtime/port
must **always succeed** even when the umount fails. `test_cleanup_branch_edges.py` enforces
this — e.g. `test_release_candidate_overlay_unmount_failure_does_not_block_release` asserts
the release is still recorded (`recorded == [False]`) when teardown fails. We must **add to**
these invariants, never regress them: a umount failure must still never block port reclaim.

## Locked design

Two complementary, bounded mechanisms — port/runtime reclaim still happens on the first pass
exactly as today:

1. **Bounded inline retry** inside `_teardown_terminal_auth_overlay()` — handles the common
   *transient* "target is busy" race within a single release pass. A small fixed number of
   immediate attempts (no sleep); each failed attempt logs with its reason code + attempt
   index; success short-circuits and returns `True`; exhaustion returns `False` exactly as
   today.

2. **Deferred re-sweep** for *persistent* failures — when inline retries are exhausted
   (`auth_overlay_unmounted is False`), record a `pending` marker event **in the same DB
   transaction** as `terminal_runtime_released` (atomic; port still reclaimed). A new
   secondary sweep, **piggybacked on the existing terminal-runtime-release scan** (mirroring
   the existing `_resume_pending_planning_scope_auto_retries_after_terminal_release` call in
   `_release_terminal_runtime_resources`), re-attempts the umount on later cycles until it
   succeeds or a bounded number of deferred sweeps is reached. No new periodic scan / no
   `manager.py` / `config.py` wiring required.

Marker events (event-type existence/count only — dialect-safe, no JSONB value comparison, no
migration):

- `workspace.terminal_auth_overlay_unmount_pending` / `TERMINAL_AUTH_OVERLAY_UNMOUNT_PENDING`
  — recorded when inline retries are exhausted on the release pass, and re-appended (with an
  incremented `attempt` in payload) on each failed deferred sweep. **Count of these events =
  number of attempts**, which bounds the deferred re-sweeps (the event-based counter, in the
  spirit of "retries must preserve reason codes, logs, and events").
- `workspace.terminal_auth_overlay_unmount_resolved` / `TERMINAL_AUTH_OVERLAY_UNMOUNT_RESOLVED`
  — terminal: a later sweep succeeded (or found nothing to unmount). Removes the workspace
  from the deferred-candidate set.
- `workspace.terminal_auth_overlay_unmount_exhausted` / `TERMINAL_AUTH_OVERLAY_UNMOUNT_EXHAUSTED`
  — terminal: the deferred-sweep bound was reached. Removes the workspace from the set; GC's
  loud-failure path (`CLAUDE_AUTH_OVERLAY_UNMOUNT_INCAPABLE`) remains the final backstop.

Deferred-candidate predicate: terminal-status workspace on this node (or `node_id IS NULL`,
matching `_list_terminal_runtime_candidates`) with a non-empty `repo_url`, that has ≥1
`pending` event and **no** `resolved` and **no** `exhausted` event.

Bounds (module-local constants in `cleanup.py`, to respect the stated scope; noted as
movable to `constants.py` later for consistency):
- `_TERMINAL_AUTH_OVERLAY_UNMOUNT_INLINE_ATTEMPTS = 3`
- `_TERMINAL_AUTH_OVERLAY_UNMOUNT_MAX_DEFERRED_SWEEPS = 5`

Reason codes flow end-to-end (`reason_code=` on both the `WorkspaceEvent` and the structured
log). The reason-catalog coverage gate (`tests/unit/docs/test_catalog_coverage.py`) only
scans `error_code=` literals, **not** `reason_code=`, so these new worker reason codes do not
require `docs/REASON_CATALOG.md` entries (consistent with the existing
`TERMINAL_RUNTIME_RELEASE_FAILED` etc.).

## Files / modules to touch

- `src/awf/control/worker/cleanup.py` (only production file):
  - `_teardown_terminal_auth_overlay()` — wrap the existing single teardown call in a bounded
    immediate-retry loop; preserve the exact exception set
    (`OverlayUnmountUnverifiableError`, `OSError`, `subprocess.SubprocessError`), the
    three-valued return (`True`/`False`/`None`), and the existing warning event/reason
    code/`stderr` forwarding (add an `attempt` field).
  - `_record_terminal_runtime_released()` — inside its existing `_operation`, after the
    `terminal_runtime_released` `add_event`, when `auth_overlay_unmounted is False` also
    `add_event(pending, payload={..., "attempt": 1})`. Atomic with the release; single commit.
    Behavior for `True`/`None` (and all early-return/dedup/status-guard paths) unchanged.
  - `_release_terminal_runtime_resources()` — after the existing resume-pending scan, add a
    guarded (swallow-and-log, never-raise, `CancelledError` re-raised) call to the new
    `_retry_pending_terminal_auth_overlay_unmounts(limit=...)`. Placed so it does **not**
    perturb the existing release-error aggregation / final re-raise.
  - New `_list_pending_terminal_auth_overlay_unmount_candidates(self, *, limit)` — candidate
    query per the predicate above (modeled on `_list_terminal_runtime_candidates`; node
    scoping, `repo_url` skip, `run_db_operation_with_retry`, `_log_transient_db_retry`).
  - New `_retry_pending_terminal_auth_overlay_unmounts(self, *, limit)` — per candidate:
    re-run `_teardown_terminal_auth_overlay`; `True`/`None` → record `resolved`; `False` →
    if `pending`-count ≥ `MAX_DEFERRED_SWEEPS` record `exhausted`, else append a new `pending`
    (attempt+1) and log a warning. Per-candidate failures routed to a small failure handler
    (mirror `_resume_pending_…`); `CancelledError` re-raised immediately.
  - New small helpers `_record_terminal_auth_overlay_unmount_resolved` /
    `_record_terminal_auth_overlay_unmount_exhausted` / `_append_terminal_auth_overlay_unmount_pending`
    using `WorkspaceRepository.add_event` + `run_db_operation_with_retry(commit=True)` with
    `SELECT FOR UPDATE SKIP LOCKED` dedup (mirror `_record_terminal_runtime_released`).
  - New module-local constants + event-type/reason-code literals.
- `tests/unit/control/test_cleanup_branch_edges.py` (and/or a focused sibling
  `test_cleanup_auth_overlay_retry.py` for the new surface) — see below.

Explicitly **not** touched: `bootstrap.py`, `auth_mounts.py`, `auth_mounts_claude.py`,
`pre_push_validation.py`, `manager.py`, `config.py`, DB models / migrations.

Inline-retry (`_teardown_terminal_auth_overlay`):

   `CalledProcessError` on attempt 1, returns on attempt 2 → returns `True`; exactly one
   `worker.terminal_auth_overlay_unmount_failed` warning (carries `attempt`); release records
   `auth_overlay_unmounted=True`.

   never raises. (Extends existing
   `test_release_candidate_overlay_unmount_failure_does_not_block_release` /
   `_unverifiable_does_not_abort_sweep`, whose `any(...)` assertions still hold.)
3. **No work dir** → `None`, no teardown call (existing `_skips_overlay_when_no_work_dir`
   stays green).

Pending-marker write (`_record_terminal_runtime_released`):
4. `auth_overlay_unmounted=False` → both `terminal_runtime_released` **and**
   `terminal_auth_overlay_unmount_pending` (`attempt=1`) added in one operation.
5. `auth_overlay_unmounted=True`/`None` → only the released event; no pending marker.
6. Existing status-guard / dedup / `skipped()` paths still add **no** events (regression of
   `test_record_released_returns_when_status_no_longer_terminal` /
   `_returns_when_event_already_exists`).

Deferred sweep:
7. **Persistent failure recorded for later sweep without blocking port reclaim** (the headline
   RULES scenario): release pass records released + pending; the candidate query surfaces the
   workspace on the next sweep; teardown still fails → a new `pending` (attempt 2) appended,
   warning logged, no `resolved`/`exhausted`.
8. **Later sweep succeeds** → teardown returns `True`/`None` → `resolved` recorded; workspace
   no longer a candidate.
9. **Bound reached** → after `MAX_DEFERRED_SWEEPS` pending events, a failing sweep records
   `exhausted` (not another pending); workspace drops out.
10. Candidate query: empty for non-positive `limit`; skips rows without `repo_url`; excludes
    workspaces that already have `resolved` or `exhausted`.
11. `_retry_pending_…` routes a per-candidate failure to its handler (not aborting the scan)
    and re-raises `CancelledError` (mirror existing resume-pending tests).

Invariant preservation (add to `test_cleanup_branch_edges.py`):
12. The 4 existing `_release_terminal_runtime_resources` tests get the new
    `_retry_pending_terminal_auth_overlay_unmounts` attribute (async no-op) added to their

## Risks & assumptions

- **Existing-test churn (low risk, allowed):** adding the secondary-sweep call into
  `_release_terminal_runtime_resources` requires the 4 existing workers to expose the new
  method. Mitigation: add it as an async no-op; assert their existing log/return invariants
  are byte-for-byte unchanged (task explicitly permits "add to them; don't regress them").
- **Dialect safety:** the deferred-candidate query intentionally uses event-type
  existence/count predicates only (no JSONB boolean value comparison), so it behaves
  identically on Postgres (prod) and SQLite (tests). The `attempt` payload is for audit only.
- **Bounded, never blind:** both retry mechanisms are fixed-count and every failed attempt is
  logged with its reason code (+ `umount(8)` `stderr` and `attempt`), satisfying "never hide
  failures behind retries." After the bound, `exhausted` is recorded and GC's loud-failure
  path remains the visible backstop — no silent give-up.
- **Concurrency:** record helpers reuse `SELECT FOR UPDATE SKIP LOCKED` + idempotent
  event-existence guards so NULL-`node_id` multi-worker races (Phase 2) cannot double-write
  `resolved`/`exhausted`; single-node (Phase 1) is a no-op.
- **No sleeps:** inline retries are immediate (catch ultra-transient namespace races); the
  deferred sweep's natural scan interval (~`terminal_runtime_release_scan_interval_seconds`,
  default 300s) is the backstop for longer-lived "busy" states. Keeps the worker loop
  non-blocking and tests delay-free. Assumption: an immediate inline re-attempt is worthwhile;
  if it proves useless in practice, `INLINE_ATTEMPTS` can be set to 1 and the deferred sweep
  alone carries the fix.
- **Assumption:** `_teardown_terminal_auth_overlay` re-invoked on a later sweep is idempotent
  and safe (it re-checks `is_mounted` / capability each call) — confirmed by reading
  `node/auth_mounts_claude.teardown_workspace_auth_overlay`.

## Non-goals

- No change to GC (`service/gc.py`) or the API-container capability-less path; its
  detect-and-skip + loud-failure behavior stays the final backstop.
- No change to overlay mount/unmount mechanics in `auth_mounts*.py`.
- No new periodic worker scan, config knob, DB column, or migration.
- No change to `terminal_runtime_released` semantics for the success/no-overlay cases, nor to
  the port/runtime reclaim ordering.
- Not making umount failure block release (explicitly forbidden by the locked design).
