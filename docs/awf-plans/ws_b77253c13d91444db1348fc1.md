## 1. Goal

Update the public first-run documentation now that the T01/T04/T05/T10/T12/T13
foundations are merged. The docs should let a first-time evaluator choose one
complete lane and follow only that lane:

1. curl installer: release-installed, least inspectable before execution.
2. `uv tool` / `pipx`: release-installed, package-manager mediated.
3. source checkout with global tool install: inspectable source, installs `awf`
   as a global tool from the checkout.
4. source checkout with no global install: fully inspectable and does not place
   an `awf` executable on the global PATH; commands run through `uv run` from the
   checkout.

Each lane must cover setup, start, project init, mocked smoke, upgrade, and
uninstall. Public examples should use the real first-run grammar (`awf setup`,
`awf start`, `awf init <path>`) and local loopback URLs as `127.0.0.1` where the
reader is opening or curling the local API/console.

During implementation, create the protocol-required `plans/T15_FIRST_RUN_DOCS_PLAN.md`
before source/doc edits and `plans/T15_FIRST_RUN_DOCS_VALIDATION.md` after changes,
using this AWF plan artifact as the source of truth.

## 6. Risks and mitigations

- Docs coordination overlap exists on `docs/` with active workspaces. Mitigation:
  keep this T15 diff tightly scoped to first-run docs and docs tests, and expect
  AWF stale-overlap policy to handle any target-branch changes that land first.
- Public installer URLs may not be live in this workspace. Mitigation: document
  the release contract using the checked-in installer/manifest semantics and
  avoid claiming Homebrew or unsupported channels are available.
- The curl lane is convenient but least inspectable before execution. Mitigation:
  state that explicitly and point source-lane evaluators to clone-first options.
- Uninstall guidance can accidentally imply destructive deletion of service data.
  Mitigation: separate CLI/tool uninstall from local service/workspace cleanup
  and link to troubleshooting for state cleanup.
- Existing docs still contain expert `awf service bootstrap` references.
  Mitigation: remove it as first-run/evaluator guidance, but allow expert or
  troubleshooting mentions where they are clearly not the primary lane.
- `localhost` remains valid in some internals and expert examples. Mitigation:
  only enforce `127.0.0.1` for first-run local API/console URLs in this docs
  slice, avoiding broad unrelated churn.
