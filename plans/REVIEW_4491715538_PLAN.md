# Review 4491715538 Fix Plan

## Problem Statement and Scope

Address the review-level comment for PR comment `issue:4491715538`.

The review flags two maintainability and behavior issues in the protected
quality-gate implementation:

- Unused `_git_diff_text` helpers sit next to the actively used `_git_show_text`
  path and can mislead maintainers about diff-text plumbing.
- `_VALIDATION_COMMAND_TOKEN_RE` treats broad prose words such as `build`,
  `lint`, `deploy`, `publish`, and `release` as validation commands even when
  they appear inside harmless `echo` or logging steps.

Scope is limited to the protected workflow classifier, tests for the reviewed
edge cases, and removal of dead helper code plus any directly affected tests.

## Requirements Checklist

- Add regression coverage proving informational `echo`/log steps mentioning
  broad validation words remain allowed.
- Preserve blocking behavior for real validation, build, deploy, publish, or
  release commands.
- Remove unused `_git_diff_text` helper code that is not called by production.
- Keep existing quality-gate safety behavior fail-closed for ambiguous or risky
  protected workflow edits.
- Commit the fix locally on the existing AWF branch without pushing or changing
  branches.

## Implementation Steps

1. Add failing quality-gate regression tests for informational workflow steps
   containing broad prose words.
2. Add or keep tests proving real broad commands are still blocked.
3. Replace broad prose token matching with command-aware validation detection.
4. Remove unused `_git_diff_text` helpers and adjust tests to cover remaining
   safe-directory git helpers.
5. Run narrow tests for `quality_gates` and the affected PR monitor helper test.
6. Run focused lint/type checks if the narrow tests pass.
