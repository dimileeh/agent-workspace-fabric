# REVIEW_4395053161 Plan

## Problem Statement

CodeRabbit's review-level summary for PR #313 includes one valid nitpick in
`src/awf/common/owned_paths.py`: `interworkspace_owned_paths` normalizes
non-empty, non-internal paths twice because it calls `normalize_owned_path` for
the empty check and then calls a helper that normalizes again.

The same summary also repeats an inline suggestion to remove literal wildcard
characters from generated plan artifact names. Existing regression tests and
the original plan for this PR intentionally classify `ws_*` generated artifact
globs as internal plan artifacts, so that suggestion should not be applied.

## Scope

- Add focused coverage proving `interworkspace_owned_paths` normalizes each
  candidate path once.
- Refactor the internal plan artifact check so callers that already normalized
  a path can reuse that value without changing public helper behavior.
- Preserve wildcard generated artifact support covered by existing tests.

## Requirements Checklist

- `interworkspace_owned_paths` calls `normalize_owned_path` no more than once
  per input item.
- Public `is_internal_plan_artifact_owned_path` behavior stays unchanged.
- Existing `ws_*` generated artifact glob tests remain intact and passing.
- Full AWF/GitHub validation is left to AWF after agent completion.

## Implementation Steps

1. Add a focused failing test in `tests/unit/common/test_owned_paths.py` that
   counts normalization calls made by `interworkspace_owned_paths`.
2. Run that focused test to confirm the current double-normalization behavior
   fails.
3. Add a normalized-path private helper in `src/awf/common/owned_paths.py` and
   route both public helpers through it as appropriate.
4. Re-run the focused owned-path tests and a focused lint check for touched
   files.
