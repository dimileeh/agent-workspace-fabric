# Review 4585090228 Plan

## Problem Statement And Scope

Address the review-level PR feedback for comment `issue:4585090228`. The scope is limited to:

- preventing duplicate planning-scope auto-retry blocked audit events for source-runtime-not-released retries;
- removing wasted cleanup scan work caused by considering manual `workspace.retry_requested` events in the pending blocked-event subquery;
- documenting the caller-side safety invariant for `ignore_source_runtime_check=True`.

## Requirements Checklist

- Add or update regression coverage before behavior changes where practical.
- Dedupe repeated `PLANNING_SCOPE_AUTO_RETRY_SOURCE_RUNTIME_NOT_RELEASED` blocked events the same way host-port conflict blocked events are deduped.
- Keep manual retry events as terminal state for executor-side pending checks, but avoid selecting them in the cleanup worker's pending blocked-event candidate scan.
- Document that `ignore_source_runtime_check=True` is safe only for callers that have already established source runtime release or have an equivalent pre-launch safety gate.
- Keep changes scoped to affected code/tests and avoid broad AWF/GitHub-owned validation.

5. Split cleanup worker latest-event constants so cleanup candidate scans consider only resumable blocked/resume-failed event types, while executor pending checks still treat manual retry as terminal.
