# Review 4445667428 Plan

## Problem Statement And Scope

PR review comment `issue:4445667428` reports two edge cases in the primary-failure
causality work:

- `workspace.secondary_failure_recorded` can be emitted for an already-failed
  workspace when no primary-failure evidence exists, producing a public callback
  payload without the structured causality keys.
- The `event_order` backfill migration uses uuid-derived event IDs as a
  same-timestamp tie-breaker, which can invert historical insertion order.

Scope is limited to these two issues plus focused regression coverage.

## Requirements Checklist

- Add a regression test proving cleanup failure on an already-failed workspace
  without primary evidence does not emit malformed
  `workspace.secondary_failure_recorded` events.
- Keep existing preservation behavior for already-failed workspaces that do have
  primary evidence.
- Add or update migration regression coverage so same-timestamp historical
  events are backfilled by persisted insertion chronology rather than random
  uuid-derived IDs.
- Update the migration backfill ordering without introducing branch changes,
  pushes, or unrelated refactors.
- Commit the scoped fix locally.

## Implementation Steps

1. Update focused tests first and confirm they fail against current behavior
   when practical.
2. Gate `workspace.secondary_failure_recorded` emission in
   `src/awf/service/controls.py` on the presence of primary failure evidence.
3. Update the event-order migration to use PostgreSQL heap insertion position as
   the historical same-timestamp tie-breaker, with an inline rationale.
4. Run the narrow affected tests, then run the relevant lint/type or broader
   unit surface as time allows.
