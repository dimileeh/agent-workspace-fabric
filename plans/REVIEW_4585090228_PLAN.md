# Review 4585090228 Plan

## Problem Statement And Scope

Address the two actionable gaps reported in PR review comment issue:4585090228:

- Retry queue decisions should include a resource summary when retry creates a reservation for a source workspace that had no prior reservation.
- Provisioner compose-fail backstop commit failure should not re-raise the original `ComposeOperationError` after recording the terminal `COMPOSE_FAIL_COMMIT_FATAL` failure.

Scope is limited to the retry admission path, the compose failure handler, and focused regression tests for those behaviors.

## Requirements Checklist

- Update the no-source-reservation retry regression so the retried workspace queue decision stores the created reservation summary instead of `{}`.
- Populate `retry_resource_summary` from the constructed retry reservation regardless of whether the source reservation existed.
- Update the compose-fail backstop commit regression so `provision_claimed()` returns after recording `COMPOSE_FAIL_COMMIT_FATAL` instead of propagating the original compose error.
- Adjust the provisioner compose-fail commit failure path to avoid duplicate caller failure handling while preserving the terminal failed row and event.
- Keep changes scoped and avoid broad AWF/GitHub-owned validation.
