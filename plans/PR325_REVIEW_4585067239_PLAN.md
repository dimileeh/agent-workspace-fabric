## Problem Statement and Scope

Greptile's review-level comment on PR #325 identified two secondary issues in
the workflow-scope push failure handling:

- `_workflow_scope_push_block` treats the generic `remote rejected` push footer
  as enough workflow-file context when separate output mentions workflow scope.
- Sync-base and CI-repair workflow-scope push failures terminate the workspace
  without first posting the explicit PR-level human notification used by the
  comment-repair path.

Scope is limited to PR monitor workflow-scope detection and notification
behavior. No protected workflow, quality-gate, or broad configuration files are
in scope.
