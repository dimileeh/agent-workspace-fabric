# Review 4482045018 Plan

## Problem Statement And Scope

Address the review-level feedback on PR comment `issue:4482045018` for the
local-service bootstrap environment flow. The fix must preserve the existing
root `.env` migration behavior while avoiding incomplete `docker/compose/.env`
files, remove the redundant bootstrap env reload in CLI bootstrap paths, and
make init env-example search-path deduplication explicit.

## Requirements Checklist

- Seed first-run `docker/compose/.env` from the compose-specific template when
  it exists, while preserving values from an existing root `.env`.
- Keep existing env-file non-clobbering behavior: an existing target env file is
  never overwritten.
- Ensure `awf init` and `awf service bootstrap` pass the same resolved service
  environment to bootstrap that they used for settings/preflight, instead of
  forcing `run_service_bootstrap` to reload the same env file.
- Preserve `run_service_bootstrap` support for provider-only environment
  overlays in non-CLI callers.
- Make `_init_env_example_search_paths` deduplication obviously cover the full
  candidate list.
- Add or update focused regression tests for the changed behavior.

3. Add an explicit `service_environ` parameter to `run_service_bootstrap` and

4. Replace list-membership deduplication in `_init_env_example_search_paths`
