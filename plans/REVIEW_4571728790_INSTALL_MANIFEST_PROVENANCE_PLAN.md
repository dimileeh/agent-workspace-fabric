# Review 4571728790 Install Manifest Provenance Plan

## Problem Statement and Scope

Greptile's review-level comment reports two manifest release-tooling gaps:
release manifests generated by GitHub Actions omit commit provenance, and the
`prerelease` channel rejection path for final versions lacks direct test
coverage.

The suggested workflow edit touches `.github/workflows/publish.yml`, which is a
protected quality-gate file and is not explicitly declared as owned by this
workspace. Scope is therefore limited to non-protected release generator and
test changes that satisfy the provenance requirement without editing the
workflow.

## Requirements Checklist

- Do not edit `.github/workflows/publish.yml` without explicit protected-file
  ownership.
- Ensure the manifest generator records `GITHUB_SHA` as `source.commit` when it
  runs under GitHub Actions and no explicit `--commit` value is supplied.
- Preserve existing explicit `--commit` behavior and local non-Actions behavior.
- Add regression coverage for final versions rejected from the `prerelease`
  channel.
- Run only focused validation; full AWF/GitHub validation remains managed after
  agent completion.

## Implementation Steps

1. Add focused tests for GitHub Actions `GITHUB_SHA` provenance fallback and the
   final-version `prerelease` rejection.
2. Confirm the provenance fallback test fails before implementation when
   practical.
3. Update the manifest CLI path to resolve the commit from explicit `--commit`
   first, then from `GITHUB_SHA` only in GitHub Actions.
4. Run focused generator tests and targeted lint for the touched files.
5. Record evidence in the matching validation document.
